# Plan 06.6-01: Declarative Linear Products and IfcRailing Bugfix

## Objective

Close the workflow gap that silently drops confirmed `IfcRailing` facts while
creating a bounded reusable contract for storey-local linear products. Use
strict vertical-slice TDD and preserve accepted Easy/Medium behavior.

## Constraints

- JSON Schema remains the only Formal BIM JSON structural truth.
- Do not add a second BIM model or a generic alias accepted by Formal
  validation.
- Do not invent railing endpoints, elevation, height, or thickness.
- Do not weaken existing deterministic Gates.
- Do not claim curved, typed, post-and-baluster, or materialized railing
  support.
- Do not modify frozen `STD-D-MUL-01`.
- A live successor input must carry a new hash and `supersedes` provenance.

## Wave 1: RED - projection and package ownership

Add focused tests at the public `build_expected_facts` seam using a ready
two-storey Design Brief with two explicit railings.

Expected failing behavior:

- `products` contains both stable railing IDs and exact source geometry;
- `total_counts.IfcRailing == 2`;
- `required_relationships.containment.products == 2`;
- the `storey-2` package owns both IDs;
- unknown storey and incomplete geometry produce deterministic package issues
  rather than silently disappearing.

Run the focused tests and retain the RED output before implementation.

## Wave 2: GREEN - declarative product projection

Implement the smallest additive family registry and projection needed for
`known_facts.railings`. Extend package ownership through generic product
records. Do not refactor existing wall/door/window paths.

Verification:

```powershell
.venv\Scripts\python -m pytest tests/agent/test_phase6_3_expected_facts.py tests/agent/test_phase6_5_generation_packages.py -q
```

## Wave 3: RED/GREEN - generic containment and geometry Gates

At the public `evaluate_dynamic_gates` and
`build_design_geometry_expectation` seams, add one failing behavior at a time:

1. missing expected `IfcRailing`;
2. correct class on the wrong storey;
3. shifted segment endpoints;
4. wrong base elevation, height, or thickness;
5. valid matching segment.

Implement generic product identity, containment, bounding-box, and linear-
segment comparison. Issue paths must reference `/products/<id>` and use stable
codes. Do not introduce an Audit-only acceptance path.

Verification:

```powershell
.venv\Scripts\python -m pytest tests/agent/test_phase6_3_dynamic_gates.py tests/agent/test_phase6_4_geometry_truth.py -q
```

## Wave 4: RED/GREEN - prompt pattern and compiler fixture

Add a focused linear-segment few-shot using `IfcRailing`, register its hash,
and add prompt-asset assertions for explicit facts and prohibited defaults.
Add a deterministic Formal BIM JSON fixture with two straight railing segments,
compile it to IFC2X3, reopen with IfcOpenShell, and assert:

- exactly two `IfcRailing` entities;
- supported `Representation` on each;
- both are contained by `storey-2`;
- reopened bounding boxes match the explicit endpoints, height, and thickness
  within tolerance.

Compiler production code changes are allowed only if the RED fixture proves a
real compiler gap.

## Wave 5: Regression and Difficult successor preparation

Run focused Agent tests, prompt registry checks, compiler tests, compileall,
and the full Agent suite. Then create `STD-D-MUL-02` without changing the
frozen source. The successor must explicitly state:

- atrium bounds and two railing centerlines;
- railing height and simplified solid thickness;
- door/window placement policy;
- a non-conflicting stair/opening zone;
- an explicitly supported stair geometry;
- every altered room/corridor dimension;
- `supersedes: STD-D-MUL-01`, reason, source hash, and `model_output: null`.

Do not run the provider until deterministic manifest and prompt checks pass.

## Wave 6: Real-provider UAT and verification

Run the revised Difficult manifest once with the established 64K runtime
budget. Preserve all provider, package, Gate, Audit, compile, reopen, hash,
usage, and secret-scan evidence.

Acceptance requires:

- no unresolved Design Brief question;
- Formal BIM JSON 2.0 validation;
- two expected and two generated `IfcRailing` entities;
- correct second-storey containment;
- centerline alignment with the declared atrium edges;
- correct height and thickness;
- both slab openings and the stair represented without collisions;
- IFC2X3 compile and independent reopen;
- non-blocking Audit and zero secret findings;
- human visual review before `STABLE-01` becomes 3 / 3.

If the live run fails, append one classified experiment and issue entry before
any further TDD. Do not tune multiple variables between observations.
