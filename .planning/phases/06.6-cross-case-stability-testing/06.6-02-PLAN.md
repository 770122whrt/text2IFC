# Plan 06.6-02: Stair-Wall Collision Gate and Difficult Successor

## Objective

Reject a generated stair flight that physically crosses an ordinary wall, then
create and run a provenance-linked Difficult input whose stair has an explicit
wall passage, exterior clearance, matching slab opening, and upper-floor
opening guards.

## Fixed Diagnosis

Session `53df7ac99abf41e8` reconstructed the `STD-D-MUL-02` coordinates
faithfully. The input simultaneously required a stair through `y=3750..8000`,
a full wall across `y=5000`, and a north exterior wall centered at `y=8000`.
The compiler did not move either component. The defect is an inconsistent
input contract plus a missing deterministic cross-category geometry Gate.

## Wave 1: Record and RED

Add a minimal compiled fixture where the expected and generated stair flight
matches its own bounding box but intersects a generated wall. Assert a blocking
`STAIR_WALL_INTERSECTION` issue containing stair, flight, and wall IDs plus the
world overlap bounds. Confirm the existing Gate incorrectly passes before
implementation and commit the RED test separately.

Add a second fixture with two wall segments and an explicit gap around the
stair. It must remain accepted so the repair does not ban valid open passages.

## Wave 2: GREEN Gate

Extend the generated-IFC geometry Gate after wall and stair bboxes are reopened.
For each expected stair flight and expected wall, reject positive three-axis
solid bounding-box overlap larger than tolerance. Touching without positive
volume is allowed. Do not delegate acceptance to Audit and do not infer a wall
opening that is absent from explicit geometry.

## Wave 3: Freeze `STD-D-MUL-03`

Preserve `STD-D-MUL-02` unchanged. Add a successor with a new input hash and
`supersedes: STD-D-MUL-02`:

- stair flight bounds `x=10000..11000, y=4000..7750`;
- start `[11000,7750,0]`, run direction `-Y`, rise 3300 mm;
- 18 risers, 17 treads, total run 3750 mm, tread depth `3750/17` mm;
- stair opening `x=9900..11100, y=4000..7750`;
- split the corridor/stair-hall wall into `x=7000..9900` and
  `x=11100..12000`, leaving a 1200 mm open passage;
- move the hosted stair-hall door to the west wall segment without changing
  its explicit center;
- reduce second-storey corridor and bedroom-two east bounds to `x=9900` so
  neither space overlaps the stair opening;
- keep the two atrium guards;
- add west, east, and north second-storey stair-opening guards, leaving the
  south arrival edge open;
- require five `IfcRailing` entities total and zero stair-wall intersections.

## Wave 4: Deterministic Verification

Run focused Gate, expected-fact, package, prompt, compiler, and manifest
identity tests. Run the complete Agent and compiler/contract regressions,
compileall, diff check, and configured-secret scan before a provider call.

## Wave 5: One Real Successor Observation

Run `STD-D-MUL-03` once with the established real provider and 64K completion
budget. Acceptance requires Formal BIM JSON 2.0, five expected railings, two
independent slab openings, one stepped stair flight, zero stair-wall collision
issues, all deterministic Gates, non-blocking Audit, IFC2X3 compile/reopen,
preservation rate 1.0, and zero secret findings.

Machine acceptance does not close `STABLE-01`; retain the IFC for a new human
visual check of wall passage, exterior clearance, stair opening, and all five
