# Phase 6.5 AI Contract

## Roles

### Design Brief Agent

Unchanged responsibility: preserve user facts, identify missing facts, and
produce a ready or Draft brief. It does not create ChangeSets.

### Initial BIM JSON Generator

Produces either the first complete candidate or a package ChangeSet when the
orchestrator is in staged-composition mode. It receives an explicit generation
scope and cannot claim the partial workspace is Formal.

### ChangeSet Generator

Receives:

- original user text and conversation;
- ready Design Brief and expected facts;
- compact stable-ID candidate index, not an unconstrained replacement request;
- exact base/evidence hashes;
- normalized Issues with expected and actual evidence;
- deterministic allowed entity, relationship, and field scope;
- dependency closure and forbidden untouched IDs;
- complete ChangeSet schema and focused examples.

It returns exactly one ChangeSet object or canonical Draft. It does not return
raw IFC, a full Formal BIM JSON replacement, prose, or compiler objects.

### Audit Agent

Receives the original intent, Design Brief, revision summary, applied
operations, preservation report, complete Gate bundle, and IFC evidence. It
may accept, block, dispute applicability, or recommend another scoped revision.
It cannot expand scope or override deterministic failure.

## Prompt Requirements

- Use a dedicated versioned template, not conditional paragraphs added to the
  existing full Generator prompt indefinitely.
- Include one minimal single-component correction example and one coupled
  host/opening/filling or stair/slab dependency example.
- State that every operation must cite issue IDs and modify only declared IDs
  and paths.
- State that missing user facts require Draft and unsupported compiler/schema
  capability requires a blocked result through routing.
- Do not include benchmark-specific room names, fixed storey counts, or exact
  acceptance-case coordinates in production prompt rules.

## Live Evidence

Every ChangeSet call records provider response ID, model, finish reason, usage,
prompt template ID/hash, renderer inputs, raw response reference, parsed output,
contract result, base revision, and application result. Secret values and
private provider URLs are never persisted.

## Evaluation Dimensions

| Dimension | Metric | Required result |
|---|---|---|
| Contract | ChangeSet parse/schema validity | 100% for accepted rounds |
| Scope | unauthorized operation count | 0 |
| Preservation | unrelated semantic hash preservation | 1.0 |
| Repair | blocking issue reduction | strictly improves or stops |
| Fidelity | applicable expected facts satisfied | 100% at acceptance |
| IFC | compile/reopen and geometry Gates | all pass |
| Audit | recommendation | accepted with no deterministic failure |
| Stability | consecutive accepted live runs | 3/3 per canonical case |
