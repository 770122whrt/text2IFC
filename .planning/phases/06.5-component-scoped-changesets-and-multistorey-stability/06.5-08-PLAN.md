# Phase 6.5-08: Standard-input Coverage UAT and Issue Triage

## Goal

Run three distinct frozen Chinese Text2IFC inputs at Easy, Medium, and
Difficult levels, retain complete evidence, and establish whether the current
pipeline is operationally stable across cases without tuning against failures
during the observation batch.

## Boundaries

- This plan starts as UAT and evidence collection, not TDD.
- Do not change production code, schemas, prompts, few-shots, Gates, Audit
  rules, or expected outputs while the three primary runs are being collected.
- Every failure is appended to `06.5-ISSUE-REGISTER.md` before diagnosis.
- Unsupported explicit requirements remain Draft/blocking; they are not
  silently dropped to make a case pass.

## Task 1: Freeze Inputs and Run Manifests

1. Read `tests/text2ifc_basic_test_inputs.md` as UTF-8.
2. Extract the three sections named in `06.5-STANDARD-INPUT-ACCEPTANCE.md`.
3. Write immutable case manifests containing source path, heading, exact text,
   SHA-256, provider/model configuration identifiers, and acceptance version.
4. Verify that no manifest contains credentials or hidden model answers.

## Task 2: Execute the Three-case Observation Batch

Run `STD-E-RES-01`, then `STD-M-OFF-01`, then `STD-D-MUL-01` through the real
Text -> BIM JSON 2.0 -> IFC2X3 workflow. Preserve clarification transcripts,
provider IDs, candidates, ChangeSets, Gate/Audit evidence, reports, and IFC
artifacts. Do not repair code between cases.

## Task 3: Record and Classify Issues

1. Add every discrepancy to `06.5-ISSUE-REGISTER.md` at `observed` status.
2. Complete the three-case batch even if an earlier case fails, unless a
   credential, security, or destructive runtime blocker prevents continuation.
3. After all runs, classify ownership and compare failures for a common cause.
4. Do not begin TDD. Produce a triage recommendation for user review.

## Task 4: Acceptance Report

Generate one matrix row per case with input hash, clarification count,
Formal/Draft result, schema and semantic status, Gate/Audit results,
compile/reopen result, preservation, secret scan, IFC/report paths, and human
review status. Mark the suite accepted only when all three primary cases pass.

## Completion Gate

- All three frozen inputs have traceable run records.
- All observed problems are present in the unified issue register.
- No implementation or prompt change occurred during the observation batch.
- If all three pass, report bounded cross-case operational stability.
- If any fails, report partial coverage and await issue-triage approval; do not
  claim completion and do not automatically start TDD.
