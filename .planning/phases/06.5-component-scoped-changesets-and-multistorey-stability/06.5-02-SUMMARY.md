# Phase 6.5-02 Summary: ChangeSet Generator and Feedback Loop

**Completed:** 2026-07-12
**Status:** Deterministic scoped-feedback milestone complete

## Delivered

- Registered a dedicated ChangeSet Generator prompt with canonical ChangeSet
  and Draft schemas plus generic single-component and coupled-dependency examples.
- Added a provider-backed ChangeSet stage that records prompt identity, rendered
  inputs, raw response, parsed output, provider metadata, usage, validation, and
  metrics without exposing secrets.
- Added exact resolution from candidate collection paths to stable entity or
  relationship IDs. Unknown or out-of-range refs block instead of widening scope.
- Added one bounded scoped round: derive scope, call the provider, validate the
  response, apply transactionally, write a new revision, and report preservation.
- Replaced the active Audit/Gate feedback execution path that previously called
  the full-document Generator. The initial full candidate remains intact as trace
  evidence; later model calls can only propose a ChangeSet or canonical Draft.
- Reruns semantic coverage, deterministic Gates, IFC compile/reopen, generated
  geometry checks, and Audit after each successfully applied revision.
- Preserves a maximum of three feedback rounds and stops cleanly when ChangeSet
  output is invalid or cannot be scoped.

## Deterministic Proof

- Accepted ChangeSet: provider stage plus immutable application creates
  `revision-01` and preserves all unrelated component hashes.
- Draft: canonical Draft is accepted as an explicit non-application outcome.
- Scope violation: unauthorized paths and targets create no candidate revision.
- Stale binding: stale candidate/revision hashes are blocked before promotion.
- Bounded non-improvement: existing structured issue signatures and the
  three-round feedback limit remain binding; issue count alone is not treated as
  proof of improvement.
