# Phase 6.5-10: Canonical Single-storey Design Brief Projection

## Goal

Resolve `P65-UAT-004`: a complete single-storey request must project to one
storey and its explicit spaces, walls, doors, and windows instead of silently
becoming an empty generation scope.

## Success Criteria

For the frozen Easy facts, deterministic projection yields exactly:

- 1 storey;
- 1 space;
- 4 walls;
- 1 door;
- 1 window;
- a non-empty per-storey generation package and entity authorization.

A `ready` Design Brief that cannot produce any storey must fail closed with a
specific projection diagnostic. It must never continue as `storey_count=0`.

## Boundaries

- Do not change the frozen Easy natural-language input.
- Do not add default dimensions, walls, openings, or user semantics.
- Use one canonical internal dialect: `known_facts.storeys[]`, including for a
  one-storey building.
- A deterministic migration may preserve explicitly supplied legacy singular
  facts, but downstream code and new Prompt examples must use only the
  canonical dialect.
- Do not address Medium corridor enclosure policy, Difficult response
  truncation, provider token limits, compiler geometry, or IFC output here.
- No live provider rerun is required until deterministic replay is green.

## Task 1: RED Contract Tests

1. Add a test proving the complete-room few-shot uses canonical
   `known_facts.storeys[]` with stable IDs and nested components.
2. Add an Easy projection test asserting the exact 1/1/4/1/1 inventory.
3. Add a fail-closed test proving a `ready` but unprojectable Design Brief
   raises a named diagnostic rather than emitting zero storeys.
4. Commit RED before production or Prompt changes.

## Task 2: Minimal GREEN Contract Repair

1. Update the single-room few-shot and Design Brief Prompt instructions to use
   the same canonical storey structure already used by multi-storey examples.
2. Update the Prompt registry hash without changing unrelated templates.
3. Add the smallest projection guard needed to reject empty `ready` results.
4. Avoid a growing alias matrix or a second Design Brief model.

## Task 3: Offline Easy Replay and Regression

1. Replay the canonical Easy Design Brief through `build_expected_facts` and
   `build_generation_package_manifest` without provider access.
2. Verify all explicit values and host IDs are preserved.
3. Run focused Prompt, Design Brief, expected-facts, package, and live-harness
   tests, followed by the complete Agent regression and compileall.
4. Scan changed Prompt/planning artifacts for sensitive values.

## Completion Gate

- RED failure is retained in Git history.
- All success-criteria counts pass deterministically.
- Empty ready projection is impossible without a specific error.
- No Medium/Difficult behavior or IFC compiler behavior changes.
- `P65-UAT-004` is marked resolved only after regression evidence passes.
