# Phase 6.5-09: Prompt Identity Portability Repair and Frozen Rerun

## Goal

Resolve `P65-UAT-003` without changing prompt semantics, then rerun the exact
Easy, Medium, and Difficult manifests from Wave 8 through the real provider
pipeline.

## Frozen Boundaries

- Do not edit Prompt text, few-shots, schemas, capability profiles, compiler
  behavior, Gates, Audit rules, or expected outputs.
- Do not edit the three manifest inputs or their recorded SHA-256 values.
- Prompt identity is the SHA-256 of UTF-8 bytes after CRLF is normalized to LF.
  Other bytes remain unchanged.
- Keep the original Wave 8 artifacts immutable. Write rerun artifacts to a new
  Wave 9 directory and link both attempts in the final report.
- Do not tune between Easy, Medium, and Difficult runs. Collect the complete
  batch before classifying any new issue.

## Task 1: RED and Root-cause Evidence

1. Add a public-interface regression test proving that a registered Prompt has
   the same identity under LF and CRLF checkout forms.
2. Run the focused test and retain the expected `PromptRegistryError` as RED.
3. Commit the test and approved repair plan before production changes.

## Task 2: Minimal GREEN Repair

1. Canonicalize CRLF to LF only at Prompt hash computation.
2. Migrate `bim-json-generator.v3` from its legacy CRLF hash to the canonical LF
   hash. Do not change the template file.
3. Run the focused RED test, all Prompt Registry tests, Mimo Prompt asset tests,
   and the Phase 6.5 live harness configuration test.
4. Commit the deterministic repair independently from live-run artifacts.

## Task 3: Exact Three-case Rerun

1. Verify the source input SHA-256 and all three manifest hashes are unchanged.
2. Run `STD-E-RES-01`, `STD-M-OFF-01`, and `STD-D-MUL-01` once each using the
   configured DeepSeek OpenAI-compatible provider.
3. Preserve clarification, provider, candidate, Gate, Audit, compile/reopen,
   report, and IFC evidence. Never log credentials or provider URLs.
4. Do not modify implementation between cases.

## Task 4: Verification and Decision

Produce a machine-readable matrix and Markdown report. For each case record
whether it reached the provider, Draft/Formal status, clarification count,
schema/semantic/Gate/Audit status, IFC compile/reopen status, artifact paths,
and secret-scan result. Update the unified issue register before any further
repair.

## Completion Gate

- Prompt Registry tests pass on the Windows CRLF worktree.
- The registered identities are canonical and reproducible across LF/CRLF.
- All three frozen inputs were attempted without between-case tuning.
- A case is accepted only when it produces valid Formal BIM JSON 2.0 and a
  reopenable IFC2X3 artifact with passing required Gates and Audit.
- Phase 6.5 stability is accepted only if all three cases pass. Otherwise the
  report remains partial and newly observed issues await separate triage.
