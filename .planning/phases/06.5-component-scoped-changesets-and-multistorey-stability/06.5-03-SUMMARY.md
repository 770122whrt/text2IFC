# Phase 6.5-03 Summary: Staged Multi-storey Composition

**Completed:** 2026-07-12
**Status:** Deterministic staged-composition milestone complete

## Delivered

- Dynamic package manifests with one deterministic skeleton, one local package
  per explicit storey, and one cross-storey package for any storey count.
- Draft routing for missing elevations, unresolved ownership, missing hosts,
  blocking expected facts, and unknown vertical endpoints.
- Explicit wall expected-fact extraction from top-level, storey-map, and nested
  Design Brief structures without deriving unprovided wall segments.
- Package ownership/reference Gates for duplicate IDs, multiple owners,
  unresolved references, cross-storey host mismatches, orphan openings, and
  local/cross component-class boundaries.
- Provider-backed staged generation using canonical ChangeSets and full
  per-package prompt/response/validation traces.
- Partial workspaces marked `partial_not_formal` and never compile-eligible.
  Only the complete composed document is promoted after BIM JSON 2.0 validation.
- Package-local retry up to three attempts. Accepted package hashes remain
  frozen and Draft stops immediately.
- Dynamic spatial skeletons for two, three, five, or other explicit storey
  counts, plus a selectable CLI `staged` strategy while legacy full generation
  remains the rollout default.

## Honest Boundary

- Deterministic two- and three-storey staged fixtures compose to Formal BIM JSON
  and retain real provider-adapter trace structure, but this is not live DeepSeek
  quality evidence.
- Live staged generation requires an explicit wall inventory in the Design Brief
  or expected facts. Existing briefs that only name selected host walls are not
  silently treated as complete wall topology.
- Final IFC compile/reopen, revision-aware reports, timing, and compact evidence
  are Wave 4 responsibilities.
