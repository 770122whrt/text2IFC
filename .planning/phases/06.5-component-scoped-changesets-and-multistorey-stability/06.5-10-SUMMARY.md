# Phase 6.5-10 Summary: Canonical Single-storey Design Brief Projection

## Outcome

Wave 10 resolved the deterministic portion of `P65-UAT-004`. A complete
single-storey room now has one canonical internal projection with one storey,
one space, four exterior walls, one door, and one window. The generated
storey-local package contains owned components, opening/fill relationships,
and explicit host-wall references.

The original Wave 10 implementation did not rerun DeepSeek. A follow-up on
2026-07-16 used the unchanged frozen `STD-E-RES-01` manifest and produced one
accepted, reopenable IFC. `STABLE-01` is therefore open at 1 / 3 accepted IFC
files.

## Root Cause

The Easy Design Brief was marked `ready` but used singular objects under
`known_facts`: `storey`, `space`, `door`, and `window`, with `walls` represented
as a count/enclosure summary. The Prompt registry selected a matching simple
room few-shot that taught the same singular dialect. The expected-facts
projector only consumed `known_facts.storeys[]` and silently returned an empty
list, producing `storey_count: 0` and an empty generation authorization.

This was a workflow contract mismatch, not an incomplete Easy natural-language
request. The broad Design Brief schema allowed the mismatch because
`known_facts` remains an extensible semantic container.

## Changes

- The Design Brief Prompt now requires `known_facts.storeys[]` for every
  building, including a single-storey building, and forbids singular top-level
  storey/component keys.
- All simple-room Design Brief few-shots now use the same nested storey
  structure as the multi-storey examples.
- The Prompt registry hash for `design-brief.v2.1` was regenerated using the
  repository's canonical LF hashing rule.
- `expected_facts.py` now raises
  `DESIGN_BRIEF_PROJECTION_EMPTY` for an unprojectable `ready` brief instead of
  continuing with zero storeys.
- A bounded migration accepts only an explicitly complete historical room:
  positive length/width/height, four closed walls, and explicit wall
  thickness. It preserves supplied wall, door, window, and semantic fields and
  maps known south/north/west/east host labels to stable wall IDs. It is not a
  general alias matrix and does not fill missing required facts.
- The historical REPL fixture now includes the answered wall thickness when it
  declares the second-round brief `ready`.
