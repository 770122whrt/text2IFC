# Phase 6.5 Medium Geometry Contract Bugfix Spec

## Status

The live Medium session `6413b537e99bba35` is rejected despite its previous
Gate/Audit acceptance. IFC reopen succeeds, but independent geometry review
found first-storey space and interior-wall drift plus stair/opening drift.

This bugfix is a provider-independent contract repair. It is not a collection
of DeepSeek-output aliases and it does not authorize silent geometry fixes.

## Root Cause Boundary

The compiler serializes the supplied BIM JSON profile and placement. The
current false acceptance occurs earlier:

1. Prompt and few-shot examples do not state the rectangle center-origin or
   stair coordinate rules precisely enough.
2. The expectation extractor reads legacy shapes such as `bounding_box` and
   `from`/`to`, while canonical expected facts use `bounds` and `connects`.
3. A partially populated semantic expectation is allowed to continue, so
   omitted spaces, interior walls, slabs, stairs, and openings are not checked.
4. Audit is told that deterministic geometry passed and cannot recover the
   missing checks by inspection alone.

## Canonical Contract

### Design Brief fields

- Space: `bounds: {"x": [x_min, x_max], "y": [y_min, y_max]}` plus storey.
- Interior wall: `connects: [space_a_id, space_b_id]`.
- Slab/roof: `polygon: [[x, y], ...]` plus elevation and thickness.
- Stair and floor opening: explicit bounds, source/target storeys, and one
  coordinate frame.

The existing canonical fields remain authoritative. Production parsing does
not add aliases merely because one model response used a different spelling.

### BIM JSON geometry

- A rectangular `IfcSpace`, wall, stair flight, or opening profile uses its
  geometric center as the local placement origin.
- For bounds `[x_min, x_max]`, `[y_min, y_max]`, the center is
  `((x_min+x_max)/2, (y_min+y_max)/2)` and dimensions are the positive spans.
- An interior wall is placed on the unique shared boundary of the two spaces
  referenced by `connects`. Missing or non-unique boundaries are Draft/Issue,
  not guessed geometry.
- Stair orientation is represented once. Parent placement and child profile
  must not both rotate the same axis.
- The upper slab opening must contain the stair arrival footprint with the
  configured tolerance and must remain on the target storey slab.

## Deterministic Issue Contract

The Gate must emit one issue per failing component with:

```text
code
component_id
expected
actual
evidence_refs
owner
route
status
```

Required issue codes for the current rejected Medium candidate:

- `SPACE_BBOX_MISMATCH`
- `INTERIOR_WALL_SHARED_BOUNDARY_MISMATCH`
- `STAIR_BBOX_MISMATCH`
- `FLOOR_OPENING_BBOX_MISMATCH`

The default owner/route is `generator/regenerate_json` for schema-valid but
semantically wrong geometry. Syntax/schema-only failures remain
`repair/repair_json`. Missing user facts route to Design Brief/User Draft.

## Post-acceptance wall-junction finding

Manual review of live session `a95a0f967982690a` found that the current
shared-boundary contract is insufficient to prove a coherent wall network.
This is recorded as an open bugfix requirement; it is not yet an implemented
Gate.

- Do not require every interior wall to connect directly to an exterior wall.
  Interior walls may terminate at another interior wall, an explicitly modeled
  opening or stair void boundary, or an explicitly declared open/virtual
  boundary.
- Each interior-wall endpoint must nevertheless have one of those supported
  termination conditions. A free endpoint cannot pass merely because the wall
  lies on the shared boundary of two spaces.
- `wall-2-core-east-north` is not a defect. The input, Design Brief, expected
  facts, BIM JSON, and IFC all place it on `x=5800`, `y=2400..4000`, the exact
  overlap between `space-2-core-lobby` and `space-2-east-north`. Human review
  accepts its north endpoint at `(5800,4000)` as an intentional interior open
  termination for this fixture. A future fixture should express that open
  termination explicitly so a deterministic Gate does not have to infer it.
- Separate perimeter-facing walls exhibit a confirmed 100 mm datum gap: the
  exterior outline is a wall centerline while affected space bounds use a
  200 mm inset. Coordinate-datum repair and endpoint-topology validation must
  remain separate findings.

The future deterministic issue is limited to an interior wall that is expected
to meet a perimeter wall but stops short of its inner face. It must identify
the wall ID, endpoint coordinate, target exterior wall, measured gap, and
expected termination evidence. It must route unresolved model geometry to
`generator/regenerate_json` and must never silently extend a wall. Intentional
interior open ends such as `wall-2-core-east-north` must not be reported.

## Progressive Repair Groups

1. First-storey spaces.
2. First-storey interior walls, with repaired spaces as read-only evidence.
3. Stair, flight, upper-slab opening, and their relationships.

After each group, run the relevant local Gates. After all groups, run global
schema, containment, compile/reopen, geometry, opening/filling, Audit, and
unchanged-component hash checks.

## Human-visible Progress

Console and generated report output must expose each issue and transition:

```text
[Issue 03/13]
code: SPACE_BBOX_MISMATCH
component: space-storey-1-meeting
expected: <bounded summary>
actual: <bounded summary>
owner: generator
route: regenerate_json
status: open
```

After repair, the same issue becomes `resolved`, `still_open`, or `superseded`.
The canonical machine records remain `progress.jsonl`,
`feedback-rounds.json`, and generated `report.md`; no file-per-issue expansion
is introduced.

## Non-goals

- No case-specific room names, coordinates, or storey counts in production.
- No silent center correction, polygon closure, or stair rotation rewrite.
- No broad compatibility layer for arbitrary provider dialects.
- No Hard live run until the Medium deterministic replay is green.

## Acceptance

- Prompt and few-shot tests prove the canonical coordinate rules are present.
- Extractor tests cover canonical `bounds`, `connects`, polygon, stair, and
  opening facts and reject unresolved required geometry.
- Offline replay finds the known 13 Medium issues with no false pass.
- Scoped revisions preserve unrelated semantic hashes at 1.0.
- One fresh real DeepSeek Medium run passes all deterministic Gates, Audit,
  compile/reopen, secret scan, and manual IFC handoff.
