# Phase 6.5-01: Immutable Applicator and Dependency Scope

**Goal:** Apply only authorized semantic changes and prove everything else is unchanged.

**Architecture:** Build a stable-ID candidate index, derive dependency closure
from current entities/relationships and Issue evidence, validate a ChangeSet
against that scope, then apply it to a deep copy and validate the complete
result through the canonical BIM JSON validator.

## Task 1: Candidate index and component hashes

**Files:**
- Create: `src/text2ifc_agent/candidate_index.py`
- Create: `tests/agent/test_phase6_5_candidate_index.py`

1. RED: index entities and relationships by semantic ID independent of array
   order; reject duplicates and missing stable IDs.
2. RED: prove semantically identical reordered collections produce identical
   per-component hashes.
3. GREEN: canonicalize one component at a time without mutating the source.
4. Commit RED and GREEN atomically as separate commits.

## Task 2: Deterministic dependency closure

**Files:**
- Create: `src/text2ifc_agent/change_scope.py`
- Create: `tests/agent/test_phase6_5_change_scope.py`
- Reuse: `src/text2ifc_agent/issues.py`
- Reuse: `src/text2ifc_agent/expected_facts.py`

1. RED: map component-specific Issues to initial targets using actual/expected
   refs and stable IDs, never English/Chinese name guessing alone.
2. RED: cover host wall -> opening -> filling, element -> containment,
   space -> boundary wall, and stair -> flight/landing/slab opening closures.
3. RED: unresolved target identity must block as
   `CHANGESET_TARGET_UNRESOLVED`, not broaden to the whole model.
4. GREEN: return an explainable scope whose every added dependency records its
   parent target and relation reason.

## Task 3: Immutable ChangeSet applicator

**Files:**
- Create: `src/text2ifc_agent/changeset_apply.py`
- Create: `tests/agent/test_phase6_5_changeset_apply.py`
- Reuse: `src/text2ifc_agent/fact_delta.py`

1. RED: add/update/remove targeted entity and relationship operations produce
   a new candidate while preserving the original bytes.
2. RED: reject stale hashes, unknown targets, implicit cascade delete,
   out-of-scope fields/IDs, evidence-free changes, duplicate additions, and a
   composed document that fails `validate_v2_document`.
3. GREEN: validate all operations first, apply to a copy, canonicalize
   collections, run Formal validation, compute revision/component hashes, and
   write only after all checks pass.
4. Generate a preservation report with changed, dependency, unchanged, and
   forbidden-drift ID sets plus the preservation rate.

## Task 4: Regression and checkpoint

1. Run ChangeSet/revision/index/scope/applicator tests.
2. Run existing repair fact-delta, issue, expected-fact, and contract-v2 tests.
3. Write `06.5-01-SUMMARY.md`; update STATE and ROADMAP only with passed facts.

## Completion Gate

A deterministic fixture can repair a coupled opening/filling error and a
stair/slab-opening error while all unrelated component hashes remain identical.
