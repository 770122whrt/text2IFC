# Phase 6.5 Standard-input Acceptance

## Decision

Phase 6.5 uses coverage-oriented stability evidence instead of repeatedly
running one prompt. The acceptance source is the user-provided Chinese input
pool in `tests/text2ifc_basic_test_inputs.md`.

The source contains nine cases across three building domains and three
difficulty levels. Three cases form the primary acceptance gate; the remaining
six form an expansion suite.

## Frozen Primary Set

| ID | Difficulty | Source section | Coverage purpose |
|---|---|---|---|
| `STD-E-RES-01` | Easy | `2.2 Easy: 单个矩形房间` | Basic space enclosure, four walls, slab, one door, one window, and host relations |
| `STD-M-OFF-01` | Medium | `3.3 Medium: 三间办公室与公共走廊` | Shared-wall deduplication, corridor connectivity, multiple spaces, doors, and windows |
| `STD-D-MUL-01` | Difficult | `4.4 Difficult: 带挑空区域的两层建筑` | Storeys, stairs, slab opening, void area, railing, containment, and vertical topology |

These sections must be copied byte-for-byte into each run manifest before the
first provider call. They cannot be weakened or rewritten after seeing output.
Any clarification transcript is retained as part of the input evidence.

## Expansion Set

The other six cases remain part of the test pool and should be run after the
primary gate or when diagnosing a capability boundary. An expansion failure
does not erase a primary pass, but it must be recorded and cannot be hidden
from reports.

## Per-case Acceptance

Each primary case passes only when all applicable checks succeed:

1. A real provider processes the frozen natural-language input; fake, file,
   replay, or prewritten model output does not count.
2. Clarification remains explicit and does not silently invent required facts.
3. Formal BIM JSON 2.0 validates against the canonical JSON Schema.
4. Semantic coverage and all applicable deterministic Gates pass.
5. IFC2X3 compiles, reopens with IfcOpenShell, and passes postcompile geometry
   and relationship checks.
6. Audit is non-blocking and does not override a failed deterministic Gate.
7. Any ChangeSet keeps unrelated-component preservation at `1.0`.
8. Prompt/provider IDs, candidate and evidence hashes, report, IFC path, and
   a zero-finding secret scan are retained.
9. Human review confirms there is no obvious missing component, broken room
   enclosure, incorrect storey assignment, or incoherent spatial relation.

All three primary cases must pass. The result may be described as bounded
cross-case operational stability, not as a statistical success rate.

## Observation-first Rule

The three primary runs form one observation batch. A failure is written to
`06.5-ISSUE-REGISTER.md` with exact evidence before anyone changes prompts,
code, schemas, Gates, few-shots, or test expectations. After the batch, issues
are classified and prioritized. TDD begins only for an explicitly approved
fix plan.
