# Phase 6.5 Validation Strategy

## TDD Rule

Each eligible behavior begins with a focused failing test committed separately
from its minimal implementation. No real provider run substitutes for a RED
test, and fake providers cannot satisfy live acceptance.

## Test Layers

1. **Contract tests**: ChangeSet schema, stable IDs, hashes, operations, paths,
   evidence, and canonical Draft alternatives.
2. **Applicator tests**: immutable revisions, deterministic ordering, add/update/
   remove semantics, stale bases, and rollback on failure.
3. **Scope tests**: issue-to-target mapping, host/opening/filling closure,
   stair/slab/opening closure, containment, and unrelated drift rejection.
4. **Loop tests**: Audit/Gate failure -> ChangeSet -> apply -> local/global Gates
   -> Audit; non-improvement and three-round stop behavior.
5. **Composition tests**: dynamic skeleton, two/three storey packages,
   cross-storey ownership, duplicate IDs, and final Formal validation.
6. **Compiler/Gate regression**: existing BIM JSON compiler, stair, slab, roof,
   opening/filling, storey, expected-fact, geometry, and report suites.
7. **Live DeepSeek UAT**: independent sessions with real response evidence.

## Required Commands

Focused commands will be finalized against created test modules in each plan.
Final verification must include:

```powershell
.venv\Scripts\python -m pytest tests\agent -q
.venv\Scripts\python -m pytest tests\compiler tests\contract_v2 tests\ifc_quality -q
.venv\Scripts\python -m compileall src scripts tests
```

It must also execute the Phase 6.5 deterministic matrix, two-storey live
campaign, three-storey live campaign, artifact verifier, and secret scanner.

## Live Acceptance Matrix

Each row records:

- case and session hashes;
- provider/model and response IDs;
- first-candidate status;
- ChangeSet round count and operation count;
- issue count before and after each round;
- changed IDs and dependency closure;
- unrelated preservation rate;
- schema, semantic, compile, reopen, geometry, Audit, and secret-scan results;
- final IFC and report paths;
- elapsed time by stage and total duration.

## Stop Conditions

- Stop and report if a ChangeSet would require facts absent from user evidence.
- Stop and report if dependency closure cannot be derived deterministically.
- Stop and report if provider output repeatedly violates the ChangeSet contract.
- Stop after three non-accepted ChangeSet rounds.
- Never weaken a correct Gate solely to make a live case pass.
