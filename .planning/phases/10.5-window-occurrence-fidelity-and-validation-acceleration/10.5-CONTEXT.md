# Phase 10.5: Window Occurrence Fidelity and Validation Acceleration - Context

**Gathered:** 2026-07-26
**Status:** Ready for planning
**Source:** Window fidelity review after the LargeBuilding, vvo, and
AdvancedProject repair comparisons

<domain>
## Phase Boundary

Phase 10.5 makes the existing Window repair path as complete as practical
before the Registry expands to Door, Opening, Beam, or Column operations.

The phase must prove that a complete, authorized natural-language description
plus a damaged IFC2X3 model can restore the selected Window and its Opening to
the Ground Truth's geometry, relationships, effective occurrence semantics,
and relevant quantities. It also makes the unchanged blocking Production
evaluation complete within 180 seconds on AdvancedProject.

This phase does not require byte-identical IFC, original STEP IDs, original
GlobalIds, the same Pset ownership graph, or the same low-level geometry node
count. Those differences remain visible through `authoring_exactness` but do
not block publication.

</domain>

<decisions>
## Implementation Decisions

### D-01 — Required fidelity boundary

- The blocking repair boundary is the repaired `IfcWindow` plus its
  `IfcOpeningElement` chain.
- Required equivalence includes geometry, host/fill/containment relationships,
  effective occurrence attributes, effective scalar Pset values, and relevant
  Window/Opening quantities.
- The existing global preservation gate remains blocking for every
  non-authorized root.

### D-02 — L3 remains diagnostic

- Original GlobalIds, STEP IDs, serialization order, byte identity, exact
  placement/representation graphs, exact Pset ownership graphs, and total
  non-Root entity counts are not Phase 10.5 success criteria.
- These differences must be reported as `authoring_exactness` evidence rather
  than being silently ignored.

### D-03 — Authorized semantic sources

- A repaired fact may come from one of five explicit sources:
  `explicit_value`, `deterministic_derived`, `type_inherited`,
  `approved_occurrence_prototype`, or `authorized_type_cohort`.
- Every authored fact retains source kind, source reference, and bounded public
  provenance through RepairIntent, bound ChangeSet, compiler evidence, and
  evaluation.
- Property knowledge retrieval may resolve what a property means and its exact
  IFC2X3 path/type. It never invents the missing value.

### D-04 — Exact occurrence and cohort reuse

- An exact named/GUID-selected surviving occurrence may be used only when the
  user explicitly authorizes copying its occurrence semantic package.
- Same-Type cohort reuse is allowed only when the user explicitly authorizes
  that mode. A value is reusable only when all eligible surviving occurrences
  agree after canonical typing and units.
- Zero matches, multiple exact-reference matches, empty cohorts, or conflicting
  cohort values produce bounded clarification; they never select a candidate
  or value silently.

### D-05 — Contextual facts are not copied blindly

- Identity-, placement-, host-, and storey-dependent facts are supplied
  explicitly or recomputed from the repaired chain.
- Examples include GlobalId, Tag/Mark, storey/Level, host reference, sill
  height, placement-derived elevation, and geometry-derived quantities.
- The implementation must keep this policy in one extensible registry rather
  than scattering Window-only string checks through the compiler.

### D-06 — Direct engineer input remains first-class

- The user may state exact scalar values as `Pset.Property = value` with an
  optional IFC measure/unit, or express the same intent naturally for the Phase
  10.2 knowledge resolver to map to an exact IFC2X3 property.
- The request may explicitly state relevant Window or Opening quantities.
- The system may derive deterministic geometry quantities from authorized
  dimensions; it must record the derivation and must not ask the user to repeat
  values already deterministically known.

### D-07 — Multi-Window reuse without shared-Type mutation

- One request may define a reusable occurrence semantic bundle and reference it
  from multiple Window operations, with per-operation overrides.
- The compiler expands the bundle into operation-local bound assignments before
  application. Editing one repaired Window must not mutate surviving
  occurrences or a shared Type.
- Shared-Type mutation remains deferred. Existing Type inheritance and
  explicitly authorized Type reuse remain supported.

### D-08 — Ground Truth comparator and statuses

- A private benchmark comparator must compare the original and repaired
  Window/Opening effective-fact snapshots and classify every difference as:
  `matched`, `not_in_user_text`, `unsupported_authoring`, `wrong_value`, or
  `ownership_only`.
- Evaluation exposes four independent summary fields:
  `geometry_relationship_success`, `semantic_fidelity_success`,
  `occurrence_fidelity_success`, and diagnostic `authoring_exactness`.
- For a complete-replication benchmark, every Ground Truth fact in the selected
  supported boundary must be authorized or deterministically derived and must
  match. `not_in_user_text`, `unsupported_authoring`, and `wrong_value` are
  blocking in that benchmark.

### D-09 — Validation acceleration without weakening evidence

- IfcOpenShell baseline validation results may be cached by IFC SHA-256,
  IFC schema, IfcOpenShell version, validator policy version, and diagnostic
  normalization version.
- Cache entries contain immutable normalized diagnostics, never mutable
  IfcOpenShell model objects. Hash/version mismatch is a cache miss.
- Independent read-only comparator and validator work may run in bounded
  parallel workers only when results are identical to sequential execution and
  peak RSS remains at or below 4 GiB. Timeout, worker failure, partial cache
  data, or result disagreement fails closed.
- AdvancedProject full Production evaluation must complete within 180 seconds.
  The timed boundary begins when the repair request enters the supported
  orchestrator and ends at the terminal publication decision.

### D-10 — Required acceptance matrix

- One single-Window case supplies a complete explicit occurrence description.
- One single-Window case authorizes an exact surviving occurrence as the
  semantic reference.
- One case authorizes same-Type cohort consensus and includes a deliberate
  conflicting fact that must clarify rather than guess.
- One five-Window case uses a shared semantic bundle plus per-window contextual
  overrides in one atomic ChangeSet.
- One real DeepSeek UAT uses the same public contracts with no synthetic
  fallback and records honest success or failure.
- AdvancedProject supplies the full-model preservation, validation-runtime, and
  memory acceptance evidence.

### D-11 — Ground Truth privacy boundary

- The Provider never receives the private original IFC, private mutation
  mapping, private comparator output, or hidden Gold values.
- A benchmark request derived from known original facts is treated as a frozen
  public user fixture. Its manifest enumerates every fact deliberately exposed
  in that request.
- The private Ground Truth is opened only after application by benchmark-only
  evaluation code.

### the agent's Discretion

- Exact class/function names for the semantic-source policy registry and
  content-addressed validation cache.
- Whether bounded parallel work uses processes or threads, provided
  IfcOpenShell safety, deterministic equality, the 4-GiB limit, and fail-closed
  behavior are proven.
- Which one additional non-Window fixture is used only to prove that generic
  occurrence scalar-property interfaces are not hard-coded to `IfcWindow`.

</decisions>

<specifics>
## Specific Ideas

- Preserve the existing two-Agent architecture: Stage 1 interprets the request,
  deterministic code resolves/reuses facts, and Stage 2 receives only bounded
  authorized assignments.
- Prefer one shared bundle plus five small contextual overrides over repeating
  28–30 properties in each Window operation.
- Reports must show deleted/repaired Window names and GUIDs, semantic source
  counts, missing/extra/mismatched facts, and whether differences are blocking
  or authoring-only.

</specifics>

<deferred>
## Deferred Ideas

- Door, opening-only, Beam, Column, Wall, and Space authoring remain in later
  phases; Phase 10.5 only leaves reusable interfaces.
- Shared-Type mutation and its full impact-list confirmation remain deferred.
- Enumerated, list, table, reference, and complex IFC properties remain outside
  the authoring contract unless a selected Ground Truth fixture makes one a
  separately approved blocker.
- Curved/free-form walls, L3 identity/serialization fidelity, default 128k
  input, and whole-IFC JSON input remain out of scope.

</deferred>
