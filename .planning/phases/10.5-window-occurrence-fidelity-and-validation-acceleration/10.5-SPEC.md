# Phase 10.5: Window Occurrence Fidelity and Validation Acceleration - Specification

**Status:** Complete — 2026-07-26
**Date:** 2026-07-26
**Ambiguity score:** 0.07 (gate: <= 0.20)

## 1. Problem

The current pipeline can restore Window geometry, wall/opening/fill
relationships, selected L2 facts, and atomic five-Window transactions.
Comparison with the original IFCs exposed two remaining product gaps:

1. A reused `IfcWindowStyle` supplies Type-owned/inherited facts but cannot
   recreate the original occurrence-direct Psets or quantities. AdvancedProject
   repaired Windows therefore retain geometry and required L2 success while
   omitting many Ground Truth occurrence facts.
2. Full Production evaluation on AdvancedProject exceeds the 180-second
   pipeline budget even though Comparator 0.2 itself now completes within the
   preservation budget. Repeated baseline/candidate IfcOpenShell validation is
   the remaining dominant work.

Phase 10.5 closes those gaps without expanding the operation family or
weakening global preservation.

## 2. Goal

For the selected IFC2X3 Window benchmarks:

> A complete, authorized natural-language request plus a damaged IFC produces
> one bound ChangeSet and one repaired IFC whose Window/Opening geometry,
> relationships, effective occurrence scalar properties, and relevant
> quantities are equivalent to Ground Truth, while the unchanged full
> Production publication decision completes within 180 seconds.

## 3. Actors

- **Engineer/user:** describes the repair, exact property/quantity values, or
  explicitly authorizes a surviving occurrence/cohort as a semantic source.
- **Stage 1 Agent:** extracts structured intent and provenance; it does not
  choose unsupported values.
- **Deterministic resolver/compiler:** resolves targets, Types, properties,
  occurrence references, cohort consensus, derived facts, and bundle
  expansion.
- **Stage 2 Agent:** emits only operations permitted by the bounded public
  contract and deterministic evidence.
- **Production evaluator:** validates source binding, global preservation,
  operation L1/L2, occurrence fidelity, and IfcOpenShell regression.
- **Benchmark evaluator:** privately compares repaired Window/Opening facts to
  Ground Truth after application.

## 4. Public Input Contract

The version following RepairIntent 0.3 must support all existing selectors and
property intents plus the following concepts:

### 4.1 Reusable semantic bundle

A request may define a named bundle containing:

- existing exact or natural-language `property_intents`;
- exact Window/Opening scalar quantity intents;
- public provenance for each member.

Multiple operations may reference the same bundle. Operation-local property or
quantity intents override members with the same canonical fact key. Bundle
expansion occurs before the bound ChangeSet is compiled; there is no shared
mutable IFC Pset object between repaired occurrences.

### 4.2 Quantity intent

Each quantity intent contains:

- scope: `window_occurrence` or `opening_occurrence`;
- exact quantity set and quantity name;
- scalar value, IFC measure type, and optional unit;
- public source excerpt.

Geometry-derived quantities may omit a repeated user value only when the
compiler has a registered deterministic derivation from already-authorized
dimensions. The bound evidence records the formula and input facts.

### 4.3 Occurrence reuse intent

One operation may contain one optional reuse instruction:

- mode: `exact_occurrence` or `same_type_consensus`;
- reference kind: exact GUID, exact human-readable occurrence identity, exact
  Type GUID, or exact Type name as appropriate to the mode;
- include patterns limited to occurrence Psets and quantities;
- explicit public authorization provenance.

`same_type_consensus` may emit a fact only when every eligible surviving
occurrence agrees after type/unit canonicalization. Conflicts become
clarification evidence with candidate identities and bounded conflicting
values.

### 4.4 Semantic source policy

Every bound semantic assignment uses exactly one source kind:

- `explicit_value`
- `deterministic_derived`
- `type_inherited`
- `approved_occurrence_prototype`
- `authorized_type_cohort`

Contextual or identity facts are never copied blindly. They are explicitly
provided, derived from the repaired target/host/storey/placement, or omitted
with a visible blocking classification when required by the complete benchmark.

## 5. Output Contract

One successful run produces the existing immutable run artifacts plus:

- the expanded semantic bundle and operation-local assignments;
- per-assignment semantic source/provenance evidence;
- Window and Opening occurrence-fidelity report;
- validation-cache hit/miss/version evidence;
- sequential/parallel equivalence and timing/RSS metrics in benchmark mode.

Terminal status remains compact JSON. Detailed artifacts stay in the run
directory. A failed clarification, compiler, evaluation, timeout, or cache
integrity condition publishes no successful IFC.

## 6. Evaluation Contract

### 6.1 Public Production statuses

- `geometry_relationship_success`: existing L1 geometry, wall, opening, fill,
  placement, and relationship contract.
- `semantic_fidelity_success`: existing operation-specific L2 contract,
  including material only when the source/request requires it.
- `occurrence_fidelity_success`: all authorized/derived Window and Opening
  effective facts and quantities are present with canonical value/type/unit.
- `authoring_exactness`: diagnostic comparison of ownership graph, GUID/STEP,
  representation graph, node counts, and serialization differences.

The first three fields are independently reported. Required false/partial/
not-evaluable states block publication. `authoring_exactness` never overrides
them in Phase 10.5.

### 6.2 Private Ground Truth classifications

For the selected Window and Opening, every supported Ground Truth fact is
classified:

| Classification | Meaning | Complete benchmark |
|---|---|---|
| `matched` | Canonical effective value/type/unit matches | Pass |
| `not_in_user_text` | Gold contains a value not authorized or derivable from the public request | Blocks only a supported fact declared required by the complete benchmark; otherwise diagnostic |
| `unsupported_authoring` | Public request authorized the fact but the compiler cannot author it | Block |
| `wrong_value` | Repaired effective value differs | Block |
| `ownership_only` | Effective value matches but IFC ownership/graph differs, including an explicitly authorized Type-inherited value replacing a duplicate Ground Truth direct value | Diagnostic |

The Phase 10.5 blocking Ground Truth boundary is Window scalar Psets,
Window/Opening quantities and geometry-derived Window overall dimensions.
Name, Tag, ObjectType, GUID, STEP, owner identity and relationship-root identity
remain authoring-exactness diagnostics.

Ground Truth facts are never included in Provider context. The benchmark
manifest lists only which facts were intentionally exposed as the public user
fixture.

## 7. Performance Contract

- Baseline validation cache key:
  `(ifc_sha256, ifc_schema, ifcopenshell_version,
  validator_policy_version, diagnostic_normalization_version)`.
- Cache payload: immutable normalized diagnostics plus counts and payload
  SHA-256. No IfcOpenShell entity/model objects.
- A mismatch, malformed entry, partial write, or unsupported version is a miss,
  not a pass.
- Independent work may use at most two bounded workers unless benchmark
  evidence proves a higher value remains below 4 GiB.
- Sequential and accelerated modes must return the same blocking status,
  diagnostic signatures, comparator fingerprints, and publication decision.
- AdvancedProject cold and warm full Production runs each have a 180-second
  hard limit from supported request entry to terminal publication decision,
  with peak RSS at or below 4 GiB. If the cold target is not achieved, the
  phase remains incomplete rather than moving the timing boundary.

## 8. Requirements

### WFID-01 — Complete occurrence input

**Current:** RepairIntent supports attributes and scalar property intents, but
not reusable semantic bundles, Window/Opening quantity intents, or a complete
occurrence-description contract.

**Target:** One bounded public request can express all supported effective
Window/Opening occurrence facts needed for a selected complete-replication
case.

**Acceptance:** A schema fixture containing exact and natural property intents,
Window/Opening quantities, one bundle, and per-operation overrides validates;
the bound ChangeSet contains canonical operation-local assignments with public
provenance.

### WFID-02 — Authorized occurrence reuse

**Current:** Existing Type reuse cannot recover occurrence-direct Psets, and
there is no public contract for exact occurrence or cohort reuse.

**Target:** Exact occurrence packages and explicitly authorized unanimous
same-Type cohort facts are resolvable without silent selection or value
invention.

**Acceptance:** Exact-reference success, ambiguous reference, unanimous cohort,
empty cohort, and conflicting cohort tests prove deterministic binding or
clarification. Contextual facts are recomputed/overridden rather than copied.

### WFID-03 — Atomic multi-Window semantic bundles

**Current:** Five Window operations can be atomic, but property facts are
repeated per operation and Ground Truth occurrence packages are not restored.

**Target:** One shared semantic bundle plus per-window overrides expands into
five isolated operation-local authoring plans inside one unified ChangeSet.

**Acceptance:** The vvo or AdvancedProject five-Window fixture authors the
requested scalar Psets/quantities on exactly the repaired occurrences; one
invalid bundle member rolls back all five operations; surviving occurrences and
shared Types remain unchanged.

### WFID-04 — Ground Truth occurrence comparator

**Current:** Existing L1/L2 and IfcDiff evidence do not explain whether each
missing Ground Truth occurrence fact was absent from the request, unsupported,
wrong, or merely authored through a different ownership graph.

**Target:** A Window/Opening comparator reports canonical effective facts,
semantic-source coverage, five stable difference classifications, and four
summary statuses.

**Acceptance:** Synthetic and real original/damaged/repaired cases cover every
classification. A complete public request passes occurrence fidelity despite
ownership-only differences; omitted, unsupported, or wrong required facts fail.

### WFID-05 — Full validation under 180 seconds

**Current:** Comparator 0.2 meets its own budget, but AdvancedProject full
Production evaluation exceeds 180 seconds because baseline/candidate schema
validation is repeated.

**Target:** Content-addressed validation reuse and safe bounded parallel work
preserve exact evidence while meeting the full Production budget.

**Acceptance:** Cache integrity/freshness tests, sequential-versus-accelerated
equivalence tests, timeout/worker-failure tests, and fresh AdvancedProject cold
and warm runs prove <=180 seconds, <=4 GiB, and zero changed blocking outcomes.

### WFID-06 — Window acceptance matrix and live UAT

**Current:** Existing cases prove selected L1/L2, atomic batch repair, and
preservation, but not complete authorized occurrence replication.

**Target:** Offline and real-Provider evidence covers direct complete input,
exact occurrence reuse, cohort consensus/conflict, five-Window bundle
application, and AdvancedProject full Production performance.

**Acceptance:** Each run directory contains source/damaged/repaired hashes,
deleted/repaired Window names and GUIDs, public request, RepairIntent,
ChangeSet, source evidence, L1/L2/occurrence reports, IFC comparison, timing,
RSS, and honest Provider outcome. Real DeepSeek has no synthetic fallback.

## 9. Acceptance Scenarios

1. **Complete explicit single Window:** Text provides every supported
   non-derived occurrence fact; geometry supplies registered quantities; all
   required statuses pass.
2. **Exact reference occurrence:** Text names one surviving Window occurrence;
   copy-safe Psets/quantities reuse; contextual facts derive from the new chain.
3. **Cohort consensus:** Text authorizes same-Type consensus; unanimous facts
   reuse; one injected conflict returns clarification and no IFC.
4. **Five-Window bundle:** One bundle and five override blocks produce one
   atomic ChangeSet; each repaired occurrence has independent evidence.
5. **Gold privacy:** Canary/private original/mutation data never appears in
   either Provider request.
6. **Validation integrity:** Corrupt/stale cache, timeout, worker exception, and
   sequential/parallel disagreement all block publication.
7. **Advanced performance:** Fresh cold and warm AdvancedProject full
   Production runs meet the time/memory gates without reducing compared roots,
   validation rules, or L1/L2 checks.

## 10. Out of Scope

- Shared-Type mutation.
- Non-scalar IFC property authoring.
- Door, opening-only, Wall, Beam, Column, and Space operations.
- Curved/free-form walls.
- Whole-IFC JSON sent to an LLM.
- L3 GUID/STEP/graph/serialization or byte identity.
- Default 128k Provider input.
