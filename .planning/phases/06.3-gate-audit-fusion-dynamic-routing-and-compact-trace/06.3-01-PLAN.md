# Objective

Create a shared Gate-Audit evidence bundle for the exact candidate under
review. This fixes scattered evidence and makes Audit responsible for dynamic
classification while preserving deterministic gate authority.

# Tasks

## T1 - RED: gate summary schema

Write tests for a `GateSummary` payload with:

- `candidate_hash`,
- `candidate_path`,
- `expected_facts_path`,
- `expected_facts_hash`,
- `artifact_hashes` for decisive inputs and outputs,
- evidence sections for schema validation, semantic coverage, compile/reopen,
  geometry, containment, opening/fill, and repair history,
- `gates[]`,
- each gate containing `name`, `applicability`, `status`, `basis`,
  `issue_count`, `issues`, `source_paths`, and stable `issue_codes`,
- `overall_status`.

Allowed applicability values:

- `applicable`
- `not_applicable`
- `inconclusive`
- `gate_dispute_candidate`

Allowed status values:

- `passed`
- `failed`
- `blocked`
- `skipped`
- `inconclusive`

## T2 - RED: hash binding and stale evidence rejection

Add a failing test proving that Audit cannot receive a gate summary whose
`candidate_hash` or `expected_facts_hash` differs from the candidate under
review. The expected route is blocked with an evidence-mismatch issue code, not
accepted or repaired.

## T3 - GREEN: implement bundle writer

Add `gate_audit_bundle.py` with deterministic serialization and candidate hash
calculation. Integrate it after candidate gates and before decisive Audit.
Record a deterministic `gate_summary_hash` in the manifest/report layer so
later route decisions can bind to the exact evidence Audit saw.

## T4 - RED/GREEN: Audit prompt consumes bundle

Update Audit prompt rendering so `audit/prompt-render-input.json` includes
`GATE_SUMMARY`, `GATE_SUMMARY_HASH`, `CANDIDATE_HASH`, and
`EXPECTED_FACTS_HASH`, not only separate gate fragments.

## T5 - RED/GREEN: Audit override remains impossible

Add a regression proving `Audit accept` over any applicable failed gate becomes
`audit_override_attempt` or blocked route.

## T6 - Documentation

Write summary with examples of applicable failure vs inconclusive gate dispute.
Include one example of stale hash rejection so future implementers do not treat
Gate/Audit evidence as loose text context.

# Success Criteria

- Every decisive Audit receives a gate summary for the exact candidate hash.
- Gate summary and Audit prompt bind to the exact expected-facts hash.
- Gate applicability is explicit.
- Audit cannot accept failed applicable gates.
- Stale or mismatched candidate/gate evidence blocks before acceptance.
