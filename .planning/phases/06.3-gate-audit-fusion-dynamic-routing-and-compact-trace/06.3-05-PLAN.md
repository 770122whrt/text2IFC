# Objective

Reduce default artifact writes during normal generation while preserving enough
evidence for human review and verifier checks.

# Tasks

## T1 - RED: trace-level CLI contract

Add tests for `--trace-level compact|debug|full`.

Default must be `compact`.

## T2 - RED: compact artifact set

Test that compact mode writes only top-level review artifacts:

- `report.md`,
- `output.ifc` when accepted,
- `candidate.json` when Formal exists,
- `expected-facts.json`,
- `gate-summary.json`,
- `route-decision.json`,
- `session-export.json`,
- `trace-manifest.json`.

Provider prompt/raw sidecars must not be top-level by default.

## T3 - RED: debug/full evidence availability

Test that debug/full mode preserves rendered prompts, redacted requests, raw
responses, parsed outputs, validation diagnostics, repair outputs, Audit
evidence, and provider metadata.

## T4 - GREEN: implement trace policy

Add trace-level policy helpers and integrate them into live trace writers and
report generation. Do not change provider prompts or candidate semantics.

## T5 - GREEN: failure escalation policy

Define when compact mode auto-retains deeper evidence:

- provider parse failure,
- schema invalid output,
- Design Brief omission or design revision route,
- Generator omission or generator regeneration route,
- local repair route,
- blocked failure,
- route decision needing developer review,
- gate dispute,
- secret scan finding.

For every non-accept route, `trace-manifest.json` must include at least:

- redacted provider request/response path or recoverable bundle reference,
- prompt-render input hash,
- raw response hash when a provider call happened,
- parsed output hash when parsing succeeded,
- diagnostics hash,
- `candidate_hash` when a Formal candidate exists,
- `expected_facts_hash`,
- `gate_summary_hash` when gates ran,
- `route_decision_hash`.

The deep evidence may live under `trace/` or a bundle, but compact mode must
not leave the run with only a human sentence and no reproducible evidence.

## T6 - Measurement

Add a lightweight test or script assertion that compares compact vs debug file
counts and records the reduction in summary. Runtime timing may be noisy, so
file write count is the primary deterministic metric.

The measurement must count eager top-level writes separately from deferred
trace/bundle evidence so the speed goal does not become an excuse to delete
failure evidence.

# Success Criteria

- Compact is default.
- Compact writes fewer files than debug for the same deterministic run.
- Report and trace manifest remain sufficient for review.
- Debug/full trace preserves provider evidence when needed.
- Design Brief omission, Generator omission, local repair, gate dispute, and
  blocked failure outcomes remain auditable from compact trace manifest links.
