# Objective

Turn Gate-Audit findings into explicit stage routes. The result must tell the
system and the user whether to go back to Design Brief, Generator, local repair,
Draft clarification, gate-dispute review, or blocked failure.

# Tasks

## T1 - RED: route decision schema

Test canonical routes:

- `accept`
- `design_revision_required`
- `generator_regeneration_required`
- `local_repair_required`
- `draft_required`
- `blocked_gate_dispute`
- `blocked_failure`

Each route requires owner stage, reason codes, source gate/audit findings,
attempt index, allowed next action, `candidate_hash`, `expected_facts_hash`,
`gate_summary_hash`, and source issue codes.

Add a stale-evidence assertion: if `route-decision.json` references a
candidate or gate summary hash different from the current candidate under
review, acceptance is blocked with an evidence mismatch route.

## T2 - RED: Design Brief back-route

Fixture: Design Brief omits a window fact present in original input.

Expected: route is `design_revision_required`, not Generator repair.

## T3 - RED: Generator omission route

Fixture: Design Brief expects second-floor doors but candidate omits them.

Expected: route is `generator_regeneration_required` or blocked if attempts are
exhausted.

## T4 - RED: local repair route

Fixture: candidate includes all facts but one repairable host/placement
relationship is inconsistent.

Expected: route is `local_repair_required`.

## T5 - RED: non-two-storey route coverage

Use the non-two-storey fixture from Wave 3 or an equivalent three-storey
fixture. Force one dynamic gate failure, such as a third-storey containment
mismatch or missing third-storey opening/fill relation.

Expected: the route decision identifies the owning stage from issue ownership,
not from second-floor-specific rules.

## T6 - GREEN: implement route controller

Implement route decision logic and integrate it after Audit. Add attempt limits
and stall detection:

- record `input_issue_count`,
- record `output_issue_count`,
- block when issue count does not decrease,
- default to one attempt per stage unless configured.

## T7 - Report and terminal integration

Ensure terminal output, session export, and `report.md` show the final route and
why it was chosen. The report must display or link the same `candidate_hash`,
`expected_facts_hash`, and `gate_summary_hash` used by the route decision.

# Success Criteria

- Blocked outcomes name the next owning stage.
- Design Brief, Generator, and Repair routes are distinct.
- Non-improving loops stop with evidence.
- Hash mismatches block acceptance before repair or acceptance.
- Non-two-storey routes are data-driven and do not depend on second-floor issue names.
