# Objective

Add gates that catch missing requested entities, wrong containment, and
unembedded doors/windows before Audit can accept complex generated IFC.

# Tasks

## T1 - RED: missing entity completeness

Test that a candidate missing requested second-floor doors fails with a stable
issue code such as `EXPECTED_ENTITY_MISSING`.

## T2 - RED: window without opening/fill

Test that a candidate with requested windows but no corresponding
`IfcOpeningElement`, `IfcRelVoidsElement`, or `IfcRelFillsElement` fails with
stable issue codes.

## T3 - RED: wrong storey containment

Test that second-floor windows or walls attached to first-floor hosts fail
when expected facts imply second-floor ownership.

## T4 - RED: non-two-storey gate coverage

Add a three-storey or otherwise non-two-storey fixture that reaches dynamic
gate logic, not just expected-fact extraction. It must include at least one of:

- missing third-storey door/window facts,
- cross-storey containment mismatch,
- stair/roof/slab expectation mismatch,
- host wall relationship mismatch on a non-second storey.

The test must fail/pass based on facts in `expected-facts.json`, not on a
literal `"second_floor"` or fixed two-storey rule.

## T5 - GREEN: implement dynamic gates

Implement gates with applicability rules:

- run completeness only when expected facts contain explicit counts or lists,
- run containment only when expected storey/space membership is known,
- run opening/fill only when host and embedding are required by capability,
- return inconclusive instead of guessing when required evidence is absent.

## T6 - Integrate with GateSummary

Add dynamic gate results to `gate-summary.json` before Audit.

## T7 - Documentation

Write summary showing hard-case failures caught before false acceptance and
explain which non-two-storey fixture proves the gate is data-driven.

- Window/door embedding obligations are explicit.

- Non-two-storey dynamic gate tests pass without special-case storey logic.
