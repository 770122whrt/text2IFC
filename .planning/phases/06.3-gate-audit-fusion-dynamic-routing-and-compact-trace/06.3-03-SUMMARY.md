# 06.3-03 Summary

Wave 3 added dynamic expected-fact gates before decisive Audit:

- `src/text2ifc_agent/dynamic_gates.py`
- `dynamic_entity_completeness`
- `dynamic_storey_containment`
- `dynamic_opening_fill`
- `dynamic-gates.json` inside each run directory when candidate and
  `expected-facts.json` are both present

The gates compare the current BIM JSON candidate against Design Brief-derived
`expected-facts.json`. They do not add a second BIM JSON model and do not
change BIM JSON 2.0 schema.

Covered failure classes:

- requested entities missing from the candidate,
- requested doors/windows missing on a specific storey,
- exact expected entity ids attached to the wrong storey,
- door/window host-wall mismatch,
- missing explicit `IfcRelFillsElement`,
- missing explicit `IfcRelVoidsElement`.

The opening/fill gate intentionally requires explicit relationships. Product
placement can help diagnose host and storey, but it does not satisfy the
relationship obligation when `expected-facts.json` requires embedded
door/window openings.

Non-two-storey coverage:

- the reusable three-storey fixture now reaches dynamic gate logic;
- the test fails on missing `storey-3` door/window facts without any
  hard-coded two-storey or second-floor rule.

GateSummary integration:

- `write_gate_summary()` now includes dynamic gates before Audit;
- `dynamic-gates.json` is hash-addressed through GateSummary artifact hashes
  when written;
- failed dynamic gates set the overall summary status to `failed`.
