# Objective

Build a dynamic `expected-facts.json` sidecar from Design Brief known facts.
This sidecar tells gates what the user actually requested without changing the
BIM JSON schema.

# Tasks

## T1 - RED: extract multi-storey expected facts

Write tests that convert Design Brief facts into:

- building/storey expectations,
- space expectations per storey,
- door expectations per storey,
- window expectations per storey,
- slab/roof/stair expectations when present,
- host wall and relative position phrases when present.

The two-storey fixture should expect four second-floor doors and nine total
windows.

## T2 - RED: no two-storey hard-coding

Add a three-storey simplified fixture and assert expected facts derive three
storeys without changing implementation constants.

This fixture must be saved or factored so Waves 3 and 4 can reuse it for
dynamic gate and route assertions. Extraction-only coverage is not sufficient
for Phase 6.3 acceptance.

## T3 - GREEN: implement expected fact extraction

Implement `expected_facts.py` with conservative extraction:

- preserve raw source paths,
- include confidence/source evidence,
- leave ambiguous facts as unresolved expectations,
- never invent dimensions or missing host walls.

## T4 - GREEN: write sidecar in pipeline

Write `expected-facts.json` after Design Brief ready and before Generator gates.
Include the path in gate summary, report, and session export.

## T5 - Documentation

Document which Design Brief shapes are supported in Wave 2 and which remain
unresolved.
