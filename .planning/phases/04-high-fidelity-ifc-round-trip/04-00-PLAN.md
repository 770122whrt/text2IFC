# Plan 04-00: Generated IFC Correctness Gate

<objective>
Create the Phase 4 entry gate that proves generated IFC from text -> Agent
prompt -> Agent BIM JSON -> IFC is spatially, structurally, and semantically
correct for two simple architectural cases.
</objective>

<truths>
- Reopenable IFC is not sufficient; spatial correctness is required.
- Current `mimo-live-simple-room-v2` is valid and reopenable but has incorrect
  wall geometry.
- BIM JSON Schema remains the structural truth; the new gate is semantic and
  geometric validation around compiled IFC.
- The model must not output raw IFC, STEP text, low-level IFC helper objects,
  hidden defaults, or unverified repairs.
- Reports must preserve input, prompt, raw response, candidate JSON,
  diagnostics, metrics, and IFC output without secrets.
</truths>

<tasks>

<type>tdd</type>

## Task 2: GREEN reusable IFC quality checker

<type>implementation</type>
<files>scripts/ifc_quality/check_generated_ifc.py, src/text2ifc_quality/</files>
<action>
Implement an IfcOpenShell-based checker that reads an IFC file and expected
case JSON. It must compute or inspect world geometry, product identity, spatial
containment, void/fill endpoints, dimensions, attributes, and selected
properties. It must emit machine-readable diagnostics and a pass/fail summary.
</action>
<verify>python -m pytest tests/ifc_quality/test_generated_ifc_gate.py -q</verify>
<acceptance_criteria>
- Invalid wall orientation, open enclosure, wrong opening host, wrong
  dimensions, missing containment, and orphaned relationships are detected.
- Corrected fixtures pass within documented tolerances.
</acceptance_criteria>
