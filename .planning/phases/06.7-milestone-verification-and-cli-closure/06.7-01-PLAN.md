# Plan 06.7-01: v1.0 Verification Closure and Archival Readiness

## Objective

Close the v1.0 evidence and traceability gaps without changing model behavior,
weakening deterministic Gates, or running another Easy/Medium/Difficult
stability campaign.

## Wave 1: Evidence Inventory

Cross-check every milestone requirement against `REQUIREMENTS.md`, the owning
phase summaries, verification artifacts, deterministic tests, retained live
provider evidence, generated reports/IFCs, and accepted UAT. Correct the stale
milestone requirement count and distinguish verified delivery from deferred
technical debt.

## Wave 2: Verification Backfill

Create concise `VERIFICATION.md` artifacts for completed phases that lack one:
03, 04, 05, 06, 06.1, both 06.2 phase directories, 06.3, 06.4, and 06.6.
Each artifact must identify the evidence source, requirement IDs, current
supersession status, and any limitation. Historical live claims may use
retained provider evidence; they must not be recreated with fake or replay
providers.

Explicitly prove:

- `CLI-08`: an actual Chinese human-facing REPL showed questions before user
  input and retained terminal/live evidence;
- `CLI-09`: deterministic generated-IFC feedback reached Audit/routing before
  final acceptance, and Audit could not override failed Gates.

If existing evidence cannot prove either requirement, leave it open and block
milestone archival rather than manufacturing evidence.

## Wave 3: Deterministic Regression

Run the focused Agent, compiler, IFC-quality, and contract suites needed by the
milestone evidence; run `compileall`; verify retained accepted IFC paths can be
reopened where the files remain available; scan committed/planned artifacts
for secret material; and run `git diff --check` on the closure changes.

Do not read provider token values into reports or command output. Do not make a
new live call unless `CLI-08` cannot be proven from retained real interaction
evidence.

## Wave 4: Requirement and Phase Closure

Write `06.7-VERIFICATION.md` and `06.7-01-SUMMARY.md`. Update requirement
checkboxes and traceability only for facts proven by the evidence inventory.
Mark Phase 6.7 complete in ROADMAP and STATE. Record repeated-run reliability,
axis-aligned stair collision limits, and double-leaf door semantics as future
work rather than v1.0 acceptance claims.

## Wave 5: Milestone Audit Gate

Regenerate `.planning/v1.0-MILESTONE-AUDIT.md` using the corrected requirement
count and three-source cross-check. Archival is allowed only if the audit
reports `passed` or contains only explicitly accepted non-blocking technical
debt. The archive operation itself remains a separate safety commit after the
audit passes.

## Acceptance

1. All completed v1.0 phases have a passed verification artifact or an
   evidence-backed supersession statement.
2. All milestone requirements have accurate three-source status; `CLI-08` and
   `CLI-09` are not orphaned.
3. Focused regression, compileall, IFC/report checks, secret scan, and diff
   checks pass or have an explicit non-product environmental limitation.
4. The refreshed milestone audit reports `passed` before archival begins.
