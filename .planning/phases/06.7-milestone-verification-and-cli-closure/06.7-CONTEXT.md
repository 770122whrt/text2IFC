# Phase 6.7 Context

## Purpose

Close v1.0 milestone evidence gaps. Phase 6.6 and `STABLE-01` are already
accepted; this phase does not add another generation capability or another
three-case stability campaign.

## Locked Decisions

- Treat existing SUMMARY, VALIDATION, test output, provider trace, accepted
  BIM JSON/IFC, Audit, report, secret scan, and human UAT as reusable evidence.
- Backfill concise `VERIFICATION.md` artifacts for completed phases that lack
  the milestone audit's required third source.
- Explicitly map evidence to TEXT-01..03, E2E-01, LIVE-01..06, OBS-02, and
  CLI-01..09.
- For CLI-08, first determine whether existing real terminal/session evidence
  proves a human-facing interactive run. Run at most one focused UAT only when
  the existing trace is insufficient.
- For CLI-09, prove that generated-IFC diagnostics reach Audit/repair with
  deterministic Gate authority; do not add a second feedback mechanism.
- Do not make live provider credentials part of deterministic verification.
- Do not rerun Easy, Medium, and Difficult cases. Repeated-run success rate is
  a separate future requirement, not v1.0 gap closure.

## Acceptance

1. Every v1.0 phase has a passed verification artifact or an explicit,
   evidence-backed supersession record accepted by the audit.
2. All 76 unique requirements receive a three-source milestone status; CLI-08 and
   CLI-09 are no longer orphaned.
3. Relevant focused tests, compileall, report/IFC path checks, and secret scan
   pass without exposing provider configuration.
4. A rerun of the v1.0 milestone audit reports `passed` or only explicitly
   accepted non-blocking tech debt.
5. Only then may `$gsd-complete-milestone v1.0` archive and tag the release.
