# Phase 6.1 Research: Real Mimo Experiment Findings

## Evidence Source

The findings below come from actual calls to the configured Mimo Anthropic API
on 2026-06-22. Secret values and the private base URL are intentionally omitted.
Raw local evidence currently lives under
`dataset/processed/agent-demo/phase6-mimo-live/` and is diagnostic, not final
acceptance evidence.

## Connectivity Baseline

The request used model `mimo-v2.5-pro` and asked for one exact JSON object. The
API returned HTTP 200 with:

- `type: "message"`
- `role: "assistant"`
- `model: "mimo-v2.5-pro"`
- `stop_reason: "end_turn"`
- a `content` array containing text and thinking blocks
- usage containing input, output, and cache-read token counts

The existing adapter loses most of this envelope, so connectivity success is
not yet equivalent to an auditable Agent call.

## Live Attempt Timeline

### Attempt 01: Design Brief contract under-specified

- Real Mimo call completed with `stop_reason: end_turn`.
- PowerShell transport mangled Chinese input into question marks.
- Prompt lacked the exact Design Brief output schema.
- Result: nine schema issues.

**Learning:** UTF-8 preservation and exact output contracts are provider-path
requirements, not prompt cosmetics.

### Attempt 02: Valid Design Brief, excessive clarification

- Input was read from a UTF-8 file.
- Full Design Brief schema was supplied.
- Result validated with zero schema issues.
- Mimo nevertheless asked for wall thickness, door swing, and window type.

**Learning:** Schema validity does not prove question relevance. The prompt must
derive necessity from the current request and supported generation semantics.

### Attempt 03: User supplied wall thickness

- User answer: wall thickness 300 mm.
- Real Mimo merged the answer and returned a schema-valid Design Brief.
- Response was wrapped in one outer `json` Markdown fence.
- Strict parser rejected the fence; diagnostic removal of exactly that outer
  wrapper produced zero schema issues.
- The Brief retained contextual ambiguities around “中央” and north/south.

**Learning:** one bounded, visible normalization is useful; arbitrary brace
extraction is unsafe. Ambiguity must be handled by the Agent/user loop, never by
the supervisor silently deleting it.

### Attempt 04: Generator invented a Draft schema

- Real Mimo Generator returned with `stop_reason: end_turn`.
- The response parsed as JSON but failed Formal validation with nine issues.
- It used `schema_version: "text2ifc/draft-envelope/1.0"`, a nonexistent
  contract, and fields not present in the canonical Draft schema.
- Prompt supplied only the Formal schema while mentioning Draft by name.
- Router recognized Draft only by the canonical `draft_version`, so the unknown
  envelope fell through to Formal validation.

**Learning:** the model invented a plausible contract because the prompt did not
provide the actual one. Both schemas and exact discriminators must be supplied;
unknown versions must block before either validator.

### Attempt 05: Aborted supervisor repair

- A supervisor-authored file began resolving ambiguity and preparing repair.
- The user stopped the run and rejected the semantic intervention.
- No real repair response or IFC was produced.

**Learning:** the Observer diagnoses prompt, contract, routing, or provider
failure. It cannot decide what the user meant. This attempt must remain marked
aborted and cannot support any quality claim.

## Architecture Conclusion

The live chain should have three normal semantic roles and one conditional
mode:

1. real Mimo Design Brief Agent, including its own clarification questions;
2. real Mimo Generator;
3. conditional real Mimo Generator repair mode;
4. real Mimo Audit Agent.

Parsing, validation, routing, compilation, geometry checks, secret scanning,
metrics, events, and report generation remain deterministic. There is no
separate Question Planner Agent and no semantic Supervisor Agent.

## Prompt Design Conclusion

Prompts need exact contracts, relevant context, and examples of conditional
reasoning. They should not encode one fixed room template or a universal list of
required/optional fields. Prompt versions must change when behavior changes, and
the registry must retain historical v1 hashes rather than overwriting evidence.

## Acceptance Evidence Gap

At the time of this specification there is no complete real-Mimo
Text -> Design Brief -> BIM JSON -> IFC -> Audit run. Therefore Phase 6.1 is
planned, not complete, regardless of passing fake-provider tests or successful
API connectivity.
