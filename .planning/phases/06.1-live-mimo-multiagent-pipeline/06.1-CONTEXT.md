# Phase 6.1 Context

## Why This Phase Was Inserted

Phase 6 created useful deterministic contracts, but its final service and
experiment harness instantiate `FakeAgentProvider` and fixture-authored Design
Brief/BIM JSON. Those artifacts prove compiler and trace mechanics, not real
model behavior. The user correctly rejected the broader workflow claim.

Phase 6.1 preserves the Phase 6 foundation while changing the acceptance source
of semantic outputs to real Mimo.

## Locked Decisions

- Work only in the C-drive `multiagent-design` worktree.
- Chinese-first interaction.
- One to three questions per clarification turn.
- No default template when required facts are unknown.
- JSON Schema is the only BIM JSON structural truth.
- Real Mimo calls are mandatory for Design Brief, Generator, conditional Repair,
  and Audit acceptance evidence.
- Fake/file providers are allowed only in isolated tests and replay, never as
  acceptance or quality evidence.
- Design Brief Agent alone authors clarification questions.
- Necessity is derived dynamically from request, conversation, schema,
  capability context, and relevant examples; it is not a fixed field list.
- Observer and supervisor cannot modify semantics.
- Repair is conditional and limited to facts already present in evidence.
- Formal IFC compilation occurs only after canonical BIM JSON 2.0 validation.
- A canonical Draft is not compiled.
- The final human-review entry point is generated `report.md`; the final Formal
  artifact is a real IFC file.
- Exact provider envelope fields and stream events must be retained without
  secrets.

## Flexible Implementation Choices

- Internal event class names and directory helper APIs.
- Whether streaming is implemented in the existing provider module or a small
  transport module.
- The retrieval mechanism used to select relevant schema/capability fragments
  and few-shots, provided retrieved evidence is persisted and deterministic for
  a given index version.
- Console presentation, provided the same events are persisted.
- Whether the accepted report inlines small JSON objects or links large raw
  responses; both must remain reviewable from one report.

## Deferred

- Fine-tuning and large-scale Chinese benchmark generation.
- General IFC knowledge RAG beyond the relevant supported capability subset.
- Multiple repair iterations and autonomous prompt optimization.
- Source-equivalent BIMNet complexity.
- IFC4 and IFC4x3.

## Existing Assets to Reuse

- Prompt registry and hash verification in `src/text2ifc_agent/prompt_registry.py`.
- Design Brief schema and validator in `src/text2ifc_agent/design_brief.py`.
- Formal schema validator `validate_v2_document`.
- Draft validator and `schemas/bim-json/draft/1.0/schema.json`.
- Generator routing primitives in `src/text2ifc_agent/generator.py` and
  `src/text2ifc_agent/failure_routing.py`.
- IFC compiler and Phase 4 geometry/relationship gates.
- Phase 6 trace/report contracts.
- Environment-only Mimo configuration in `src/text2ifc_agent/providers.py`.

## Current Risks

- `MimoAgentProvider` currently returns extracted text rather than the exact API
  envelope and defaults to 4096 tokens/60 seconds.
- `run_phase6_case` always instantiates a fake provider.
- Service acceptance hard-codes semantic fixtures.
- Generator Draft detection checks only the canonical version; malformed
  unknown versions fall through to Formal validation.
- Design Brief and legacy deterministic question planning duplicate ownership.
- Current live prompts are v1 files with uncommitted strengthening changes.
- Live experiment artifacts include an aborted supervisor-mutated attempt that
  must never be reported as a valid run.

## Product Questions That Must Stop Execution

- The live provider rejects the documented model or 131072-token request and no
  compatible documented setting can be established.
- Provider credentials fail after local configuration and transport diagnostics.
- A requested IFC semantic capability is outside the declared generation
  profile and the correct Draft behavior conflicts with product intent.
- Committing raw model traces would violate licensing, privacy, or repository
  policy.

All other parser, prompt, routing, test, and report defects should be diagnosed
and fixed without asking the user to make implementation decisions.
