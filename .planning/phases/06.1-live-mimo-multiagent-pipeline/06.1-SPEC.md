# Phase 6.1 Specification: Live Mimo Multi-agent Pipeline

## 1. Purpose

Phase 6 proved the deterministic contracts, trace format, compiler gates, and
service packaging with fake/file providers. It did not prove that the real Mimo
model can execute the same workflow. Phase 6.1 closes that gap with a
Chinese-first, observable, real-provider pipeline:

```text
Chinese request
  -> real Mimo Design Brief Agent
  -> clarification loop when needed
  -> real Mimo BIM JSON Generator
  -> deterministic Formal/Draft classification and validation
  -> conditional real Mimo repair when eligible
  -> BIM JSON 2.0 to IFC2X3 compiler and geometry gates
  -> real Mimo Audit Agent
  -> generated report.md and output.ifc
```

The final claim is deliberately narrow: the selected supported-scope live cases
must complete with real Mimo evidence. Fake/file output cannot satisfy this
phase.

## 2. Problem Statement

The first live experiments exposed six contract failures hidden by deterministic
fixtures:

1. The provider adapter discarded the API response envelope, including
   `stop_reason`, token usage, and non-text content blocks.
2. The Design Brief prompt allowed Markdown fences and did not initially include
   the exact output schema.
3. The Design Brief over-classified optional or contextual details as blockers.
4. Clarification ownership was split between the Design Brief Agent and a
   deterministic question planner.
5. The Generator received only the Formal schema, invented
   `text2ifc/draft-envelope/1.0`, and the router misclassified it as Formal.
6. A manual supervisor attempt began rewriting ambiguity instead of diagnosing
   and routing the failure. That attempt was stopped and is not acceptance
   evidence.

The solution is not a hard-coded global list of required and optional fields.
Necessity depends on the current request, the canonical JSON schemas, generation
capability, prior user answers, and the semantics the user explicitly requests.

## 3. Goals

- Make real Mimo calls mandatory for all semantic roles in phase acceptance.
- Preserve exact, redacted provider responses and streaming events.
- Give the Design Brief Agent sole semantic ownership of known facts, missing
  facts, ambiguities, unsupported requests, corrections, and questions.
- Ground each clarification question in the current request plus real schema or
  capability evidence instead of a universal field checklist.
- Give the Generator both exact canonical output contracts: Formal BIM JSON 2.0
  and BIM JSON Draft Envelope 1.0.
- Route malformed, unknown-version, Draft, repairable, and blocked results
  without silent coercion.
- Produce a real, reopenable, geometry-checked IFC2X3 file and a generated
  single-entry review report.
- Let a human observe live stage progress and inspect every material input and
  output after the run.

## 4. Non-goals

- Proving source-equivalent fidelity for all 25 BIMNet models.
- Fine-tuning Mimo during this inserted phase.
- Adding IFC4/IFC4x3 output.
- Letting any model emit raw IFC/STEP or compiler-level IFC objects.
- Treating the Observer, router, validator, or compiler as an Agent.
- Building a second BIM JSON model outside the canonical JSON Schemas.
- Automatically inventing defaults when the user says a required fact is
  unknown.
- Using a fixed project-wide `required` / `not_required` list to decide all
  clarification behavior.

## 5. Actors and Responsibilities

### 5.1 Design Brief Agent: real Mimo

**Does:** interprets the original request and conversation; records facts,
corrections, ambiguities, unsupported intent, and up to three clarification
questions. It cites the schema/capability/example evidence that makes a missing
fact relevant to this request.

**Does not:** emit BIM JSON, emit IFC, assume project dimensions, or ask for a
detail merely because that detail exists somewhere in IFC.

### 5.2 Clarification Controller: deterministic code

**Does:** checks question count, question-to-missing-fact mapping, evidence-path
existence, transcript ordering, and terminal status. It sends user answers back
to the Design Brief Agent with the full history.

**Does not:** author questions, rank domain facts, reinterpret answers, or add
semantic facts. The legacy `Question Planner` name is not used in the live
architecture.

### 5.3 BIM JSON Generator: real Mimo

**Does:** converts a ready Design Brief into exactly one Formal BIM JSON 2.0
object, or returns exactly one canonical Draft Envelope when the provided
contracts require it.

**Does not:** emit Markdown, raw IFC, low-level IFC helper entities, unknown
schema versions, or multiple candidate objects.

### 5.4 Deterministic Gates

**Do:** normalize only one whole-response outer JSON fence, parse one object,
classify by exact version discriminator, validate against the canonical schema,
compile Formal output, reopen IFC, run geometry/relationship/structure checks,
scan secrets, and record metrics.

**Do not:** search arbitrary prose for JSON, migrate unknown versions, repair
semantic content, or override a failed gate.

### 5.5 Repair Mode: real Mimo, conditional

**Does:** receive the original request, conversation, ready Design Brief,
candidate, exact schemas, and deterministic feedback. It may correct only what
is derivable from those inputs.

**Does not:** run on first-pass success, remove unresolved ambiguity, add
supervisor-authored facts, or guess user intent. If repair requires a new user
fact, it returns the canonical Draft route.

### 5.6 Audit Agent: real Mimo

**Does:** compare user intent, Design Brief, final BIM JSON or Draft,
deterministic diagnostics, IFC metrics, and artifact references. It reports
semantic omissions and contradictions with evidence.

**Does not:** modify artifacts or convert a deterministic failure into a pass.

### 5.7 Observer

**Does:** persist events, classify failure roots, compute metrics, generate the
report, and notify the user of live progress.

**Does not:** make semantic decisions. When provider behavior, prompts, or
claims are inconsistent, it blocks the claim and records the inconsistency.

## 6. Functional Requirements

### FR-01 Real provider provenance

Every acceptance role call MUST use `MimoAgentProvider`. The trace MUST preserve
the exact redacted API envelope with `id`, `type`, `role`, `model`,
`stop_reason`, all `content` blocks, and `usage`. An output is eligible for
parsing only when HTTP succeeds and `stop_reason == "end_turn"`.

### FR-02 Exact runtime policy

The live model MUST come from `TEXT2IFC_MIMO_MODEL`. For `mimo-v2.5-pro`,
`max_tokens` MUST be exactly `131072` unless the provider rejects the documented
limit; such rejection blocks the run and requires an explicit recorded product
decision. Live calls MUST use streaming and a timeout suitable for a 128 Ki-token
upper bound. Credentials and base URL come only from environment variables.

### FR-03 Dynamic Design Brief grounding

The Design Brief prompt MUST receive original request, transcript, Design Brief
schema, relevant BIM JSON schema fragments, generation capability evidence, and
relevant few-shot examples. Missing-fact decisions MUST be made per request.
Each requested fact MUST include a reason and evidence path that exists in the
provided context.

Examples guide conditional reasoning: a missing dimension needed to place a
requested opening may require a question; window operation does not require a
question when the user did not request it; when the user explicitly requests an
unsupported operation it must be preserved as unsupported/Draft rather than
dropped.

### FR-04 Single clarification owner

Only the Design Brief Agent authors user-facing clarification questions. Each
turn contains one to three questions, and every question maps to an open missing
fact or ambiguity with real evidence. The deterministic controller validates but
does not generate or semantically rank questions.

### FR-05 Multi-turn preservation

Every original utterance, Agent question, user answer, correction, and status
transition MUST be appended to an immutable transcript. A new answer triggers a
new real Design Brief Agent call with full history. Unknown answers remain
explicit and cannot trigger a default template.

### FR-06 Exact Formal and Draft contracts

The Generator and Repair prompts MUST include both canonical schemas. Accepted
Formal output has `schema_version == "bim-json/2.0"`. Accepted Draft output has
`draft_version == "bim-json-draft/1.0"` and
`target_schema_version == "bim-json/2.0"`. Any other discriminator is
`blocked_failure`; it is never sent to the Formal validator as if it were
Formal.

### FR-07 Bounded normalization

The parser MAY remove one outer `json` or unlabelled Markdown fence only when
the fence encloses the entire response. The normalization MUST emit a diagnostic
and preserve the untouched model text. Preambles, suffixes, multiple objects,
and arbitrary brace extraction MUST be rejected.

### FR-08 Conditional repair routing

Routes are `no_repair_needed`, `repair_attempted`, `draft_required`, and
`blocked_failure`. Repair eligibility is based only on deterministic issue
classes. At most one repair attempt is allowed in the first live acceptance
version. A repair trace MUST include before/after issues and prove that no new
user facts were introduced.

### FR-09 Deterministic IFC gate

Only Formal BIM JSON that passes `validate_v2_document` may compile. The output
MUST reopen as IFC2X3 and pass the Phase 4 supported-scope geometry, enclosure,
opening/fill, containment, attributes, structure, and secret-scan checks.

### FR-10 Real Audit Agent

Audit MUST be a separate real Mimo call after the terminal generation and
deterministic gate state is known. Audit output MUST cite trace artifact paths
for every finding and repeat the deterministic gate status without changing it.

### FR-11 Observable execution

The runner MUST append timestamped, stage-scoped `events.jsonl` records while
streaming. Human-readable console updates identify stage start, provider
response ID, `stop_reason`, usage, parser result, gate result, route, and final
artifact, without printing secrets or private URLs.

### FR-12 Generated report

`report.md` MUST be generated from trace sidecars, not hand-written. It MUST
show or link every material input/output: original text, transcript, Design
Brief prompt/request/raw response/parsed output, clarification turns, Generator
evidence, normalization, Formal/Draft validation, repair route, IFC and geometry
checks, Audit evidence, metrics, provider metadata, and secret scan.

## 7. Acceptance Scenarios

### A. Complete supported room

A sufficiently complete Chinese room request completes Design Brief,
Generator, validation, compile/reopen, geometry checks, Audit, and report using
real Mimo. The run records `no_repair_needed` or one evidence-backed repair and
writes `output.ifc`.

### B. Incomplete room with clarification

An incomplete Chinese request causes the real Design Brief Agent to ask one to
three grounded questions. Scripted user answers are stored as actual user turns;
the Design Brief Agent is called again. The completed case reaches IFC without
silent defaults.

### C. Unknown user answer

When the user says they do not know a fact required for the requested geometry,
the terminal result is canonical Draft. No IFC is written.

### D. Invalid output contract

A response with an unknown Draft/Formal version or non-whole-response JSON is
blocked with exact raw evidence. It is not repaired through supervisor edits.

### E. Repairable deterministic failure

A schema/semantic candidate error that can be corrected from existing facts
causes one real Mimo repair call. Before/after issue counts and fact-delta checks
are recorded. If the error needs new user information, route to Draft instead.

## 8. Final Acceptance Artifacts

The canonical accepted Formal run directory is:

`dataset/processed/agent-demo/phase6.1-mimo-live/`

It MUST contain at least:

- `input.txt`, `conversation.json`, and `events.jsonl`
- per-call rendered prompts, redacted requests, exact raw responses, extracted
  text, parsed outputs, normalization diagnostics, and response metadata
- `design-brief.json`, `candidate.json` or `draft.json`
- validation, route, repair, geometry, IFC verification, audit, and metrics
  sidecars
- `output.ifc`
- generated `report.md`
- `secret-scan.json`

An additional incomplete-to-clarified case MUST be retained under a sibling
case directory with the same trace rules.

## 9. Security and Truthfulness Constraints

- Never persist token values, `Authorization` headers, `.env` contents, or the
  private provider URL.
- A redacted request records model, max tokens, message roles, content hashes,
  and prompt artifact paths, but not credentials or endpoint.
- Raw provider content is preserved; provider transport metadata is filtered
  only for secrets.
- Any live API failure, undocumented response shape, truncated stop reason,
  hand-authored candidate, or fake provider label blocks a live acceptance
  claim.
- The aborted `attempt-05-repair` is diagnostic history only and MUST be marked
  aborted or quarantined before final acceptance.

## 10. Acceptance Criteria

- All seven Phase 6.1 requirements are verified by machine-readable evidence.
- Unit/regression tests pass; fake/file providers are labelled unit/replay only.
- At least one complete and one clarified real-Mimo run are retained.
- Every required semantic role has a real provider response ID and
  `stop_reason == "end_turn"`.
- The accepted Formal run compiles and reopens `output.ifc` with all supported
  geometry/relationship/structure gates passing.
- `report.md` is regenerated from sidecars and passes report completeness tests.
- Artifact secret scan reports zero findings.
- No supervisor-authored semantic mutation appears in the accepted trace.
