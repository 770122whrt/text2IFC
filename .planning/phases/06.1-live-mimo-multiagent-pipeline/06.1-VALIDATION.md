# Phase 6.1 Validation Strategy

## Evidence Classes

| Class | Provider | Purpose | Counts for live acceptance |
|---|---|---|---|
| Unit | fake/file | Deterministic parser, router, event, report tests | No |
| Replay | saved real response | Regression without network | No |
| Live smoke | real Mimo | Transport and envelope compatibility | Only Wave 0 |
| Live role | real Mimo | Prompt/Agent behavior | Yes |
| Live E2E | real Mimo plus compiler | Final phase acceptance | Yes |

Every report and metric must label its evidence class. A fake/replay result
cannot be aggregated into live provider quality metrics.

## TDD Policy

Eligible deterministic behavior follows RED commit, GREEN commit, optional
REFACTOR. Provider behavior itself is tested through saved-response replay plus
explicit live acceptance commands. Tests may use fake/file providers, but phase
completion requires the live matrix and cannot be skipped when credentials are
absent.

## Wave Gates

### Wave 0: transport and observability

- exact envelope fields survive adapter reconstruction
- all stream events persist in order
- `stop_reason != end_turn` blocks parsing
- `max_tokens == 131072`
- no secret or private URL in traces
- one real Mimo JSON smoke call passes

### Wave 1: Design Brief

- real response validates against Design Brief schema
- no outer Markdown after prompt strengthening; bounded normalizer remains
  tested for defensive compatibility
- all questions map to missing/ambiguous facts and real evidence paths
- question count is one to three when clarification is required
- no global required/not-required list exists in prompt or runtime policy

### Wave 2: clarification

- original request and answers remain byte-preserved UTF-8
- every answer triggers a new real Design Brief call
- unknown answer remains Draft
- no deterministic helper authors the user-facing question text

### Wave 3: generation

- both canonical schemas are prompt inputs
- exact Formal/Draft discriminator routing passes
- unknown version is blocked before Formal validation
- one real ready Brief produces a canonical object

### Wave 4: repair

- successful first pass records zero repair attempts
- eligible failure produces one real Mimo repair call
- before/after issues and fact delta are recorded
- missing user fact routes Draft instead of repair invention
- aborted supervisor-mutated attempt is excluded from acceptance

### Wave 5: audit and report

- Audit is a real Mimo response with exact envelope evidence
- Audit cannot pass deterministic failure
- report is generated only from sidecars
- report completeness test covers every required section and link
- console and `events.jsonl` show live stage progression

### Wave 6: final live matrix

- complete supported room reaches IFC
- incomplete room asks questions, consumes scripted user answers, reruns the
  Design Brief Agent, and reaches IFC
- unknown-answer case ends canonical Draft without IFC
- invalid-version case blocks with raw evidence
- repairable case exercises one real repair call, unless no deterministic way
  exists to induce a safe provider error; in that case the route remains tested
  by replay and is explicitly not claimed as live quality evidence

## Required Commands

Planned command names are acceptance contracts and may be refined only with a
recorded plan deviation:

```powershell
python -m pytest tests/agent tests/service
python -m pytest tests/phase4 tests/compiler

python scripts/agent/run_phase6_1_live.py --check-config
python scripts/agent/run_phase6_1_live.py --case complete-room --live
python scripts/agent/run_phase6_1_live.py --case clarified-room --live

```

## Final Metrics

- live role call count by role
- HTTP success and `end_turn` rate
- parse and exact-contract validity rate
- bounded-normalization rate
- clarification relevance and evidence-validity rate
- unsupported-question rate
- first-pass Formal validity rate
- repair invocation/success/fact-invention rate
- Draft and blocked route rate by reason
- compile, reopen, geometry, relationship, and IFC-structure pass rate
- Audit agreement with deterministic gates
- report completeness and secret-scan pass rate

## Completion Rule

Phase 6.1 cannot be marked complete if the live provider is unavailable, any
mandatory role is fake/file/replay, a terminal response lacks `end_turn`, the
accepted Formal case lacks `output.ifc`, the report is hand-authored, or the
secret scan has findings. Such a state is `blocked` or `in progress`, never
“passed with optional live smoke.”
