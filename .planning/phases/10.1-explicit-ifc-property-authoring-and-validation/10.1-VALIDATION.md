# Phase 10.1 Validation Strategy

## Validation objective

Prove that an exact user-requested scalar Pset fact is authorized from public
evidence, written only at the confirmed ownership scope, independently visible
after IFC reopen and mandatory in L2, while invalid/custom/unconfirmed/stale
paths fail closed without changing source IFC bytes.

## Requirement-to-evidence matrix

| Requirement | Primary automated evidence | Integration/live evidence |
|---|---|---|
| PROP-01 | intent schema/model/prompt contract tests | captured Stage 1 exact intent |
| PROP-02 | registry resolution and custom confirmation tests | standard and custom LargeBuilding runs |
| PROP-03 | Type reuse/clarification/template and Type-mutation-deferred tests | existing/generated Type evidence and preservation |
| PROP-04 | Type creation, create/update/override/duplicate and rollback tests | reopened candidate plus source hash |
| PROP-05 | dynamic L2 and terminal truth-table tests | offline/private and real DeepSeek UAT |

## Test layers

### Layer 1: contract and exact resolution

- Accept exact standard/custom scalar inputs with public provenance.
- Reject old/new version confusion, extra fields, missing tuple members,
  non-scalar values and private source kinds.
- Verify registry manifest, exact case-sensitive path, applicable class,
  `TypePropertySingleValue`, data type and unit family.
- Preserve historical RepairIntent 0.1 fixtures.

### Layer 2: clarification and authority

- Bind custom preview/answer to request/model/target/tuple/scope hash.
- Reject stale, negative, altered, replayed and cross-run answers.
- Confirm occurrence scope never emits a Type authoring action.
- Confirm an explicit shared-Type mutation request stops before Binder/apply
  with a stable deferred result.
- Confirm exact unique Type reuse, ambiguous-Type clarification and no-Type
  deterministic template selection are mutually exclusive.
- Confirm no runtime branch silently chooses a same-size/similar existing Type.

### Layer 3: IFC authoring and L2

- Create new direct Pset/property.
- Append to one existing direct Pset.
- Update one direct property.
- Accept an exact matching inherited value without direct duplication unless
  an occurrence override was explicitly requested.
- Override an inherited-only property at occurrence scope.
- Create and formally bind one deterministic dedicated `IfcWindowStyle` when
  no Type intent was supplied.
- Reject duplicate direct exact-name sets/properties.
- Reopen and compare exact typed value, unit and direct/inherited ownership.
- Inject failures before/after mutation and prove atomic rollback.

### Layer 4: end-to-end acceptance

- LargeBuilding standard `Pset_WindowCommon.FireRating=EI30` occurrence run.
- LargeBuilding custom `Custom_Asset.AssetCode=W-007` confirmation run.
- Cover explicit existing-Type reuse in one case and no-Type system-template
  creation in the other; ambiguous Type remains a deterministic fixture.
- Production and private benchmark L1/L2 pass; L3 remains `not_required`.
- Same-Type non-target Windows and Type facts remain unchanged for occurrence
  requests.
- Explicit shared-Type property requests publish no successful IFC.
- Real DeepSeek runner records actual Stage 1/2 calls and never substitutes an
  offline response.

## Completion gate

- All PROP-01..05 tests map to at least one deterministic assertion.
- Standard/custom/occurrence/Type-deferred/duplicate/unit/rollback negative
  paths exist.
- Public prompt/artifact canary scans contain no private Gold identifiers.
- LargeBuilding offline Production/private L1/L2 pass.
- Real DeepSeek UAT succeeds or its exact Provider failure is reported without
  synthetic substitution; a success claim requires both frozen live cases.
