<objective>
Add resumable, tamper-evident confirmation for custom properties, plus
explicit Type-reuse/template selection and occurrence-only scope enforcement.
</objective>

<threat_model>
- T-10.1-06 (critical): an occurrence request edits a shared Window Type. Mitigation: null/omitted scope normalizes to occurrence_direct and Type is never inferred.
- T-10.1-07 (critical): an explicit Type request reaches the Binder/applicator. Mitigation: return a stable deferred result before executable fact creation.
- T-10.1-08 (high): a custom confirmation is replayed for another target/property/run. Mitigation: confirmation hash includes request/model/target/tuple/scope and run identity.
- T-10.1-09 (high): negative or altered answer is treated as approval. Mitigation: closed answer enum plus exact preview hash match.
- T-10.1-10 (high): existing project custom property bypasses the agreed confirmation rule. Mitigation: only official exact registry resolution skips custom confirmation.
- T-10.1-10A (critical): no-Type input silently chooses a neighboring same-size Type. Mitigation: null PrototypeIntent selects deterministic system-template authority; only exact/confirmed references may reuse existing Types.
</threat_model>
