# Phase 10.1 Plan 04: LargeBuilding exact-property acceptance Summary

**LargeBuilding now proves exact standard and confirmed custom occurrence
properties through the public IFC-plus-text pipeline, including real DeepSeek,
reopen L1/L2 and honest private Ground Truth comparison.**

## Accomplishments

- Added raw-Provider public API acceptance for
  `Pset_WindowCommon.FireRating=EI30` with exact existing Type reuse.
- Added the full `Custom_Asset.AssetCode=W-007` lifecycle: pause, runtime
  preview hash confirmation, resume, system-template Type and publication.
- Reopened both IFC outputs and verified exact value, `IfcLabel` type and
  occurrence-direct ownership.
- Hashed the existing shared Type and every pre-existing same-Type non-target
  Window before/after; no collateral semantic mutation occurred.
- Added private benchmark evaluation only after public success.
- Added an opt-in two-case DeepSeek runner with no synthetic fallback and a
  secret-free `--check-config`.
- Recorded a final real UAT in
  `dataset/processed/ifc-repair/phase10.1-live-uat/uat-20260723T055315222853Z/`.
- Documented the exact Phase 10.2 candidate-tuple boundary and explicitly
  excluded aliases, vector matching and RAG from Phase 10.1.

## Implementation Corrections Found by Acceptance

- A generated `IfcWindowStyle` without representation maps was using the
  mapped-Type placement offset; it now follows the locally generated geometry.
- System-template Windows now carry deterministic host-derived
  `Pset_WindowCommon.IsExternal` evidence.
- Deterministic quantity facts now use the IFC2X3 reopened representation
  (`IfcQuantityLength` / `IfcQuantityArea`) instead of measure-value labels.
- Multiple direct Psets receive unique application/audit roles rather than
  colliding on one `semantic_pset` role.
- Pset ownership remains a strict L2 comparison, while relationship and
  quantity facts no longer misuse the direct/inherited flag.

## Real Provider Evidence

Provider/model: `deepseek-openai-compatible / deepseek-v4-flash`.

- `exact-standard-occurrence`: Stage 1 = 1, Stage 2 = 2, Production L1/L2
  passed, private L1/L2 passed, `contract_pass=true`.
- `custom-property-confirmation`: Stage 1 = 1, Stage 2 = 2,
  `property_confirmation` resumed with the runtime preview hash, Production
  L1/L2 passed, private L1 passed and L2 failed as an expected authoring
  difference, `contract_pass=true`.
- Final UAT status: `passed`; `synthetic_fallback=false`.

Earlier real attempts remain immutable. One exposed a request wording that
caused `prototype_selection`; another exposed the runner's incorrect assumption
that system-template fallback must equal the original private Type. Neither was
rewritten into success.

## Verification

- Focused LargeBuilding/publication/security suite: `8 passed`.
- Full `tests/knowledge + tests/ifc_repair`: `508 passed, 1 skipped` in
  `499.72s`.
- `compileall` passed for knowledge, IFC repair and repair scripts.
- DeepSeek `--check-config`: ready, 65,536 / 65,536, secret redacted.
- Final live UAT: both cases `contract_pass=true`, overall `passed`.
- Phase files pass `git diff --check`; secret canary scan found no API key.

## Deviations from Plan

- The plan expected private L2 to pass for both cases. That is invalid for the
  deliberately no-Type custom case: private Gold knows the removed author's
  Type, while Production is forbidden to use it without user authorization.
  The result is now reported as Production L2 passed / private L2 failed,
  preserving the agreed L1/L2/L3 responsibility split.
- Acceptance uncovered and fixed generated-template quantity, placement and
  multiple-Pset audit gaps before the real UAT.

## Next Phase Readiness

Phase 10.2 may rank exact property tuples from non-exact language. It must feed
the existing Phase 10.1 intent/confirmation contract and cannot bypass Binder,
atomic authoring, reopened L2 or publication gates.
