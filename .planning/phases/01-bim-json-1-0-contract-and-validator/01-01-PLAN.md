<feature>
  <name>Canonical structural BIM JSON validation</name>
  <files>pyproject.toml, schemas/bim-json/1.0/schema.json,
  src/text2ifc_contract/__init__.py, src/text2ifc_contract/schema.py,
  src/text2ifc_contract/validation.py, scripts/bim_json/validate.py,
  tests/contract/fixtures/complete.json,
  tests/contract/test_schema_validation.py</files>
  <behavior>
Create `ValidationIssue` as an immutable record with `code`, `path`, and
`message`, and expose `validate_document(document) -> list[ValidationIssue]`.

RED cases must assert:

- The complete fixture validates with an empty issue list and contains exactly
  the nine kinds `wall`, `column`, `beam`, `slab`, `door`, `window`, `stair`,
  `stair_flight`, and `roof`.
- Missing or non-`bim-json/1.0` `contract_version` returns
  `REQUIRED_FIELD` or `INVALID_ENUM` at `/contract_version`.
- Non-`IFC2X3` `target_schema` and non-`MILLIMETRE` `units.length` return
  `INVALID_ENUM` at their exact paths.
- Missing required fields, wrong types, unknown fields, unsupported kinds, and
  zero/negative dimensions return stable project codes and pointer-like paths.
- Calling validation does not mutate the input mapping.
- `load_schema()` runs `Draft202012Validator.check_schema()` and the schema
  contains no remote `$ref`.
- The CLI emits one JSON object with `valid` and `errors`, rejects files above
  10 MiB, caps emitted errors at 1000, and uses exit codes 0/1/2 as specified.
  </behavior>
  <implementation>
First create `pyproject.toml` with Python `>=3.12`, dependency
`jsonschema>=4.19,<5`, pytest paths `src` and `.deps/python312`, and test path
`tests`.

Write `schema.json` with `$schema` Draft 2020-12, local `$defs`,
`additionalProperties: false`, constants for version/schema/unit, non-empty
hierarchy names and IDs, at least one storey, and a discriminator-based element
union. Use the exact dimensions table in `01-RESEARCH.md`; every dimension has
`exclusiveMinimum: 0`.

Map JSON Schema keywords to codes:
`required -> REQUIRED_FIELD`, `type -> INVALID_TYPE`,
`enum/const -> INVALID_ENUM`, `minimum/exclusiveMinimum -> VALUE_OUT_OF_RANGE`,
`additionalProperties -> UNSUPPORTED_FIELD`, and other structural failures to
`INVALID_STRUCTURE`. Sort issues by `(path, code, message)`.

The CLI reads UTF-8 only, checks file size before parsing, returns
`INVALID_JSON` through exit 2 for decode/parse errors, and never imports
IfcOpenShell.
  </implementation>
</feature>
