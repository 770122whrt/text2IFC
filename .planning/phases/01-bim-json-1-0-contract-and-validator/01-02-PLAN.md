<feature>
  <name>Semantic identity and storey-reference validation</name>
  <files>src/text2ifc_contract/validation.py,
  tests/contract/test_semantic_validation.py</files>
  <behavior>
RED cases must assert:

- Reusing an ID between two storeys, two elements, or a storey and an element
  emits `DUPLICATE_ID` at every duplicate occurrence after the first.
- An element whose `storey_id` is absent emits
  `UNRESOLVED_STOREY_REFERENCE` at `/elements/{index}/storey_id`.
- Duplicate checks include project, site, building, storeys, and elements so
  the whole document has one stable identity namespace.
- Multiple semantic errors are returned together and sorted by path/code.
- A structurally malformed document returns structural issues only and semantic
  validation does not raise an exception.
- The complete fixture still returns no issues and the input is unchanged.
  </behavior>
  <implementation>
Split the public function into a structural helper and a semantic helper while
keeping only `validate_document` as the normal entry point. Build IDs in
document order and retain the first path for diagnostics; do not rename or
repair duplicates. Build the valid storey-ID set separately and check every
element reference. Run the semantic helper only when the structural issue list
is empty, then sort the combined public result by `(path, code, message)`.
  </implementation>
</feature>
