  <behavior>
RED cases must assert:

- Discovery yields exactly 53 records: 25 basic, 25 enhanced, and 3 round-trip
  models.
- Every record has source path, source selector, SHA-256, disposition, and
  diagnostics; `converted + rejected == total == 53`.
- Every converted output has `contract_version == "bim-json/1.0"` and passes
  `validate_document`.
- Running the audit twice produces byte-identical JSON and converted outputs.
- SHA-256 values of all source JSON files are unchanged before and after.
- Alias normalization covers `elev/elevation`, `w/width`, `h/height`, and
  `pretype/predefined_type`.
- Missing IDs receive deterministic family/ordinal IDs plus a provenance note.
- Missing required dimensions, non-unique storey-name resolution, or unknown
  source shape rejects the whole model with stable migration codes.
- Materials, MEP, or opening data omitted because it is outside Phase 1 is
  listed in `omissions`; supported elements are never dropped.
  </behavior>
  <implementation>
Implement pure `migrate_model(source, source_ref)` separately from fixed-root
filesystem discovery. Normalize project/site/building singleton list-vs-object
shapes and known aliases only. Map a source storey name to a canonical ID only
when unique. Reuse existing IDs where present; otherwise generate
`{kind}-{ordinal:04d}` in source order and add an `ID_GENERATED` note.

Derive dimensions only from explicit source fields. For round-trip rectangle
profiles, map wall `x_dim/y_dim/depth` to `length/thickness/height`; do not infer
dimensions from names or fallback constants. Reject the whole model when any
supported source element cannot satisfy its canonical family schema.

The CLI owns only these fixed inputs:
`ifc_parsed_data.json`, `ifc_parsed_enhanced.json`, and
`roundtrip_json/*.json`. It writes sorted, LF-terminated JSON under
`dataset/processed/bim-json-1.0/`, removing stale files only inside that output
root after resolving and checking the absolute path.
  </implementation>
</feature>
