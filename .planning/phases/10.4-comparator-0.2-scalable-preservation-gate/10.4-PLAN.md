# Phase 10.4 Plan: Comparator 0.2 Scalable Preservation Gate

**Requirements:** CMP-01, CMP-02, CMP-03, CMP-04, CMP-05
**Depends on:** Phases 8 and 10.3
**Plan count:** one plan, five sequential waves

## Wave 1: Baseline, instrumentation and RED contracts

**Files**

- `src/text2ifc_ifc_repair/compare.py`
- `src/text2ifc_ifc_repair/evaluation.py`
- `tests/ifc_repair/test_compare.py`
- new focused comparator regression/performance tests

**Work**

1. Record per-stage wall time, cache counts and peak RSS without changing the
   report decision.
2. Add failing tests for STEP reorder, duplicate/empty GUID, ordered aggregate
   semantics, shared-representation mutation, cache isolation and timeout.
3. Capture current vvo/LargeBuilding outputs as compatibility expectations.

**Exit:** tests demonstrate the current weaknesses and metrics identify the
expensive stage.

## Wave 2: Complete memoized fingerprint engine

**Work**

1. Add typed canonical encodings and domain-separated hashes.
2. Calculate shared entity/representation content once per immutable model.
3. Handle cycles deterministically without depth truncation.
4. Compare root GUID sets and root fingerprints; expand details only for
   changed roots.

**Exit:** the new engine passes the fault corpus and agrees with the legacy
comparator on small/medium fixtures.

## Wave 3: Production integration and bounded deep checks

**Work**

1. Integrate the new global gate behind the existing public API.
2. Derive the deep-check neighborhood from the bound ChangeSet/policy.
3. Measure repeated wall/volume work and add another cache only if the agreed
   large-file budget cannot be met through shared subgraph memoization.
4. Keep L2 and publication semantics unchanged.

**Exit:** full existing repair/evaluation tests pass with no report-contract
drift.

## Wave 4: Equivalence, security and performance regression

**Work**

1. Run old/new shadow comparison on vvo and LargeBuilding.
2. Exercise unauthorized geometry, property, relationship and shared-map
   mutations.
3. Exercise cache corruption/cross-file reuse, timeout and comparator
   contradiction.
4. Verify vvo runtime is not more than 20% slower.

**Exit:** no missed drift, false pass, public result drift or unbounded cache
growth.

## Wave 5: Fresh AdvancedProject acceptance

**Work**

1. Reapply the saved real DeepSeek ChangeSet to a fresh damaged/source input
   and new run directory.
2. Run three clean-process global comparisons and one fresh full Production
   replay.
3. Record comparator median time, full-replay wall time, peak RSS, result
   hashes and final L1/L2 status.
4. Package the source/damaged/repaired IFC references and comparator report.

**Exit:** all budgets and correctness checks in `10.4-SPEC.md` pass. Otherwise
record an honest failed/not-evaluable result and do not advance to Phase 11.

**Recorded deviation:** no additional wall/volume measurement cache was added.
The comparator passed at a 39.638-second median and 1.083-GB peak RSS, so the
conditional cache work was unnecessary.

## Stop conditions

Stop and investigate before proceeding if any test shows:

- an unauthorized change missed by the new comparator;
- a cache result reused across different IFC hashes or algorithm versions;
- duplicate/empty root GUIDs silently accepted;
- a timeout or partial scan reported as passed;
- a disagreement with legacy behavior that cannot be explained by a proven
  legacy bug.
