# Phase 10.4 Specification: Comparator 0.2 Scalable Preservation Gate

## Goal

Make Evaluation 0.2 finish on BIMNet-scale IFC2X3 files without weakening the
blocking global preservation guarantee or changing the established L1/L2
contract.

## Inputs and outputs

### Inputs

- source/damaged IFC;
- reopened repaired IFC;
- bound unified ChangeSet;
- evaluation policy and authorized operation targets;
- optional diagnostic `IfcDiff` request.

### Outputs

- the existing Evaluation 0.2 L1/L2 report shape;
- unchanged `normalized_model_diff` created/modified/removed semantics;
- stage timing, cache and peak-memory metrics;
- bounded details for changed roots;
- optional full `IfcDiff` diagnostic evidence.

No successful IFC is published when a blocking comparator result is failed,
not evaluable, timed out, internally inconsistent, or incomplete.

## Blocking evaluation design

### 1. Artifact gate

Before semantic comparison, verify that both IFCs can be opened, match the
expected schema family, and have identities appropriate for comparison.
Duplicate or empty root GUIDs fail closed.

### 2. Complete global preservation gate

Build one content-addressed fingerprint graph per IFC:

- primitive values have typed canonical encodings;
- entity nodes include entity class and ordered attribute slots;
- references use referenced content hashes, not STEP identifiers;
- cycles use a deterministic strongly connected/cycle-safe representation;
- ordered and unordered aggregates have different encodings;
- shared representation subgraphs are calculated once per model.

Compare the complete set of root GUIDs and their root fingerprints. This gate
remains blocking for publication.

### 3. Authorized-neighborhood deep checks

Derive the repair neighborhood from the bound ChangeSet and evaluation policy.
Perform existing human-readable structural and geometry checks for authorized
targets, hosts, openings, fills, containment, types and requested semantic
facts. Reuse representation/subgraph fingerprints within the comparison run;
do not replace operation-specific wall/volume measurements with hashes.

### 4. L2

L2 rules and semantic authority do not change in this phase.

### 5. Full IfcDiff diagnostic

Full `IfcDiff` can be requested for audit or benchmark evidence. It is
non-blocking when it finishes after publication. If a pre-publication result
contradicts the blocking comparator, publication stops with
`COMPARATOR_CONTRADICTION`.

## Compatibility requirements

- `evaluate_independent_l1` remains the supported entry point.
- Existing Evaluation 0.2 check identifiers and status vocabulary remain
  stable.
- `normalized_model_diff` retains its public call signature and
  `created`/`modified`/`removed` output contract.
- Small/medium fixtures first run old and new implementations in shadow mode;
  any disagreement is a release blocker.

## Cache rules

- In-process caches are scoped to one immutable IFC source hash.
- Any persistent cache key includes IFC SHA-256, schema, comparator version and
  algorithm version.
- Missing or invalid cache data causes recomputation or `not_evaluable`; it
  never causes a pass.
- Partial results from timeout or cancellation are not reusable as complete
  evidence.

## Acceptance criteria

1. The regression corpus detects unauthorized attribute, placement, geometry,
   shared-representation, Pset and relationship changes.
2. STEP reordering alone causes no semantic difference.
3. Duplicate/empty GUIDs, malformed values, cache contamination and timeouts
   fail closed.
4. Existing vvo and LargeBuilding expected ChangeSet/evaluation results remain
   equivalent; vvo runtime regresses by no more than 20%.
5. Three clean-process `AdvancedProject.ifc` comparator runs have a median
   global preservation time at most 120 seconds and peak RSS at most 4 GiB.
6. One fresh end-to-end replay of the saved real DeepSeek ChangeSet completes
   application and Production L1/L2 within 180 seconds and records its honest
   publication decision.

## Explicitly deferred

- new operation families or L2 facts;
- background/async publication;
- cross-machine cache services;
- exact L3 authoring identity;
- 128k Provider context;
- general-purpose IFC graph database work.

## Implementation note

The measured implementation did not add a second wall/volume measurement cache.
The global comparator met both time and memory budgets after shared subgraph
memoization, so an additional operation-measurement cache would add invalidation
complexity without an acceptance need.
