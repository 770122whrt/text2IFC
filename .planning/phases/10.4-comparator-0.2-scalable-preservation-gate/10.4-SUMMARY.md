# Phase 10.4 Summary

**Evaluation 0.2 now performs complete, fail-closed global preservation on
BIMNet-scale IFC2X3 files without repeatedly expanding shared geometry.**

## Accomplishments

- Replaced repeated recursive snapshots with typed, schema-aware,
  cycle-safe fingerprints memoized once per immutable IFC model.
- Preserved ordered IFC aggregates, normalized only SET/BAG semantics and
  removed STEP identifiers from cross-file semantic identity.
- Kept the existing `evaluate_independent_l1` and
  `normalized_model_diff` contracts while expanding human-readable details
  only for changed roots.
- Made duplicate/empty root GUIDs, unsupported canonical values, timeout,
  cancellation, incomplete scans and cache contamination fail closed.
- Kept full `IfcDiff` diagnostic by default and release-blocking only when a
  pre-publication result contradicts the mandatory comparator.
- Added baseline-aware IfcOpenShell validation: repairs may retain existing
  source diagnostics but may not introduce new ones.
- Aligned mapped-Window geometry evaluation and effective IFC material
  precedence without changing the saved Provider output or Bound ChangeSet.

## Verification

- Comparator correctness and compatibility regression: **517 passed,
  1 skipped**.
- `AdvancedProject.ifc`: 770,172 STEP entities and approximately 47,000
  compared roots.
- Three clean comparator runs: **39.638 seconds median**, **1.083 GB maximum
  RSS**, identical `42 created / 5 modified / 0 removed` results.
- Fresh saved-ChangeSet replay after evaluator alignment: application,
  global preservation and five independent L1/L2 gates passed; publication
  completed in approximately **94 seconds** without another Provider call.
- IfcOpenShell validation-delta replay: damaged and repaired files both had
  286 baseline diagnostics, with **0 new diagnostics** and a publishable
  result.

## Deviations and Remaining Evidence Boundary

- The conditional wall/volume measurement cache was not added because shared
  subgraph memoization already met the comparator time and memory budgets.
- Adding the full validation-delta pass increased the later
  `AdvancedProject` end-to-end run to approximately **356 seconds**. This is a
  correctness pass but not evidence that comparator plus schema validation
  still satisfies the former 180-second combined latency budget.
- L3 authoring identity, asynchronous publication, distributed caches and
  128k Provider context remain out of scope.

## Next-Phase Readiness

The common preservation and validation gates are operation-neutral and ready
for Beam and Column expansion. Phase 12 must add only operation-specific
target, placement, containment, Type/material and L1/L2 contracts; it must not
fork or weaken the comparator. Large-model latency and the 128k input decision
remain Phase 13 concerns.
