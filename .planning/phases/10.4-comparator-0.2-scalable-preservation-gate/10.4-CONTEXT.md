# Phase 10.4 Context: Comparator 0.2 Scalable Preservation Gate

## Why this phase exists

The five-Window repair on `AdvancedProject.ifc` reached a valid applied IFC,
but Production evaluation did not finish within 15 minutes. The model contains
770,172 STEP entities. The current comparator recursively expands
representations for every `IfcRoot`, repeatedly serializes shared geometry into
large Python trees, and then hashes the serialized trees.

This is an evaluator scalability failure, not a Provider, ChangeSet, or IFC
application failure.

## Decisions already confirmed

1. Production publication still waits for a complete global preservation
   result. A timeout, incomplete scan, cache error, or comparator contradiction
   never counts as a pass.
2. Full `IfcDiff` is diagnostic by default, not a routine publication gate. If
   it is run before publication and contradicts the blocking comparator, the
   run fails closed.
3. The first `AdvancedProject.ifc` acceptance budget is:
   - global preservation: at most 120 seconds;
   - complete Production L1/L2 evaluation: at most 180 seconds;
   - peak resident memory: at most 4 GiB.
4. Evaluation 0.2 public statuses, existing check identifiers, report shape and
   publication semantics remain compatible.

## Frozen scope

Phase 10.4 does only the following:

- replace repeated recursive snapshots with complete, cycle-safe,
  memoized content fingerprints;
- preserve deep checks for the policy-derived authorized repair neighborhood;
- cache repeated geometry facts inside one evaluation run;
- add correctness, compatibility and performance evidence;
- rerun the saved real DeepSeek ChangeSet in a fresh output directory.

It does not add Door, Opening, Beam, Column, new L2 semantics, asynchronous
publication, generic distributed caching, 128k context, or a whole-IFC graph
platform.

## Correctness boundary

The optimized path may change how evidence is computed, but not what
unauthorized changes are allowed. Global fingerprints cover every `IfcRoot` and
its reachable comparison content. Hashing must:

- include schema/comparator version, entity class, attribute name or index, and
  aggregate semantics;
- preserve order for ordered aggregates and normalize only unordered
  aggregates;
- avoid using STEP numbers as cross-file identity;
- be cycle-safe without silently truncating at an arbitrary depth;
- reject empty or duplicate `GlobalId` values for compared roots;
- bind reusable cache data to source hash, schema and comparator version.

When global fingerprints differ, the comparator computes bounded human-readable
details only for the changed roots. It does not materialize a complete expanded
snapshot for every unchanged root.

## Evidence hygiene

Final acceptance must use a new run directory. Existing
`deterministic-continuation` evidence is not an acceptance source because a
rerun reused its repaired output and overwrote application/evaluation files.
