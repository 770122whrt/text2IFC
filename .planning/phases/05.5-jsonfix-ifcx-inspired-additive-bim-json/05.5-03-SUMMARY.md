## Prompt Contract

The canonical assets are:

- `prompts/jsonfix/semantic-patch-v1.md`
- `prompts/jsonfix/semantic-patch-fewshot.md`

The prompt binds:

- Chinese user repair request;
- immutable base document id;
- base BIM JSON semantic content;
- validator/reviewer feedback;
- local patch schema;
- checked-in few-shot examples.

The provider must return one JSON patch object. It must not return a full BIM
JSON replacement, raw IFC/STEP, STEP ids, low-level IFC helper objects, mesh
points, face indices, or generic transform matrices.

If required facts are unknown, the provider emits `mark_missing` with 1-3
Chinese questions. Validator and reviewer feedback use separate provenance
layers. Existing source facts require explicit `overwrite: true`.

## Few-shot Coverage

The examples cover:

1. adding a missing `IfcWallStandardCase`;
2. setting `Pset_WallCommon.FireRating`;
3. recording unsupported source geometry with
   `mark_unsupported_loss` and `substitution: "none"`.

## Deterministic Repair Case

`build_repair_case("missing-piece-repair", output_dir)` writes:

- `input.txt`;
- `base.json`;
- `patch.json`;
- `expected.json`;
- `metadata.json`.

The base is valid Formal BIM JSON 2.0 containing a 6000 x 4000 x 3000 mm room
with south, north, and east walls. The Chinese request explicitly adds the
missing west wall at `(0, 2000, 0)`, oriented along Y, without changing other
entities. Composition produces the checked expected document.

## Provider Handoff

`run_repair_handoff` performs:

1. prompt rendering;
2. provider output guardrails and JSON parsing;
3. patch validation;
4. `mark_missing` Draft detection;
5. patch composition and Formal BIM JSON validation.

Fake and file providers replay the same semantic patch and produce the same
Formal candidate. Invalid JSON remains a provider parse diagnostic and never
reaches composition.

## Live-provider Boundary

No live provider was called and no `.env` value was read in this plan.
Live-provider quality remains an experiment, not a deterministic acceptance
dependency. Future live runs must use the same checked-in prompt renderer and
must retain raw response, patch diagnostics, composition diagnostics, and
prompt version without writing credentials.
