# Plan 05.5-04: Missing-Piece json2IFC Demo and Quality Gate

<objective>
Run the full jsonfix path from text repair intent to patch, composed BIM JSON,
validated BIM JSON 2.0, compiled IFC2X3, reopened IFC, and quality report.
</objective>

<truths>
- A patch is not accepted merely because it validates as patch JSON.
- The composed result must validate as formal BIM JSON 2.0.
- The IFC output must pass compile, reopen, and generated-IFC quality checks.
- IFC2X3 identity is a hard fact: both the serialized STEP header and the
  reopened IfcOpenShell model must report IFC2X3.
- External IFC corpora are read-only evidence; mixed-schema files must be
  inventoried and filtered before extraction.
- The final artifact is a real IFC file.
</truths>

## Task 1: RED IFC2X3 artifact and external inventory gates

<type>tdd</type>
<files>tests/jsonfix/test_ifc2x3_artifact_gate.py, tests/jsonfix/test_external_ifc_inventory.py</files>
<action>
Write failing tests for a strict artifact checker and a read-only external IFC
inventory.

The artifact checker must:

- accept a valid generated IFC whose structurally parsed STEP header contains
  exactly the single schema identifier IFC2X3 and whose
  reopened `model.schema` is IFC2X3;
- reject IFC4, IFC4X3, missing/multiple/ambiguous `FILE_SCHEMA`, reopen failure, and IFC
  validation errors;
- return machine-readable schema and validation evidence.

The inventory must classify files by declared schema, reopen status, and
reopened schema without modifying source files. It must exclude non-IFC2X3
files from the eligible extraction subset and retain repo-relative source and
license metadata.

Commit RED before implementation.
</action>

<acceptance_criteria>
