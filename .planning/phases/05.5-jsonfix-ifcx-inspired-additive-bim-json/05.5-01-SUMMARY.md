- `docs/reference/bim-json-patch-1.0.md`
- Positive and negative fixtures under `tests/fixtures/jsonfix/`

The contract requires an IFC2X3-targeted envelope, immutable base document id,
ordered provenance layers, and semantic operations. The validator rejects raw
IFC/STEP, STEP ids, low-level IFC helper objects, unsupported operations, and
unreviewed destructive intent with stable diagnostic codes.

The supported operation list is stored once in the JSON Schema extension
`x-supported-operations`. Runtime validation and generated reference
documentation consume that same list.

## Decisions

- Patch validation proves only that a transformation request is structurally
  and semantically allowed. It does not prove that the result is Formal or
  compilable.
- `request_tombstone` records deletion-like intent but cannot delete source
  facts in Phase 5.5.
- Unknown or unsupported facts remain explicit through `mark_missing` and
  `mark_unsupported_loss`.
- Normal validation resolves only the checked-in local schema.
