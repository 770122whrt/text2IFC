# Plan 05.5-01: Patch Envelope Schema and Validator

<objective>
Define `bim-json-patch/1.0` as a separate, provenance-bearing patch envelope
that targets BIM JSON 2.0 without creating a competing Formal BIM JSON model.
</objective>

<truths>
- BIM JSON 2.0 remains the Formal document structural truth.
- A patch document describes changes to be composed, not a compilable model.
- Patch output must not contain raw IFC, STEP text, STEP IDs, or low-level IFC
  helper objects.
- Patch layers require provenance.
- Normal destructive deletion is out of scope.
</truths>

Create positive and negative fixtures before implementation.

Positive fixtures:

- one `add_entity` patch with layer provenance;
- one `set_property` patch that resembles the IFCx FireRating example but
  targets BIM JSON semantic IDs;

Negative fixtures:

- missing provenance;
- unsupported operation;
- raw STEP text;

- missing `target_schema_version`;

## Task 2: GREEN patch schema and validator

<type>implementation</type>
<files>schemas/bim-json-patch/1.0/schema.json, src/text2ifc_jsonfix/validation.py, scripts/jsonfix/validate_patch.py</files>
<action>
Implement the patch schema, validator API, and CLI.

The schema must require:

- `patch_version: "bim-json-patch/1.0"`;
- `target_schema_version: "bim-json/2.0"`;
- `target_ifc_schema: "IFC2X3"`;
- `target_document_id`;
- ordered `layers[]`;
- layer `id`, `kind`, `provenance`, and `operations[]`;
- operation `op`, `target`, `value` or operation-specific payload.

The validator must add semantic guardrails that JSON Schema alone cannot
express, including raw IFC/STEP and low-level helper object rejection.

Commit GREEN after focused tests pass.
</action>
<verify>python -m pytest tests/jsonfix/test_patch_schema.py -q</verify>
<acceptance_criteria>
All positive fixtures pass and all negative fixtures fail with stable error
codes.
</acceptance_criteria>
