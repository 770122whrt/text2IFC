## Final semantic routing boundary

- `confirmed`: the request directly and sufficiently identifies exactly one
  offered canonical property.
- `clarification_required`: the target entity and repair capability are
  plausibly supported, but the request does not yet identify one safe,
  executable intent. This includes an unspecified property edit, multiple
  plausible properties, and a resolved property whose value or unit requires
  correction.
- `unsupported_property`: the property intent is sufficiently specific, but
  no such property exists in the current authoritative supported universe.
- `unsupported_operation`: the requested repair operation itself is outside
  the supported repair capability.

The production Stage 1.5 schema remains unchanged: both unsupported subtypes map
to its existing `unsupported` terminal decision. Their distinction belongs to
the evaluator taxonomy and product-scope explanation, not to a new executable
Provider field.

`Top-K empty`, weak retrieval, or an underspecified phrase is not evidence of
unsupported capability. The stage boundary remains:

```text
property phrase + IFC class + supported scope
-> semantic retrieval/resolution
-> canonical property identified
-> deterministic value/type/unit validation
-> execute or request clarification/value correction
```

No case ID, literal `未知门属性` match, alias, phrase dictionary, compatibility
normalizer, or post-Provider override implements this rule.
