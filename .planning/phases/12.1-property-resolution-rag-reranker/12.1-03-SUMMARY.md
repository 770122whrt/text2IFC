# Phase 12.1 Plan 03: Bounded Property Resolution Provider Summary

**Stage 1.5 now performs one independent semantic comparison over one claim and
its offered Top-K, while remaining unable to construct an IFC property intent.**

## Accomplishments

- Added `generate_property_resolution_decision(...)` with query/candidate
  schema validation before optional Provider factory construction.
- Rendered only the four registered public Prompt inputs and used the existing
  `ifc-property-resolution.v0.1` template unchanged.

  issues from attempt 1; raw Provider content is not converted into aliases or
  alternate keys.

## Contract Boundary

- Input: one validated public query and its persisted offered candidate set.
- Provider authority: semantic `confirmed`, `clarification_required`, or
  `unsupported` decision using offered IDs only.
- Program checks: exact schema, decision shape, offered membership, response
  bounds and public-output boundary.
- Output: semantic decision plus attempt/trace evidence only. No
  `ExactPropertyIntent`, Binder input, ChangeSet or Stage 2 call is produced.
