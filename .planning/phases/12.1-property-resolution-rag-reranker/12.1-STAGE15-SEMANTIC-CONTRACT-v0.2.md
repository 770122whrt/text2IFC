## Correct semantic boundary

Stage 1.5 remains a bounded semantic selector over one public property query and
its offered authoritative candidates.

- `confirmed`: the user's language supplies direct and sufficiently specific
  semantic evidence that uniquely authorizes exactly one offered canonical
  property.
- `clarification_required`: the request is meaningful and potentially
  repairable, but does not uniquely authorize one executable property or repair
  interpretation. This includes both multiple plausible offered candidates and
  a broader repair goal for which one related offered candidate is only one
  possible interpretation.
- `unsupported`: the request is genuinely outside the supported repair
  capability or cannot be resolved into a supported repair action even through
  clarification.

Semantic relatedness, retrieval rank, nearest-candidate status, a plausible
engineering means, or one possible way to achieve the user's broader goal is
not confirmation evidence. No case ID, family phrase, keyword blacklist,
`LoadBearing` special case, Chinese phrase mapping, alias, or compatibility
normalizer implements this boundary.

The authority split is unchanged:

```text
Retrieval -> offered authoritative candidates
Stage 1.5 -> confirmed / clarification_required / unsupported
Admissibility -> membership, authority, class, type, unit, scope and policy
Program code -> ExactPropertyIntent
```

Deterministic admissibility does not perform a second natural-language semantic
classification.
