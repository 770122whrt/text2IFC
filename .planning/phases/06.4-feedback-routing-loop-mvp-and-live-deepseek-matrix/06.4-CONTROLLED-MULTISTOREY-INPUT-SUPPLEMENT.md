# Phase 6.4 Controlled Multi-storey Input Supplement

**Date:** 2026-07-09
**Document type:** Explanation + reference
**Audience:** text2IFC project maintainers and Agent prompt/debug reviewers
**Goal:** clarify what extra facts the hard two-storey input needs before it is a fair controlled Generator/Gate/Audit test

## Short Answer

The original two-storey input is not bad. It is rich enough for a human to
sketch a plausible house, but it is not fully constrained enough for a
no-fabrication text2IFC Agent to produce a deterministic, auditable IFC.

The main missing facts are not basic dimensions. They are layout closure facts:

- exact room rectangles or coordinates;
- corridor/transition area geometry;
- per-storey exterior wall shells;
- storey-scoped host walls for every door/window;
- exact or rule-based opening positions;
- stair geometry;
- roof slab thickness and placement;
- interior wall segment definitions.

Without those facts, DeepSeek has two possible behaviors:

1. Ask for more information or return `draft_required`, which is conservative
   and often correct.
2. Guess layout defaults, which may produce an IFC but violates the current
   no-silent-fabrication boundary.

For a controlled benchmark, we should provide these facts explicitly.

## What The Current Input Already Provides

The current prompt already gives many important facts:

- building outline: 10000 mm by 8000 mm;
- two storeys;
- storey clear height: 3000 mm;
- wall thickness: 200 mm;
- floor slab thickness: 150 mm;
- coordinate convention: southwest origin, X east, Y north, Z up;
- room names and approximate quadrant positions;
- room sizes;
- door/window sizes;
- some opening host-wall descriptions;
- stair start/end Z values;
- requested IFC classes: building, storeys, spaces, walls, slabs, roof, stair,
  doors, windows.

These facts are useful but not enough to make every wall, room, opening, and
stair relation deterministic.

## Missing Facts The Agent Reasonably Needs

### 1. Storey Z Datum

The input says first floor starts near Z=3150 and roof near Z=6150, but it mixes
clear height, slab thickness, and floor/finished-floor wording.

For controlled generation, state explicitly:

- ground-floor finished floor top is Z=0;
- ground-floor wall base is Z=0;
- first-floor slab top is Z=3150;
- second-storey wall base is Z=3150;
- roof slab bottom or top Z is explicit.

Recommended controlled choice:

```text
Ground floor finished floor top is Z=0. Ground-floor walls start at Z=0 and
extend to Z=3000. The second-floor slab top is Z=3150. Second-floor walls start
at Z=3150 and extend to Z=6150. The roof slab thickness is 150 mm and its
bottom elevation is Z=6150.
```

### 2. Space Rectangles

"Southwest", "southeast", "northeast", and "northwest" are human-friendly, but
the Generator needs exact rectangles.

Recommended controlled ground-floor rectangles:

```text
Ground floor spaces:
- living_room: x=0..6000, y=0..4500
- kitchen: x=6000..10000, y=0..3500
- bathroom_1: x=7500..10000, y=5500..8000
- stairwell: x=0..3500, y=4500..8000
- ground_corridor: x=3500..7500, y=3500..8000
```

Recommended controlled second-floor rectangles:

```text
Second floor spaces:
- master_bedroom: x=0..5000, y=0..4000
- second_bedroom: x=6000..10000, y=0..3500
- study: x=7000..10000, y=5500..8000
- bathroom_2: x=0..2500, y=5500..8000
- corridor: x=2500..7000, y=3500..5500
- stair_landing: x=0..3500, y=4500..5500
```

These rectangles are a proposed controlled benchmark layout, not a hidden
default for arbitrary user input.

### 3. Exterior Wall Shell Per Storey

The earlier bad IFC strongly suggests the Generator reused first-floor exterior
wall IDs for second-floor windows. To avoid this ambiguity, the input should
explicitly require an independent exterior wall loop for each storey.

Recommended controlled statement:

```text
Create four exterior walls on each storey. Do not reuse ground-floor wall IDs
as second-floor host walls. The second floor has its own south, east, north,
and west exterior walls at Z=3150.
```

### 4. Interior Wall Segments

Room rectangles imply interior boundaries, but they do not directly say which
wall segments exist. For a controlled benchmark, provide segment endpoints.

Recommended minimum:

```text
Interior walls should be generated along shared boundaries between adjacent
space rectangles. Split interior walls at door openings where needed. Each wall
belongs to exactly one storey and should have a storey-scoped id.
```

If the Generator still fails, the next stronger version should enumerate each
interior wall segment by start/end XY coordinates.

### 5. Door Positions

Many doors have dimensions and host descriptions, but not exact offsets. For a
controlled benchmark, use "centered on host segment" or exact center
coordinates.

Recommended controlled rule:

```text
Unless an exact offset is specified below, each door is centered on its host
wall segment. Door width is measured along the wall direction.
```

Then specify exceptions or centers:

```text
Ground-floor exterior door:
- living_room south exterior wall, centered at x=3000, y=0

Ground-floor interior doors:
- living_room to kitchen on shared wall x=6000, centered at y=2250
- kitchen to ground_corridor on wall y=3500, centered at x=8000
- bathroom_1 to ground_corridor on wall y=5500 or x=7500, centered on chosen segment
- stairwell to ground_corridor on wall x=3500, centered at y=6250

Second-floor doors:
- all room doors connect to corridor and are centered on the shared wall segment
- bathroom_2 door width is 750 mm, other room doors are 900 mm
```

### 6. Window Positions

The input gives sizes and sill heights, but some windows lack exact horizontal
location. For a controlled run, use centered placement or specific centers.

Recommended controlled rule:

```text
Unless explicitly stated otherwise, each window is centered on its host wall
segment. Living-room and master-bedroom paired windows are symmetrically placed
on either side of the door or room centerline as described below.
```

Recommended positions:

```text
Ground floor:
- living_room south wall has two windows centered at x=1750 and x=4250, y=0
- kitchen east wall window centered at x=10000, y=1750
- bathroom_1 north wall window centered at x=8750, y=8000

Second floor:
- master_bedroom south wall has two windows centered at x=1500 and x=3500, y=0
- second_bedroom east wall window centered at x=10000, y=1750
- study north wall window centered at x=8500, y=8000
- bathroom_2 west wall window centered at x=0, y=6750
```

### 7. Stair Geometry

The original says straight or dog-leg are both acceptable. That gives the model
permission to choose, but under no-fabrication rules it may still hesitate
because the specific stair body is not defined.

For controlled generation, choose one:

```text
Use a straight stair inside the ground-floor stairwell. Stair footprint:
x=500..3000, y=5000..7500. Stair width is 1000 mm. It rises from Z=150 to
Z=3150 and connects to the second-floor stair_landing. If detailed treads are
not supported, generate a simple IfcStair-equivalent semantic element with the
same footprint and vertical connection facts, and record unsupported detailed
tread geometry as a loss or Draft note rather than inventing it.
```

### 8. Roof

The original says roof near Z=6150 but not thickness. Add:

```text
Roof slab covers the full outer outline x=0..10000, y=0..8000. Roof slab
thickness is 150 mm. Roof slab bottom elevation is Z=6150.
```

## Controlled Two-storey Prompt Draft

Use this as the next controlled live test input. It intentionally supplies more
layout facts than a normal user would, because this benchmark is meant to test
Generator/Gate/Audit behavior, not the clarification Agent.

```text
创建一个两层小型住宅建筑，单位为毫米。建筑外轮廓为矩形，西南角为坐标原点，X 轴向东，Y 轴向北，Z 轴向上。外轮廓尺寸为 x=0..10000，y=0..8000。建筑共两层。首层完成地面顶标高为 Z=0，首层墙体从 Z=0 到 Z=3000。二层楼板顶标高为 Z=3150，二层墙体从 Z=3150 到 Z=6150。所有墙厚 200。首层地板厚 150，二层楼板厚 150。屋面板厚 150，屋面板底标高 Z=6150，覆盖 x=0..10000、y=0..8000。

请为每一层分别生成独立的四面外墙闭合环。不要复用首层外墙作为二层门窗宿主。首层外墙包括 south、east、north、west 四面墙，二层外墙也包括独立的 south、east、north、west 四面墙。所有墙体必须关联到对应楼层。

首层空间矩形如下：living_room 为 x=0..6000、y=0..4500；kitchen 为 x=6000..10000、y=0..3500；bathroom_1 为 x=7500..10000、y=5500..8000；stairwell 为 x=0..3500、y=4500..8000；ground_corridor 为 x=3500..7500、y=3500..8000。请生成这些 IfcSpace，并沿相邻空间边界生成必要内墙，内墙在门洞处断开或包含门洞关系。

二层空间矩形如下：master_bedroom 为 x=0..5000、y=0..4000；second_bedroom 为 x=6000..10000、y=0..3500；study 为 x=7000..10000、y=5500..8000；bathroom_2 为 x=0..2500、y=5500..8000；corridor 为 x=2500..7000、y=3500..5500；stair_landing 为 x=0..3500、y=4500..5500。请生成这些 IfcSpace，并沿相邻空间边界生成必要内墙，二层外墙必须形成完整外轮廓。

门的位置如下。首层 living_room 南外墙设置外门，宽 1200、高 2200，门中心位于 x=3000、y=0。living_room 与 kitchen 的门位于共享墙 x=6000，中心 y=2250，宽 900、高 2100。kitchen 与 ground_corridor 的门位于 y=3500，中心 x=8000，宽 800、高 2100。bathroom_1 与 ground_corridor 的门位于其共享边界，居中，宽 750、高 2100。stairwell 与 ground_corridor 的门位于 x=3500，中心 y=6250，宽 900、高 2100。二层所有房间门都连接到 corridor 或 stair_landing，门在共享墙段居中；master_bedroom、second_bedroom、study 的门宽 900、高 2100，bathroom_2 的门宽 750、高 2100。

窗的位置如下。首层 living_room 南外墙有两扇窗，均宽 1500、高 1200、窗台高 900，中心分别为 x=1750、y=0 和 x=4250、y=0。kitchen 东外墙有一扇窗，宽 1200、高 1000、窗台高 1000，中心 x=10000、y=1750。bathroom_1 北外墙有一扇窗，宽 800、高 600、窗台高 1600，中心 x=8750、y=8000。二层 master_bedroom 南外墙有两扇窗，均宽 1500、高 1200、窗台高 900，中心分别为 x=1500、y=0 和 x=3500、y=0。second_bedroom 东外墙有一扇窗，宽 1400、高 1200、窗台高 900，中心 x=10000、y=1750。study 北外墙有一扇窗，宽 1200、高 1000、窗台高 900，中心 x=8500、y=8000。bathroom_2 西外墙有一扇窗，宽 800、高 600、窗台高 1600，中心 x=0、y=6750。所有门窗必须嵌入对应楼层的宿主墙，不能挂到其他楼层的墙上。

楼梯位于 stairwell 内，采用直跑楼梯。楼梯 footprint 为 x=500..3000、y=5000..7500，宽 1000，从 Z=150 上升到 Z=3150，连接首层 stairwell 与二层 stair_landing。请生成 IfcStair 或当前 BIM JSON 2.0 能表达的等效楼梯构件；如果详细踏步几何暂不支持，请保留垂直连接和楼梯语义，不要编造低层 IFC 实体。

请生成 IfcBuilding、两个 IfcBuildingStorey、所有 IfcSpace、外墙、内墙、首层地板、二层楼板、屋面板、楼梯、门和窗，并保持空间归属、相邻关系、楼层归属、门窗宿主墙、开洞填充关系和 IFC2X3 结构正确。输出必须是可验证的 BIM JSON 2.0 或明确 Draft；如果仍有无法表达的事实，请列出缺失或不支持项，不要静默补默认值。
```

## Expected Behavior For This Controlled Input

This input is intentionally explicit enough that the Design Brief Agent should
prefer `ready` instead of `needs_clarification` or `draft_required`.

If the workflow still fails after this supplement, the likely owner should be:

- `generator`, if BIM JSON misses second-floor exterior walls, wrong host
  walls, storey assignment, or space boundaries;
- `repair`, if only schema-level issues such as open polygon rings remain;
- `compiler`, if BIM JSON uses a supported semantic fact that the compiler
  cannot yet emit;
- `gate`, if generated IFC is visually/geometrically correct but gate evidence
  is too strict or incorrectly derived;
- `schema`, if the desired controlled fact cannot be represented in BIM JSON
  2.0 without schema expansion.

It should not route to `ask_user` unless the Agent can point to a genuinely
missing user fact not included above.
