## Loop Behavior

| Route | Target stage | Attempted action | Automatic behavior |
|---|---|---|---|
| `accepted` | `none` | `none` | Stop accepted |
| `ask_user` | `user` | `stop_for_user_input` | Stop as Draft/user-needed; no invented facts |
| `revise_design_brief` | `design_brief` | `prepare_design_brief_feedback` | Prepare evidence for rerun |
| `regenerate_json` | `generator` | `prepare_generator_feedback` | Prepare evidence for rerun |
| `repair_json` | `repair` | `prepare_repair_feedback` | Prepare evidence for repair |
| `blocked_as_unsupported` | `schema` or `compiler` | `stop_unsupported` | Stop with unsupported evidence |
| `gate_issue` | `gate` | `stop_gate_review` | Stop for gate review |
| `provider_retry` | `provider` | `prepare_provider_retry` | Prepare provider retry evidence |
| `runtime_blocked` | `runtime` | `stop_runtime_blocked` | Stop failed |

## Safety Rules Verified

- Default `max_feedback_rounds` is 2.
- Non-improving issue counts stop as `blocked_non_improving`.
- Round index at or beyond the max stops as `blocked_attempt_limit`.
- `ask_user` does not automatically retry because the system cannot add user
  facts by itself.
- Every planned round records source stage, input/output issue counts, issue
  delta, route, target stage, retry permission, attempted action, terminal
  status, normalized issues, and the embedded RouteDecision v2.
