## Core Decision

Phase 6.4 prioritizes feedback-loop correctness over complex-building success.
The complex multi-storey run may still block, but it must block with structured
issues, a route decision, feedback-round evidence, and a report that tells the
next owner what to do.

## Required Feedback Flow

```text
Round N
  -> Design Brief / Generator / Repair / Provider attempt
  -> Validate / Compile / Gate / Audit
  -> Normalize Issues
  -> RouteDecision
  -> feedback-rounds.json append
  -> bounded rerun when allowed
  -> accepted, draft, blocked, or failed
```

## Route Vocabulary

Phase 6.4 uses the user-approved route vocabulary:

- `accepted`
- `ask_user`
- `revise_design_brief`
- `regenerate_json`
- `repair_json`
- `blocked_as_unsupported`
- `gate_issue`
- `provider_retry`
- `runtime_blocked`

## Live DeepSeek Rule

Deterministic tests and matrix tests come first. Real DeepSeek runs happen only
after GREEN. Live acceptance must use the OpenAI-compatible provider path with
the configured `.env`, but secrets and private provider URLs stay redacted.

Live acceptance must include:

1. JSON smoke response from DeepSeek.
2. One accepted IFC-producing workflow run.
3. One non-accept workflow run with correct Issues/RouteDecision/report.
4. A transcript generated from actual model questions or adaptive semantic
   interaction, not a fixed `answers.json` or exact scripted question match.

## Non-negotiable Boundaries

- No RAG, fine-tuning, deployment, or schema redesign.
- No production special case for one two-storey prompt.
- No acceptance from fake/file/replay provider evidence.
- No final live acceptance from prewritten `answers.json` or exact scripted
  LLM wording.
- No secrets in artifacts.
- `finish_reason=length` blocks acceptance.
- Audit and deterministic gate failures cannot be accepted.

## Completion Criteria

- Issue normalization exists for all required failure sources.
- RouteDecision v2 exists and is derived from Issues.
- Feedback rounds are bounded and persisted.
- Matrix artifacts exist and cover success plus failure routes.
- Real DeepSeek live smoke and workflow UAT are executed after deterministic
  tests pass.
- At least one DeepSeek live run writes an accepted IFC.
- At least one DeepSeek live non-accept run writes Issues, RouteDecision,
  feedback rounds, and report.
- Roadmap, state, summaries, and verification evidence are updated.
