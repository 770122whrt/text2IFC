# Objective

Introduce the feedback loop controller that records each round, applies route
decisions, and either performs a bounded rerun or stops with explicit evidence.

# Tasks

## T1 - RED: feedback-round contract

Add tests for `feedback-rounds.json` structure:

- round index,
- source stage,
- input issue count,
- output issue count,
- issue delta,
- route,
- target stage,
- retry allowed,
- attempted action,
- terminal status.

## T2 - RED: bounded rerun and stall detection

Add tests proving that generator, repair, and provider retry routes stop after
two rounds and stop earlier if issue counts do not decrease.

## T3 - RED: route target dispatch boundaries

Add tests for:

- `ask_user` stops and reports user target,
- `revise_design_brief` prepares Design Brief feedback but does not invent
  facts,
- `regenerate_json` reruns or records target Generator,
- `repair_json` invokes repair when eligible,
- `blocked_as_unsupported`, `gate_issue`, and `runtime_blocked` stop.

## T4 - GREEN: implement feedback controller

Implement the minimal controller needed for Phase 6.4. Prefer explicit
preparation of a target route over over-automating uncertain stage loops.

## T5 - Integrate with CLI flow

Integrate the controller into `run_ready_session_to_ifc` or the closest
existing orchestration seam so `feedback-rounds.json` is generated for success
and failure routes.

## T6 - Summary

Write `06.4-02-SUMMARY.md` with loop behaviors and routes that are prepared
but not automatically rerun yet.
