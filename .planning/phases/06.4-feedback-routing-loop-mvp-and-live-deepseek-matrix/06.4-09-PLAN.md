# Phase 6.4-09: Multi-storey Datum and Stair Geometry Bugfix

## Objective

Close the verified gap between the canonical Design Brief, expected-fact
extraction, BIM JSON local placement, IFC stair compilation, and deterministic
geometry gates. The fix must reject the previously accepted bad slab, roof,
stair-flight, and stair-opening geometry without directly rewriting model
coordinates.

## Locked Contract

1. Canonical Design Brief fields are `building.outline`, `floor_slabs`,
   `roof_slab`, and `stairs`. Existing `outer_bounds`, `slabs`, and `roof`
   remain bounded compatibility aliases only.
2. `ObjectPlacement.origin` is local to `relative_to`. A global target is
   converted to local coordinates exactly once.
3. A floor slab with `top_elevation_mm` occupies
   `[top_elevation_mm - thickness_mm, top_elevation_mm]`.
4. A roof slab with `bottom_elevation_mm` occupies
   `[bottom_elevation_mm, bottom_elevation_mm + thickness_mm]`.
5. An `IfcStairFlight` uses a vertical placement frame. Its stepped side
   profile expresses run and rise; extrusion expresses width. Do not encode
   the incline in both placement and representation.
6. The stair opening is checked in world coordinates against the confirmed
   `opening_bounds`. The compiler and Gate must not infer missing dimensions.

## TDD Waves

### Wave 1: RED - contract extraction and expectations

- Prove `floor_slabs` are currently omitted from expected facts.
- Prove mapping-form `building.outline`, explicit roof, stair, and opening
  bounds are currently absent from the geometry expectation.

### Wave 2: RED - stair compilation and IFC Gate

- Prove a stepped `IfcStairFlight` currently compiles with the wrong world
  orientation.
- Prove the current Gate accepts wrong roof, stair, and opening bounds.
- Require component-specific evidence and issue codes.

### Wave 3: GREEN - minimal implementation

- Align expected-fact extraction with canonical fields and bounded aliases.
- Extend semantic geometry expectations with floor slabs, roof, stairs, and
  floor openings.
- Apply the existing stair side-profile coordinate convention to
  `IfcStairFlight`.
- Extend the generated IFC Gate with roof, stair footprint/rise/step, and
  stair-opening checks.
- Align Generator prompt and the standard two-storey few-shot with the same
  contract.

### Wave 4: verification

- Run focused RED/GREEN tests and the complete regression suite.
- Compile and reopen a corrected deterministic two-storey fixture.
- Run a real DeepSeek two-storey UAT. Success requires either a Gate-accepted
  IFC or an honest bounded regeneration/block with component-specific evidence.
- Update Phase 6.4 summary/state with verified facts, commit atomically, and
  push `origin/multiagent-design`.
