# Phase 6.4-09 Summary: Datum and Stair Geometry

## Outcome

The deterministic compiler and Gate defects are fixed. Real DeepSeek runs no
longer receive false acceptance when floor/roof datums, stair geometry, or the
stair opening are wrong. The live workflow is still not reliably capable of
producing one fully accepted two-storey IFC because full-document regeneration
can change components that passed the prior round.

## Root Causes Fixed

1. `floor_slabs` was not read by expected-fact extraction.
2. Mapping-form `building.outline`, explicit roof, stairs, and floor openings
   were absent from the semantic geometry expectation.
3. `IfcStairFlight` did not use the stair step-profile coordinate mapping.
4. The original stair mapping required a counter-intuitive negated width
   direction. `IfcStairFlight.direction` now means the actual width extrusion
   vector; legacy `IfcStair` behavior is unchanged.
5. Geometry issue normalization discarded structured `expected` and `actual`
   evidence before Generator regeneration.
6. Live Design Brief output used the observed `plan_bounds` alias. The prompt
   now requires canonical `bounds`, and the extractor has one bounded alias so
   the stair Gate cannot silently disappear.
7. Generator feedback was limited to two regenerations despite the established
   repair limit of three. Both bounded feedback controls now allow three.

## New Deterministic Evidence

The Gate now emits and routes:

- `SLAB_BBOX_MISMATCH`
- `ROOF_BBOX_MISMATCH`
- `VERTICAL_SLAB_WALL_GAP`
- `STAIR_FOOTPRINT_MISMATCH`
- `STAIR_RISE_DIRECTION_MISMATCH`
- `STAIR_STEP_PROFILE_MISSING`
- `STAIR_OPENING_BBOX_MISMATCH`

The standard two-storey Generator few-shot compiles and passes the new Gate
with floor slab Z `3.00..3.15 m`, roof Z `6.15..6.30 m`, stair bounds
`x=0.50..1.50 m, y=4.05..7.95 m, z=0.15..3.15 m`, a stepped profile, and the
stair opening at `x=0..2 m, y=4..8 m, z=3.00..3.15 m`.

## Live DeepSeek Findings

Six real two-storey runs were retained locally under
`dataset/processed/agent-demo/phase6.4-datum-stair-live-deepseek*`.

- Early runs exposed missing canonical Design Brief slab records and the
  `plan_bounds` alias that disabled stair checking.
- A run reported accepted before the alias fix. Rechecking its IFC with the
  corrected expectation rejected it with `STAIR_FOOTPRINT_MISMATCH`; it is not
  valid acceptance evidence.
- Later runs proved the Gate/Audit/Generator loop receives exact component IDs
  and expected/actual world bboxes.
- Run `15af8672d730c618` ended with the stair passing while the stair opening was
  shifted down 150 mm.
- Run `35d96102c4f907c2` used three regenerations. The stair passed, but the
  stair opening and several window openings drifted during full regeneration.

No final live IFC from this bugfix is claimed as accepted.

work should introduce a schema-validated component-level edit/JSON Patch
contract so Generator regeneration can change only issue-owned entities and
