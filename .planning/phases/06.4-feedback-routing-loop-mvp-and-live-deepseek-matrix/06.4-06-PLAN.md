# Phase 6.4 Wave 6 Plan: Supplemental Live Chain Coverage Evidence

**Status:** Implemented
**Scope:** Phase 6.4 supplement, not Phase 6.5

## Goal

Prove that the Phase 6.4 workflow links are backed by auditable evidence from
real DeepSeek runs and deterministic gates. The output is a human-readable
matrix plus machine-readable result file that identifies each required link,
its evidence level, response IDs where applicable, route, status, and artifact
paths.

## Required Links

1. Provider config to JSON smoke.
2. Accepted user input to Design Brief.
3. Accepted Design Brief to BIM JSON Generator.
4. Accepted BIM JSON to deterministic gates.
5. Accepted deterministic gates to Audit Agent.
6. Accepted Audit route to IFC and report.
7. Non-accept user input to Design Brief Draft.
8. Non-accept Issues to `ask_user` route and report.

## Acceptance

- `live-chain-coverage-result.json` exists under the Phase 6.4 live DeepSeek
  output root.
- `live-chain-coverage-report.md` exists under the same root.
- Every required link has `status: "passed"`.
- Model-backed links must have provider response IDs and non-truncated
  `finish_reason` / `stop_reason` evidence.
- Deterministic links must be labelled `deterministic_verified`, not model
  verified.
- Artifact-only terminal links must be labelled `artifact_verified`.
- Missing generator or Audit live metadata must fail the coverage check.
- The supplement must not create a new phase number, provider, architecture, or
  hard-coded success claim.

## Implementation Plan

1. Add RED tests for a live-chain coverage builder.
2. Implement a small evidence reader that consumes existing run artifacts and
   writes the result/report files.
3. Add a CLI wrapper for repeatable coverage generation.
4. Generate the coverage report from the real Phase 6.4 DeepSeek accepted and
   non-accept sessions.
5. Run focused tests, Phase 6.4 regressions, compileall, and artifact secret
   scan.
