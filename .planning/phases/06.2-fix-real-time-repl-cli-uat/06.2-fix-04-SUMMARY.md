# Phase 6.2-fix Wave 4 Summary: Geometry Feedback to Audit and Repair Loop

**Date:** 2026-06-27
**Status:** Implementation and automated verification complete; final real
human-terminal Mimo REPL UAT still pending.

## What Changed

- Added a pre-Audit candidate gate stage that compiles/reopens IFC and writes
  `ifc-verification.json`, `geometry-expectation.json`, and
  `geometry-feedback.json` before decisive Audit.
- Audit prompt inputs now include generated-IFC gate evidence for the candidate
  under review.
- Audit `accept` over failed deterministic gates is rejected as
  `AUDIT_OVERRIDE_ATTEMPT` and blocks acceptance.
- Audit `revise` over true geometry failure can trigger one bounded repair
  attempt. If repair returns a valid Formal candidate, it is promoted, gated
  again, audited again, and only then can be accepted.
- Geometry repair is bounded to evidence-backed wall placement/representation
  paths derived from the affected wall IDs in geometry feedback.
- Generated `report.md` now exposes generated-IFC gate sidecars,
  `geometry-feedback.json`, `repair/repair-attempts.json`, and
  `audit/validation.json`.
- `audit-v2.md` now explicitly names `gate_dispute`,
  `audit_override_attempt`, and the rule that Audit must not override
  deterministic gates.

## Verified Behavior

- A geometry-failed candidate with Audit `accept` no longer ends as
  "Audit accepted, late final geometry blocked"; it becomes `audit_blocked`
  with `AUDIT_OVERRIDE_ATTEMPT`.
- A geometry-failed candidate with Audit `revise` routes through one repair
  attempt, promotes the repaired candidate, reruns gates, reruns Audit, and can
  compile when all gates pass.
- The report and session artifacts expose the gate -> Audit -> repair/block
  route.
