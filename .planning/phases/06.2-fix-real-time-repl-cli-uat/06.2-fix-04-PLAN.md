<objective>
Fix the real UAT ordering defect where Audit accepted before final geometry
feedback existed. The corrected pipeline must put generated-IFC gate evidence
in front of decisive Audit, then route confirmed geometry failures to bounded
repair or block gate disputes.
</objective>

<why>
The user expects the Audit Agent to review the same evidence that determines
whether an IFC is acceptable. If geometry fails after Audit, the system appears
to have two contradictory truths: "Audit accepted" and "final gate blocked".
That is not a trustworthy multi-agent system. The fix is not for Audit to
overrule deterministic gates, but for Audit to see gate evidence and decide the
next route.
</why>

<observed_defect>
Real REPL UAT session `f2a8cdea36b88997` produced:

- Design Brief ready.
- Generator Formal BIM JSON.
- Repair route `no_repair_needed`.
- Real Audit `accepted`.
- IFC compile/reopen success.
- Final geometry failure with `WALL_ORIENTATION_MISMATCH` for `wall-west` and
  `wall-east`, plus `ROOM_ENCLOSURE_OPEN`.

The immediate defect is stage order. `audit/prompt-render-input.json` did not
include `geometry-feedback.json`; final geometry feedback was written later by
the final acceptance stage.
</observed_defect>

<non_goals>
- Do not add new geometry checker semantics in this plan unless a test proves
  the existing gate is wrong.
- Do not let Audit accept failed schema, compile, reopen, geometry, report,
  verifier, or secret-scan gates.
- Do not add supervisor-authored geometry facts to make a live run pass.
- Do not make repair mandatory for successful first-pass candidates.
- Do not broaden the product surface beyond the terminal REPL and existing
  Phase 6.2 query/export/report artifacts.
</non_goals>

<target_sequence>
1. REPL turns produce a ready Design Brief, Draft, or blocked state.
2. Generator emits Formal BIM JSON 2.0 or Draft.
3. Deterministic candidate gates run on the Formal candidate:
   schema validation, compile, reopen, generated-IFC geometry, report-path
   readiness, and artifact references.
4. Audit reviews Design Brief, candidate, repair route, deterministic gate
   evidence, and linked artifacts.
5. If all deterministic gates pass and Audit accepts, the session may become
   final accepted.
6. If geometry gates fail and Audit classifies the failure as a true candidate
   problem, the same feedback routes to bounded repair/generation.
7. The repaired candidate reruns schema, compile, reopen, geometry, Audit,
   report, verifier, and secret scan.
8. If Audit classifies the gate as questionable, the run becomes
   `blocked_failure` or `gate_dispute`; it does not produce accepted IFC.
</target_sequence>

<decision_contract>
The implementation must follow the detailed decision rules in
`06.2-fix-SPEC.md`. The critical executable rules are:

1. Audit input must include Design Brief, candidate BIM JSON path/hash,
   validation diagnostics, compile/reopen result or skip reason, geometry
   feedback or skip reason, repair route, attempt count, and artifact refs.
2. Missing deterministic gate evidence is a pipeline defect and blocks final
   acceptance.
3. Any Audit `accept` over failed validation, compile, reopen, geometry,
   verifier, report, or secret-scan gates is rejected as
   `audit_override_attempt`.
4. `gate_dispute` blocks for human/developer review. It never produces accepted
   IFC.
5. A geometry issue is repair-eligible only when issue codes, affected entity
   IDs, observed/expected context, supported BIM JSON fields, and sufficient
   known user facts are present.
6. Phase 6.2-fix defaults to one repair attempt per candidate route. Any other
   limit must be written to report/session export with `max_repair_attempts`,
   `attempt_index`, and a reason.
7. A run is accepted only when all deterministic gates pass, Audit accepts,
   final verifier passes, and secret scan reports zero findings.
</decision_contract>
