## Non-negotiable Acceptance Boundary

The final accepted Phase 6.2-fix run must not be produced with
`--scripted-stdin`, answer files, replay output, fake providers, or a hidden
preloaded answer list. Those paths remain useful for tests only.

Final acceptance must identify:

- `interaction_mode: "human_repl_live"`
- `input_source: "terminal"`
- real Mimo provider evidence for model-backed turns
- REPL transcript events showing assistant question display before user answer
- deterministic schema, compile, reopen, and geometry feedback available to
  decisive Audit before acceptance
- Audit classification for failed gates without override authority
- bounded repair evidence for true geometry failures, or blocked gate-dispute
  evidence when the deterministic gate itself is uncertain
- generated IFC, generated report, session export, secret scan, and verifier
  result

## Corrected Gate Order

The Phase 6.2-fix final route must be:

1. User REPL turns produce a ready Design Brief or Draft/blocking state.
2. Generator emits Formal BIM JSON 2.0 or Draft.
3. Deterministic validation, compile, reopen, and geometry gates produce a
   candidate gate-evidence bundle.
4. Audit reviews the Design Brief, candidate, gate evidence, repair route, and
   artifact references.
5. If all gates pass and Audit accepts, the run can become final accepted.
6. If geometry gates fail and Audit classifies the issue as a true candidate
   problem, the feedback routes to bounded repair/generation and gates rerun.
7. If Audit finds the gate result itself questionable, the route is a blocked
   gate dispute for human/developer review, not acceptance.
