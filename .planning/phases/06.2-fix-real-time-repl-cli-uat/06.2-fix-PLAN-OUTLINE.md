## Non-negotiable Acceptance Boundary

The final accepted Phase 6.2-fix run must not be produced with
`--scripted-stdin`, answer files, replay output, fake providers, or a hidden
preloaded answer list. Those paths remain useful for tests only.

Final acceptance must identify:

- `interaction_mode: "human_repl_live"`
- `input_source: "terminal"`
- real Mimo provider evidence for model-backed turns
- REPL transcript events showing assistant question display before user answer
- deterministic schema, compile, reopen, and geometry feedback available to
  decisive Audit before acceptance
- Design-Brief-derived semantic geometry expectations for supported
  rectangular rooms, not only candidate-derived wall expectations
- semantic capability profile evidence for what BIM JSON/IFC facts are
  supported, compiler-generated, unsupported, waived, or blocked
- semantic coverage evidence proving every explicit user fact has a terminal
  state before Formal acceptance
- parseable invalid Formal Generator output entering bounded repair/regeneration
  when diagnostics are actionable instead of blocking as `previous_candidate=None`
- canonical Design Brief support vocabulary for deterministic gates, including
  `"外侧"` mapping to `outside_boundary`
- Audit classification for failed gates without override authority
- bounded repair evidence for true geometry failures, or blocked gate-dispute
  evidence when the deterministic gate itself is uncertain
- generated IFC, generated report, session export, secret scan, and verifier
  result

## Corrected Gate Order

The Phase 6.2-fix final route must be:

1. User REPL turns produce a ready Design Brief or Draft/blocking state.
2. Generator emits Formal BIM JSON 2.0 or Draft.
3. Semantic capability and coverage gates classify explicit Design Brief facts
   as represented, compiler-generated, unsupported/Draft, waived, or blocked.
4. Parseable invalid Formal Generator output routes to one bounded
   repair/regeneration attempt when diagnostics are actionable; nonrepairable
   or unsupported facts route Draft/blocking with evidence.
5. Deterministic validation, compile, reopen, and geometry gates produce a
   candidate gate-evidence bundle.
6. Audit reviews the Design Brief, semantic coverage, candidate, gate evidence,
   repair route, and artifact references.
7. If all gates and semantic coverage pass and Audit accepts, the run can
   become final accepted.
8. If geometry gates fail and Audit classifies the issue as a true candidate
   problem, the feedback routes to bounded repair/generation and gates rerun.
9. If an explicit fact is unsupported and unwaived, the route is Draft or
   blocked; it is not accepted through custom text preservation.
10. If Audit finds the gate result itself questionable, the route is a blocked
   gate dispute for human/developer review, not acceptance.

## Short Decision Matrix

- All deterministic gates pass + Audit accepts + verifier/secret scan pass:
  final accepted IFC is allowed.
- Any deterministic gate fails + Audit says `accept`: reject as
  `audit_override_attempt`; no accepted IFC.
- Geometry gate fails + Audit says true candidate issue: bounded repair/generator
  retry, then rerun all gates and Audit.
- Geometry gate fails + Audit says `gate_dispute`: block for human/developer
  review; no accepted IFC.
- Missing required user facts: Draft or clarification, not repair and not IFC.
- Unsupported explicit user facts: Draft/blocking unless explicitly waived by
  the user.
- Parseable invalid Formal with actionable diagnostics: one bounded
  repair/regeneration attempt, then rerun validation and downstream gates.
- Parseable invalid Formal with missing user facts or unsupported product
  semantics: Draft/blocking, not silent repair.
- Candidate-derived wall expectations alone: compiler-fidelity evidence only,
  not sufficient for semantic acceptance.
- Missing gate evidence in Audit input: pipeline defect and blocked outcome.
