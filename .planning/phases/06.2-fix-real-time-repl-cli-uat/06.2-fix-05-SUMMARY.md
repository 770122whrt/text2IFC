# Phase 6.2-fix Wave 5 Summary: Semantic Fidelity Gate and Capability Contract

**Date:** 2026-06-27
**Status:** Implementation and automated verification complete; final real
human-terminal Mimo REPL UAT still required.

## What Changed

- Added `semantic-capabilities.json`, a fact-level capability profile for the
  current BIM JSON 2.0 / IFC2X3 generation stack.
- Added `semantic-coverage.json`, a deterministic gate that classifies every
  Design Brief known fact as represented, compiler-generated, waived, or
  unsupported/blocking.
- Explicit unsupported user facts such as
  `/known_facts/door/opening_direction` now block Formal IFC acceptance unless
  the user explicitly waives them.
- Added `semantic-geometry-expectation.json` for supported rectangular rooms
  where walls are stated to sit outside the room boundary.
- Generated IFC geometry gates now use Design-Brief-derived wall expectations
  when available, rather than relying only on candidate-derived wall boxes.
- Generated reports now include `## Semantic Coverage` and link semantic
  capability, coverage, and semantic geometry sidecars.
- Audit inputs now include semantic coverage and capability evidence through
  deterministic gates and evidence paths.
- Phase 6.2-fix verifier now requires semantic coverage for compiled
  acceptance, supports relative `--session-from final-acceptance.json`, reads
  final metrics stage names used by the live pipeline, and accepts valid
  no-clarification REPL sessions.

- A candidate that places outside-boundary walls 100 mm away from the stated
  clear room boundary now fails with `WALL_OUTSIDE_BOUNDARY_GAP`.
- A Design Brief that contains `door.opening_direction: "into_space"` now
  remains Draft/blocked under current capabilities and writes no accepted IFC.
- Supported room cases without unsupported explicit facts still compile,
  reopen, pass geometry, run Audit, and produce reports.
- Reports include semantic coverage sidecars and the final verifier rejects
  compiled acceptance without semantic coverage.
