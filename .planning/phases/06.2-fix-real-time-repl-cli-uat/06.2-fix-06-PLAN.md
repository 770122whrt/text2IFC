# Objective

Fix the live REPL failure class exposed by session `3aa55eb71f464ff8`:
Mimo returned parseable Formal BIM JSON 2.0, but the object failed validation
because `IfcDoor` missed required semantic geometry and the model emitted
unsupported explicit relationships. The pipeline saved the object as
`generator/parsed-output.json`, but repair only looked for
`generator/candidate.json`, so the route blocked with
`previous_candidate=None` before Audit or bounded repair could reason about the
real candidate.

This plan adds one narrow recovery loop: parseable invalid Formal output can
enter bounded repair/regeneration when diagnostics are actionable and all
required user facts already exist. It also normalizes supported Design Brief
vocabulary used by deterministic gates, especially wall placement values such
as Chinese "outside" wording.

# Non-goals

- Do not build an unbounded autonomous multi-agent loop.
- Do not let Repair invent dimensions, hosts, placements, rooms, storeys,
  openings, or unsupported semantics.
- Do not accept invalid Formal output or copy it to `candidate.json` as if it
  had passed validation.
- Do not treat Audit, Observer, or supervisor reasoning as authority to
  override schema, semantic coverage, compile, reopen, geometry, verifier, or
  secret-scan gates.
- Do not solve broad RAG, fine-tuning, public API, or arbitrary topology in
  this fix.

# Required Route

1. Design Brief reaches `ready`, or the run remains Draft/blocking.
2. Generator returns Formal, Draft, invalid JSON, or blocked output.
3. If Formal parses but validation fails:
   - preserve `generator/parsed-output.json`,
   - preserve validation diagnostics,
   - classify whether diagnostics are actionable,
   - if actionable and attempts remain, write an explicit recovery source such
     as `repair/invalid-candidate.json`,
   - call Repair/regeneration with the invalid Formal candidate and exact
     diagnostics,
   - never call this invalid object accepted.
4. Repaired Formal output must rerun validation, semantic coverage, compile,
   reopen, geometry gates, Audit, report, and verifier.
5. Nonrepairable invalid Formal output routes to Draft/blocking with evidence.
6. Report, session export, and terminal output expose the attempted route.

# TDD Tasks

## T1 - RED: invalid Formal is a repair source

Add `tests/agent/test_phase6_2_fix_invalid_formal_recovery.py`.

Fixture shape:

- `generator/parsed-output.json` contains parseable Formal BIM JSON 2.0.
- `generator/validation.json` contains:
  - `MISSING_REPRESENTATION` for an `IfcDoor`,
  - `UNSUPPORTED_RELATIONSHIP_CLASS` for `IfcRelAggregates`,
  - `UNSUPPORTED_RELATIONSHIP_CLASS` for
    `IfcRelContainedInSpatialStructure`.
- `generator/candidate.json` is absent.

Expected RED behavior:

- `run_repair_stage` must not return `blocked_failure` solely because
  `candidate.json` is absent.
- It must treat the parsed invalid Formal object as the previous repair
  candidate.
- It must write `repair/invalid-candidate.json`.
- It must record `source_document_kind: "invalid_formal"` and provider call
  evidence when repair is attempted.

## T2 - RED/GREEN: repair eligibility is precise

Add focused tests around `assess_repair_eligibility`.

Repair-eligible:

- Missing door `Representation` when door size, host, and placement facts are
  known.
- Extra explicit `IfcRelAggregates` /
  `IfcRelContainedInSpatialStructure` relationship objects, because current
  Formal profile treats those as compiler-generated or unsupported model
  output, not user-authored facts.

Not repair-eligible:

- Missing user facts such as unknown door width, host wall, wall thickness, or
  room dimensions.
- Unsupported explicit product semantics such as door opening operation when
  the user has not waived the fact.

## T3 - GREEN: implement bounded invalid Formal recovery

Implementation boundaries:

- Add a helper in the live pipeline to resolve the repair source:
  `candidate.json` first, otherwise parseable invalid Formal from
  `parsed-output.json` plus validation diagnostics.
- Pass that object to failure routing as `previous_candidate`.
- Do not mutate or overwrite `generator/parsed-output.json`.
- Do not create `generator/candidate.json` until validation succeeds.
- Record attempt count and repair source path in `repair/route.json`.
- If repair produces valid Formal, promote only the repaired valid object to
  the downstream candidate path.

## T4 - RED/GREEN: Design Brief gate vocabulary normalization

Add or extend semantic fidelity tests so `walls.placement` values equivalent to
outside-boundary intent activate the same gate as `outside_boundary`.

Examples:

- `outside_boundary`
- `external_boundary`
- Chinese "outside" wording preserved by the Design Brief
- text such as "walls outside room boundary"

Implementation boundaries:

- Normalize values at gate/capability interpretation time.
- Preserve the raw Design Brief value in trace evidence.
- Do not rewrite the original Design Brief artifact.
- Unknown placement values remain unknown and cannot be silently treated as
  supported outside-boundary intent.

## T5 - RED/GREEN: observability and report evidence

Add assertions that a failed or repaired invalid Formal run exposes:

- generator status and response ID when present,
- validation diagnostics,
- repair eligibility,
- recovery source artifact path,
- repair attempt count,
- terminal route,
- generated report section and session export references.

# Success Criteria

- Invalid parseable Formal output no longer blocks with
  `previous_candidate=None` when diagnostics are actionable.
- Repaired output, if produced, is validated before compile and reruns all
  semantic and generated-IFC gates.
- Unsupported explicit facts still block or Draft; they are not hidden by the
  repair loop.
- Supported Design Brief wall placement wording consistently activates
  Design-Brief-derived semantic geometry checks.
- `report.md`, `session-export.json`, and terminal summaries explain the
  invalid-generator route without requiring the user to open every sidecar
  manually.
