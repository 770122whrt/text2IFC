## What Was Fixed

Wave 6 fixes the live UAT defect where a parseable Formal BIM JSON 2.0
Generator output failed validation but could not enter repair because it had
not been promoted to `generator/candidate.json`.

The pipeline now:

- preserves parseable invalid Formal output as `generator/parsed-output.json`;
- treats it as an explicit `invalid_formal` repair source when diagnostics are
  actionable;
- writes `repair/invalid-candidate.json` instead of pretending the invalid
  object is an accepted candidate;
- routes missing door semantic `Representation` and extra unsupported compiler
  relationships into one bounded repair attempt when user facts are already
  known;
- records `source_document_kind`, `source_document_path`, and
  `repair_source_artifact` in route and metrics evidence;
- preserves the rule that unsupported explicit product semantics remain
  Draft/blocking rather than silently repaired into acceptance.

Wave 6 also normalizes Design Brief wall placement wording for supported
semantic gates. Values equivalent to outside-boundary intent, including Chinese
"outside" wording and known mojibake variants from existing artifacts, now
activate the same Design-Brief-derived rectangular-room geometry gate as
`outside_boundary`, while preserving the raw value in trace evidence.

## Prompt Changes

The Generator and Repair prompts were hardened:

- Formal `IfcDoor` and `IfcWindow` entities must include semantic
  `Representation` geometry.
- `IfcRelAggregates` and `IfcRelContainedInSpatialStructure` must not be
  explicitly emitted by the model in BIM JSON; they are compiler-generated
  unless the schema/context explicitly says otherwise.
- Repair may remove those compiler-generated relationship mistakes inside
  allowed paths, but may not invent replacement facts.

Prompt registry hashes were updated after the prompt edits.
