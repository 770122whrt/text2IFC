<objective>
Close the post-UAT semantic fidelity gap before final Phase 6.2-fix acceptance.
The corrected system must prove that Formal BIM JSON/IFC output covers the
user's explicit facts, not merely that IFC compilation matches the generated
candidate.
</objective>

<why>
The live REPL run `d462b95089755d47` reached real Mimo Generator, real Mimo
Audit, compile/reopen success, geometry success, and a viewable IFC. That is
valuable evidence, but review found two remaining trust gaps:

1. The geometry expectation can be derived from the candidate wall placements.
   This catches compiler/output drift, but it can miss candidate drift from the
   Design Brief.
2. The Design Brief preserved `door.opening_direction: "into_space"`, while
   current BIM JSON/IFC support does not faithfully carry that semantic fact.
   Accepting Formal output silently drops an explicit user fact.

The fix is a semantic coverage gate plus a capability contract. It should make
the system honestly say "Draft/unsupported" when current capability cannot
represent a requested fact.
</why>

<observed_defects>
- `semantic_expectation_self_reference`: `run_candidate_gate_stage` writes
  `geometry-expectation.json` through `_wall_geometry_expectation_from_candidate`.
  Expected wall boxes can therefore mirror the candidate's own incorrect
  placement.
- `unsupported_fact_loss`: door inward opening intent can exist in the Design
  Brief but disappear from Formal BIM JSON/IFC acceptance.
- `reportability_gap`: the REPL report links gate artifacts, but lacks a
  dedicated semantic coverage section that lets a human trace each explicit
  fact to represented/Draft/waived/blocked state.
- `verifier_false_negative`: the final verifier can reject a legitimate
  no-clarification live session shape and can look for old metric stage names.
</observed_defects>

<non_goals>
- Do not implement new IFC support for `IfcDoorStyle`, door swing arcs, or
  full opening operation semantics in this plan.
- Do not add broad RAG, fine-tuning, or knowledge-base expansion.
- Do not use `custom:` property sets as proof that a semantic fact is
  faithfully represented in IFC.
- Do not replace BIM JSON Schema or create a second structural model.
- Do not weaken deterministic validation, compile, reopen, geometry, secret
  scan, or report gates.
- Do not commit live tokens, provider URLs, headers, or secret-bearing traces.
</non_goals>

<target_sequence>
1. REPL turns produce a Design Brief with explicit known facts, missing facts,
   unsupported facts, and source transcript references.
2. The pipeline writes a semantic capability profile for the current BIM JSON
   and IFC2X3 generation stack.
3. Generator receives the Design Brief plus capability profile and emits
   Formal BIM JSON 2.0 only when all explicit facts are representable,
   compiler-generated, or waived.
4. The semantic coverage gate compares Design Brief facts, capability profile,
   candidate BIM JSON, validation diagnostics, and generated sidecars.
5. For supported rectangular-room facts, the geometry expectation is derived
   from Design Brief facts and candidate space facts, not candidate wall boxes
   alone.
6. Compile/reopen/geometry gates run, then Audit reviews deterministic gates
   plus semantic coverage.
7. If unsupported or uncovered facts remain, the run writes Draft/blocking
   artifacts and no accepted IFC. If all gates and coverage pass, final
   verifier and secret scan may accept.
</target_sequence>

<semantic_coverage_states>
- `represented`: supported BIM JSON/IFC output carries the fact.
- `compiler_generated`: the compiler creates the fact deterministically from
  higher-level supported facts.
- `unsupported_draft`: the fact is explicit and meaningful, but current
  support cannot carry it; the run remains Draft unless waived.
- `waived_by_user`: the user explicitly agrees the fact is not required for
  this run.
- `blocked_unknown_capability`: the system cannot prove support; it blocks
  instead of accepting.
</semantic_coverage_states>
