# Phase 10.3: Batch Window Repair and Dataset Benchmark Hygiene - Specification

**Created:** 2026-07-24
**Status:** Approved for implementation
**Requirements:** DATA-01, DATA-02, BATCH-01, BATCH-02, BATCH-03, BATCH-04,
BATCH-05
**Depends on:** Phases 10, 10.1 and 10.2

## Goal

Prove that the existing unified ChangeSet architecture is a real batch
transaction rather than a single-Window demonstration:

```text
one source IFC2X3
  -> remove five valid Window + Opening chains once
  -> one damaged IFC
  -> one natural-language request describing five repairs
  -> one RepairIntent containing five operations
  -> one bound ChangeSet containing five operations
  -> one all-or-nothing IFC transaction
  -> per-operation and aggregate L1/L2
  -> one published repaired IFC or an honest failed run
```

The primary benchmark is `dataset/ifc/train/vvo.ifc`. Larger compatible files
are admitted through a machine-readable benchmark manifest and exercised as a
compatibility/performance matrix without changing the bounded Provider input
contract.

## Locked decisions

### Dataset hygiene

- Existing raw IFC paths are immutable. In particular, `dataset/ifc/train` and
  `dataset/ifc/test` are historical source folders, not the project split.
- No dataset file is deleted automatically in this phase.
- An audit validates path, SHA-256, IFC schema and duplicate identity for
  current manifests.
- Processed artifacts are classified as `retain`, `regenerable` or
  `review_before_delete`; classification is evidence, not deletion authority.
- A benchmark manifest records source identity, size, entity/window/chain/wall
  metrics, intended role and suitability reason.

### Five-Window fixture

- The fixture contains exactly five valid Window–Opening–Wall chains.
- Primary `vvo.ifc` targets use distinct host walls and retain at least one
  surviving occurrence of every explicitly reused Window Type.
- The mutation is performed against one in-memory model and written once.
- Source bytes remain unchanged. Five Windows and their five Openings are
  absent, all five host walls survive, and all five void regions are closed.
- Private Ground Truth stores original target facts and never enters either
  Provider prompt.

### Public input and token boundary

- Public projection emits one bounded batch specification with five operations.
- The user request identifies each host by stable GUID plus human-readable
  name/storey and gives local offset, dimensions, sill and explicitly selected
  Type information.
- Stage 1 may emit up to five `add_window_with_opening_to_wall` operations in
  request order. Stage 2 receives resolved bounded contexts and emits one draft
  ChangeSet.
- The complete IFC, private manifest, Gold facts and unrelated candidates are
  never placed in the prompt. Prompt size is measured and reported.

### Transaction and evaluation

- Binding is operation-specific, but application is one atomic transaction.
- Duplicate operation IDs, repeated target walls where disallowed, unresolved
  targets, stale source fingerprints or one invalid operation fail before
  publication.
- L1 and L2 are evaluated for every operation, then aggregated. Total success
  requires all five `geometry_relationship_success` and all required
  `semantic_fidelity_success` results.
- `authoring_exactness` remains optional/report-only.
- Benchmark L2 may compare against the original IFC only inside the private
  evaluator. Production L2 uses request and authorized surviving facts.

## Benchmark set

| Order | IFC | Role |
|---:|---|---|
| 1 | `dataset/ifc/train/vvo.ifc` | Primary five-Window full pipeline |
| 2 | `dataset/ifc/train/px4_1.ifc` | Medium compatibility/performance |
| 3 | `dataset/ifc/train/AdvancedProject.ifc` | High-window-count retrieval/index stress |
| 4 | `dataset/ifc/train/BasicHouse.ifc` | Optional large serialization/reopen stress |

Files enter the executed matrix only if the audit confirms IFC2X3, sufficient
valid chains, supported straight host walls and acceptable local resources.
Curved/free-form walls remain deferred.

## Acceptance criteria

- [ ] All dataset manifests pass deterministic path/hash/schema/duplicate
  validation, with failures reported rather than rewritten silently.
- [ ] A checked-in benchmark manifest describes `vvo`, `px4_1`,
  `AdvancedProject` and `BasicHouse` with reproducible metrics and roles.
- [ ] The dataset inventory distinguishes raw, manifest, split, retained
  evidence and regenerable output; no file is deleted by the audit command.
- [ ] A single batch mutation creates one damaged `vvo.ifc` with exactly five
  Window/Opening chains removed and five host voids closed.
- [ ] One public text request produces one RepairIntent and one unified
  ChangeSet with exactly five ordered operations.
- [ ] Applying the ChangeSet is all-or-nothing and reopens as IFC2X3.
- [ ] Every operation has separate L1/L2 evidence and the aggregate result
  cannot pass if any operation fails.
- [ ] Private comparison reports each repaired Window against the corresponding
  original target without exposing Gold to Stage 1 or Stage 2.
- [ ] The offline `vvo.ifc` full chain passes and publishes a repaired IFC.
- [ ] One real DeepSeek `vvo.ifc` batch UAT is attempted without fake fallback;
  only a real five-operation L1/L2 pass satisfies live acceptance.
- [ ] Larger-file compatibility records indexing/mutation/reopen time, memory
  where available, counts and bounded prompt size.
- [ ] Focused tests, IFC repair tests, compileall and `git diff --check` pass.

## Out of scope

- Deleting or moving existing dataset files.
- Automatic repair of every Window in a model.
- Curved/free-form wall geometry.
- Door, opening-only, Beam or Column operations.
- Shared-Type mutation.
- L3 identity/serialization exactness.
- Changing the default Provider budget from 64k to 128k.
