# Phase 10.3 Implementation Plan

## Objective

Deliver a reproducible dataset audit and one genuine five-Window batch repair
on `vvo.ifc`, then measure compatibility on larger BIMNet IFC2X3 files.

## Wave 2 — Five-chain mutation and public projection

<task type="auto" tdd="true">

## Wave 3 — Unified transaction and evaluation

<task type="auto" tdd="true">
  <name>Five-operation offline end-to-end pipeline</name>
  <behavior>
    Feed one text request through RepairIntent, deterministic resolution,
    one ChangeSet, atomic apply, reopen and per-operation/aggregate L1/L2.
  </behavior>
  <acceptance_criteria>
    vvo produces exactly five bound operations and publishes one repaired IFC
    only when all five operations pass both mandatory levels.
  </acceptance_criteria>
</task>

<task type="auto" tdd="true">
  <name>Rollback and evidence isolation</name>
  <behavior>
    Inject one invalid operation and prove no partial successful IFC is
    published; compare valid repair targets against evaluator-only original.
  </behavior>
  <acceptance_criteria>
    Failure is atomic, per-operation failure is visible, aggregate status fails
    and Provider artifacts contain no private Ground Truth.
  </acceptance_criteria>
</task>

## Stop conditions

Stop for user confirmation only if a discovered IFC/license fact changes the
approved benchmark scope, a batch contract would require shared-Type mutation,
or a real Provider authentication/configuration decision cannot be inferred
from the accepted local environment. Provider quota failure is recorded
honestly and does not trigger a fake fallback.
