# Phase 6.2 Wave 0 Summary: OpenAI-Compatible Mimo Checkpoint

Date: 2026-06-24

## Result

Wave 0 is complete. The accepted implementation route for later Phase 6.2
waves is:

`native_orchestrator_with_openai_sdk_provider`

The native OpenAI Python SDK Chat Completions path is the acceptance provider
path because it preserves the required response evidence. OpenAI Agents SDK is
classified as `limited_sdk`: it can call Mimo and return assistant text, but it
does not expose `response_id` or `finish_reason` as first-class final-result
metadata in the Chat Completions path.

## Implementation Notes

Implemented:

- `src/text2ifc_agent/openai_compat.py`
- `scripts/agent/run_phase6_2_cli.py --check-openai-compat`
- `tests/agent/test_phase6_2_openai_compat.py`

Key guardrails:

- Missing config reports required environment variable names only.
- Raw token values and provider URLs are not printed in config status.
- `finish_reason: length` raises a blocking compatibility error.
- Failed OpenAI SDK smoke returns `decision: blocked`, not a false native-route
  pass.
- Agents SDK `AsyncOpenAI` client is explicitly closed after the smoke. This
  fixed a live `.venv` issue where the Python function returned `0` but the
  process exited with code `1`.

## Follow-Up

Wave 1 can now start. The CLI should use the native text2IFC orchestrator and
OpenAI SDK provider calls, not OpenAI Agents SDK, as the acceptance path. Agents
SDK can remain a research reference but cannot replace the shared SQLite DB,
prompt registry, raw provider evidence, deterministic gates, or generated
run report.
