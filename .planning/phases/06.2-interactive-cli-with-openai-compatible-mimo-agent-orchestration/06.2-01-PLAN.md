<objective>
Build the terminal session shell and shared SQLite session store that accept
user input, record transcript/events/agent evidence, and provide the stable
execution surface for later agent waves.
</objective>

<why>
Without a shared session store, "interactive" becomes a thin wrapper around
scripted files and scattered artifacts. The user needs to query prior sessions,
resume incomplete sessions, and export one run's evidence by session hash.
</why>

<must_haves>
- Read initial request from stdin or `--prompt`.
- Support `help`, `status`, and `quit` without corrupting state.
- Persist UTF-8 Chinese text exactly.
- Create or migrate a shared `sessions.sqlite` DB.
- Store sessions, turns, events, agent calls, prompts, responses, gates,
  artifacts, and metrics keyed by `session_id`.
- Generate a stable `session_hash` for artifact paths and user-facing lookup.
- Expose `sessions list/show/turns/calls/artifacts/resume/export` query
  commands.
- Export one session to `runs/<session_hash>/session-export.json` without
  treating the export as the primary truth store.
- Do not call live Mimo in this wave except optional config checks.
</must_haves>

<threat_model>
- Terminal encoding corruption of Chinese input.
- User interrupt leaves misleading completed artifacts.
- CLI logs reveal provider config or secrets.
- Session query mixes rows from different `session_hash` values.
- Exported bundles drift from DB truth.
</threat_model>
