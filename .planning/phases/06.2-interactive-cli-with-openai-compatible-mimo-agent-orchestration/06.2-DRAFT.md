# Phase 6.2 Draft: Interactive CLI with OpenAI-Compatible MiMo Agent Orchestration

Status: draft
Created: 2026-06-23
Branch: `multiagent-design`

Superseded note: the executable Phase 6.2 contract now lives in
`06.2-SPEC.md`, `06.2-PLAN-OUTLINE.md`, and the `06.2-00` through `06.2-06`
plan files. Those formal documents require one shared SQLite session DB,

This is a lightweight draft, not the final GSD SPEC. It captures the current
direction before the OpenAI Agents SDK feasibility spike is complete.

## Purpose

Phase 6.1 proved that a real MiMo-backed multi-agent pipeline can produce a
traceable BIM JSON 2.0 to IFC2X3 artifact. Its multi-turn clarification path is
still scripted through `--answers answers.json`. Phase 6.2 should turn that
scripted path into a live terminal conversation:

```text
user types request
  -> Design Brief Agent asks 1-3 Chinese questions when needed
  -> user answers in the CLI
  -> session transcript is persisted in shared sessions.sqlite
  -> Generator produces BIM JSON 2.0
  -> deterministic gates compile/reopen/check IFC
  -> Audit Agent reviews
  -> runs/<session_hash>/report.md and output.ifc are linked to the session
```

## Current Open Questions

- Whether OpenAI Agents SDK can run cleanly against MiMo's OpenAI-compatible
  Chat Completions endpoint.
- Whether the SDK can expose or preserve the exact raw response metadata needed
  by text2IFC trace and report requirements.
- Whether MiMo supports the SDK features we might want: streaming, function
  calling, structured output, and handoffs.
- Whether using the SDK reduces code enough to justify the dependency, without
  hiding evidence needed for BIM/IFC auditing.

## Early Findings

- MiMo OpenAI-compatible `POST /v1/chat/completions` is reachable from this
  worktree.
- MiMo `POST /v1/responses` returned 404 in the initial smoke test; Phase 6.2
  must not assume Responses API availability.
- OpenAI Python SDK can call MiMo Chat Completions through
  `OpenAI(base_url=..., api_key=...)`.
- `openai-agents` is not yet part of the repository environment; install it
  only into the local `.venv` created for this worktree.

## Proposed Scope

### In scope

- A local interactive CLI runner.
- Session persistence for transcript, agent calls, status, and artifact paths.
- Real MiMo calls for Design Brief, Generator, optional Repair, and Audit.
- OpenAI-compatible MiMo provider support.
- OpenAI Agents SDK feasibility spike.
- Generated trace bundle and `report.md`.
- Final `output.ifc` for the happy-path interactive demo.

### Out of scope for Phase 6.2

- Web UI.
- Public API service.
- Fine-tuning.
- Broad fallback/default policy for unknown or unimportant facts.
- Source-equivalent BIMNet geometry fidelity beyond current supported gates.

## Proposed Waves

### Wave 0: OpenAI-compatible MiMo and Agents SDK spike

- Install `openai-agents` into `.venv`.
- Verify OpenAI SDK and Agents SDK calls against MiMo Chat Completions.
- Record whether streaming, function calls, structured output, and handoffs are
  usable.
- Decide whether Phase 6.2 should use Agents SDK directly or keep a native
  orchestrator with OpenAI SDK provider calls.

### Wave 1: CLI session shell

- Implement `scripts/agent/run_interactive_cli.py --live`.
- Read user input from the terminal.
- Persist session state, transcript, events, and artifact paths.
- Support quit/status/help commands.

### Wave 2: Interactive Design Brief loop

- Call the Design Brief Agent with the current transcript.
- Print one to three Chinese clarification questions.
- Read user answers live from the terminal.
- Append answers to transcript and rerun Design Brief until `ready` or Draft.

### Wave 3: Generator and deterministic gates

- Call the BIM JSON Generator once the Design Brief is `ready`.
- Validate exact BIM JSON 2.0 or canonical Draft.
- Compile Formal output to IFC2X3 only after validation.
- Reopen IFC and run geometry gates.

### Wave 4: Audit and bounded repair

- Run Audit Agent after deterministic gate state is known.
- If repair is eligible, allow at most one Generator repair pass.
- Preserve before/after issues and fact-delta evidence.

### Wave 5: Acceptance artifacts and report

- Write:
  - `dataset/processed/agent-demo/phase6.2-interactive-cli/sessions.sqlite`
  - `dataset/processed/agent-demo/phase6.2-interactive-cli/final-acceptance.json`
  - `dataset/processed/agent-demo/phase6.2-interactive-cli/runs/<session_hash>/output.ifc`
  - `dataset/processed/agent-demo/phase6.2-interactive-cli/runs/<session_hash>/report.md`
  - `dataset/processed/agent-demo/phase6.2-interactive-cli/runs/<session_hash>/session-export.json`
  - linked large-object artifacts
- Run artifact secret scan and focused tests.

## Acceptance Sketch

The first accepted demo should look like:

```text
text2ifc> 创建一个6米乘4米、高3米的矩形房间，南墙有门，北墙有窗
Design Brief Agent> 墙体厚度是多少？
user> 300mm
text2IFC> BIM JSON valid.
text2IFC> IFC reopen valid.
text2IFC> Geometry valid.
text2IFC> Wrote output.ifc and report.md.
```

The CLI does not need to solve every fallback in the first version. Unknown or
unimportant answers can be recorded and routed to Draft while the happy path is
made observable and reliable.
