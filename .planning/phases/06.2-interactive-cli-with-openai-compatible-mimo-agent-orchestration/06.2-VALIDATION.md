# Phase 6.2 Validation Strategy

## Evidence Classes

| Class | Provider | Purpose | Counts for live acceptance |
|---|---|---|---|
| Unit | fake/file | Deterministic parser, session, CLI, report, and gate tests | No |
| Replay | saved real response | Regression without network | No |
| SDK smoke | real Mimo | OpenAI SDK / Agents SDK compatibility | Only Wave 0 compatibility |
| Live CLI | real Mimo | User-facing interactive session | Yes |
| Live E2E | real Mimo plus compiler | Final output.ifc acceptance | Yes |

Every artifact and metric must label evidence class. Fake, file, or replay
output cannot be aggregated into live Mimo quality metrics.

## TDD Policy

Eligible deterministic behavior follows RED commit, GREEN commit, optional
REFACTOR. Live provider behavior is verified through saved-response replay plus
explicit live smoke/demo commands. The final phase cannot be marked complete
without real Mimo CLI evidence unless it is explicitly recorded as blocked.

## Wave Gates

### Wave 0: OpenAI-compatible Mimo and Agents SDK checkpoint

- `.venv` imports `openai` and `agents`.
- OpenAI SDK chat-completion smoke succeeds with redacted evidence.
- Responses API absence is recorded and does not break the native path.
- Agents SDK compatibility is classified as adopt, limited, or reject.
- Required provider metadata is preserved or SDK acceptance is rejected.

### Wave 1: CLI session shell

- CLI reads request from stdin or `--prompt`.
- `help`, `status`, and `quit` are safe and traceable.
- `conversation.json`, `events.jsonl`, `session.json`, and trace manifest are
  created.
- Chinese input remains UTF-8 byte-preserved in persisted artifacts.

### Wave 2: interactive Design Brief loop

- Design Brief prompt receives current transcript and role-specific context.
- Agent-authored questions are printed as one to three Chinese questions.
- User answers append as user turns, not prewritten answer files.
- Unknown-answer route reaches canonical Draft when appropriate.

### Wave 3: Generator and deterministic IFC gates

- Generator receives ready Design Brief plus exact Formal/Draft contracts.
- Exact discriminator routing is enforced.
- Formal output passes `validate_v2_document`.
- IFC compiles, reopens as IFC2X3, and passes geometry/relationship/structure
  gates.

### Wave 4: Audit, conditional repair, and report integration

- Successful first pass records `no_repair_needed`.
- Eligible deterministic failure may trigger at most one repair attempt.
- Audit cannot override deterministic gate failures.
- `report.md` is generated from sidecars and covers all required sections.

### Wave 5: interactive acceptance matrix

- Complete-room CLI case reaches IFC.
- Clarified-room CLI case asks and consumes live user answers, then reaches IFC.
- Unknown-answer CLI case reaches Draft and writes no IFC.
- Final accepted Formal artifacts are written under
  `dataset/processed/agent-demo/phase6.2-interactive-cli/`.

### Wave 6: final verification and documentation

- Focused tests pass.
- Necessary regression tests pass.
- `python -m compileall src scripts -q` passes.
- Artifact secret scan reports zero findings.
- Requirement coverage for CLI-01 through CLI-06 is documented.
- ROADMAP and STATE are updated with verified facts only.

## Final Metrics

- OpenAI SDK and Agents SDK compatibility status.
- Live role call count by role.
- Finish-reason pass/block rate.
- Parse and exact-contract validity rate.
- Clarification turn count and question-count compliance.
- Unknown-answer Draft route count.
- Repair invocation and success count.
- Compile/reopen/geometry/relationship/structure pass rate.
- Report completeness pass rate.
- Artifact secret finding count.

## Completion Rule

Phase 6.2 cannot be marked complete if the CLI only uses prewritten
`answers.json`, if live semantic roles are fake/file/replay, if `output.ifc` is
missing for the accepted Formal case, if `report.md` is hand-authored, if the
SDK path hides mandatory evidence while being claimed as adopted, or if artifact
secret scan finds credentials/private provider URLs.
