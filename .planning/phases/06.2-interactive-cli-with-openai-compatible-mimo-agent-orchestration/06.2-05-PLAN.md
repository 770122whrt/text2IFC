<objective>
Run and verify the Phase 6.2 acceptance matrix, including the final real-time
Codex-as-user CLI conversation that generates an IFC artifact.
</objective>

<why>
The phase is accepted by live conversation evidence, DB records, and artifacts,
not by architecture alone. The user must be able to query the session, inspect
the transcript and intermediate outputs, and open the final IFC from the
session's run bundle.
</why>

<must_haves>
- Complete-room case reaches IFC with no clarification.
- Clarified-room case asks a real question and consumes user answer through
  stdin before reaching IFC.
- Final UAT repeats the clarified-room route with Codex typing answers in a
  real-time CLI loop rather than preloading all answers through scripted stdin.
- Unknown-answer case reaches canonical Draft and no IFC.
- Final accepted session is recorded in `final-acceptance.json` with
  `session_id` and `session_hash`.
- Verification command reopens IFC and checks report, DB rows, query/export
  results, artifact paths, and secret scan.
</must_haves>

<threat_model>
- Acceptance case accidentally bypasses stdin by preloading answers.
- The final artifact directory mixes old traces with new evidence.
- `final-acceptance.json` points to a session hash whose DB rows do not match
  the exported bundle.
- A manual visual check is used instead of machine-readable gates.
</threat_model>
