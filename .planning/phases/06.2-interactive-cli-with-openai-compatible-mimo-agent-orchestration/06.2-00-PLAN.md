<objective>
Research OpenAI Agents SDK first, then prove or reject SDK adoption against the
real Mimo OpenAI-compatible API before building the interactive CLI on top of
it.
</objective>

<why>
Mimo Chat Completions is reachable, but Responses API returned 404. A framework
that hides response metadata or depends on unsupported endpoints cannot support
the project's audit and report requirements. The project must understand the SDK
architecture, supported model/provider entry points, tracing behavior, handoff
model, structured output support, and metadata access before it writes CLI code
around the SDK.
</why>

<must_haves>
- Use the local `.venv` and `requirements-phase6.2.txt`.
- Support `API_KEY`, `MIMO_API_KEY`, or compatible OpenAI-style env names
  without printing values.
- Preserve response ID, model, finish reason, usage, raw text, and redacted
  request metadata.
- Reject `finish_reason: length` for semantic acceptance.
- Write `06.2-SDK-RESEARCH.md` before the live compatibility smoke. It must
  summarize official SDK concepts, the installed package surface used by the
  spike, Mimo-specific compatibility risks, and the adoption criteria.
- Write a compatibility decision: `adopt_agents_sdk`, `limited_sdk`, or
  `native_orchestrator`.
</must_haves>

<threat_model>
- Secret leakage through config diagnostics, request dumps, or exception text.
- False adoption claim when SDK smoke uses a different endpoint or fake model.
- Metadata loss when a framework returns only assistant text.
</threat_model>
