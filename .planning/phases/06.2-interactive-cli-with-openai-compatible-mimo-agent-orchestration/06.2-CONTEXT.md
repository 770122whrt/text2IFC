# Phase 6.2 Context

## Why This Phase Was Inserted

Phase 6.1 made the live Mimo pipeline honest: semantic outputs came from real
Mimo calls, deterministic gates compiled a real IFC, and `report.md` was
generated from captured evidence artifacts. The remaining interaction model is
still too scripted for the product goal. Users need to type the initial request and answer
clarification questions in a CLI, while the system preserves enough context to
continue the multi-agent workflow safely.

Phase 6.2 therefore focuses on an interactive terminal experience and the
OpenAI-compatible Mimo path. Public API packaging can wait.

## Locked Decisions

- Work only in the C-drive `multiagent-design` worktree.
- Do not edit the E-drive working tree.
- Chinese-first interaction remains the product default.
- Each clarification turn asks one to three user-facing questions.
- The Design Brief Agent owns the question text and missing-fact reasoning.
- A shared SQLite session DB is the primary evidence store for all Phase 6.2
  conversations.
- Every conversation has a stable `session_id` and user-visible
  `session_hash`.
- Session list/show/turns/calls/artifacts/resume/export interfaces are in
  scope.
- Deterministic code validates and routes; it does not author semantic facts.
- JSON Schema remains the only BIM JSON structural truth.
- Real Mimo evidence is mandatory for live acceptance claims.
- Fake/file/replay providers are unit or replay tools only.
- The OpenAI-compatible provider path uses environment variables and never
  stores API keys, provider headers, private URLs, or `.env` content.
- The first CLI version should prioritize a happy-path live session plus a
  Draft route for unknown required facts.
- OpenAI Agents SDK is a candidate only if it preserves trace requirements and
  works with Mimo's available API surface.
- A generated `report.md` is the user-facing review entry point for every
  session export.
- Final acceptance requires Codex acting as the user in a real-time Mimo-backed
  CLI conversation; scripted stdin is regression support only.

## Flexible Implementation Choices

- Internal storage is SQLite for Phase 6.2. JSON/JSONL exports are allowed for
  review bundles and large artifacts, but they are not the primary truth store.
- The CLI may support both fully interactive mode and scripted stdin/replay for
  deterministic tests.
- The OpenAI Agents SDK may be used for agent objects, handoffs, tracing, or not
  used at all, depending on Wave 0 compatibility evidence.
- Streaming is preferred when it preserves evidence. Non-streaming is acceptable
  for Phase 6.2 if the official OpenAI-compatible endpoint returns complete
  response IDs, finish reasons, usage, and raw content.
- Console formatting can stay simple as long as persisted trace artifacts are
  complete and report generation is deterministic.

## Deferred Ideas

- Web UI.
- Public API service.
- Full deployment hardening.
- Broad fallback/default policy for all ambiguous BIM requests.
- Large-scale data expansion and fine-tuning.
- RAG beyond deterministic few-shot/context selection.
- Multiple repair iterations and autonomous prompt optimization.

## Product Questions That Must Stop Execution

- The configured live provider cannot authenticate after local diagnostics.
- Mimo rejects the documented OpenAI-compatible chat endpoint for reasons that
  cannot be fixed without new credentials or provider policy information.
- The user wants an unsupported IFC semantic capability to be silently
  approximated instead of routed to Draft/loss.
- The selected framework hides required evidence and the user still wants it
  used for live acceptance.
- A trace/report would need to store secrets, private provider URLs, or
  licensed/private source content beyond approved policy.

All other parser, CLI, session, prompt, routing, report, and test defects should
be diagnosed and fixed without asking the user for implementation choices.
