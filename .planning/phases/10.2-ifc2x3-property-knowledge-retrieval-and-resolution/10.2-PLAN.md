# Phase 10.2 Implementation Plan

**Phase:** 10.2-ifc2x3-property-knowledge-retrieval-and-resolution
**Specification:** `10.2-SPEC.md`
**Execution mode:** Goal-driven, single agent, test-first
**Created:** 2026-07-23

## Delivery outcome

Deliver one production-capable path:

```text
IFC + natural-language property request
  -> RepairIntent 0.3
  -> bounded local property retrieval
  -> exact authorized Phase 10.1 property fact
  -> bound ChangeSet
  -> occurrence-only IFC authoring
  -> reopen + L1 + requested-property L2
  -> published IFC and evidence
```

The live acceptance case uses `LargeBuilding.ifc`, DeepSeek, local BGE-M3 and
Qdrant, and `Pset_WindowCommon.IsExternal`.

## Public test seams

Tests observe behavior only through these approved boundaries:

1. `RepairIntent.from_dict()` and `generate_repair_intent()`.
2. A versioned `PropertyKnowledgeQuery`/resolver public API.
3. The Operation Registry plus `apply_changeset()`.
4. The public Repair API/live runner and reopened IFC evidence.

## Wave 1 - Authoritative records and index lifecycle

### Slice 1.1 - Enriched IFC2X3 records

**RED**

- Add parser tests proving PSD definitions, applicability, template, data type,
  unit families and provenance survive generation.
- Add record tests proving unsupported templates remain searchable but are not
  authorable.

**GREEN**

- Extend the PSD parser without changing existing exact registry meanings.
- Add immutable standard/project property record models.
- Add deterministic corpus and record fingerprints.

**Acceptance**

- The current 317-Pset corpus loads with stable hashes.
- SingleValue authorability is explicit.
- IFC inheritance supports `IfcWallStandardCase -> IfcWall` applicability.

### Slice 1.2 - Reusable stores and reviewed aliases

**RED**

- Test standard-store reuse by corpus hash.
- Test project-record aggregation by source IFC hash.
- Test unique reviewed aliases and alias conflicts.

**GREEN**

- Add SQLite-backed metadata/record store.
- Add a checked-in, reviewed Chinese/English alias seed set.
- Keep project property values out of embedding text.

**Acceptance**

- Repeated builds reuse matching records.
- Alias conflict cannot auto-authorize.
- Project-only candidates remain custom.

### Slice 1.3 - Replaceable embeddings and Qdrant

**RED**

- Test a deterministic fake embedding provider and fake/in-memory vector
  backend through the public retrieval seam.
- Test collection-fingerprint reuse and drift rejection.
- Test explicit vector-unavailable behavior.

**GREEN**

- Add `EmbeddingProvider` and `VectorIndex` protocols.
- Add lazy local BGE-M3 and Qdrant adapters with optional imports.
- Add explicit knowledge-health reporting.

**Acceptance**

- Normal unit tests load neither Torch nor the BGE-M3 model.
- A live collection is keyed by corpus, alias and model fingerprints.
- Qdrant never becomes the authoritative record store.

## Wave 2 - Intent 0.3 and deterministic resolution

### Slice 2.1 - Discriminated Stage 1 contract

**RED**

- Test exact and natural-language property claims.
- Test incomplete natural-language claims and historical 0.1/0.2 compatibility.
- Test that Stage 1 cannot emit canonical/authorization fields for a natural-

**GREEN**

- Add RepairIntent/body schemas 0.3.
- Add domain models and prompt 0.3.
- Register the new prompt and request-stage contract.

**Acceptance**

- DeepSeek-compatible schema is strict and bounded.
- Existing 0.1/0.2 tests remain green.

### Slice 2.2 - Hybrid query and decision

**RED**

- Test canonical exact, reviewed alias, keyword/vector consensus, vector-only,
  conflict, inapplicability and custom outcomes.
- Test bounded candidate evidence and deterministic ordering.

**GREEN**

- Implement exact, alias, keyword and vector retrievers.
- Implement applicability/template/type hard filters.
- Implement the checked-in resolution-policy contract.

**Acceptance**

- Exact and reviewed aliases may auto-resolve.
- Hybrid consensus may auto-resolve only under the frozen policy.

### Slice 2.3 - Scalar and unit normalization

**RED**

- Test strings, booleans, integers, reals and `mm`/`cm`/`m`.
- Test source-project-unit conversion and ambiguous/incompatible failures.

**GREEN**

- Implement deterministic normalization into `ExactPropertyIntent`.
- Preserve raw claim, normalized result and evidence separately.

**Acceptance**

- IFC value type comes from standard/project evidence, never Provider memory.
- Unsupported calculations and unit families fail closed.

## Wave 3 - Generic occurrence authoring and validation

### Slice 3.1 - Operation Registry contract

**RED**

- Test registration and schemas for `set_occurrence_properties`.
- Test target whitelist: Wall, WallStandardCase, Door and Window.

**GREEN**

**Acceptance**

  Type relationship.

### Slice 3.2 - Safe occurrence upsert

**RED**

  copy-on-write.

**Acceptance**

### Slice 3.3 - L1/L2 and publication

**RED**

**GREEN**

**Acceptance**

- Wall, Door and Window deterministic cases publish only after L1/L2.

## Stop conditions

Stop and ask the user only if:

- an authoritative corpus or model download requires unavailable permission;
- a DeepSeek/Qdrant credential/service decision cannot be inferred from the
  accepted local configuration;
- the implementation exposes a contract contradiction that would change the
  approved user-visible behavior;
- live UAT repeatedly fails for an external condition after safe retries and
  diagnostics are exhausted.
