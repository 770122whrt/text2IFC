## Delivered contract

Phase 10.2 now supports this bounded production path:

```text
IFC2X3 + user text
  -> DeepSeek RepairIntent 0.3 claim
  -> local IFC property resolution
  -> exact authorized property fact
  -> DeepSeek ChangeSet draft
  -> deterministic Binder
  -> occurrence-only atomic authoring
  -> IFC reopen + L1 + requested-property L2
  -> published IFC or honest failure
```

The local resolver uses the checked-in IFC2X3 PSD registry, source-IFC project
facts, reviewed aliases, deterministic keyword retrieval and local BGE-M3
vectors in Qdrant. Vector evidence is rebuildable and cannot authorize a
property by itself.

## Fail-closed evidence from UAT development

Earlier live attempts were retained rather than rewritten:

1. incomplete Hugging Face model cache stopped at knowledge preparation;
2. the first ready-knowledge run exposed a natural-language-to-exact
   Production Evidence binding gap before Stage 2;
3. the next run exposed an over-broad surviving-fact authoring scope and was
   rejected by unified audit;
4. after source-bound claim matching and `explicit_request_only` authoring were
   implemented, the same real chain passed.

These failures demonstrate that neither Provider success nor a generated
ChangeSet is treated as IFC repair success.

## Deferred boundaries

- Enumerated, list, table, reference and complex IFC property templates remain
  searchable but are not authorable.
- Shared Type mutation remains deferred; Phase 10.2 writes occurrence facts
  only.
- Beam, Column and Space authoring are not enabled yet. The knowledge record,
  query and resolver interfaces are operation-neutral and remain reusable.
- Target/prototype retrieval remains the deterministic Phase 7/09.1 SQLite
  path; Phase 10.2 does not replace it with vector retrieval.
