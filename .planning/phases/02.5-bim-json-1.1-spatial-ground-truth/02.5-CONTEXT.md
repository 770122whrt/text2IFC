# Phase 2.5 Context

## Why This Phase Was Inserted

Phase 2 proved that BIM JSON 1.0 can describe hierarchy, supported element
families, basic dimensions, and selected properties, then compile that subset
to valid IFC2X3. It also intentionally used synthetic placement because the
contract contains no source coordinates or orientation.

Before building the formal Text-to-JSON dataset, the project inspected all 25
BIMNet IFC2X3 files and 10 licensed buildingSMART IFC4/IFC4X3 samples. The
audit showed that a model trained against BIM JSON 1.0 could learn what
elements exist but could not learn where they are, which rooms they form, or
how doors and windows fill wall openings.

Phase 2.5 therefore establishes the spatial ground-truth contract required by
Phase 3.

## Locked Decisions

- BIM JSON remains a task-oriented semantic contract, not a JSON clone of the
  complete IFC object graph.
- BIM JSON 1.1 extends the versioned schema rather than silently changing
  `bim-json/1.0`.
- BIM JSON 1.0 remains readable through an explicit, deterministic migration
  path.
- Hierarchical local placement records `relative_to`, origin, axis, and
  reference direction. A flat world-space XYZ alone is insufficient.
- Spaces and opening/filling relationships enter the formal contract before
  Text-to-JSON training.
- IFC extraction is an offline ground-truth construction step. It is not part
  of the runtime Natural Language to IFC request path.
- Every source IFC object or relationship outside the supported 1.1 subset is
  counted and reported. The extractor never silently drops source content.
- The 25 authorized BIMNet files are the primary IFC2X3 source set.
- Dataset splits are assigned by Matterport scene family, so `px4`,
  `px4_1`, and `px4_2`, for example, cannot cross train, validation, or test.
- The 10 CC BY 4.0 buildingSMART files form a separate cross-schema and
  relationship test track. They are not mixed blindly into the IFC2X3 split.

## Phase 2.5 Candidate Scope

1. BIM JSON 1.1 schema and generated reference.
2. Placement, orientation, optional georeferencing, and space structures.
3. Opening, host, and filling references.
4. Structural and semantic validation for spatial references and transforms.
5. Deterministic IFC2X3 to BIM JSON 1.1 extraction for the supported subset.
6. Per-file provenance and machine-readable loss reports.
7. Explicit BIM JSON 1.0 to 1.1 migration.
8. Minimum compiler support required to preserve 1.1 placement, spaces, and
   opening/filling relationships.

## Deferred to Phase 4

- Material layer and constituent fidelity
- Type-object and mapped-representation reuse
- Arbitrary profiles, BReps, tessellation, and presentation styles
- Wall/path and general element connection topology
- Additional architectural, structural, furnishing, and MEP classes
- Full IFC4 and IFC4X3 output

## Dataset Authorization

The user confirmed on 2026-06-11 that Matterport3D/BIMNet authorization has
been obtained and that the 25 IFC files may be used for local training.
Redistribution remains governed by the source terms and is not inferred from
local training permission.
