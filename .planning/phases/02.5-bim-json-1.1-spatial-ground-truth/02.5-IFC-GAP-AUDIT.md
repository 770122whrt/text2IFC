# IFC to BIM JSON 1.0 Gap Audit

## Scope and Method

The audit opened:

- 25 authorized BIMNet IFC2X3 files
- 8 buildingSMART IFC4 files
- 2 buildingSMART IFC4X3 files

IfcOpenShell 0.8.5 enumerated products, spatial objects, local-placement
chains, relationship classes, material associations, type objects, property
sets, quantities, representation items, units, and georeferencing metadata.

The purpose was not to mirror every IFC entity. It was to identify information
that is necessary for a natural-language system to describe and regenerate a
spatially meaningful building.

## Current BIM JSON 1.0 Coverage

BIM JSON 1.0 represents:

- one project, site, and building
- one or more storeys and elevations
- nine element kinds
- rectangular-envelope dimensions
- element-to-storey containment
- `is_external`, `load_bearing`, and `predefined_type`
- stable semantic IDs

It does not represent local placement, orientation, rooms, openings, filling
relationships, materials, reusable types, arbitrary geometry, or connectivity.

## Geometry Evidence

BIMNet representations include:

| Representation item | Count |
|---|---:|
| `IfcExtrudedAreaSolid` | 5,181 |
| `IfcPolyline` | 1,651 |
| `IfcFacetedBrep` | 1,327 |
| `IfcMappedItem` | 1,033 |
| `IfcFaceBasedSurfaceModel` | 125 |
| `IfcBooleanClippingResult` | 20 |

Basic dimensions plus placement can express the current minimum box-like
compiler subset, but they cannot reproduce arbitrary profiles, BReps, mapped
geometry, or boolean results. These unsupported representations require an
explicit extraction loss rather than an invented primitive.

## Material and Type Evidence

BIMNet contains:

- 1,533 `IfcMaterialLayerSetUsage` associations
- 793 `IfcMaterialList` associations
- 181 `IfcMaterialLayerSet` associations
- 47 direct `IfcMaterial` associations
- 1,012 type-instance relations across wall, door, window, plate, covering,
  column, slab, beam, member, and other type classes

These structures matter for high-fidelity regeneration but are not required
to establish the first spatial Text-to-JSON baseline. They remain explicit
Phase 4 work and must appear in Phase 2.5 loss reports.

## buildingSMART Evidence

The 10 official samples add:

- IFC4 and IFC4X3 schema coverage
- one canonical wall-opening-window chain
- tessellated geometry through 67 `IfcTriangulatedFaceSet` items
- base quantities for walls, beams, and slabs
- architectural, structural, and HVAC type coverage
- material constituent sets not present in the BIM JSON 1.0 vocabulary

They are valuable as cross-schema normalization and relationship fixtures,
but they are not interchangeable with the IFC2X3 BIMNet training split.

## Gap Classification

### Required Before Phase 3

1. Hierarchical local placement and orientation.
2. Spaces with storey membership and supported geometry.
3. Opening-host and opening-filling references.
4. Optional site georeferencing and true north.
5. Deterministic source IDs and provenance.
6. A loss report covering every unsupported object, relationship, property,
   material, type, and representation.
7. Scene-family split identity to prevent train/evaluation leakage.

### Required for Phase 4 Fidelity

1. Material layers and constituents.
2. Type objects and reusable mapped representations.
3. Arbitrary profiles, BReps, tessellation, and boolean geometry.
4. Element/path connection topology.
5. Broader architectural, structural, furnishing, and MEP classes.
6. Full schema-aware IFC4/IFC4X3 normalization and output.

### Intentionally Excluded from the Language Contract

- STEP line numbers
- `IfcOwnerHistory` and application bookkeeping
- serializer timestamps
- presentation-only style internals unless appearance becomes a product goal
- schema implementation details that cannot be expressed as user intent

## Obvious Structural Error in BIM JSON 1.0

The most important defect is not merely a missing optional field. The contract
requires every element to belong to a storey but provides no way to locate it
inside that storey. Consequently two different buildings with identical
element counts and dimensions collapse to the same BIM JSON representation.

That makes BIM JSON 1.0 unsuitable as the final supervision target for
spatial Text-to-JSON training.

## Recommended Spatial Primitive

A placement should be parent-relative:

```json
{
  "relative_to": "storey-001",
  "origin": {"x": 1200.0, "y": 3500.0, "z": 0.0},
  "axis": {"x": 0.0, "y": 0.0, "z": 1.0},
  "ref_direction": {"x": 1.0, "y": 0.0, "z": 0.0}
}
```

Validation must require finite coordinates, non-zero direction vectors,
orthogonality within a defined tolerance, resolvable parent references, and
acyclic placement chains.

## Conclusion

BIM JSON 1.0 is a valid minimum compiler contract, but not a sufficient
spatial learning target. Phase 2.5 must establish BIM JSON 1.1 and a
deterministic IFC ground-truth extractor before Phase 3 generates formal
Text-to-JSON datasets.
