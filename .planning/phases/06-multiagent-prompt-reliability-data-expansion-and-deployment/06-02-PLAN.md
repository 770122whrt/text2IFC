<objective>
Implement registry-rendered BIM JSON generation and conditional failure routing
using Design Brief input, validator feedback, geometry feedback, schema summary,
capability profile, and few-shot examples.
</objective>

<why>
The project needs one controlled place where model output becomes BIM JSON or
Draft. Successful first-pass generation should not require repair. Failed
generation must route to safe repair, Draft clarification, or blocking failure
without inventing facts or forking into an untraceable second prompt system.
</why>

<must_haves>
- Generator consumes Design Brief, not raw user text alone.
- Generator output is formal BIM JSON 2.0 or Draft update only.
- Successful runs record zero repair attempts.
- Failed runs record a route: repair attempted, Draft clarification, or blocked.
- Any repair attempt uses the same output boundary and records before/after
  diagnostics.
- No raw IFC, STEP, STEP IDs, or low-level helper objects are allowed.
</must_haves>

<threat_model>
- Threat: failure routing hides invalid output. Mitigation: every run records
  `no_repair_needed`, `repair_attempted`, `draft_required`, or `blocked_failure`.
- Threat: repair loop fabricates dimensions or placements. Mitigation: repair
  receives known facts and must return Draft if feedback cannot be fixed from
  those facts.
- Threat: prompt drift between generation and repair. Mitigation: any repair
  attempt uses the same registry-backed generator family and records mode
  metadata.
</threat_model>
