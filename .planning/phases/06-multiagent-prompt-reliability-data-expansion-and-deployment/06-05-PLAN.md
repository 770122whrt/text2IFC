<objective>
Expand approved training/evaluation data only under licensing, provenance,
split, and sidecar constraints, then compare prompt-only, optional RAG, and
fine-tune candidates before selecting a deployable model approach.
</objective>

<why>
Fine-tuning is expensive and can hide data leakage or unsupported-source truth.
The project should train only after prompt and repair baselines have measurable
failures that additional data can plausibly improve.
</why>

<must_haves>
- Data expansion is license-reviewed and provenance-linked.
- Scene-family split separation remains binding.
- Draft/loss sidecars remain linked and are not silently treated as Formal.
- Model decision report compares options using metrics, not preference.
</must_haves>

- Threat: training data leaks validation/test scene families. Mitigation:
  manifest builder rejects split leakage.
- Threat: sidecar losses are converted into fake formal truth. Mitigation:
  manifest requires explicit sidecar links and formal-target validation.
- Threat: unclear external license. Mitigation: missing license status blocks
  training eligibility.
</threat_model>
