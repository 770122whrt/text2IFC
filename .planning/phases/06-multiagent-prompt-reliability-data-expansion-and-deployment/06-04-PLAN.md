<objective>
Create an experiment harness that runs prompt-only, conditional repair, Draft,
blocking-failure, and audit paths over controlled cases and writes
machine-readable metrics plus generated Markdown run reports that expose all
critical intermediate inputs and outputs in one human-review document.
</objective>

<why>
Prompt changes, repair loops, and model comparisons need quantitative evidence.
This harness turns subjective prompt tuning into repeatable experiments with
failure classes and metric deltas.
</why>

<must_haves>
- Experiments record prompt IDs, hashes, provider mode, repair count, metrics,
  failure classes, and artifact paths.
- Experiments distinguish Draft, invalid JSON, invalid BIM JSON, compile
  failure, geometry failure, audit mismatch, and success.
- Reports include the original input, Design Brief, rendered prompt reference,
  raw model output reference, parsed BIM JSON or Draft, validation feedback,
  geometry feedback, failure/repair route, audit result, metrics, final IFC
  path when compiled, and artifact paths back to source trace files.
- Reports are stable enough for later model and fine-tune decisions, and are
  generated from trace artifacts rather than hand-written demo prose.
</must_haves>

<threat_model>
- Threat: experiments compare runs with missing prompt metadata. Mitigation:
  record validation fails if identity fields are absent.
- Threat: data leakage in benchmark cases. Mitigation: records include split
  and source provenance.
- Threat: report becomes a shallow summary that hides bad intermediate output.
  Mitigation: report-section tests require each critical input/output section
  and artifact path.
- Threat: report leaks provider secrets while showing prompts and raw outputs.
  Mitigation: report writer redacts secrets and secret scan covers the report.
</threat_model>
