<objective>
Create an experiment harness that runs prompt-only, conditional repair, Draft,
blocking-failure, and audit paths over controlled cases and writes
machine-readable metrics plus markdown reports.
</objective>

<why>
Prompt changes, repair loops, and model comparisons need quantitative evidence.
This harness turns subjective prompt tuning into repeatable experiments with
failure classes and metric deltas.
</why>

<must_haves>
- Experiments record prompt IDs, hashes, provider mode, repair count, metrics,
  failure classes, and artifact paths.
- Experiments distinguish Draft, invalid JSON, invalid BIM JSON, compile
  failure, geometry failure, audit mismatch, and success.
- Reports are stable enough for later model and fine-tune decisions.
</must_haves>
