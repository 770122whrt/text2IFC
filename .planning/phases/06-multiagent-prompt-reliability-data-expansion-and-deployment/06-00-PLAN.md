<objective>
Create the Phase 6 control layer for prompt input, prompt identity, rendered
prompt traces, and multi-agent responsibility boundaries.
</objective>

<why>
The current repository has useful prompt files, but no central registry proves
which template and inputs produced a model response. Without this layer, prompt
iteration is not reproducible and geometry-gate artifacts can be mistaken for
live multi-turn provider traces.
</why>

<must_haves>
- Every provider-backed model call has a template ID and template hash.
- Rendered prompt, structured renderer inputs, raw response, parsed response,
  validation feedback, metrics, and artifact paths are traceable.
- `two-room-suite` remains documented as a deterministic geometry gate, not a
  live provider prompt proof.
- Multi-agent roles are documented before implementation.
</must_haves>

<threat_model>
- Threat: prompt traces leak provider secrets. Mitigation: trace metadata may
  include env var names but never token values, headers, or private URLs.
- Threat: registry bypass through ad hoc prompt strings. Mitigation: provider
  orchestration requires prompt metadata before accepting live/file outputs.
- Threat: documentation overclaims current capability. Mitigation: architecture
  doc explicitly labels geometry-gate cases as deterministic where applicable.
</threat_model>
