<objective>
Package the selected supported-scope multi-agent path behind a repeatable CLI
or service demo that produces a real IFC2X3 file, complete trace bundle, and
generated Markdown run report.
</objective>

<why>
The project goal is not a collection of scripts; it is a deployable text2IFC
path that can accept natural language, ask or record clarification when needed,
produce validated BIM JSON, compile IFC, and explain the result.
</why>

<must_haves>
- Final artifact is a real IFC file.
- Service path uses prompt registry, Design Brief, generator, conditional
  failure routing, validation, IFC quality gate, and audit.
- Draft remains Draft and is not compiled.
- Complete runs write `report.md` as the human review entry point. The report
  must expose the full text -> Design Brief -> prompt -> raw output -> BIM JSON
  or Draft -> validation -> geometry -> audit -> IFC chain.
- Provider config is environment-based and secret-safe.
</must_haves>

<threat_model>
- Threat: deployment compiles invalid or Draft content. Mitigation: service
  checks `validate_v2_document` before compile.
- Threat: live provider config leaks. Mitigation: env-only config and artifact
  secret scan.
- Threat: service overclaims unsupported geometry. Mitigation: Phase 4 quality
  gates and loss sidecars remain part of the report.
- Threat: final demo passes by producing IFC while hiding bad intermediate
  agent behavior. Mitigation: final acceptance requires the generated
  `report.md` with every intermediate input/output section.
</threat_model>
