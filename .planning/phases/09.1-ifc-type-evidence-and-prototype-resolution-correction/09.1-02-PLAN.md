<objective>
Let users authorize IFC Types by unique human-readable name or by confirming a
deduplicated evidence-bearing Type candidate, while preserving explicit
authorization and fail-closed ambiguity.
</objective>

<threat_model>
- T-09.1-05 (critical): similarity or the Agent silently authorizes a Type.
  Mitigation: retrieval-only candidates and stored affirmative answer binding.
- T-09.1-06 (high): a candidate token is replayed across operation/run/source
  revisions. Mitigation: token binds operation ID, Type GUID and current run
  state; existing answer revision checks remain mandatory.
- T-09.1-07 (high): occurrence repetition biases or overwhelms clarification.
  Mitigation: one TypeRecord candidate per reliable Type and top-K byte bounds.
- T-09.1-08 (medium): candidate output leaks full project Psets. Mitigation:
  fixed public projection fields and approved dimension evidence only.
</threat_model>
