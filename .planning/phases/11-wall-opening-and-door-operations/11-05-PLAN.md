<threat_model>

- **Provider secret leakage:** Read existing configuration through normal
  provider setup; redact requests/metadata; never print, copy or commit API
  keys/base secrets.
- **Synthetic success:** Live scripts must identify actual provider/model,
  attempts and fallback status. No offline fixture may replace a failed live
  response.
- **Ground Truth leakage:** Mutation manifest and original comparison remain
  private evaluator inputs and are asserted absent from both rendered prompts.
- **Evidence cherry-picking:** Runner has a fixed case matrix and writes a
  terminal record for failures as well as successes. Proof receives only
  accepted cases with all required files/hashes.
- **Large-file drift:** Every original/damaged/repaired artifact is SHA-256
  bound; IFC reopen and source hash are rechecked by an independent validator.
- **Regression masking:** Full existing IFC repair tests and Window proof
  validation run before completion.

</threat_model>
