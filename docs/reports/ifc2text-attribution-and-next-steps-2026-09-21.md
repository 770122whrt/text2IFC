# IFC2Text：重新归因、真实探针与下一步指南

更新：2026-09-21。基线为 `e7e89379`；本轮探针先提交于 `8327408c` 后再执行。工作区为 `E:\code for project\bimnet`，分支 `codex/bim2text-research`。本报告补充原研究方案和实施决策，不另建研究路线。

## 1. 结论先行

当前不是单一的“地理位置丢失”，也不能将全部差异归给 Generator。模型世界坐标与地理坐标不是同一个验收项目；本轮没有验证经纬度、CRS 或地图定位保真。

已有 hxp 源/重建 IFC 重新提取后，仍得到 66 个匹配对象、0 缺失、0 多余、12 个几何超差、5 个材料内容差异、3 个关系差异。34 个 unassessed 均由墙的测量方式不同触发。这些是旧重建的重新诊断，不是新模型质量提升。

本轮完成两次真实 Provider 的公共 Design Brief 调用、原始产物逐阶段追踪、一个空间字段投影反事实和三面墙的截面/无洞口网格复验。没有重新生成整栋 IFC，也没有将原诊断 IFC 晋升为成功产物。

### 2.1 五个空间：信息存在，但消费者没有读取

原 Brief 的 R001–R005 均有多边形轮廓及 `z_mm=[-1140.0,1298.4]`。`semantic_coverage.py` 的空间期望读取 `bounds`、`height_mm`，缺少高度时退到 `net_height_mm`；它没有将这些空间的 polygon/z_mm 转成所需字段。

离线实验只修改 Expected Facts 的独立副本：由原 Brief 已有 polygon 计算 XY bounds，由 z_mm 计算高度 2438.4 mm。不读取源 IFC 来补答案，也不改生产代码。结果为：可构造空间期望 **0→5**，未解决项 **8→3**。剩余3项仍是楼层净高要求，没有为了通过而填假值。

这说明最先应统一字段合同与投影。它只证明包围范围期望可以从既有事实生成，不证明房间用途、实际通行或精确多边形形状已经通过。

### 2.2 三面墙：轴对了，截面不一样

三面源墙均为 `IfcArbitraryClosedProfileDef`，重建均为 `IfcRectangleProfileDef`。关闭门窗洞口布尔切割后，源/候选包围盒仍有如下差异：

| 墙 | 无洞口时主要范围差 | 解释 |
|---|---:|---|
| W011 | Y方向 77.73 mm | 源截面端部不是完整矩形，不能仅由轴长和厚度恢复。 |
| W013 | Y方向 109.23 mm | 源多边形端部形状被矩形替代。 |
| W015 | X方向 81.52 mm | 源截面有不等长边及斜端，候选使用矩形。 |

两侧轴端点通常只差约0.05 mm。关闭洞口后仍有差异，排除了“全部由洞口切错造成”的解释。IFC2Text 虽写了特殊包围盒，但包围盒并不能唯一确定这些截面。

门窗也是类似的分层问题：D001 的名义宽高和实体包围盒进入了 Brief，但 Generator 选择 `basic_filling/door-left`，源模型则使用映射几何。其范围差不能直接当作编译器 Bug；要区分输入未提供的完整造型和已经提供但未遵循的外包范围。

## 3. 两次真实 Provider 实验

两组都通过现有公共 Brief controller，使用同一注册 `design-brief.v2.24`、Brief Schema 2.7、相同证据内容和 few-shot 内容。响应 model 均为 `deepseek-flash`；请求显式开启 thinking，输入/输出配置上限均131072，复用旧200万累计账本。两组均完整返回 `finish_reason=stop`。工具等待超时没有触发额外重试；结果以实际响应和结算账本为准。

A 使用原8255字符的完整说明。B只在同一说明末尾追加通用规则：记录楼层与宿主墙归属是不同关系，分别保留；无法表达时说明冲突，不静默改变归属。没有给B额外坐标、源IFC、解析事实或Compare结果。

| 对照 | A：原文本 | B：加通用保留规则 |
|---|---|---|
| 窗的实际Brief数组归属 | 三扇窗均在 storey-s01 | 三扇窗均在 S02 |
| 记录楼层/宿主分离 | 源S02只在歧义说明里；实际采用宿主层 | 逐窗 recorded_storey=S02、host_storey=S01，原host_wall保留 |
| 控制器终态 | draft_required | draft_required |
| 主要阻断 | 非分层多材料不支持 | 非分层多材料不支持，另报告记录楼层/宿主规则冲突 |
| 本次token | 120872 | 110537 |
| 新IFC | 无，未调用Generator | 无，未调用Generator |

结论：更显式的通用说明在该次对照中避免了静默改写楼层，但没有打通正向生成。每组只有一次、同一已揭示建筑，不能作为统计意义上的因果证明或跨建筑提升。

B把限制解释成“同一构件同时归属两个楼层”；这里实际要保留的是构件记录楼层和宿主关系，不要求两个 containment。该解释是模型的输出，不能据此宣称 IFC 标准或整个编译器必然不支持。下游是否可表达、哪里有同层限制，需要独立合同/编译测试。

材料结论则有独立代码证据：当前 Schema 的材料 oneOf 不含 material_list，`materials.maxItems=1`，直接验证器测试拒绝列表。两次真实调用都把已给的多材料视为阻断项；旧运行只是非阻断记录。这个变化提示 unsupported 的阻断策略仍受模型输出影响，不能把旧 ready 当作稳定能力。

另一个重要观察：三次 Brief 都保留了空间上下界数值，但字段名不同。旧版是 z_mm，A是 elevation_range_mm，B是 bottom_elevation_mm/top_elevation_mm。不能因为只查某一个键得到 null 就说几何丢了；后续需要规范字段，不是逐次添加定点别名。

## 4. 下一步指南：先修什么、怎样验收

### 第一步：修空间事实到评估的字段衔接

先固定一个规范的空间几何合同，明确轮廓、底标高、高度及来源；确认既有 Schema 是否足以表达，必要时新增版本，不覆盖历史版本。只从确认的数值进行单位和字段转换；不把层高、墙高、空间高度互相代替，不给参考标高强补净高。

验收：原5个空间的期望可构造；缺少Z、非法轮廓、上下界冲突仍正确阻断；具有明确非零楼层偏移的空间按真实底标高评估，不误判或强制落在楼层标高上。原/候选用同一个新评估器重算。减少未评估项不等于旧IFC自动合格。

### 第二步：独立拆开记录楼层、宿主和放置参考

把本轮有效的保留规则纳入下一版通用描述策略，并在Brief规范字段、Expected Facts、Generator上下文和最终关系检查中贯通；同时审查示例里“门窗应放入宿主墙楼层”的默认规则。不能只在备注中保存源关系，也不能让模型把两个不同关系理解为双重归属。

验收：构件记录层与宿主层相同/不同两类正例，以及未知记录层、多宿主等负例；几何位置不变，关联记录独立正确。先用冻结中间结果编译测试，再安排新的真实往返。

### 第三步：给非分层多材料建立真实可执行合同

材料列表与分层材料分开。需要版本化地连通 Brief、BIM JSON、Generator、Compiler、重新打开IFC后的材料关联检查。不得把木材、金属涂层列表强行写成虚构厚度的层集，也不能任选一种材料当作完整恢复。

验收：D003–D007和独立的非门构件例子都保留列表；单材料、分层材料与缺材料行为不回退。不支持的场景明确保持不支持，不靠一次模型给ready绕过。

### 第四步：只为异常几何增加必要描述

普通墙保留紧凑“轴+厚+高”；带斜端、截短或特殊截面的墙额外写实测截面顶点和参考系。这样无需回到全文IFC转储，也不必扩大所有构件的文本量。门窗先分别约定位置/名义尺寸、实体外包范围和详细造型三个保真目标，避免名义尺寸正确却宣称形状相同。

验收：在已保留轴位置的前提下，异常截面误差下降，其他构件不变。一次只改描述或重建中的一个主要因素，源模型与20mm比较容差不动。

### 第五步：补齐Compare可比范围

34条未评估记录全部源于轴测量方法不同。可统一实际截面/轴提取，或建立独立的几何度量；不能删掉“方法不同”的标记就算减少错误。材料引用方向/偏移仍单列，内容相同不证明物理层方向相同。

建议先完成第一步的离线修复和第二步的关系合同核对，再考虑新增整栋重建；不先扩大建筑数，也不把同一个hxp反复重试称为跨建筑学习。
