## “无 C loop 与完整链路都是121份”的含义

本地消融权威 `dataset/processed/experiments/harness-ablation-deepseek-20261011/runs/qwen-g400-20261013/REPORT.md` 已确认三组各400题全部终态，IFC产出分别为0、2、121。这里是封存产物数，不是修复正确数；原始运行目录不随本页上传。

2026-10-17补充服务器只读核验：这些实验都选自同一个1200题公开数据集。此前“样本集合不同”指实际选中的题单，不是底层数据集不同。关系如下：

| 批次 | 选题数 | 与消融每组400题的关系 |
|---|---:|---|
| 本地 F / 本地 G | 共用同一批200题 | 0题重合；本地G执行仍保持原暂停，本次未操作 |
| 服务器 F | 200 | 全部包含在服务器G及消融题单内 |
| 服务器 G | 400 | 与消融400题完全一致 |
| 消融 no_a / direct_b / no_c_loop | 每组400 | 三组共用服务器G的400题，共1200个运行项 |

服务器消融的准备清单明确引用服务器G，源batch文件SHA与现场G完全一致；执行与准备清单的400条输入及预算完全一致。服务器G与消融的冻结model.ifc及有效request.txt哈希400/400相同，服务器F对应200/200相同，每题预算也相同。服务器选题收据明确排除了本地200题。因此完整Harness汇总121份＝本地F66＋服务器F55，来自另一组400题，其中只有服务器F的200题与消融重合。不能拿两边121的总数当作同题效果相等。[当前输入血缘核验](dataset-lineage-verified.json)保留600个不同题号的归属及服务器manifest文件哈希；本次没有重新哈希大型输入IFC。

旧的“12对／7相同／5不同”只来自10月15日早期无C的29份产物清单，与服务器F55份清单相交。旧的“新增92份”＝最终121−早期29，指当时尚未收集的元数据行，不表示服务器缺文件或92题失败。

本次已只读补齐无C最终400条状态和121份封存产物清单，121份文件均存在，早期29份的记录哈希保持。与服务器F的既有55份清单连接后，最终为**43对同题产物，32对记录SHA-256相同、11对不同**。共同200题的产出分布如下；另200题无C产出59份，没有本次F对应运行。

因此共同200题中，F产出55份，无C产出62份。这是描述性产出统计，既不是正确率，也不能单独证明C的因果作用。[最终逐题产物配对清单](artifact-pairs-final.json)包含所有200题的输出交叉情况和121份无C产物元数据。服务器F侧复用10月15日已核对文件哈希的55份冻结清单，本次未重新收集F或重读IFC；无C侧本次核对文件存在性和封存哈希元数据，未重新哈希IFC。字节不同可能只是序列化，也可能是语义或几何不同，需进一步检验。

当前批次明确 `paired=false`，没有同配置完整ABC基线；两边上下文/输出上限、运行版本及发布/检验要求未统一，历史模型标签不能代替实际后端绑定。`no_c_loop` 实际移除了独立C检验、发布门和反馈循环，保留B内部事务与后置条件，并非仅将循环次数设为零。完整组配置最多2次反馈，但现有短摘要未给出实际触发次数。
