# text2IFC 研究方案：可接受解空间、知识效率与受控编辑

更新：2026-09-16。本文是当前研究问题、贡献边界和实验设计的唯一主稿；文献见[简版](literature-review-short.md)与[完整版](literature-review-full.md)。以下实验均为设计，未在本轮执行。工程量是熟悉仓库的一名研究工程师的人周估算，不是交付承诺。

**当前判断：三个想法相容，但不是三项已经成立的方法创新。现有系统适合验证一个受控 BIM Agent 的 Demo；未来优先研究 D1“有效设计模式覆盖”和 D2“多步编辑交互学习”。省 token 是共同目标，可审计与回滚是共同基础。**

## 1. Motivation：从生成文件到完成设计任务

Coding Agent 可以写 IfcOpenShell 程序、原始 IFC 或 BIM JSON，但代码执行成功不代表建筑任务完成。结果还要同时满足几何、宿主与空间关系、用户要求，并在修改中保留不应改变的内容。text2IFC 的研究对象是这些可执行设计状态及其变化。

这种困难不是 IFC 独有：普通代码也有多种正确实现、隐含规格、状态和副作用。IFC 的研究价值在于，同一对象同时参与几何与语义关系；看起来相同的两份模型可能有不同宿主或楼层归属，而不同布局又可能都满足用户要求。这提供了具体、可测的任务结构，不能仅凭“领域复杂”推出新方法。

### 三个想法分别处于什么位置

| 想法 | 现在可做什么 | 还要补什么 | 创新判断 |
|---|---|---|---|
| 多种可接受方案 | 使用已有生成、编译与重开路径，对多个候选分别验收；小范围并排展示可行 | 独立需求评分、多方案调度、语义去重、设计模式定义和选择恢复 | 多次采样、多个视图、多个正确答案均不新；D1研究覆盖策略 |
| 节约 token、有效使用知识库、约束输入输出 | 已有 schema/authoring contract、局部上下文选择和预算记录 | 公平成本比较、知识适用范围、压缩后关键关系是否丢失；生成与属性检索知识不能混为一谈 | 压缩、RAG和约束生成已有先例；先作为实验变量，不凑第三项方法创新 |
| 可审计、可回滚 | 已有运行记录、修订绑定、受限 ChangeSet、部分失败隔离机制 | 用户可见历史版本恢复、分支选择、失效检查，以及撤销后重新验证 | 有系统价值；日志、事务和版本管理本身不是新 AI 方法 |

这里的“多模态”需拆开：文本、图像、三维模型是不同模态；同一要求对应多个布局，是**多解性或设计模式多样性**。论文主张先用后者。不能未经测量就说当前分布单峰，更不能用几张不同图片证明生成分布变成多峰。

### 可接受解空间怎样定义

将需求拆成四部分：必须满足的硬约束 H、软偏好 P、允许自由变化的设计变量 F，以及仍需澄清的歧义 U。歧义不是任意生成许可；尺寸、宿主或安全要求不明确时，应先保留未知或询问。

对已澄清请求 q，定义受支持表示内的形式可行集合：

`S(q) = {x : x 可编译并重开，且满足 H(q)}`。

这不等于用户最终接受的全部设计。用户偏好和未表达要求仍可能排除其中的结果。输出集合 A 是 S(q) 中的有限候选；目标是在预算 B 内，提高有效模式覆盖与用户选择价值，同时保留逐候选证据。

“不同”按任务预先定义：如房间连通结构、走廊组织、允许变化的宿主安排。改 GUID、换代码顺序、等价坐标变换、相机角度或不影响任务的尺寸抖动，不自动算新模式。朝向若与采光等要求有关，则不能作为可忽略变换。

### 三者的真实张力

| 张力 | 研究与实现处理 |
|---|---|
| 方案越多，通常总成本越高 | 同时测总预算下覆盖、每个有效独特方案的成本；不拿单次 token 下降代替总节约 |
| 约束越强，越可能排除合法设计 | 硬要求固定；编译器默认值与模板偏好不得冒充用户要求；测合法候选误拒与模式损失 |
| 上下文越短，越可能漏掉跨对象依赖 | 保留目标、宿主、接口和保全条件；用真实执行检查压缩损失，不只测文本相似度 |
| 非确定生成与可重放 | 保存当次实际响应、输入和版本；重放确定性执行，不假设再次调用 LLM 会给出同一答案 |
| 回滚与后续依赖 | 优先恢复完整已验证快照并新建修订；选择性撤销必须重新检查依赖，不能简单逆序调用所有动作 |

## 2. 当前研究问题与可写贡献

### RQ0：现有系统应回答什么

**在有明确需求和修改范围的 Text-to-IFC 任务中，受控结构化生成与局部修改，能否在相同预算下比普通 Coding Agent 更可靠地完成任务，并保留非目标状态？**

当前可描述的系统机制包括：需求澄清后进入 ready 状态；BIM JSON 经确定性编译与产物检查；问题、候选修订和可写范围绑定到 ChangeSet；修改后再次验收。Generation 与 Repair 有相关基础，但尚不能称为一个已经统一训练或统一规划的模型。

**Novelty 的诚实边界：**可以主张并评估具体的系统设计与保障范围；暂不能主张已发现新 AI 算法。“需求→规格→模型→检查→修订”已与 [Self-Verification](https://ec-3.org/wp-content/uploads/2026/08/EC32026_444.pdf) 直接重合。“没有发现完全相同组合”不等于已经证明方法创新。工程做得更完整，需要实验支持，也不能自动转换成算法首创。

### 当前实现边界

- [ChangeSet apply](../../../src/text2ifc_agent/changeset_apply.py)使用候选副本及范围/保全检查；失败不接受结果，不等于任意历史步骤均可撤销。
- [Repair apply](../../../src/text2ifc_ifc_repair/apply.py)拒绝原地覆盖，在内存执行并通过后置检查后写临时IFC，重开检查再原子替换输出；这是未提交结果的失败隔离，不是反向操作。该函数的文件发布不等于完整最终验收。
- [修订记录](../../../src/text2ifc_agent/revisions.py)和[会话存储](../../../src/text2ifc_agent/session_store.py)提供追溯基础；记录存在不等于完整交互式分支、选择性撤销和用户恢复均已实现。
- [Authoring contract](../../../src/text2ifc_agent/authoring_contract.py)、[ChangeSet context](../../../src/text2ifc_agent/changeset_context.py)提供合法输出和相关上下文；这不是直接控制闭源模型每个 token 的语义约束解码。
- [预算管理](../../../src/text2ifc_agent/generation_budget.py)有预留和结算；usage 缺失时预留量不能写成实测 token。
- [Expected Facts](../../../src/text2ifc_agent/expected_facts.py)来自 Brief；[semantic coverage](../../../src/text2ifc_agent/semantic_coverage.py)不能独立证明最终 IFC 满足每一条原始请求。已有几何/关系门禁仍需要独立意图评价补充。

2026-09-16静态核查还确认：上下文会递归扩展只读依赖，不能写成完整读白名单；会话artifact记录主要登记路径，哈希和记录本身不等于不可篡改存储。上述模块及少量对应测试只做阅读，未在本轮执行测试。

### E0：当前系统的实验

| 实验 | 比较与控制 | 核心指标 | 能支持的结论 |
|---|---|---|---|
| E0.1 生成与局部编辑 | 直接写 IFC、通过 IfcOpenShell 写程序、使用同一 JSON/编译器的 Coding Agent、当前系统；统一模型、任务、时间/费用上限和可用资料 | 原始要求＋几何＋关系联合成功，非目标状态保持，全部失败与重试成本 | 系统有效性；跨表示比较只说明整套系统差异 |
| E0.2 机制消融 | 在相同 JSON/编译器、检查器和底层动作权限下，比较整模修订、普通局部 patch、绑定 revision/issue/scope 的 ChangeSet | 意外修改、错误放行、任务完成、修改轮数 | 受控修改机制的贡献；不能把编译器优势归因于 Agent |
| E0.3 知识与 token | 全量文档、普通检索、机械去重、结构切片、当前上下文策略；另比较同内容的完整/紧凑编码 | 总成本—成功率曲线、合法方案误拒、关系遗漏、调用数 | 是否有实际效率收益；输入缩短不等于能力提升 |
| E0.4 审计与恢复 | 缺记录、过期修订、应用中断、验证失败、来源不一致；恢复功能补齐后再测历史快照恢复 | 记录完整性、源不变、失败隔离、恢复后重开与语义/几何一致性 | 实际已测路径的系统可靠性；不是 AI 方法创新 |

E0.2 的机制消融在隔离副本中进行；放宽某一研究变量不意味着放松公共产品边界。各方法使用同一外部评分器。已有回归测试和成功 Proof 不能替代上述任务集实验。

## 3. 未来方向 D1：预算内覆盖更多有效设计模式

**研究问题：**对于具有多个合法布局的同一要求，Agent 如何把计算用于尚未覆盖的设计模式，并避免对同一无效结构反复修补？

**候选创新：**将“几何失败属于哪个结构决策”和“哪些设计模式尚未被覆盖”结合起来，决定下一步开放哪个设计自由度、保留哪个有效子结构，以及怎样分配剩余生成预算。学习或搜索的是**结构分支选择与冲突迁移条件**，不是要求 LLM 再画三张图。

最小机制：先生成可选择的关系结构，再编译具体几何；对可核验失败提取局部冲突及适用范围；据已覆盖模式选择下一分支。只有已证实冲突才能禁用相关组合；求解超时只能记未知。用户硬要求不参与自动放宽。

**先例压力很高。** [TileGPT](https://arxiv.org/html/2405.09997v1)已有 QD 数据、语言生成和约束细化；[PSDL](https://arxiv.org/html/2510.16147v1)已有保留程序结构的参数搜索；AIDL 已开放分层自由度；传统约束求解已有冲突回溯。因此“质量＋多样性＋约束”不是新意。必须证明候选的结构冲突定位和预算决策，在相同搜索空间下有额外作用；否则只保留为有价值的 Demo 功能。

### D1 ↔ E1

| 待证假设 | 最小实验 | 必须比较 | 否定条件 |
|---|---|---|---|
| H1a：普通采样大量重复同类有效解 | 小型正交布局；预定义连通/布局模式；统计同预算采样覆盖 | 温度采样、best-of-N、去重重采样 | 并无明显模式重复，或任务实际只有一种有效模式 |
| H1b：冲突驱动结构调整比数值修补有效 | 数值可修、必须换结构、形式不可行三类任务；固定约束与候选动作 | PSDL式参数搜索、枚举结构＋求解、同变量CP-SAT/SMT、原始错误反馈 | 标准求解器同预算占优；提升只因多试候选 |
| H1c：覆盖决策提高单位预算内有效模式数 | 固定模型/求解器，覆盖目标×冲突机制的2×2消融；覆盖多个预算点 | 同一表示上的MAP-Elites/QD、uniform分支、diverse beam、候选策略 | 只靠放宽要求、错误合并或指标定制增加“多样性” |

小型离散任务可枚举可行模式，计算真实覆盖率；较大任务只报告预定义描述空间覆盖和独特有效数，**不称覆盖了完整解空间**。预算耗尽无结果计失败。不要仅在成功样本上报告需求匹配。

建议先用24–40个开发请求诊断模式与失败类型，冻结后另建按建筑/结构组合隔离的测试集；重复运行并给建筑组级置信区间。数目是先导建议，不是论文统计功效保证。用户偏好研究放在策略有效之后；并排候选允许“都不接受”和补充要求，避免强迫选择。

**落地与难度：中高。**先导诊断1–2人周，受限原型4–6人周，包含可靠模式定义、冲突来源和公平评价的方法研究约10–18人周。若只做多候选展示会更快，但不能据此承诺方法贡献。首版不要求训练基础模型，不扩展到任意建筑与曲面。

## 4. 未来方向 D2：学习多步编辑的相互作用

**研究问题：**在需要保持已有模型的连续修改中，Agent 能否从少量执行中学会哪些操作会互相破坏、哪些能够交换或复用，并减少不必要的试错？

例如，同墙两个开口可以引用不同 ID，但几何范围仍会冲突；先修改墙再修改窗，与相反顺序可能有不同结果。单次操作合法不保证操作组合有效。这个问题使 Generation 和 Repair 通过“模型状态如何变化”连接起来，而不是简单串接两个入口。

**候选创新：**学习具有适用条件和不确定性的关系—几何交互效果，并选择少量有区分力的执行来修正该模型；将可靠的效果用于规划与等价顺序合并。未知交互保留并交给真实执行，不因预测自信而跳过最终检查。核心增量必须来自跨操作的效果迁移与主动辨别，不能只是单动作前提/效果表。

**知识与 token 在这里的角色：**知识库从整段成功轨迹转为有条件的操作知识：前提、影响对象、增加/删除的关系、几何影响范围、有效/无效证据和适用版本。Agent 每次取得与当前决策有关的合同和必要关系。测量这种表示是否保留决策需要的信息，而不是以“更短”定义成功。若常规结构切片同样有效，压缩不单独宣称创新。

**先例压力：**WorldCoder 已学程序化转移模型，Contract2Tool 已学前提/效果，TraceCAD 已有局部回溯与条件技能，传统规划有部分序消减。需要对比这些思想，而非只对比无记忆 ReAct。审计和回滚提供干净的探测轨迹，不自动使世界模型新颖。

### D2 ↔ E2

| 待证假设 | 最小实验 | 必须比较 | 否定条件 |
|---|---|---|---|
| H2a：单动作效果不能解释组合失败 | 受支持3–4类操作，构造2/4/6步任务；区分独立、共享几何、顺序依赖 | 单步规则、加性效果模型、人工精确效果诊断上界 | 失败全是已有确定性bug，或简单规则已解决 |
| H2b：主动辨别交互比随机探测有效 | 相同开发执行预算，留出建筑与操作组合；自动抽取效果 | 随机探测、单动作不确定性采样、候选交互探测 | 收益来自人工逐例标注、测试泄漏或更多执行 |
| H2c：交互模型减少规划成本而不丢有效计划 | 同搜索器/动作集，去交互、去顺序合并、去主动探测消融 | WorldCoder式转移模型、TraceCAD式局部搜索、真实执行beam/MCTS | 精确执行已经足够便宜；预测错误剪掉有效计划 |
| H2d：关系合同压缩保留决策能力 | 相同模型与知识内容，比较全文、去重、依赖切片、效果合同；跨文案/ID/API表面变化 | 普通RAG、结构切片；若训练知识选择器，再加PURPLE/DearICL式集合模型 | token下降却任务/保全退化；无法跨新组合迁移 |

主指标：最终联合成功、非目标状态保持、错误剪枝、操作交互判断误差、全部执行/LLM成本。必须同时报告首次知识学习成本与后续累计成本、冷启动与复用结果；不能只挑已学会的任务计算节约。训练数据与评测按建筑家族隔离，另做操作组合留出。

**落地与难度：高。**诊断1–2人周，短计划原型3–5人周，可靠交互学习与组合泛化研究8–14人周。不以“先训一个大世界模型”起步；冻结基础模型，用符号记录或小型效果预测器。已有不支持的移动/删除不能假定已实现，必须单列能力扩展成本。

## 5. 统一评价：多解不等于没有标准

评价标准从“与一个 IFC 一模一样”转为“满足独立标注的要求，并符合声明的保全条件”。合法替代设计应当通过；外观相同但宿主错误应当失败。私有参考模型可用于构造或最终评分，不能泄漏到被测 Agent、检索库或 repair 提示中。

| 维度 | 应报告 | 避免混淆 |
|---|---|---|
| 正确性 | 编译/重开、几何、关系、原始要求分别报告，并给全部同时满足的比例 | 单项平均或可视化漂亮不是联合成功 |
| 多解性 | 有效独特方案数、预定义模式覆盖、重复率；同一预算下比较 | pass@k不是多样性；无效模型之间的差异不计收益 |
| 效率 | 输入/输出/可获得的推理token，失败、重试、知识构建、检索、检查、求解和渲染成本 | 分开实测、预留和缺失usage；不只报最终成功一轮 |
| 保全与恢复 | 非目标对象/关系保持、源不变、恢复后实体与世界坐标几何、历史与产物绑定 | 文件hash相同与语义相同分开；日志不是正确性证明 |
| 泛化 | 未见建筑、未见关系组合、不同长度任务和至少一个独立模型复核 | 同一建筑变体不算独立建筑 |
| 用户价值 | 理解差异、选择耗时、接受/拒绝/不确定、是否需返工 | 模拟用户不代替真人接受度；强制选一会虚增满意度 |

**Self-verification 要单独校验。**先固定已有输出集，用独立正确/错误标签比较静态Gate、Self-Verification式生成检查、有效变异检查；同时测错误放行与合法替代解误拒。再接入闭环，否则“越修越好”可能只是让模型迎合有漏洞的评分器。V1检查学习保留为评价支线，不再平行列成第三主方向。

外部 IFC 可提供真实关系结构和编辑素材，但不自动形成文本—多解成对真值。沿用[external数据说明](../../../dataset/external/GENERATION_DATASETS.md)，按来源/建筑家族分组；合成受限任务与真实模型任务分开报告。不可行标签需来自已知形式系统证明，超时或Agent失败只记未知。

所有真实LLM实验应先满足[现有阶段准入协议](../../validation/agent-capability-evaluation.md)。本稿没有授权或执行新的Provider调用，没有把代码阅读当测试通过。

## 6. 下一步怎么取舍

**当前 Demo 主线：**自然语言要求进入可检查、可修改、可追溯的 IFC 工作流。补齐真实的版本恢复与候选对比后，展示用户选择一个方案、提出局部修改、查看影响、恢复先前有效状态。展示范围必须以实际实现和通过的路径为准。WWW / AI Demo 是目标定位，具体届次的征稿范围与要求提交前另核，不能从本稿推定录用机会。

**推荐顺序：**先做E0的独立需求与成本基线，以及D1/D2各一个小诊断；随后只选证据更强的一条深入。偏近期Demo，优先D1，直观展示设计选择；偏后续AI方法，D2更直接检验组合推理，但技术风险更大。不要同时实现完整D1、D2和新的训练系统。

| 层次 | 建议写法 |
|---|---|
| 现有可描述系统贡献 | 受控结构化生成、可追溯局部修改、确定性产物检查；范围和限制明确 |
| 当前尚待实验证明 | 相同预算下更可靠、更少意外修改、更低总成本 |
| D1可能贡献 | 在不放宽要求的条件下，冲突与覆盖驱动的决策提高有效设计模式覆盖 |
| D2可能贡献 | 可迁移的关系—几何交互模型减少多步规划试错且不损害保全 |
| 不再包装为新方法 | Agent loop、普通RAG、保存技能、JSON约束、写日志、回滚、多次采样 |

这两条仍是可否定的研究假设。只有强基线、消融和未见任务支持后，才能改写成论文贡献句；若未成立，完整可靠的系统与可复现评测仍可作为Demo成果，但不应虚构AI创新。
