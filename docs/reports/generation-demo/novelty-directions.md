## 1. Motivation：真正值得研究的问题

### 1.1 不把 IFC 和 Coding 人为对立

通用 Coding Agent 可以写 IfcOpenShell 脚本，也可以输出 BIM JSON。类型、依赖、测试、程序修复和需求歧义在普通编程中同样存在，因此不能用“IFC 更复杂”证明方法创新。

IFC 提供了一个有价值的研究场景：同一次操作会影响**几何、对象关系和用户要求**，这些影响可以在最终产物上分别检查；合法答案还可能不唯一。例如，窗看起来位置正确，并不代表宿主和洞口关系正确；重新生成一个合法模型，也不代表保留了用户要求不变的楼层。背景见 [已有研究草案](research-proposal.md#1-motivation) 和 [IFC 评价证据](literature-evidence/ifc-evaluation.md)。

这使我们可以研究一个比“自然语言生成 IFC”更具体的问题：

> **固定基础模型，Agent 怎样把一次任务中得到的经验，转化为在新场景中仍然适用、能够组合的建模能力？当经验不适用时，它怎样发现并修正？**

这是一条候选总问题，不是当前系统已实现的能力。另一条独立路线是：**面对多种空间解释，怎样用少量有用的交互确定用户真正要的结果？** 两条路线不必强行合成一篇论文。

### 1.2 为什么只改善检索、压缩 token 不够

调研已经发现：经验规则库、自动建工具、前置条件筛选、关系检索、设计说明联合覆盖都有明确先例。典型来源是 [ACE / CRAFT / ExpeL](literature-evidence/frontier-knowledge.md)、[SkillWeaver / PolySkill / Contract2Tool](literature-evidence/frontier-skills.md) 和 [DST](literature-evidence/frontier-knowledge.md#fk09)。

更有研究价值的失败假设是：

| 可能的问题 | 一个 IFC 例子 | 为什么更多上下文未必解决 |
|---|---|---|
| 成功经验的适用范围不明 | 轴对齐墙上可用的放窗脚本，在旋转墙上失败 | 检索到了经验，但错误地认为它通用 |
| 单个操作正确，组合后的关系错误 | 创建墙、创建窗都成功，组合后宿主或坐标绑定错误 | 需要处理操作之间的前提和影响 |
| 局部设计可行，整体组合不可行 | 房间分别满足面积要求，走廊接入后出现冲突 | 固定分块或局部重试可能无效 |
| 任务具有多种合理解释 | “右侧”可能指图纸方向、立面方向或观察者方向 | 文档和模型多数意见不能代替用户意图 |

这些是应先验证是否普遍存在的现象，不是对现有系统失败分布的统计结论。本轮没有运行新的能力实验。

## 2. Novelty：八个候选，而不是八个贡献

难度是**一名熟悉项目的研究开发者做出可比较原型的估计人周**，不含完整投稿实验、论文和界面制作；数据或接口缺口可能使估计翻倍。“固定模型”指不更新基础模型/adapter 权重，仍允许学习外部规则或程序，并必须计入成本。

| ID | 候选研究问题 | 可能的方法增量 | 优先级 / 原型投入 | 对应实验 |
|---|---|---|---|---|
| N01 | 失败后应改技能、限制适用范围，还是拆成多个技能？ | 反例驱动的联合选择，兼顾新任务与旧任务 | **先做诊断**；2–4 周 | [E01](novelty-experiments.md#e01) |
| N02 | 怎样修订适合组合的新宏程序？ | 以组合表现修订程序参数化与边界；效果分组本身已有 | 下调为高风险扩展；3–6 周 | [E02](novelty-experiments.md#e02) |
| N03 | 修复经验怎样在生成前阻止同类错误？ | 学习带适用条件的冲突规则，并检验跨任务迁移 | **优先作 N01/N02 迁移验证**；2–4 周 | [E03](novelty-experiments.md#e03) |
| N04 | 局部失败时，怎样选择需要重新开放的跨层依赖？ | 按冲突和干预效果选择空间接口；进一步才考虑重分区 | 高风险方法探索；3–6 周，重分区更久 | [E04](novelty-experiments.md#e04) |

| N07 | 能否借助等价表示发现并修正参考系绑定错误？ | 有针对性地搜索表示/绑定，以独立几何检查筛选 | 低成本诊断；1–2 周，完整方法 3–5 周 | [E07](novelty-experiments.md#e07) |
| N08 | 知识片段之间的真实协同和干扰，能否用于选择上下文？ | 从执行干预学习组合价值，超越文本覆盖 | 降为备选；诊断 1 周，方法 3–5 周 | [E08](novelty-experiments.md#e08) |

<a id="n01"></a>
### N01 — 联合修订技能实现与适用范围

**直观例子。** 一个“在墙上等距放窗”的技能只在轴对齐墙上成功。遇到旋转墙失败后，有三种不同处理：改成正确的局部坐标实现；保留原实现但限制适用范围；拆成不同宿主/几何条件的技能。仅针对失败样例补丁，可能破坏原来成功的场景。

**候选机制。** 将技能表示为 `(适用条件 g，程序 p，可检查效果 e)`。针对反例产生“改 p / 改 g / 拆分”候选，在保留的正例、边界例和新反例上比较。选择目标同时考虑：覆盖了多少任务、误放行多少不适用任务、旧任务退步多少，以及技能库复杂度。若只通过不断收窄 g 避免失败，覆盖率会暴露这个退化解。

**已有工作与可能增量。** LearnAct 已能改代码/描述，SkillWeaver 已有测试和前提，Contract2Tool 已学工具合同；主动行动模型学习和 CEGIS 也使用反例。因而“给工具加合同再测试”不新。待研究的区别是：**在一组迁移任务上，怎样选择修订哪一层抽象，而不是默认只修程序或只修前提。** 是否存在足够区别，仍需与这些机制的组合做强对照。[技能证据](literature-evidence/frontier-skills.md)

补核的 [CoLLAs 2023 关系状态抽象](literature-evidence/frontier-skills.md#sk15)也联合更新谓词、行动算子和采样器。因此泛称“联合学习技能和条件”同样不足；剩余候选是面对自生成程序时，在实现修补、适用范围和库拆分之间作出更有效的竞争选择。

**方法价值的条件。** 同模型、同原语、同学习预算下，未见关系条件的成功率提高，同时降低错误复用和旧任务退步。若普通 LearnAct 式更新加同预算随机测试就达到同样效果，放弃独立创新主张。

**当前落点。** 可先在离线实验支路维护少量外部技能，不改编译器表达能力。需要新增条件表示、反例搜索和候选选择；当前项目流程中已有编译/检查，不等于已经具有这个学习机制。

<a id="n02"></a>
### N02 — 用组合表现修订新宏程序

**直观例子。** “创建墙”“开洞”“放窗”分别可执行，不代表任意顺序与对象绑定都正确。技能的可复用部分可能是“让一个填充物通过洞口连接到某个宿主”，而不是某几行代码经常同时出现。

**候选机制。** 从开发轨迹提出宏程序、参数化和边界候选，用留出的开发组合暴露干扰，再把失败反馈到宏程序本身的角色接口、参数化或拆合中。关系效果和前提用于解释组合失败，不能只给已有动作重新聚类或排序。学习对象是外部程序与关系模板，基础模型保持固定。

**已有工作与可能增量。** DreamCoder/LILO 研究库抽象，PolySkill 分离抽象目标与实现，Relational Decomposition 已使用关系事实综合程序。补核的 [SK15](literature-evidence/frontier-skills.md#sk15)更直接覆盖效果分组、对象角色及前提学习。因此原先“按关系效果形成可组合技能”的宽泛假设已下调；只保留**利用组合表现修订新宏程序本身**的探索。手工设计完美关系宏，或仅实现已有算子学习，均不足以支持新方法。[关系分解证据](literature-evidence/frontier-reasoning.md#fr05)

**价值条件。** 开发时见过各个原语，测试时没有见过它们的目标组合；新宏修订需要优于程序压缩、目标多态、SK15 式固定动作算子学习，以及使用相同关系表示的强规划器。若主要收益来自人工关系编码，应将贡献限于表示/系统设计。若最后与 N01 只能用同一修订机制解释，就合并而不另算创新。

**难点。** IFC 缺失关系不一定是真负例，效果抽取也可能不完整。不要从一条成功轨迹推导所有前提，更不要声称宏技能扩大了原语语言的数学表达能力；要测的是固定预算内能完成的任务范围。

<a id="n03"></a>
### N03 — 将修复反例转化为有条件的生成约束

**直观例子。** 某次修复发现：复制窗时复用了旧宿主绑定，导致新楼层的窗仍连接旧墙。经验不应只存“下次注意宿主”，也不能禁止所有窗复制；需要描述哪些角色绑定组合会产生冲突，以及什么时候这个结论成立。

**候选机制。** 从公开可观察的失败/修复轨迹提出小型关系冲突规则，用开发阶段的对照执行查证条件，将实例 ID 替换为有约束的角色；生成时用规则筛查候选组合。学习规则不能擅自升级为标准真理：只有确定语义或充分验证支持的约束才能硬剪枝，其余作为可撤销的风险提示/排序信号。

**已有工作与可能增量。** ExpeL、ACE、LLM-Wiki 已有成败经验和错误本，WorldCoder 已有跨任务模型重用，冲突核修复也已有研究。可能的增量仅在**条件化、可检验的冲突抽象如何迁移，并减少误剪掉合法方案**。记录错误或把 Repair 接到 Generation 后面不是新方法。[知识证据](literature-evidence/frontier-knowledge.md)、[WorldCoder 等](literature-evidence/frontier-spatial.md)、[冲突核证据](literature-evidence/frontier-reasoning.md#fr02)

**价值条件。** 比相同修复轨迹上的自然语言经验、成功案例检索和普通反例修复更早避免未见场景错误，且不过度拒绝合法生成。按建筑、错误机制及模板隔离；不能将评测 Gold 或损坏配方带回生成器。

**与 N01 的关系。** N01 学“技能应怎样改”，N03 学“哪些组合应避免”。二者先各自做实验；若实际上只能作为同一个条件学习器解释，就合成一个贡献，不拆成两个创新。

<a id="n04"></a>
### N04 — 按冲突证据选择跨层空间调整

**直观例子。** 房间内部都满足条件，但共享走廊无法同时连接。真正需要调整的是一个门的位置、一段墙的边界，还是房间之间的分块方式？重做整栋楼成本大，固定只修局部又可能一直失败。

**候选机制。** 保留局部变量与跨块依赖；根据实际冲突提出有限的接口干预，例如开放某个门的绑定或某个边界自由度。用开发期/当前公开探测估计干预能消除什么冲突、会影响哪些已满足条件，按收益和代价选择。更大的研究版本是失败后重新选择分块，但不在最小原型中默认实现。

**已有工作与可能增量。** AIDL 已有层级约束、子树求解及失败后的两阶段逐层释放；CIT-CAD 已定位意图节点并保留满足的约束。因此“分层、局部修复、释放自由度”都不新。候选只剩**针对冲突选择哪组接口干预，比固定逐层释放更有效的算法**。普通冲突图启发式或最小击中集也不是自动的新方法。[空间证据](literature-evidence/frontier-spatial.md)

**价值条件。** 在同一约束表达和求解器下，超过全局求解、AIDL 式逐层释放、随机同量变量开放及静态冲突启发式。如果只有增加求解次数才有效，或 IFC 任务规模不足以体现分解收益，应停止投入。

<a id="n05"></a>
### N05 — 针对未知决策选择查证动作

**直观例子。** 当前接口是否自动产生 void/fill 关系，查标准未必能回答；具体外墙是哪面，要查实例；窗宽由用户决定，工具探测不能回答。系统应先判断哪些执行解释尚未被区分。

**候选机制。** 保存少量会产生不同执行结果的假设，为资料读取、实例查询、隔离小模型探测、用户澄清估计“能区分哪些假设/代价多少”，选择下一步并更新。第一版可用分歧覆盖，不假称已知真实信息增益概率；若假设池遗漏正确解释，需要保留回退机制。

**已有工作与可能增量。** CF-RAG 有反事实检索，CMTF 有前置条件工具筛选，主动行动模型学习有区分性查询，MLSys 工作区分不确定性来源。仅增加动作分类不够。需证明**同一控制规则能处理不同来源缺口，并在执行结果上优于通用探测/检索**。[知识证据](literature-evidence/frontier-knowledge.md)、[技能证据](literature-evidence/frontier-skills.md)、[不确定性证据](literature-evidence/frontier-reasoning.md#fr04)

**当前判断。** 有实用价值，但直接先例较密，暂不优先于 N01。若主要收益是补全接口文档或写清禁止猜测规则，应归于工程修正。

<a id="n06"></a>
### N06 — 用可执行的空间对照进行澄清

**直观例子。** 用户说“把入口移到右侧”，系统生成两个最小空间对照，突出参照方向和受影响关系，让用户选择。对照不必生成整栋楼；也不能向用户展示两个都违背已知约束的方案。

**候选机制。** 从候选解释生成局部可执行见证，预测一次澄清会排除哪些后续不同结果，以及错误理解将造成多少修改，再选择最有价值的问题。方法焦点是**对照/问题的选择目标**，包括允许用户回答“都不是”，而不只是给聊天窗口加两张图。

**已有工作与可能增量。** ClarifyGPT/SpecFix 已比较执行行为来修订歧义需求；形式规划已支持约束协商；COMFORT 已系统研究参考系歧义。需要检验结果差异/修改代价驱动的问题选择是否优于文本熵、固定提问和相同图形界面的普通 Agent。[规格与空间证据](literature-evidence/frontier-reasoning.md)

**当前判断。** 最适合保留为独立 Demo 路线。它具有清楚的交互故事，但要成为 AI 方法需要选择机制及实验；要主张交互价值需要真实用户研究，脚本用户只能诊断算法。

<a id="n07"></a>
### N07 — 用等价表示搜索参考系绑定

**直观例子。** 同一任务在局部坐标表示下能做对，在全局坐标表示下失败。问题可能不在缺少 IFC 文档，而在把墙、楼层、建筑的坐标层级绑定错了。

**候选机制。** 将明确语义下的局部/全局坐标转换视为等价表示，先用少量检查定位产生分歧的绑定，再有针对性地重新生成该部分；用独立关系/几何检查选候选。目标是减少盲目重试，而不是多数投票决定真实方向。

**已有工作与可能增量。** COMFORT 有参考系与一致性评价，LLMorph 有变形测试，TTL-SR 有几何自洽驱动适配。测试时表示搜索本身也有大量近邻，选定本方向后需继续定向查重。剩余假设是**可定位到层级绑定的表示干预，能否比确定性坐标标准化与同预算采样更有效**。[空间一致性证据](literature-evidence/frontier-reasoning.md#fr06)

**当前判断。** 先做低成本诊断。若一个正确的确定性坐标转换就解决问题，应直接采用这个工程修正，不继续包装方法。镜像、旋转并非对所有建筑要求保持语义，例如北向或门开启方向；不满足前提的变换不能使用。

<a id="n08"></a>
### N08 — 学习知识组合的执行价值

**直观例子。** 局部坐标说明和洞口关系说明分别加入都无效，联合加入才成功；另一组相似示例可能反而互相干扰。文本相关性和覆盖度未必描述这种作用。

**候选机制。** 在开发任务上控制知识片段的有/无，测量单条及组合对可执行任务的作用，再学习或设计只依赖运行时可用信号的组合选择器。先确认交互现象，后决定是否值得训练轻量选择器；不默认微调基础模型。

**已有工作与可能增量。** SePer 已区分相关性与模型效用，HippoRAG 2 有关系检索，DST 已以多粒度设计说明覆盖选择互补示例。候选必须证明**真实执行协同/干扰不能被文本覆盖、图闭包或普通遍历解释**；否则旧“编译器感知上下文”主线没有必要继续扩展。[知识证据](literature-evidence/frontier-knowledge.md#fk05)

**当前判断。** 保留为备选，token 压缩是成本指标，不是它的新意。少量正向案例或把关键知识故意从基线拿掉不能证明该方向。

## 3. Evaluation and Experiments：先找机制，再决定论文

完整的一一对应在 [实验设计](novelty-experiments.md)。建议按以下顺序推进，**不同时实现八个方向**：

1. **先验证 N01 的必要性，N03 用作迁移检查。** 用现有可观察轨迹检查：是否存在可重复的错误迁移；失败是否能够通过改程序、改条件或条件化冲突规则区分。没有这种现象，就不建复杂学习器。Repair→Generation 本身已有先例，不另算一个方法创新。
2. **保留 N06 做 Demo 的竞争路线。** 先判断真实请求中有多少结果相关歧义，再比较问题选择；没有歧义的任务不强加交互。
3. **N02/N04 在前两步之后考虑。** 它们的方法野心更大，也更依赖新的关系表示和实验集。N05/N07/N08 先做小诊断，只有机制证据明显时提升优先级。更大改动的备选是 [在变化参数域内合成构造规则](literature-evidence/frontier-spatial.md#sp-h2)：允许尺寸变化触发对象数量/连接拓扑切换，该卡同时给出与普通参数化 Agent、常规 CEGIS 的对应实验；它不是本轮默认实施内容。

核心判据是固定模型、公开工具、编译能力和预算后，能否在**未见任务族**上取得增益；同时比较强 Coding Agent、最接近方法及只移除候选决策机制的消融。所有失败进入分母，建库和试错成本一起报告。一次失败变成功或单个 Demo 不证明能力扩大。

## 4. 怎样讲一篇论文，而不是拼三项工程功能

### 如果 N01 成立

可以围绕一个方法写三层贡献，先用条件式表述：

1. **问题/发现：** 建模经验的错误适用会造成跨场景失败；用受控任务测量它，而不是只给个案。
2. **方法：** 根据反例联合选择修改实现、收窄条件或拆分技能，提高可复用任务覆盖并控制负迁移。
3. **系统与验证：** 在自然语言到 IFC 的交互系统中，展示新场景使用、失败辨别和经验修订，用同预算未见任务实验验证。

这不是三个彼此独立的“首创”。目前只能写“我们拟研究/我们提出候选机制”，不能写“首次”“保证泛化”或“显著提升”。

### 如果 N03 成立

Generation 和 Repair 可以通过**共享的条件化关系经验**连接：Repair 提供可观察反例，学习器提出并查证规则，Generation 用它减少后续同类错误。对照必须证明它比生成后再修、普通错误本以及同样增加重试更有效。把两个产品入口放进同一个网页，只支持系统集成贡献。

### 如果 N06 更有价值

故事是“让用户通过结果差异表达空间意图”。Demo 可以清楚呈现输入、两种解释、用户选择和实际模型变化；算法贡献则依赖问题选择是否减少交互/返工。界面易用和方法新颖分别评价。

### 如果所有候选都不成立

应诚实保留“可靠的领域系统与实证评测”定位，缩小方法主张，或转向更大改动，例如关系技能学习、开放模型适配。**系统扎实值得展示；方法新意需要明确机制和证据，两者不能互相替代。** 本轮调研也没有证明“我们没有任何可能创新”，它排除了宽泛说法，并把值得投入的假设及失败条件写清楚。

### 与 WWW Demo 目标的实际关系

截至 2026-09-15，[WWW 2027 Demo 官方征稿](https://www2027.thewebconf.org/demos/)要求已经实现并测试的系统、可现场交互的演示，并与 Web 社区主题相关；篇幅上限 4 页含参考文献，当前截止日期为 **2026-11-16（AoE）**。该要求不等同于必须提出三个新算法，也不意味着工程完整就自动达到原创性要求。

我们的选题判断是：Web 上的非专家空间创作、领域知识/工具的可交互使用，可以作为关联切入点，但仅把 IFC 生成器部署成网页不足以说明研究为何属于 Web。先验证一个清楚的机制，再展示它怎样帮助用户完成任务；若最后主要贡献属于程序综合/机器人式技能学习，应同时保留更合适的 AI 系统演示或方法论文路线，不为了 WWW 把研究问题写歪。正式投稿前重新核对当届要求。

## 5. 当前实现与新增研究的边界

已有流程、编译/检查、版本化输入以及可追溯执行记录，是开展上述实验的基础，不能直接作为学习能力。当前依据见 [仓库 Claim 审核](../Text2IFC-Generation-Claim-Novelty-Audit-2026-09-14.md) 与 [项目入口](../../README.md)。本轮没有重新运行实现验收。

| 候选 | 可以利用的当前入口 | 真正需要新增的研究内容 |
|---|---|---|
| N01 / N03 | [ChangeSet 轮次入口](../../../src/text2ifc_agent/scoped_loop.py)、[独立 Repair 模块](../../../src/text2ifc_ifc_repair/workflow.py) | 合规轨迹中的条件/角色提案、反例选择、跨场景候选比较与外部技能/规则学习；现有修复循环不等于这些能力 |
| N02 / N04 | [生成分包](../../../src/text2ifc_agent/generation_packages.py)、[分包检查](../../../src/text2ifc_agent/package_gates.py) | 可学习的关系效果、空间变量/接口表达及组合/干预算法；分包所有权不等于通用约束求解器 |
| N05 / N08 | [Brief 上下文选择](../../../src/text2ifc_agent/context_selection.py)、[ChangeSet 上下文](../../../src/text2ifc_agent/changeset_context.py) | 前者当前按类别关键词与固定依赖选证据，后者按引用/语义依赖取上下文；需新增假设辨别或执行效用学习，不能仅改名称 |
| N06 / N07 | [Expected Facts](../../../src/text2ifc_agent/expected_facts.py) 及原生成/检查链 | 多解释局部见证、问题选择，或合法表示变换与绑定定位；不能把 Brief 派生事实同时充作最终意图真值 |

上表用于定位原型接口。本轮对选择器做了静态读取，对其余入口结合前轮审核定位；没有重跑行为测试，不表示这些候选已可直接执行。阶段测试仍应按各自修改范围确定。

所有候选默认在当前支持的几何/接口范围内比较。若某操作原本无法由当前 IR/编译器表达，就要单列能力扩展工程，再在相同扩展接口上比较方法，不能把新增原语的收益归因于知识利用。真正跨普通 Coding 的主张还需至少另一个不同环境的迁移验证；IFC 单域结果不足以直接推出通用 Agent 改进。
