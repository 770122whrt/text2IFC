## 1. 共同设置：避免把工具、信息或预算优势当成方法

### 1.1 两层 Coding Agent 对照

| 层次 | 对照 | 用途 |
|---|---|---|
| 完整任务 | 同模型 Coding Agent，用 Python/IfcOpenShell 直接生成或修改 IFC，允许查公开资料、执行、调试 | 回答专用系统相对通用 Coding 的实际价值；不能故意限制基线只做一次生成 |
| 方法隔离 | 同模型 Agent 输出与候选相同版本 BIM JSON，使用同一编译器、公开检查器和工具 | 排除编译器替候选完成更多工作；方法主张主要依据这一层 |
| 最近机制 | 每个 E 的专门强基线 | 回答候选是否超出已有方法；不只比较无 RAG 或静态提示 |

所有组得到同样公开信息源和可观察状态，允许相同工具种类。为原论文做 IFC 适配时，记录保留/改变的机制，标明“某方法式适配”，不把适配版伪装成原作者复现。先把基线接到完整任务路径，确认正常例可运行。

固定模型版本、采样设置、编译器/原子操作、输入信息和评价规则。若候选需要新增一个底层几何操作，先给所有适用基线同一操作；把新增接口工程与研究策略分开报告。

### 1.2 数据与划分

现有 [external 说明](../../../dataset/external/GENERATION_DATASETS.md) 可以提供模型来源、技术状态和目录；它**不是现成的自然语言—IFC 成对能力基准**。本设计没有新增数据下载，也没有修改原始模型。

- 按基础建筑/设计模板/来源家族分组，再划分开发与测试。同楼专业版本、切分文件、旋转副本和换 GUID 的副本不能算独立建筑。
- 每个方向保留正常例、困难例、合法边界例和不适用例，不只构造对候选有利的任务。所有初始 IFC 的有效性和允许操作范围先独立确认。
- 分开报告参数变化、未见关系组合、未见建筑、未见错误机制；不能混成一个泛化数字。未见组合尽量与已见组合匹配对象数和操作长度。
- 生成任务允许多解。评价请求中的约束及允许自由度，不要求复制唯一参考模型；明确坐标/尺寸的任务禁止为了评分好看而对 GT 任意平移、缩放或旋转。
- 初始技能和经验只能来自开发资料。先学习再冻结的盲测，与在线边做边学的任务流分开；后者使用先预测后更新、全组相同更新机会和多个流顺序，不能再称其后续题完全未适配。

### 1.3 独立评价与成本

**最终任务成功**：在可完成且需求充分的任务上，要求产物可重开，适用的 schema/几何检查通过，公开请求的对象、数值和关系要求满足；编辑任务还要求非目标内容保全。各项分别报告，并以全部满足的任务比例为主指标。未输出、超时、异常、错误拒绝全部进入分母。

澄清任务单列：给出合规回答后是否完成用户实际目标；不允许澄清时另报识别歧义的正确率。确实不可行任务单列正确诊断与错误承诺，不混入普通生成成功率来美化数字。有限测试不能证明永不失败。

运行时 Agent 可以使用公开编译、实例查询和已声明检查；最终评价由独立人工规格或独立测量程序定义，不能只检查候选自己写出的 Brief、合同或约束。特别检查**漏约束但形式求解成功**的情况。隐藏 Gold、损坏配方、私有对象映射、损坏前完整模型不得进入修复/生成 Agent 或经经验库间接泄漏。

**成本**包括建库、候选生成、失败、反思、探测、检索、编译及重试。报告输入/输出/可获取的 reasoning token、缓存情况、模型费用、工具耗时和端到端延迟；并行调用的低延迟不等于低总成本。宏调用展开统计底层动作，不能把十个动作包装成一个就声称十倍效率。

以一个预先固定的模型费用/计算预算上限 B 为主要比较条件，并设共同最大轮数和超时；报告实际消耗与成功—成本曲线。后续必要时再加第二预算，避免同时要求所有组实际 token、时间和调用数完全相同而产生不可能的控制。默认各角色用同一模型；若用强模型建库，要作为另一个条件。

建库摊销用 `每任务总成本(n) = 建库成本/n + 后续任务平均成本`，例如展示 n=1、5、20、100；这些只是读图位置，不是预设收益。失败成本不能删掉。

## E01 — 失败后修程序、修条件还是拆技能？

**对应 N01。** 检验联合修订是否必要，以及探测选择是否有效。这是首选的机制诊断。

**任务构造。** 先核查三个当前原语可支持的技能族，例如宿主洞口/填充、带局部坐标的重复构件、容器/楼层绑定。每族准备：原成功场景、程序本应通用但实现有误的场景、确实需换实现的场景，以及容易被过度拒绝的合法边界。改变有效初始模型的单一条件，记录合法性；最终类别由独立执行/专家确认，不由候选自标。

**初版机制。** 给技能有限关系词汇和同一初始程序；LLM 提“改程序、改适用条件、拆分”候选。探测在合法临时模型上区分候选，选择兼顾开发覆盖、误接受、退步与库复杂度的修订。第一版不自动发明整个关系语言。

| 组别 | 唯一关键区别 |
|---|---|
| A 通用学习 Agent | LearnAct 式自由更新代码/使用说明，允许其自行提出条件；不能故意禁止强基线推理 |
| B 测试技能库 | SkillWeaver 式生成测试、调试、前提过滤 |
| C 固定实现学条件 | Contract2Tool 式契约及固定程序的主动行动模型学习 |
| D 完整候选 | 显式比较三种修订，保留正负边界和旧任务约束 |

**关键消融。** 使用相同探测器比较代码单改、条件单改、允许拆分的联合改；使用相同修订器比较主动探测、随机合法扰动、通用 LLM 测试生成。无需第一轮跑完所有组合，先用最接近的 A、联合与单改找现象，随后补足分离证据。

**主要结果。** 组隔离未见任务的联合成功率；另报条件误接受率（真实不适用中被放行）、误拒绝率（真实可用中被拒绝）、未知率、旧成功任务变失败的负迁移率，以及达到某覆盖率的累计学习成本。拒绝后换用其他技能能否最终成功也计入；不能只评价单技能安全。

**支持/否定。** 联合组在 matched budget 下保留更多合法覆盖，且在代码/条件两种错误切片都有收益，才支持联合机制。若它只是更保守、只修开发反例，或与 A/随机测试等效，停止将其写成独立方法。测试通过只表明这些实例上的证据，不称正确性证明。

**最小产出。** 一组有范围歧义的场景、一个有限候选修订器、一张覆盖—误适用—成本图。原型预计 2–4 人周。

## E02 — 组合反馈能否指导新宏程序的有效修订？

**对应 N02。** 将“学出的库”与“调用库的规划器”分开，先固定后者。CoLLAs 2023 已有固定动作的效果分组和角色算子学习；本实验经补核收窄为新宏程序的参数化/边界修订，不能只测已有关系聚类。

**任务构造。** 开发含相同原语和部分组合，测试留出角色共享/先后依赖的组合拓扑；对象数、动作数和几何复杂度匹配。加入“代码相似但效果不同”和“代码不同但效果等价”的诊断对；等价只限声明的条件和有限测例。

**比较组。** 全程序检索；LILO 思路的程序压缩＋命名（允许语义重写，不只字符串去重）；PolySkill 式目标/多实现抽象；[SK15](literature-evidence/frontier-skills.md#sk15) 式固定动作的效果/角色算子学习；候选基于组合表现的新宏修订。所有组共享同一轨迹、候选原语、规划器、关系检查器、库条目及文档容量预算。人工正确宏库只作有标记的诊断上界。SK15 适配保留结构学习机制；若加入原方法的神经谓词/采样器训练，另列成本，不声称完整无训练复现。

**操纵与消融。** 相同初始宏和提案预算下，比较只给固定宏排序、允许改参数化、允许改边界/拆合；其余固定。分别移除关系效果、角色绑定和跨场景验证。为排除“最终只是库里多了一段人工正确代码”，另做交叉调用：把学习到的各库交给同一个 Agent；把同一个库交给有/无候选组合策略的 Agent。候选宏的提出/修订成本也相同。

**主要结果。** 未见组合完整成功、无效角色绑定、共享对象副作用、固定预算下组合深度，以及学库和调用总成本。单项技能都能通过而组合失败的切片单列，避免结果完全由单项 API 错误主导。

**支持/否定。** 新宏修订需要改变未见组合结果，而不只是提示长度；如果固定动作算子学习、目标多态或同预算程序综合同样好，候选增量不成立。手写宏或新原语贡献全部提升也不支持。若多个库拥有不同人工先验，结果只能支持整体系统比较。

**最小产出。** 三至四个操作族的组合面板、自动提出的角色/效果候选、同容量库的比较。预计 3–6 人周；先导用人工候选只可判断现象，不可称自动发现技能。

## E03 — Repair 经验是否能帮助未见 Generation？

**对应 N03。** 更适合作为 N01/N02 的跨流程迁移实验；单纯加入修复经验不预期足以形成独立方法创新。

**任务构造。** 开发使用来源/输入角色已确定的可观察失败和修复轨迹；测试在未见建筑生成新对象/关系。分别留出建筑、错误机制和组合模板。各组能看到完全相同的失败、修复结果及反馈，禁止仅候选获得私有正确模型或损坏映射。

**比较组。** 无经验但相同推理预算；原始修复轨迹 RAG；ExpeL/ACE 式经验；相同轨迹抽取的无条件冲突规则；带条件的候选规则。另比较“生成后修复”和“生成前使用经验”，允许两组花费相同总成本，防止候选额外享受双阶段预算。

**关键消融。** 去适用条件、去角色化、去开发反例查证；以相同数量的随机有效探测替代定向探测。设置相似但合法的反例，测规则是否错误阻止可行方案。探索性相关规则默认软排序；硬剪枝组单列，并记录错误剪枝。

**主要结果。** 第一次候选成功率、预算内最终成功、同类错误重现率、合法方案误拒绝/误剪枝、跨机制负迁移以及建库摊销。运行时编译成功不等于规则正确，最终仍独立检查需求。

**支持/否定。** 条件机制应在未见关系条件上降低错误迁移；如果只在同一种人工损坏模板上有效，不能称跨机制学习。如果普通经验或生成后修复同预算已足够，则最多保留系统经验复用，或者把本项并入 N01 的迁移验证。

**最小产出。** 角色合规的开发轨迹集、一种小型条件规则、未见生成测试。预计 2–4 人周；已有 N01 表示时成本可能降低。

## E04 — 怎样选择需要重新开放的空间接口？

**对应 N04。** 先测试接口选择，动态重分区作为后续单独变量。

**任务构造。** 制作局部可满足、合并后出现跨块冲突的任务；系统改变跨块依赖密度与冲突涉及的层数，尽量保持总变量数和约束数一致。包含单块就失败、全局可行、全局不可行三类，避免算法通过放松真实要求制造成功。

**比较组。** 同求解器全局重解；AIDL 式两阶段逐层释放；随机开放相同数量/相近影响范围的变量；静态冲突图/加权启发式；候选基于冲突和实际干预效果的选择。所有组共享初始分解、约束、求解预算和公开失败信号。增加高质量手工分解仅作上界。

**关键消融。** 只使用冲突而不学习干预效果；只按代价选；移除已满足条件的影响估计。若后续加入重分区，对“原分解＋接口策略”“新分解＋旧策略”做交叉比较，不能混为一个不知来源的提升。

**主要结果。** 完整约束满足、求解调用/时间、重新开放变量及受影响子模型数、非目标变化和不可行任务误承诺。权重和阈值在开发集确定，最终隐含/遗漏要求仍用独立评价发现。

**支持/否定。** 同预算选择更少或更有效干预，同时保持结果要求，才值得继续。如果小规模 IFC 全局求解已足够、静态启发式等效，或只是开放更多变量，则候选不成立。即使优于 AIDL 式流程，也需说明新算法超出已有约束求解启发式的哪里。

**最小产出。** 有独立可行性答案的跨块约束面板、有限接口动作集、同求解器比较。预计 3–6 人周；自动重分区不在这个估计内。

## E05 — 什么情况下该查资料、查实例、探测或澄清？

**对应 N05。** 重点是信息获取的选择，而不是新增工具。

**任务构造。** 为同一目标制作信息完整、标准/API 前提缺失、文档版本冲突、实例绑定不明、用户偏好未给、已授权自由设计六种条件。缺口不能仅由显眼模板词决定；独立标记哪些来源实际可回答，多个来源均可回答时不指定唯一 gold 动作。

**比较组。** 资料充分的强通用 Agent；混合检索 ReAct；CF-RAG 式多查询；固定诊断流程；随机合法探测；候选区分性动作选择。全部允许相同资料、实例查询、隔离探测和澄清接口。补全且正确的文档组用于检查问题是否仅是文档质量。

**关键消融。** 相同假设池下随机动作 vs 候选选择；相同动作预算下无显式假设；去实例查询/去探测仅作机制分析，不当强主基线。追加“正确解释不在初始池中”的样本，测回退和错误自信。

**主要结果。** 最终任务成功、错误规则采用、实例事实编造、不必要询问、必要未知量是否得到辨别、信息获取及执行总成本。脚本化用户只提供固定公开偏好，用于算法诊断。

**支持/否定。** 在多类缺口上优于同预算普通 Agent，并且收益不是更长禁止猜测提示带来；随机探测/固定流程等效或补文档已解决，则不保留独立方法贡献。主动查询已有深厚先例，不因结果好就称首次。

**最小产出。** 成对信息条件、有限执行假设、可区分假设的合法探测。预计 2–4 人周。

<a id="e06"></a>
## E06 — 空间对照能否帮助问出更有用的问题？

**对应 N06。** 这是 Demo 的独立竞争路线；算法选择与界面展示分开评价。

**任务构造。** 收集真实表述风格的多解请求，涉及方向参照、目标对象、相对位置、编辑范围。由独立标注者确认每种解释是否合理，并记录“多个方案均接受”与“都不是”；保留无歧义控制组。不能以唯一参考 IFC 强行定义本来允许自由设计的任务。

**算法比较。** 固定提问清单；通用 Agent 自主澄清；ClarifyGPT/SpecFix 式执行差异；文本分歧/熵驱动问题；候选按空间结果差异和预计返工代价选问题。设相同最多问题数与生成/预览计算预算；最终询问内容不同，用户可提供的信息量也要记录。

**两步分离。** 第一步所有组使用相同空间对照界面，只改变选哪个问题/对照；第二步固定问题策略，比较文字与局部模型对照。这样才知道收益来自算法还是展示。完整模型生成的额外成本纳入预算，不能只算最后一次成功。

**主要结果。** 回答之后最终目标满足率、每完成任务的用户轮次/操作时间、后续修改代价、用户纠正率和不必要澄清。返工代价预先定义为受影响对象/关系及实际编辑时间，不能由候选自己的评分同时充当最终指标。

**用户研究。** 先用脚本偏好排查逻辑；正式交互主张再做任务顺序平衡的被试内研究，按经验层次分层。12–20 人可作为可用性先导范围，不是足够统计功效的承诺；正式数量由主要终点、方差和任务相关性决定，报告同一人的多任务相关性。

**支持/否定。** 在相同界面和预算下，候选问题选择减少交互/返工并保持目标成功，才支持方法。只有图形展示提高满意度，则限于交互贡献；脚本用户结果不得写成真实用户认可。

**最小产出。** 小规模歧义请求面板、两个或多个合法局部见证、可比较的问题选择器。原型约 2–3 人周，真实用户研究另计。

<a id="e07"></a>
## E07 — 等价表示是否能定位层级参考系错误？

**对应 N07。** 第一关是排除确定性坐标转换缺陷。

**任务构造。** 从具有明确语义的空间目标出发，生成合法的局部/全局坐标表示、单位换算及层级深度变化。要求与模型同步变换，区分只是换表示和真正改变物理布局。北向、重力、门开启方向等受影响时，不使用不保持语义的旋转/镜像。副本属于同一统计组。

**比较组。** 当前表示；正确的确定性单位/坐标标准化；固定局部表示；固定全局表示；同预算多次生成＋相同公开验证器；候选先定位分歧绑定再选择表示/局部重生。基础模型权重固定，TTL-SR 仅作相关方法，不将可训练 adapter 的组混为同条件基线。

**关键消融。** 随机选等价表示；只做一致性投票；去层级定位但保留采样次数。公开验证器必须一致；最终尺寸、位置与关系由独立测量判断。

**主要结果。** 原任务联合成功、表示变化下的失败率、实际绑定定位准确性、错误自洽率、额外生成与测量成本。多解布局比较声明的约束和角色，不要求逐顶点一样。

**支持/否定。** 候选需要超过标准化和同预算采样；各表示全都一致但一起错误不算成功。如果标准化已解决问题，应做工程修正并结束该方法探索。若剩余问题是用户视角未定义，转入 E06，而不是继续采样猜意图。

**最小产出。** 合法变换集与独立坐标检查，先用 1–2 人周确认现象；完整选择/定位原型约 3–5 人周。

<a id="e08"></a>
## E08 — 知识组合存在可利用的执行交互吗？

**对应 N08。** 先找现象，再做检索方法，避免直接搭复杂 KB。

**第一步：2×2 受控干预。** 固定任务、模型、编译器、随机种子组，分别提供无 A/B、只有 A、只有 B、A+B 四种知识条件；用多次运行估计成功概率。概率尺度交互为 `Δ = p(A+B) − p(A) − p(B) + p(无)`。正 Δ 表示该尺度上的协同信号，不是普遍因果机制或统计显著性；加法尺度、难度天花板和采样噪声都影响解释。

**控制混淆。** 用等 token 的相关但不解决该依赖的材料替代缺失片段，随机化片段顺序；加入真实无交互、相互干扰以及文档已足够的任务。A/B 可以是坐标约定与绑定次序，但不能向候选独占提供最终解答。单独贡献为零也可能只是测量功效不足。

**第二步：真正的选择实验。** 只有开发期出现稳定现象才继续。比较 BM25/向量重排、DST 式多粒度覆盖、等 token 图切片、LLM-Wiki 式遍历，以及候选执行效用组合策略。候选语料、预算、可查询工具相同；oracle 最佳组合只作开发诊断上界，不能在测试时逐一尝试隐藏答案来选知识。

**学习与消融。** 选择器只能从开发执行信号学习；测试只看任务和公开状态。比较只单条效用、加两两交互、随机同规模组合；未见任务/规则组合单列。若训练轻量模型，要记录其数据和成本，不说系统“完全没有训练”。

**主要结果。** 未见任务联合成功、必要关系遗漏、成功—上下文/总成本曲线，以及开发交互估计能否预测测试收益。检索 recall 或上下文长度单独改善不等于生成能力改善。

**支持/否定。** 若无稳定交互，或 DST/图闭包达到同样收益，就不开发新组合器。真实目标可能非单调、非 submodular，不能借用文本覆盖的近似保证来保证执行正确。

**最小产出。** 若干独立任务族的 A/B 面板和现象报告；诊断约 1 人周，方法原型 3–5 人周。

## 3. 实际启动方案与停止条件

### 第一轮只回答“有没有值得追的现象”

推荐先做 E01；E03 作为同一批经验的迁移诊断，不急着单列新方法。若用户交互是更强痛点，再与 E06 竞争。E02/E04 投入较大，待有机制依据再推进。

一个可调整的起点是 **8–12 个开发任务族、另 12–24 个隔离先导任务族，每条件 2 次运行**，只选一个模型和一个预算。这里任务族是分组单位，变体与重复运行不扩充独立分母。这是发现错误与估计效应的先导规模，不保证显著性。若现有样本无法覆盖某机制，应先补有独立评价的任务，不能靠无限旋转同一个模型凑量。

在开发阶段判断现象不存在、与最近方法无法区分，或预计改动超出价值时，保存负面结果并转向；不为了论文继续增加模块。

### 确定主线后才做正式比较

根据先导方差和建筑/任务族内相关性做样本量估计；40–80 个独立任务族可以作为资源讨论起点，**不能预先称足够**。冻结主要终点、方向、数据组和预算；对同任务族做配对比较，并以建筑/任务族为单位 bootstrap 或合适的分层模型估计不确定性。重复随机种子不能当独立建筑。

预先约定“实用收益”，例如同成本完整成功提高 10 个百分点，或成功率在预定非劣界内时总成本降低 25%。这些是供讨论的门槛，不是预言，也不是显著性标准；严格的 3 个百分点非劣界可能需要远多于上述起始规模。多候选筛选后使用新的确认集，避免挑最好结果再把它当盲测。

对最终胜出的一个机制，再扩到第二模型/预算及必要的另一领域；只在出现失败或未解混淆时追加实验，避免无目的扩大调用矩阵。真实 Provider 运行前按 [能力评价协议](../../validation/agent-capability-evaluation.md)完成对应阶段准入；本轮尚未进入执行阶段。

### 什么可以写进论文

| 得到的证据 | 可支持的表述 | 不支持的表述 |
|---|---|---|
| 一两个反例被修好 | 机制可运行；这些案例得到改善 | 类别或系统能力提升 |
| 隔离测试同预算优于最近方法，消融支持 | 在声明任务范围内，候选机制带来测得的改善 | 通用 Coding/所有 IFC 都更好 |
| 只减少 token 或宏步数 | 声明口径下的效率改善 | 自动获得新的表达能力 |
| 脚本化澄清有效 | 算法诊断结果 | 真实用户体验提升 |
| 方法结果无增益但系统完整 | 系统演示、可复现评测与负面发现 | 继续声称方法新颖且显著有效 |

以上设计不要求先训练新模型，也不承诺只靠工程小改就能得到方法贡献。它让我们能较早判断：现有基础是否足以产生一个值得研究的机制，还是需要更大的关系学习/模型适配投入。
