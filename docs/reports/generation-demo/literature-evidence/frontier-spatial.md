# 空间合成与能力扩展：正文证据与方法假设

更新：2026-09-15。范围：复用当前基础模型，寻找知识库检索之外的空间表示、组合、规划与反馈方法。本文是候选方向审核，不是已完成的创新声明，也不报告本项目的新实验结果。

本轮最重要的发现是：**意图树、约束驱动生成、局部失败反馈、保留已满足约束、分层求解和逐步扩大求解范围，都已有很近的具体先例。** text2IFC 可以使用这些方法，但不能只换成 IFC 就认定有新的方法贡献。仍可研究的差别应落到一个可替换的决策机制，并直接与最接近的方法比较。

下文使用稳定证据编号 `FSP01–FSP09`。每篇均读到方法和实验正文；`FSP05` 的完整阅读对象是 AIDL 的预印本 v1，正式期刊版只核实身份，没有把两个版本混为一谈。数据集总量、评测任务数、生成次数、只在成功样本上计算的指标分别记录。没有找到的分母明确保留为未知。

## 一、先看哪些说法已被覆盖

| 拟采用的说法 | 最近的正文先例 | 对我们的限制 |
|---|---|---|
| 把用户意图转成树，再生成、检查和修复代码 | [FSP01：CIT-CAD](#fsp01) | 单独的意图树或约束反馈闭环不能作新意 |
| 修复时保留已经满足的要求 | [FSP01：CIT-CAD](#fsp01)，已有 [MANSION 记录](structured-generation.md#c06) | 单调接受规则已出现；更严格的检查本身是评测或工程贡献 |
| 分层生成空间部件，冲突时逐步开放子部件 | [FSP05：AIDL](#fsp05) | AIDL 已经先释放平移，再释放几何参数；不能把“扩大范围”当作新机制 |
| 更紧凑的 CAD 表示，并保留修改时需要的关系 | [FSP02：HistCAD](#fsp02)、[FSP03：EPICCAD](#fsp03) | token 更少和显式约束已有直接先例，且不能脱离各自 tokenizer 比数字 |
| 高层先定结构，低层再补参数；多 Agent 分工 | [FSP04：CAD-Factory](#fsp04) | 结构与参数解耦及多 Agent 不是空白；其主要方案含专门训练 |
| 把失败经验写成可迁移的程序知识 | [FSP06：WorldCoder](#fsp06) | 失败驱动的模型修订、跨任务复用本身并不新 |
| 按任务展开关系图，把确定性工作交给求解器 | [FSP07：SayPlan](#fsp07) | 图上下文选择、求解器分工与反馈的组合已存在 |
| 用求解器反馈改善约束生成 | [FSP08：Aligning Constraint Generation](#fsp08) | 需要说明我们改变的是哪种推理决策，而非把反馈接上 LLM |
| 找到需要改的片段，仅补写该片段 | [FSP09：CAD-Editor](#fsp09) | 定位再编辑已有方法和数据；局部修改不自动等于意图保持 |

已有的 [SceneCraft、MANSION、Event-B Agent 等正文记录](structured-generation.md)继续有效，本轮不把它们重复计入新读论文数。

## 二、新增正文证据

<a id="fsp01"></a>
### FSP01 — CIT-CAD：与“意图树＋保留约束的修复”直接重合

- **来源与版本：** Yali Du 等，*CIT-CAD: Constraint Intent Tree-based CAD Code Generation and Verification*，[arXiv 2609.07434v1](https://arxiv.org/html/2609.07434v1)，2026-09-07。预印本。阅读 §III、算法 1、§IV–V / Table II、Appendix VII–XI。
- **实际机制：** 先从文本生成 Constraint Intent Tree，记录实体、层次、布尔角色、局部属性和实体关系；再让模型根据文本与树写 CadQuery。预期约束来自树，实际约束来自代码 AST 与执行后的实体几何。失败关联到节点、关系或子树。修复器仍接收完整代码，接受条件要求原先满足的约束继续满足，并严格减少违反项。因此它有局部诊断，但不能据此说代码补丁必然最小或只改该子树。算法遇到未改善候选可提前停止，不是完备搜索。
- **评测与分母：** 151K 有效图文代码对经过多实体、实体数一致等筛选，留下 **26,783** 条。Appendix IX 说明输入描述还用参考代码补入尺寸、变换、实体数和布尔信息；各方法得到同样的增强文本。GPT-5.4-mini 在 Table II 的可执行率为 87.2%→90.4%，IoU@0.95 为 4.6%→5.5%，约束满足率为 16.7%→37.7%。这些指标衡量的事件不同，不能合称任务成功率。均值 IoU 只统计可执行且具有有效 IoU 的样本。
- **证据边界：** 直接生成基线没有树和修复；候选默认可做两轮修复，部分设置扩展到五轮，因而不是相同尝试成本的机制隔离实验。满足率使用生成和检查共同依赖的 CIT，不能检出 CIT 自己对用户意图的误读。§V-B 关于排除不可用生成文件的文字与 Appendix X 将缺失输出计失败的说法需要澄清，不能自行补出精确有效分母。Table I 列出的关系比 Appendix VIII / XI 明确实现的范围更广；后者主要是四类实体字段及 intersection、contact、coplanarity、shared axes，不能把整张表当作全部已实现能力。
- **对 text2IFC：** 它是必须面对的机制先例，即使其公平性和覆盖范围仍有不足。我们的独立用户要求评测、成本归一化与更难 IFC 场景可以改善证据质量，但单靠这些不能证明新的算法。

### FSP02 — HistCAD：显式约束、紧凑表示与编辑后保持已经一起评测

- **来源与版本：** Xintong Dong 等，*HistCAD: A Constraint-Aware Parametric History-Based CAD Representation, Dataset, and Benchmark with Industrial Complexity*，[arXiv 2602.19171v2](https://arxiv.org/html/2602.19171v2)。本文依据 v2，不把早期不同题名版本的内容自动视为一致。阅读 §3–6、Tables 5–13。
- **实际机制：** 使用较平的图元序列，把环路恢复交给前端；保留 **19 类草图约束**和多种建模特征。跨特征引用用三维点及内核中的邻近边匹配实现。它把一部分确定性恢复工作从模型输出中移走，同时显式保留对参数编辑有作用的约束。
- **数据与实验：** 数据总计 **170,236** 条序列，工业子集 **8,093** 条。Table 5 在共同的 **134,896** 个形状上，用 **Gemma4-31B-it tokenizer**比较：DeepCAD 平均 1,974 token，Text2CAD 590.62，HistCAD 含约束 550.35、不含约束 363.99。这是同集合表示比较，不是各模型全流程成本。
- **编辑评测：** 对输入参数做局部尺寸修改。设总编辑请求为 D，能有效重建的为 R，重建且保持规定约束的为 S，则 ER=R/D，cPCSR=S/R，OES=S/D。Table 6 对原生参考序列的回放，完整约束与只留闭合约束的 OES 分别是 **95.42% 与 64.75%**；这不是模型生成准确率。所读编辑基准正文没有给出足以重建精确 D 的任务总数，不从百分比反推。训练后的 Qwen3-8B LoRA 实验另列：Table 11 完整混合训练的平均 OES 为 73.33%，只用 DeepCAD 训练为 69.67%；同时改变训练数据，不能只归因于某一种推理机制。三子集均值是分别聚合，不能要求聚合 OES 等于聚合 ER 与 cPCSR 的乘积。
- **证据边界与启发：** 形状距离部分使用各方法共同具有有效网格的例子，需要与失败率一起读。主要编辑测试是局部尺寸变化，未充分覆盖长序列修改和复杂特征重排。“有约束，所以编辑后关系更稳定”已经有直接实验；更值得寻找的差别是跨模块耦合或拓扑切换时如何决定新的构造行为。

### FSP03 — EPICCAD：正式论文中的约束与紧凑表示先例

- **来源与版本：** Zehe Yin、Weixin Lin、Xiangbiao Kong，*A multimodal benchmark for editable constraint preserving history based CAD modeling*，[Discover Artificial Intelligence 6, 1022](https://link.springer.com/article/10.1007/s44163-026-01899-5)，2026-09-02，DOI 10.1007/s44163-026-01899-5。阅读 §3.2–3.4、§4–5。**它和 HistCAD 是不同作者、不同论文，不能合并其数据或实验。**
- **实际机制：** 把轮廓恢复放到前端，生成平展的参数化序列；在序列里表示显式约束、布尔过程和部件关系。还从几何包围盒等信息得到粗空间关系，用于构造语言标注。功能描述属于生成标签，不等于工程功能被验证。
- **实验读到的内容：** 在约 **129K** 共同形状上，用 **Qwen3-0.6B tokenizer**比较，含约束与不含约束的序列平均分别为 **476.11 与 358.87 token**，显式约束增加约 32.7% token。§3.4.3 展示 FreeCAD 中的交互编辑比较，属于定性案例，没有给出与 HistCAD 相同的量化编辑保持分母。§3.4.4 有 Qwen3-8B LoRA 生成实验，报告无效率 1.40% 和平均 CD 3.00；不能把这转述为冻结基础模型零样本能力。
- **证据边界：** 公开论文说明资源可合理申请获取；部分工业原生文件不能再分发。不能写成所有原始数据已公开可直接下载。简单学术模型占比、长装配与标准覆盖、用户层面的实用性都有局限。token 值与 HistCAD 的 tokenizer、共同集合不同，不能跨论文直接排名。
- **对 text2IFC：** 进一步削减“编译器已经知道的结构”，同时保留有效修改所需信息，是已有设计路线。我们的新意必须是如何选择或改变这条边界的机制，或者处理此前未处理的任务结构，并有相应对照。

### FSP04 — CAD-Factory：结构与参数解耦、多 Agent、反馈均有完整实现

- **来源与版本：** Yang Liu 等，*CAD-Factory: A Language-Driven CAD Generation System*，[作者项目页](https://cad-factory.github.io/)、[主文 PDF](https://cad-factory.github.io/pdf/main.pdf)、[补充 PDF](https://cad-factory.github.io/pdf/appendix.pdf)。项目页标示 SIGGRAPH 2026；本记录以作者公开主文和补充为准。阅读主文 §3.2–3.5、§4、§5，补充 B.3、C.1–C.4。
- **实际机制：** 用 **21 类 AST token**表达结构，把高层构成和数值参数分开；Manager 生成 AST，Coder 条件生成代码，执行反馈最多辅助两轮修正，Editor 通过颜色与部件对应关系接受可视化修改。实现含 LLaMA-3.2-3B 的词表扩展、领域继续预训练、各阶段 LoRA 及联合微调，不能当作仅靠现有模型编排得到的结果。
- **实验与成本：** 整理约 110K 数据，生成微调用 **50K**，编辑数据 **15K**，每类编辑 5K。补充说明四张 A100 80GB 上约 32 小时领域继续预训练、18 小时分阶段训练及 3 小时联合训练。Table 2 无参数文本任务的 AST 准确率 82.81、F1 76.06、缩放后 MCD 2.90 是不同指标。Table 5 去掉 AST 的 MCD 为 6.37，换更大的无 AST 模型为 3.35，去掉领域预训练为 13.24，支持结构和训练各自有作用，但不是冻结模型下只改变推理方式的比较。
- **分母和公平性：** 主文未给出足以核对全部文本条件评测的精确测试条数。补充 C.3 的 **9,000 个生成样本与 3,000 个参考模型**专属于无条件生成分布评测，不能挪作文本任务分母。通用模型基线也得到新格式说明、少量示例与最多两轮语法反馈，不能误写为零反馈基线；但没有同等专门训练。编辑部分主要是定性演示，不能推导出全局关系保持率。
- **对 text2IFC：** “先结构后参数”及 Agent 分工不够新。若借鉴，应优先做同模型下的结构决策研究；另开训练路线的成本明显更大。

### FSP05 — AIDL：不仅分层求解，已经会逐层释放内部自由度

- **来源与版本：** Benjamin T. Jones 等，*AIDL: A Constraint-Solving CAD Language*。[完整阅读的 arXiv 2502.09819v1](https://arxiv.org/html/2502.09819v1)，2025-02-13；[作者 PDF](https://vovakim.com/papers_small/25_PG_AIDL.pdf)也是这一预印本内容。[正式版 DOI](https://doi.org/10.1111/cgf.70250)对应 Computer Graphics Forum 44(7), e70250，2025-10-11。正式版作者列表和摘要有变化，正式 PDF 本次访问返回登录页，因此以下实验数字仅归属 **v1**。阅读 v1 §3.2–3.4、§4、Appendix B 与局限部分。
- **实际机制：** 用具名几何引用、几何约束、结构组合表达 CAD；SOLID、HOLE、ASSEMBLY 形成层次。引用约束和构造方式减少布尔之后引用不稳定的问题，但相应限制可引用对象。求解先处理局部结构，再通过迭代加深处理耦合。
- **关键细节：** §3.4 与 Appendix B 已经做两阶段自由度扩展：当前结构先独立求解、后代固定；不可解时按深度开放后代的**平移**；仍不可解，再按深度开放后代的**全部几何参数**并纳入相关约束，最终可扩大到全模型。这直接覆盖“冲突后打开更多内部参数”的一般设想。
- **实验与分母：** v1 是 **36 条人工二维任务 × 每条 10 次生成**，GPT-4o、6 个上下文示例、最多 5 次失败反馈，不是 IFC 或完整三维建筑评测。有效生成率为 AIDL 64%、去掉约束 94%、去掉层次 77%、OpenSCAD 79%。CLIP 只对有效结果算：AIDL 28.90、OpenSCAD 27.32、无层次 28.64、无约束 28.89。展示中还会对有效候选排序；不能拿精选图片证明平均任务成功。可编辑性主要是定性论证，两个消融的 CLIP 差异也不大。
- **证据边界与启发：** 报告的错误包括模型不正确地使用能力、通过删约束或结构来消除错误。后一个问题已有 CIT-CAD 的保持条件作为近邻。我们若研究跨模块接口，只能进一步问：**为什么需要开放某几个内部变量，而不是按层次深度整体释放？** 这还需要与 AIDL 直接比较，不能先宣布新意。

<a id="fsp06"></a>
### FSP06 — WorldCoder：跨任务复用失败驱动程序模型已是方法先例

- **来源与版本：** Hao Tang、Darren Key、Kevin Ellis，*WorldCoder, a Model-Based LLM Agent: Building World Models by Writing Code and Interacting with the Environment*，NeurIPS 2024。[本次阅读 arXiv 2402.12275v3](https://arxiv.org/html/2402.12275v3)，2024-09-20；[会议正式 PDF](https://papers.neurips.cc/paper_files/paper/2024/file/820c61a0cd419163ccbd2c33b268816e-Paper-Conference.pdf)。阅读 §2–3、§5、Appendix B/F。
- **实际机制：** 冻结的 GPT-4 写可执行状态转移函数和任务奖励函数。世界模型既要解释已观察的转移，也要在规划中保留到达目标的可能性；执行反例触发程序修订，REx 策略选择候选程序。动态模型和目标奖励分开，使新任务能复用动态知识。规划器在合成模型上进行 VI/MCTS，模型权重没有更新。
- **实验读到的内容：** Sokoban、MiniGrid 和改写后的 ALFWorld，包含去掉乐观条件、奖励提示等消融及迁移案例。Sokoban 初始能力形成可消耗约 **400K LLM token**，不是学习成本为零；五个以上箱子的规划仍是限制。ALFWorld 被转成**完全可观测的 PDDL fluent 状态**，Figure 5 是所选代表任务、3 个种子的结果，不能等同原始部分可观测 ALFWorld 完整测试集的成功率。
- **公平性和边界：** 游戏规则可能已在模型预训练中；部分对照的输入表示也不同，例如 Sokoban 的视觉 PPO 与对象状态形式的 WorldCoder。论文的理论需要真动态模型在假设空间中、规划器足够理想等条件，不能自动传给启发式 LLM 实现。
- **对 text2IFC：** “从失败学规则、跨任务复用、把规则写成程序”都已有直接先例。IFC 编译器和 API 已经精确实现的效果通常无需再学近似世界模型。可能有价值的是迁移**何时适用、哪些关系会受影响、何时应拒用**，但应先证明它超过现成 API 文档和普通程序案例，而非重复学习确定性实现。

<a id="fsp07"></a>
### FSP07 — SayPlan：关系上下文缩减与求解器分工是既有组合

- **来源与版本：** Krishan Rana 等，*SayPlan: Grounding Large Language Models using 3D Scene Graphs for Scalable Robot Task Planning*，CoRL 2023 / PMLR 229。[正式全文及补充](https://proceedings.mlr.press/v229/rana23a/rana23a.pdf)。阅读 §3–6、Tables 1–3、Appendix A/C/F/G。
- **实际机制：** LLM 在楼层、房间、物体组成的层次三维场景图上展开和收起节点，只保留任务相关子图及搜索记忆；路径规划交给 Dijkstra，LLM 处理较高层操作计划。仿真器的谓词反馈驱动最多五轮重新规划。
- **实验与分母：** 共 **90 个任务**：两场景上的 30 个简单与 30 个复杂搜索任务，加办公室中 15 个简单、15 个长程规划任务。正文场景规模是办公室 37 房间 / 150 物体、三层住宅 28 房间 / 112 物体；与摘要早期数字不一致，采用正文。长程任务计划正确率 73.3%、可执行率 86.6%，并非两项联合成功率。Table 2 的图输入长度明显下降，但不是包含重试和工具开销的全程 token 节省。
- **边界：** 两个既有场景图规模有限，空间距离、否定、计数仍会失败。普通 LLM / LLM+P 等比较没有全面匹配修订预算。场景图和可检验谓词事先提供，不能推出系统能从任意自然语言自动学到完备空间知识。
- **对 text2IFC：** 按任务选择关系上下文、把确定性部分交给外部规划器、用反馈继续推理，已经是完整方案。IFC 版本要增加可明确替换的选择准则，而不只是有这些组件。

<a id="fsp08"></a>
### FSP08 — Aligning Constraint Generation：求解器评分也会偏离设计意图

- **来源与版本：** Evan Casey 等，*Aligning Constraint Generation with Design Intent in Parametric CAD*，ICCV 2025，pp. 8613–8622。[正式论文](https://openaccess.thecvf.com/content/ICCV2025/papers/Casey_Aligning_Constraint_Generation_with_Design_Intent_in_Parametric_CAD_ICCV_2025_paper.pdf)。阅读 §3–6、Tables 1–2 与局限。
- **实际机制：** 从已有草图几何预测约束，以 Vitruvion 为基础先监督学习，再比较 DPO、ExIt、ReMax、RLOO、GRPO 等训练方案。Fusion 求解器提供是否充分约束、是否过约束、能否求解、量化稳定性等反馈。包含逐约束和逐序列奖励，不是只把执行报错发回提示词。
- **实验与分母：** 过滤后约 **2.8M** 个独特草图，限制最多 16 个图元、64 个约束；这是来源规模，不是测试分母。所读主文没有给出精确测试草图总数。Table 1 每个草图生成 8 组输出，RLOO 的充分约束率 93.05%，监督基线 34.24%。Table 2 更严格的多条件联合 pass@1 为 83.57% 与 33.32%，不能把 93.05% 当成用户意图成功率。求解超过 2 秒按不可解处理，不是剔除失败样本。
- **关键负面发现：** 优化求解器奖励可能导致不必要的尺寸约束和奖励投机；约束充分并不代表保留用户希望的修改自由度。追加约束比例惩罚也存在稳定性代价。预定目标没有覆盖所有主观设计意图。
- **对 text2IFC：** 检查“更多约束通过”可能误导模型。若研究设计意图，应明确哪些关系必须保持、哪些参数允许变化及何时应改变拓扑。它同时提示一条训练路线，但新训练、求解器依赖和奖励设计不是现有项目的少量补强。

<a id="fsp09"></a>
### FSP09 — CAD-Editor：定位再补写、复用未改部分已有直接比较

- **来源与版本：** Yu Yuan 等，*CAD-Editor: A Locate-then-Infill Framework with Automated Training Data Synthesis for Text-Based CAD Editing*，ICML 2025。[本次阅读 arXiv 2502.03997v2](https://arxiv.org/html/2502.03997v2)，2025-07-03；[作者代码](https://github.com/microsoft/CAD-Editor)。阅读 §4–7、Tables 1–2、Appendix E。
- **实际机制：** 先构造变化前后的 CAD 对，用多模态分步描述产生编辑指令；LCS 等方式生成需修改片段的掩码，模型先定位再补写，未修改 token 复制保留。训练使用 Llama-3-8B LoRA、约 **120K** 合成编辑数据，并有人类筛选。掩码保持是程序层面的手段，不是所有几何和用户关系保持的证明。
- **实验与分母：** **2,000 条测试编辑指令，每条 5 次生成，共 10,000 个输出**，主要指标汇总三个运行；人类评价另对 2,000 个抽样模型对由五名评价者判断。Table 1 的有效率为 95.6%，人工编辑成功率为 43.2%，二者差距很大；GPT-4o 上下文学习对照分别为 84.5% 和 15.6%。不能拿“程序有效”代替“完成指定编辑”。
- **公平性和边界：** 通用基线有检索的少量示例，但没有相同领域训练；同一训练路线内的直接生成和定位补写消融更接近机制证据。训练设置涉及四张 A800 80GB、70 个 epoch，不是低成本提示改动。合成编辑分布和原始数据相似性、长序列处理，以及未直接量化全局关系保持，限制其外推范围。
- **对 text2IFC：** 只改局部和复用其余代码并不新。若把 repair 与 generation 结合，应证明跨任务迁移出的知识在新组合中有效，并核查适用条件；不能仅展示另一个定位编辑闭环。

## 三、novelty 与实验一一对应的候选

以下均是**尚未实现、可能被对照否定的机制假设**。没有一项因为目前几篇论文未覆盖就获得“首次”资格。各臂应使用同一模型版本、同一编译器、同一公共 API、同一任务和检查器，记录全部尝试成本；不能给候选更多真实几何信息，而只给基线文本。

<a id="sp-h1"></a>
### SP-H1：冲突发生时，选择需要开放的跨层接口变量

**动机。** 模块复用可以缩小推理范围，但楼层、交通空间和立面等模块之间会耦合。接口过窄时无解，全局展开又可能使模型处理大量无关关系。AIDL 已有按深度释放内部自由度，研究问题必须比“失败后扩大范围”更具体。

**候选机制。** 在分模块求解失败后，用违反关系、参数依赖及少量受控扰动得到的影响证据，选择一小组需要跨边界公开的内部变量，再重新求解。选择目标同时考虑能解除哪些耦合以及新增上下文和求解成本；不按整层或整个子树机械展开。只开放原本允许变化的设计自由度，不把用户硬要求改松。这里的“小”是优化目标，**没有最小性或完备性保证**。先不引入自动重分模块；后者是成本更高的后续研究。

**IFC 任务。** 例如改变层高后，楼梯的平台位置和梯段需要与相邻楼层开口共同调整；扩大走廊后，门洞和房间宽度受影响，但立面其余窗不应无故变化。先使用可参数化、可复验的小型组件，再测试未见过的跨层组合，不从任意 IFC 自动抽取全部依赖作为第一阶段前提。

| 对应实验 | 必须回答的问题 |
|---|---|
| 同组件库下比较普通 coding agent、固定分区、**AIDL 式先平移后几何的逐层开放**、全局平展求解、候选 | 候选的选择规则是否优于已有层次扩展和全局解法？不能只打败弱 one-shot 基线 |
| 只用依赖图；只用冲突；只用受控扰动；完整候选 | 哪个新增信息真正有用？若简单依赖闭包已足够，新增机制不成立 |
| 小问题枚举可行开放集合，作为离线诊断上界 | 候选选中的接口是否比深度展开更接近低成本可行集合？诊断真值不给运行中的 Agent |
| 按组件家族和耦合模式隔离，测试未见过的跨层、远距离组合 | 是处理新组合，还是记住了某套房型和组件模板？ |

**指标与否定条件。** 严格任务成功、原有关系保持、开放变量/关系数、全部输入输出 token、工具调用、求解时间；比较成功率与成本曲线。若相同预算下不能优于逐层开放或全局求解，或收益完全来自手写依赖标注，应否定当前方法增量。所有扰动和失败重试都计成本，不能只报告最后一轮上下文更短。

**难度与优先级。** 冻结模型可做，但需要可观察的参数依赖和受约束求解接口，属中等以上改动。适合先做小规模判别实验，**高风险探索**。还需与一般冲突驱动分解、最小核修复等方法比对；这些由主文的其他证据记录补充，不能因本文未展开而当成空白。

<a id="sp-h2"></a>
### SP-H2：从单个模型，转向在明确变化范围内有效的构造规则

**动机。** 有效的单一 IFC 不一定是用户希望重复修改的设计。已有参数 CAD 和 HistCAD 等研究了尺寸修改保持关系；可能更难、也更有研究含量的是：参数变化触发实体数量或连接方式变化时，怎样保留同一设计规则。

**候选机制。** 在用户明确给出变化参数、合法范围和应保持要求后，让固定模型合成一个分段构造程序；编译检查产生反例，反例用于细化**参数区域与拓扑选择规则**，而非只改一个失败实例的常量。例子是层高变化时梯级数需要切换，立面宽度变化时窗数量可能变化，但梯段连接、门窗宿主和边缘间距规则继续有效。程序作为现有 BIM JSON→IFC 编译器的上游旁路产物即可，不必立即重写 IFC 表达。

**必须超过什么。** 参数化程序、设计族、约束保持编辑以及反例驱动合成都不是新思想。可能的差别仅在如何利用关系失败定位需要改变的分段边界和构造分支；如果普通参数化 coding agent 配常规 CEGIS 一样有效，该候选就没有额外方法贡献。

| 对应实验 | 必须回答的问题 |
|---|---|
| 同模型的普通参数化 Python agent；单实例生成后逐次 repair；常规随机反例 CEGIS；固定拓扑约束生成；候选分段规则 | 是否需要候选的分段与拓扑决策，而非普通程序表达能力？所有方法获得相同检查权限 |
| 去掉关系定向反例；固定分段；只修数值；完整候选 | 哪一环改善了拓扑切换边界附近的成功率？ |
| 设计家族隔离，并留出未见参数值、边界邻域和多参数组合 | 是否生成可迁移构造规则，而非对若干已测参数做过拟合？参数变体不能当独立设计家族 |
| 首次构造成本与之后多次修改累计成本分别记录 | 可复用程序何时值得？是否只把生成费用提前支付了？ |

**指标与否定条件。** 原始与留出参数上的严格成功、关系保持、拓扑切换正确率、程序分支复杂度、构造与使用总成本。有限测试只证明测试范围内表现，不宣布整个连续参数域已验证。若收益只在拓扑不变时存在、普通 CEGIS 已达到相同性能，或后续重用不能摊薄较高构造成本，应收缩或放弃该候选。

**难度与优先级。** 不必训练新模型，但需要新的程序搜索和参数域评测，改动高于 SP-H1。先限定一个明确的生成家族；不要承诺从一份 IFC 反推出全部设计意图。适合作为方法论文的后续空间，不宜作为近期 demo 必须完成的大系统。

<a id="sp-h3"></a>
### SP-H3：把 repair 经验转成有适用条件的跨任务规则

**候选机制。** 从公开输入、修复前后可观察结果和执行反馈中，提炼“何种条件下采取何种关系操作、会影响哪些其他关系”的规则。用正反例验证适用边界；新 generation 任务仅在这些条件满足时使用规则，否则回退。不能使用 pristine Gold、私有损坏配方、被删身份或只从私有真值得知的信息来学习规则。

**已知覆盖与可能增量。** WorldCoder 已经支持动态模型复用与反例修订；技能库、案例检索和语言反思也不是空白。这里只保留一个较窄假设：**来自 repair 的条件化关系规则，是否能改善未见组合的 generation，并减少误用？** 这仍不自动构成新方法，需要与普通程序库和条件规则学习近邻比较。把规则写成自然语言或 JSON 不算机制增量。

**实验配对。** 固定只来自 repair 的知识来源与 token 预算，比较成功代码库、相似案例检索、文字反思、WorldCoder 式转移模型、带适用条件的规则；消融适用条件和失败例。按建筑家族、关系类型及操作组合隔离，只在新的 generation 任务评价迁移，同时测试不该应用该规则的反例。主指标是严格成功、错误应用率、原有关系保持和学习加使用的全部成本。直接提供 API 文档或真实操作效果的对照可以检验：是否只是在重新学习编译器已经明确知道的东西。

**否定与优先级。** 若普通案例库已同样有效、收益依赖泄漏同一损坏模板、或只学到了固定 API 的已知效果，应放弃方法声明。该方向与主文的知识利用候选重叠，先作为有条件候选保留，优先级低于一个机制清晰的小型 SP-H1 判别实验；不需要另做大而全的世界模型。

## 四、下一步的取舍

1. **先检验 SP-H1 是否有真实机制空间。** 最低要求是与 AIDL 式逐层释放和全局重解直接比较，不以普通生成失败作为新意证据。若没有优势，保留层次求解作为系统实现即可。
2. **SP-H2 作为更远的思想方向。** 它把问题从单次文件生成移到有明确变化要求的构造程序，但必须面对参数化 CAD 与 CEGIS，不能仅靠新叙事。只在用户愿意承担更大改动后进入实现。
3. **SP-H3 合并进主文的迁移候选。** 重点检验条件与负例的作用，避免重复建设已知 API 的世界模型。

以上排序是实施风险和可判别性判断，不是会议录用判断。WWW / AI Demo 可以展示一个范围清楚、经过比较的系统机制；若实验只支持工程效果，就应如实写系统贡献，不强凑三个方法创新点。
