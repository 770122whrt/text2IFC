# 方法候选调研：知识利用、主动查证与跨任务迁移

核查日期：2026-09-15。本文是候选研究方向的证据和实验设计，**不是现有能力或首创声明**。本轮新增核查 9 篇原始论文的指定版本正文，覆盖方法、主要实验与相关局限；未运行作者代码或本项目 Provider。F 表示取得正文并完成这些部分的核查，不代表所有实验细节均已充分披露，也不代表结果已经复现。

已有 [论文矩阵](https://github.com/770122whrt/text2IFC/blob/09e8e9311f0b8c3ffc022dc42a12a48165ed7aa1/docs/reports/generation-demo/paper-matrix.md) 和 [Coding / 知识证据](coding-knowledge-and-control.md) 中的 Repoformer、RepoGraph、CodeMEM、ATLAS、LLMLingua 不重复计数；[Cobbie](ifc-evaluation.md#b12)、[SceneCraft](structured-generation.md#c01)、[Event-B Agent](structured-generation.md#c12) 仍是必须比较的领域近邻。这里增加跨域机制，防止把“RAG、经验库、工具封装”重新包装成创新。

## 1. 先给判断

“高效使用 knowledgebase”仍有研究空间，但相似度检索、按需检索、结构关系检索、经验积累、工具生成、前置条件筛选均已有明确先例。当前更值得探索的问题是：

> 一条知识或经验在什么条件下可以可靠迁移？当适用条件不明时，Agent 应该先查什么、试什么，再决定怎样执行？

这能连接知识利用与能力扩展，同时不要求先微调基础模型。增量应落在**适用条件如何被辨别、查证动作如何被选择、经验如何被验证后迁移**，而不是知识库变大或提示变短。下文的 K1–K4 是待证伪候选，不能全部当作一篇论文已经成立的四个贡献。

<a id="fk01"></a>
### FK01 — HippoRAG 2

- **题名与来源：** Bernal Jiménez Gutiérrez 等，*From RAG to Memory: Non-Parametric Continual Learning for Large Language Models*。核查 [arXiv v2 全文](https://arxiv.org/html/2502.14802v2) §3–6、Tables 1–5；正式发表为 ICML 2025，本文数字来自该 arXiv 版本。
- **方法：** OpenIE 三元组组成开放图；增加原始段落节点，整条查询匹配三元组，LLM 过滤种子，再用 Personalized PageRank 检索段落。图主要服务于检索，不直接把所有生成图事实作为答案。
- **规模与对照：** NQ、PopQA、MuSiQue、2Wiki、HotpotQA 各 1,000 查询，LV-Eval 124，NarrativeQA 293 查询/10 篇文档。结构方法统一 Llama-3.3-70B 与 NV-Embed-v2；比较强向量检索、RAPTOR、GraphRAG 等，并消融查询匹配、段落节点与过滤。MuSiQue Recall@5：69.7→74.7；QA F1：45.7→48.6。
- **边界：** 连续学习实验是四批语料加入；复杂 QA 随干扰语料增加仍退化，不等于已经解决经验冲突、知识失效或技能迁移。检索指标也不是可执行任务成功率。
- **对本项目：** 仅把 IFC 实体/API 连成图不够。更明确的空隙是知识的版本和适用条件发生变化时，如何判断哪些图关系仍可用于执行。

<a id="fk02"></a>
### FK02 — ACE

- **题名与来源：** Qizheng Zhang 等，*Agentic Context Engineering: Evolving Contexts for Self-Improving Language Models*；核查 [arXiv v1](https://arxiv.org/html/2510.04618v1) §3–4、Appendix B，按预印本记录，不混入后续版本结果。
- **方法：** Generator、Reflector、Curator 产生条目级增量更新；记录 helpful/harmful 次数，保留详细经验，定期去重，避免整段重写丢失信息。
- **实验与对照：** AppWorld 的 normal/challenge、FiNER、Formula；按原划分做离线适配及先预测后更新的在线适配。各角色使用同一 DeepSeek-V3.1；比较 ICL、GEPA、Dynamic Cheatsheet，另消融反思和多 epoch。AppWorld 在线平均栏由 42.4 到 59.5，**该栏是四个 TGC/SGC 数值的平均，不是一个全任务成功分母**。所读正文没有给出各划分的绝对样本数，不能据原始 benchmark 总规模擅自补齐。
- **边界：** 无可靠反馈可能负迁移：FiNER 在线无标签 ACE 67.3，基础模型 70.7。作者明确依赖 Reflector 能力；“无微调”仍有多轮离线/在线 LLM 成本。
- **对本项目：** 应比较同模型的 ACE 式记忆；候选差异应是经验的适用边界和反例验证，不能只是把经验改成有 ID 的条目。

<a id="fk03"></a>
### FK03 — CRAFT

- **题名与来源：** Lifan Yuan 等，*CRAFT: Customizing LLMs by Creating and Retrieving from Specialized Toolsets*；[ICLR 2024 正式全文](https://proceedings.iclr.cc/paper_files/paper/2024/file/af31604708f3e44b4de9fdfa6dcaa9d1-Paper-Conference.pdf)，核查 §2–4、Appendix A/B。
- **方法：** 生成具体 Python 题解，抽象变量/接口，在原问题上验证，去重；按题目、函数名、docstring 三视角检索工具。无需更新模型权重。
- **规模与对照：** VQA 建库抽样 2,000 题；表格/数学各 500；形成 525/181/282 个工具。评测三类 VQA、TabMWP、MATH algebra；后者 881 题。主实验 GPT-3.5-Turbo 执行、GPT-4 建工具；比较直接程序、LATM、CREATOR、同工具库 BM25/SimCSE。TabMWP 的 BM25 89.2 高于 CRAFT 88.4，不能写成所有设置更优。正文所读位置未明确各 VQA 实际评测分母。
- **边界：** 抽象工具主要在原生成题上验证，不提供跨参数域的正确性保证；强建库模型向弱执行模型转移知识是一个因素。CREATOR 对照移除了其原有校验/纠正，只比一次执行。
- **对本项目：** “从成功 IFC 脚本提炼工具”已经很接近本方法；需要考察反例驱动的适用条件、未见组合和同模型建库，才能提出更具体增量。

<a id="fk04"></a>
### FK04 — ExpeL

- **题名与来源：** Andrew Zhao 等，*ExpeL: LLM Agents Are Experiential Learners*；[AAAI 2024 正式全文](https://ojs.aaai.org/index.php/AAAI/article/download/29936/31635)，核查 §4–5、Algorithms 1–3。
- **方法：** 训练任务中重试取得成败轨迹；对比同任务成功/失败及跨任务成功，ADD/EDIT/UPVOTE/DOWNVOTE 自然语言经验；测试检索相似成功轨迹并读取经验。跨域“fine-tune insights”是改写经验文本，不是参数微调。
- **实验与对照：** HotpotQA、ALFWorld、WebShop，另用 FEVER 做迁移，四折报告均值和标准误；执行统一 GPT-3.5-Turbo，默认 GPT-4 提炼经验。比较 ReAct、Act、只有检索、只有经验与 Reflexion。所读正式正文未明确四折的绝对样本数，不把 benchmark 原始规模充作本论文分母。
- **边界：** 不同环境的经验与轨迹收益不同；成功经验也可能误导，所以设下调/删除。与 Reflexion 的测试重试数和离线经验成本不能合并成无成本优势。
- **对本项目：** 直接“总结修复失败、帮助下次生成”已有先例。应测试相似度高但前提不成立的经验，以及是否能有条件地复用、拒用或修改。

<a id="fk05"></a>
### FK05 — SePer

- **题名与来源：** Lu Dai 等，*SePer: Measure Retrieval Utility Through the Lens of Semantic Perplexity Reduction*；[ICLR 2025 全文](https://proceedings.iclr.cc/paper_files/paper/2025/file/c44c4afd77d5ee760e7f4bed0c50f878-Paper-Conference.pdf)，核查 §3–5、Appendix D.3–4。
- **方法：** 采样答案并做语义聚类，衡量加入检索材料前后对参考正确答案的信念变化；目标是评价检索效用，不是无需标注的在线控制器。
- **规模与对照：** 简单 QA 三套、多跳 QA 四套；默认每查询采样 10 次，消融 1/5/10/15/20；附录推理分析每套超过 1,000 时抽取 1,000。比较匹配指标、不确定性、语义熵、LLM judge。HotpotQA 效用相关系数：语义熵 0.339，软 SePer 0.660；这是与效用标签的相关性，不是任务成功率。
- **边界：** 需要参考答案；多跳中间材料标签假设各步骤均分总效用。不能将这些私有答案引入运行时检索。真实代码/空间任务的功能互补也未被该标签直接检验。
- **对本项目：** 可借鉴“知识效用依赖接收模型”的研究设计。若做决策相关知识选择，应使用可公开执行的检查信号，最终能力由独立隐藏评测判断。

<a id="fk06"></a>
### FK06 — CF-RAG

- **题名与来源：** Huaiyu Qin 等，*Counterfactual Reasoning for Retrieval-Augmented Generation*；[ICLR 2026 全文](https://proceedings.iclr.cc/paper_files/paper/2026/file/1c078897dc08d46091d0d361d9955c6b-Paper-Conference.pdf)，核查 §4、§6、Appendix B/C/N/O。
- **方法：** 改写角色、时间、实体、类别、范围生成对照问题；检索并分层采样证据、并行生成答案，使用原查询和对照查询的相关性差异评分。不微调基础模型。
- **实验与对照：** 五套 QA，两个基础 Llama 模型；默认 3 个对照问题、4 个证据簇、3 个草稿。稳定性另在 500 HotpotQA 查询重复 5 次；延迟在 1,000 查询、4×A100 上测量。主表各数据集总分母未在已读方法/附录 C 中明确。
- **边界与数字校核：** 主文把 HotpotQA 49.00→88.58 称为“absolute +80.8%”，实际是 **+39.58 个百分点、约 +80.8% 相对提升**；附录使用 Smart EM，包含 containment/语义变体，不能当标准严格 EM。存在引用原结果与重跑混合；并行延迟接近不代表总 token 成本接近。
- **对本项目：** “反事实问题帮助检索”已被覆盖。候选必须比文本相关性评分更具体，例如以可执行测试辨别规则适用条件；也不要仅因使用对照，就宣称发现了物理因果关系。

<a id="fk07"></a>
### FK07 — ToolChoiceConfusion / CMTF

- **题名与来源：** Rahul Suresh Babu、Laxmipriya Ganesh Iyer，*ToolChoiceConfusion: Causal Minimal Tool Filtering for Reliable LLM Agents*；[arXiv v1，2026-06-04](https://arxiv.org/html/2606.06284v1)，核查 §3–9、Algorithm 1、Tables 1–4。
- **方法：** 以工具的前置变量和产生变量构造状态图，BFS 找最短路径，每步只展示该路径的下一个工具。这里“causal”明确是操作依赖意义；状态是变量可用性的单调累积，不是完整真实环境因果模型。
- **规模与对照：** 102 合成任务、100 工具、四模型、六策略，共 2,448 运行；全部工具结果固定 mock，最多六步。全工具/关键词/可执行工具/整条路径/当前 frontier 比较。整路径和 CMTF 都约 0.99 成功，后者 token 2,405 对 2,555；90% 节省是相对 24,569 token 的全工具设置。
- **边界：** 当前状态和目标已给定、合同人工结构化，每任务一条 gold chain；可能惩罚其他合法路线。作者已提出状态不确定时扩展诊断/恢复工具。
- **对本项目：** 必须放弃宽泛的“必要知识/工具最小化”首创说法。尚可研究自动辨别不完整合同、非单调状态与可迁移适用边界，但不是把 BFS 工具图换成 IFC。

<a id="fk08"></a>
### FK08 — LLM-Wiki

- **题名与来源：** Haoliang Ming 等，*Retrieval as Reasoning: Self-Evolving Agent-Native Retrieval via LLM-Wiki*；[arXiv v1，2026-05-25](https://arxiv.org/html/2605.25480v1)，核查 §3–5、Appendix G 的效率表。
- **方法：** 将文档编译成带出处和双向链接的 Wiki；Agent 组合 search/read 和链接遍历，依据证据充分性停止。Error Book 记录错误原因、注入规则，并以确定性修补加 LLM 修补持续更新知识。
- **规模与对照：** 三套公开多跳 QA 各 500 问题；另有 AuthTrace。统一 GLM-5.1，向量统一 Qwen3-Embedding-8B，最多 15 工具调用；比较七基线并消融结构、渐进遍历、Error Book。MuSiQue F1 0.739，最强表中对照 LightRAG 0.659。
- **边界：** 其查询延迟不包括全部建库/跨批修复成本；单文档 AuthTrace 反低于 HippoRAG 2，说明重组知识会丢局部细节。单次 top-5 与多轮遍历的总预算不是天然匹配。
- **对本项目：** “知识库可遍历＋可自修正＋可组合”已经明确。新的能力扩展要体现执行语义、适用边界和未见任务迁移，不能只加 wiki 页面和错误本。

<a id="fk09"></a>
### FK09 — Design-Specification Tiling / DST

- **题名与来源：** Yali Du、San-Zhuo Xi、Hui Sun、Ming Li，*Design-Specification Tiling for ICL-based CAD Code Generation*；[arXiv v1，2026-03-13](https://arxiv.org/html/2603.12712v1)，核查 §2–4、Appendix B/E/F。
- **方法：** 将设计说明拆成长度 2/4/8/16/32 的 n-gram；挑选联合覆盖当前说明最多片段的示例，优化加权覆盖，使用贪心 submodular 算法。近似保证针对覆盖代理，不是建模正确率或真实知识充分性。
- **规模与对照：** Text2CAD 描述、GenCAD-Code 代码均源自 DeepCAD；筛后 151,940 三元组，按复杂度抽取各 300，共 900 测试，其余作 ICL 库。三个固定模型，主表 5-shot，与随机、BM25、编辑距离和多样性选择比较；另看 1–5-shot。
- **边界：** hard VSR 三个模型都不超过各自最强对照。附录指出示例明显减轻 API 错误，几何组合错误仍难解决。只按相同描述去重和难度随机抽样，不是设计族隔离；IoU 的体积/包围盒表述不一致。几何评分允许相对 GT 的 96 种平移、缩放、正交旋转择优，不能支持绝对尺寸/方向正确性。
- **对本项目：** K3 必须超过这种无微调的组合覆盖基线；“知识互补”不能只停在覆盖更多需求词。真实执行中的协同或干扰不必满足代理目标的单调性与边际递减性质。

## 3. 候选 novelty 与 experiment 对应

### K1 — 主动辨别知识的适用条件

**研究假设。** 当文档相关但不足以区分多个合法实现时，选择一个能够排除错误规则的最小查证动作，比继续增加相似文档或直接重试更有效。

**已有工作。** CF-RAG 改写问题区分证据，CMTF 依据已知前置条件筛工具，LLM-Wiki 主动遍历；普通“主动检索”不能做贡献。

**待实现增量。** Agent 保留少量相互冲突的可执行假设，明确各自适用前提；比较候选 `read_doc`、`inspect_instance`、`sandbox_probe` 在当前决策上能排除哪些假设。先用保守的分歧覆盖/成本规则选择动作，而非假称已知真实信息增益概率。探测后更新适用条件，执行任务并验证。目标是减少错误规则迁移，而非最小 token。

**IFC 例子。** 某次窗操作是否同时产生 opening/void/fill 关系？文档对应旧版本，当前接口行为未确认。对可丢弃的小墙窗模型试一次，检查实际关系；探测可证明这个实现/条件下的行为，不能补出用户没给的窗位置或材料。

**E-K1。** 构造同任务四类条件：文档完整、缺失前提、文档与工具版本冲突、当前实例绑定不明。比较完整文档 ReAct、混合检索 ReAct、CF-RAG 式多查询、随机/固定诊断探测、候选策略。每种都允许相同工具和总预算。衡量真实完整任务成功、错误前提采用率、有效辨别次数、无效探测、全部成本。用新 API 操作族/版本组合隔离开发与测试。消融“有探测但随机选择”和“只检索不探测”，区分多花计算与选择机制。**推翻条件：** 匹配预算后随机探测同样好，或强普通 Agent 已自行做等效探测；则不保留独立方法主张。

**投入/冲突。** 无需微调；中等投入，需要隔离探测、可观测结果和少量假设表达。经典主动学习、实验设计、程序合同推断还需定向追加调研；本轮不能宣称“首次主动学工具”。

### K2 — 用反例约束跨任务经验迁移

**研究假设。** 经验的主要问题不仅是检索不到，也可能是“找到了很像的成功经验，但当前条件不同”。附带经测试的适用边界，能提高新场景迁移并减少负迁移。

**已有工作。** ExpeL 从成败经验提炼规则；ACE 累积/修正条目；CRAFT 抽象可执行工具。只加条件字段或成功标签属于数据整理。

**待实现增量。** 对新经验进行针对性反例搜索：改变最可能影响结果的输入维度，找到失败边界，再收窄可复用规则。存储 `适用条件→操作/规则→可检验效果` 与反例；遇到不满足条件的任务时，选择拒用、补充查证或修订规则。测试时不能用测试 Gold 来筛选经验。

**IFC 例子。** “按墙的 X 坐标偏移放窗”在轴对齐墙成功，旋转墙失败；以旋转/平移的变形测试形成局部坐标适用规则。普通成功轨迹可能复制全局坐标习惯；候选需从执行反馈形成更一般或更窄且正确的规则。

**E-K2。** 固定同一基础模型及离线调用预算；比较不记忆、成功轨迹检索、ExpeL 式规则、ACE 式 playbook、相同规则＋随机测试、候选反例测试。开发任务形成经验后冻结；按建筑、操作族、几何条件留出，测试旋转、相对位置、host 类型等未见组合。主指标是任务成功与**负迁移率**：原无记忆可成功、加入经验却失败的比例；另测适用条件误放行/误拒用、已知任务回退及建库摊销成本。**推翻条件：** 只在见过的模板复述上有效，或增加同预算随机验证即可得到全部收益；则方法增量不足。

**投入/冲突。** 无需参数训练；中等投入，重心是可控制扰动和独立测量，适合连接 generation 与 repair。与测试驱动程序综合、技能库抽象高度相邻；“反例修订技能”也不能预先称新，论文应收敛到明确的适用条件表达与迁移收益。

### K3 — 针对知识互补关系选择组合

**研究假设。** 某些任务失败是缺失必须联合使用的知识，不是单条文档相关性低。分别最相关的片段未必组成可用解法。

**已有工作。** HippoRAG 2 已做多跳关系检索，RepoGraph 已做依赖子图，LLM-Wiki 已做多轮可组合检索；DST 更直接提出知识充分性和设计部件联合覆盖。仅把相关片段打包或采用集合覆盖，不足以形成方法贡献。

**待实现增量。** 选择单位是可执行子目标所需的互补知识组合；利用开发阶段的干预，识别“单独加入均无效、共同加入才起作用”的知识交互，再研究不依赖测试 Gold 的组合选择规则。初版可以用计划前置条件闭包与公开探测来估计组合是否可用，但若只剩固定闭包，应降级为基线。

**IFC 例子。** 墙体局部坐标、洞口宿主关系和窗的填充关系各自都相关；只有把正确坐标与关系建立次序一起落实，旋转墙上的窗才同时满足几何与语义。

**E-K3。** 先做小型 2×2 干预：知识 A/B 都无、仅 A、仅 B、A+B，检查是否存在超出单条收益的交互。之后在留出任务比较 BM25/向量重排、DST 式覆盖、等 token 的图切片、LLM-Wiki 式遍历、候选组合选择。预算匹配、候选语料相同；报告成功率、关键关系遗漏率和成本。开发阶段 oracle 组合仅作上界。**推翻条件：** 没有稳定交互，或普通覆盖/依赖切片取得同样收益；则没有必要开发复杂组合算法。若真实任务出现协同和干扰，也不能套用 DST 的 submodular 保证来声称我们的目标同样有保证。

**投入/冲突。** 诊断低到中等；做出通用选择器中到高。若需要训练交互预测器，应单独报训练需求，而不能说保持原模型就完全没有学习成本。此方向是备选，不建议优先于 K1/K2。

### K4 — 区分知识缺口与任务事实缺口，再选择信息来源

**研究假设。** 多种失败表面都是“不知道”，实际需要不同动作：标准知识查资料、实现行为做探测、模型事实查实例、用户偏好做澄清。来源选择错误会产生无法靠更多文档纠正的伪造事实。

**已有工作。** 按需检索、证据充分性和澄清均有长线研究；这不是“第一次让 Agent 提问”。作为独立方法，必须有决策机制和可测的跨来源收益。

**待实现增量。** 对尚未解决的决策显式表示可能影响结果的未知量，按可识别性选择信息来源。只有会改变可接受方案的未知量才触发询问/查证；如果用户已授权自由设计，应生成并标明设计选择，而不是把自由度当缺事实。可以与 K1 共用控制器，但研究问题是错误来源和不必要打断，而非工具最小化。

**IFC 例子。** “给二层东侧加窗”：窗关系规则来自标准/API；“东侧墙是哪面”需当前模型方向与实体；窗尺寸若未给且无设计授权，需要澄清。官方规范无法告诉 Agent 此项目墙的身份或用户偏好。

**E-K4。** 对同一任务制作资料缺失、实例缺失、偏好缺失、信息完整、自由设计已授权五种配对版本。比较始终检索、通用 ReAct、仅自报置信度澄清、候选决策相关来源选择。提供相同候选工具和脚本化回答；测最终正确率、捏造实例事实率、必要澄清召回、不必要澄清、用户轮次。脚本化用户不是用户研究。**推翻条件：** 收益仅来自写了更长的禁止猜测提示，或任务来源完全由模板词决定；则不支持方法新颖性。

**投入/冲突。** 无微调，初版中等投入；能力扩展价值偏交互。需要追加决策理论式澄清、可回答性和信息获取研究，不宜仅凭这 9 篇就宣布空白。

## 4. 对应关系与优先级

| 假设 | 唯一主实验 | 希望发现的机制证据 | 开发优先级 |
|---|---|---|---|
| K1 主动辨别适用条件 | E-K1：同预算信息获取动作比较 | 选择性执行探测优于多检索、随机探测和强通用 Agent | 高：适合先做小试验 |
| K2 反例约束经验迁移 | E-K2：跨条件迁移与负迁移 | 学到的适用边界提高未见条件成功，降低错误复用 | 高：能力扩展主线候选 |
| K3 互补知识组合 | E-K3：A/B 干预＋组合检索 | 联合知识具有可重复交互，常规图切片不能解释全部收益 | 中：先确认现象 |
| K4 决策相关的信息来源 | E-K4：缺口来源配对任务 | 更少事实伪造与无效用户打断，同样完成任务 | 中：可作为 K1 的交互扩展 |

K1 和 K2 最容易连成一个清楚的思想：**先确认知识何时可用，再积累可迁移的能力。** 但应先分别验证，不能把两个组件一起加上再将收益同时归因给两者。K3、K4 保留为竞争方案；不默认四条全部实施。

## 5. 共同的实验边界

1. **固定模型权重不等于成本固定。** 建库、反思、生成测试、探测和失败都计入预算；同时报告冷启动成本及摊销曲线。默认各角色用同一模型，若使用更强离线模型，单列为另一条件。
2. **规范知识、API 知识、实例事实分开。** 标准定义合法结构；API 文档与探测说明当前工具行为；实体、尺寸、方向等来自公开任务输入/模型查询。经验不能越权生成用户事实。
3. **运行时检查与最终评测分开。** Agent 可用编译、公开需求检查、隔离探测；隐藏 Gold、损坏前真值、测试标准答案只能在最终评估阶段使用。SePer 的参考答案信号不可直接用于运行时策略。
4. **任务泛化优先于随机题目划分。** 同建筑变体、同生成模板和同操作经验应按组隔离；新组合测试与新原语测试分别报告。保留正常样本，避免只为候选策略制作困难题。
5. **主要终点是可接受结果。** 重新打开、几何、语义关系、用户要求和非目标保全各报切片，同时报完整成功。不可把更多检查项当作更多独立样本。全部失败、超时、未输出均进入分母。
6. **先小规模诊断，再决定投入。** 例如每方向先选 8–12 个开发案例用于发现机制是否存在，数量不是正式统计保证；选择方向后冻结独立测试集，按期望最小收益和组内相关性估算所需规模。这里给的是实验设计，未执行任何能力实验。

## 6. 尚未关闭的调研缺口

同轮整合补充：[技能证据](frontier-skills.md#sk11)已核 ICAPS 2024 主动行动模型学习，[SK15](frontier-skills.md#sk15)已将 CoLLAs 2023 关系状态抽象从线索补为正文。因此“主动探测”“效果分组/角色化”已有更强先例，K1/K2 的泛称需继续收窄；最终优先级以 [综合方法方向](https://github.com/770122whrt/text2IFC/blob/09e8e9311f0b8c3ffc022dc42a12a48165ed7aa1/docs/reports/generation-demo/novelty-directions.md) 为准。

本轮不能证明上述机制没有更近先例。继续立项前，优先核查：主动 API 探测/工具合同学习、反例驱动技能综合、技能适用条件与负迁移、决策相关的澄清。已有文献中的 CF-RAG/CMTF 使用“causal”一词，也不意味着给我们的方法加同样名称就获得更强创新。

尤其需要避免三种混淆：文献评测不充分不等于它的方法不存在；把已有算法应用到 IFC 不自动等于方法创新；一个系统做得可靠不自动证明它比通用 Agent 更有能力。本文候选只有在实验保留的区别上成立，才值得提升为论文 Claim。
