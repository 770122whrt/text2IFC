# 可执行技能与能力扩展：正文证据、剩余假设与实验

核查日期：2026-09-15。范围：冻结基础 LLM 时，Agent 如何从执行经验形成可复用程序、识别技能适用范围，以及处理未见过的技能组合。本文是研究方向补充，不是已实现功能说明，也不表示已经取得方法创新或实验结果。

与现有材料的关系：[论文矩阵](https://github.com/770122whrt/text2IFC/blob/09e8e9311f0b8c3ffc022dc42a12a48165ed7aa1/docs/reports/generation-demo/paper-matrix.md)、[IFC 与评价证据](ifc-evaluation.md)、[Coding 与知识证据](coding-knowledge-and-control.md)。本文件只扩展技能学习方向，没有改写原矩阵的条目数量。

## 1. 先给判断

**“Agent 会写工具、保存成功代码、检索复用、根据失败修工具”已经有很强的先例。** 冻结 LLM、技能库、前后条件、主动测试、跨任务复用，也都不能单独作为新颖性依据。现有工作的实验局限值得改进，但“在 IFC 上做得更扎实”不会自动产生一个新的 AI 方法。

仍值得验证的两个问题是：

1. **失败以后，怎样判断应该修程序、收窄适用范围，还是把一个过度概括的技能拆开？** 候选方法同时修订程序抽象和适用范围，用能够区分这些解释的执行反例来决策。
2. **怎样从已有程序中学出适合组合的新技能？** 候选方法用跨场景的关系变化和对象角色决定技能抽象，而不主要依赖代码重复或文字目标相似。

这两点也有强先例压力。真正需要证明的是：在相同基础模型、原子操作、编译器、信息和总预算下，它们能增加未见任务的成功覆盖，并减少错误迁移。不能只展示更多工具、更多 token、更大的模型或更复杂的建筑。

这里的“能力扩展”指**固定预算内能完成的任务集合扩大**。若原子操作已经能表达目标，新增宏技能并没有扩大语言的理论表达能力；它可能改善的是搜索、泛化和组合效率。IFC 是具有状态、对象关系和可执行检查的研究场景，这些困难也存在于其他领域的 Coding Agent。

### SK01. Voyager

**书目与正文：** Guanzhi Wang 等，*Voyager: An Open-Ended Embodied Agent with Large Language Models*，[arXiv v2](https://arxiv.org/html/2305.16291v2)。

**方法与证据：** 自动课程提出任务，LLM 写可执行 JavaScript，环境反馈和自验证支持迭代；成功程序进入技能库，以描述检索后复用。基础 GPT-4 不更新参数。§3 探索预算为 160 次提示迭代、3 次运行；达到钻石工具的结果不是每次都成功。迁移只涉及 4 个未见任务，每任务 3 次、最多 50 次提示迭代。去掉技能库后，3 个任务仍为 3/3，钻石镐为 2/3，说明该小组实验中库的作用也包括效率。

**边界：** 提示次数不等于全部 token 或技能获得成本；4 个迁移任务不足以证明广泛泛化。ReAct/Reflexion 的环境适配与课程差异也需区别于库消融。对我们而言，“从成功程序形成能力库”应作为基础对照。

<a id="sk02"></a>

### SK02. ExpeL

**书目与正文：** Andrew Zhao 等，*ExpeL: LLM Agents Are Experiential Learners*，[arXiv v2](https://arxiv.org/html/2308.10144v2)。

**方法与证据：** §4 从同任务的成功/失败轨迹和成功轨迹组抽取自然语言经验，允许增加、修订及投票删除；部署时结合经验和检索示例。GPT-4 提炼经验，GPT-3.5 执行。§5 与附录 D 涉及 100 个 HotpotQA、134 个可解 ALFWorld、100 个 WebShop 任务，采用作者的半训练半测试划分方案；经验收集允许重试。表 2–3 比较检索、经验和手写规则。FEVER 迁移还使用目标域少量示例来适配经验。

**边界：** 文本经验与示例迁移不是新问题；获得经验的强模型调用和失败尝试也有成本。把全部经验放进提示的设置不能直接证明长期扩张后的效率。Repair→Generation 若只是把修复总结放入提示，首先要超过这个对照。

<a id="sk03"></a>

### SK03. LILO

**书目与正文：** Gabriel Grand 等，*LILO: Learning Interpretable Libraries by Compressing and Documenting Code*，[arXiv v2](https://arxiv.org/html/2310.19791v2)。

**方法与证据：** §3 用 LLM 与枚举搜索找程序，Stitch 按描述长度压缩程序库，AutoDoc 为抽象命名及写说明；允许重新组织库，不是简单文本去重。§4 分在线求解与冻结库后的离线求解，后者不靠 LLM，能较干净地验证库本身的价值。附录 B.1 训练/测试为 REGEX 491/500、CLEVR 191/103、LOGO 200/111；三随机种子。每任务最多 4 提示×4 补全，并有 600/1,000/1,800 秒枚举预算及多轮库学习。

**边界：** 与廉价一次调用不在同一成本口径。主要是有明确输入输出的 DSL 任务，未直接验证 IFC 状态副作用。但“学习程序抽象+文档”“抽象提升未见任务”已被覆盖；我们的对照不能退化为机械 AST 去重。

<a id="sk04"></a>

### SK04. LearnAct

**书目与正文：** Haiteng Zhao 等，*Empowering Large Language Model Agents through Action Learning*，COLM 2024；[arXiv v2](https://arxiv.org/html/2402.15809v2)、[论文 PDF](https://arxiv.org/pdf/2402.15809)。

**方法与证据：** §4 学习 Python 动作及其说明，执行失败后可更新动作代码或补使用注释，并从多个候选更新中选择。训练每类仅 3 个任务；涵盖 4 类规划任务和 6 类 ALFWorld 任务，每类重复 3 次。表 7 区分只采样、不改函数、不改注释等消融；§5.5 同时观察到反复优化可能过拟合。本文核查未恢复全部测试实例的统一分母，因此不把平均成功率改写为具体成功个数。

**边界：** “失败后决定修代码还是写知识”已经是非常近的先例。新增方法必须超过其自由修改动作空间的强版本，不能只比静态技能库。少量训练任务不等于少调用：候选采样、评估和多轮学习都应计入。

<a id="sk05"></a>

### SK05. SkillWeaver

**书目与正文：** Boyuan Zheng 等，*SkillWeaver: Web Agents can Self-Improve by Discovering and Honing Skills*，[arXiv v1](https://arxiv.org/html/2504.07079v1)。

**方法与证据：** §2–3 从探索轨迹生成 Playwright API，再生成参数测试并调试；文档记前置状态，检索时过滤不满足前提的工具。每网站预探索 160 轮，每轮最多 10 步。WebArena 812 任务；另在 4 个真实网站选 57 任务。表 1 GPT-4o 的 WebArena 成功率为 22.6%→29.8%。§4.3 报告错误 API、错误参数、复杂任务超出基础 Agent 能力等失败。

**边界：** 不是完全不接触目标网站的迁移。一次宏调用可能包含多个底层动作，不能直接把步数减少解释为所有计算成本下降；探索成本也需要摊销。“带测试、前提检查的技能库”本身已不足以支撑创新。

<a id="sk06"></a>

### SK06. PolySkill

**书目与正文：** Simon Yu、Gang Li、Weiyan Shi、Peng Qi，*PolySkill: Learning Generalizable Skills Through Polymorphic Abstraction*，[arXiv v1](https://arxiv.org/html/2510.15863v1)。本卡只使用该版本结果。

**方法与证据：** §3 用抽象类表达领域无关目标，具体子类适配网站；新技能以重放原任务验证。跨网站可以重新学习实现，并非完全零适配。附录表 6：Mind2Web 训练 1,009，跨任务/网站/领域测试为 252/177/912；另测 812 个 WebArena 任务。静态库并非每项都提升，Qwen 跨领域为 37.5%→35.9%，在线版本为 39.9%。

**边界：** 效率统计仅覆盖成功轨迹，且宏记为一步；§6 承认初始抽象质量、长尾目标和网站变化等限制。抽象接口、角色复用和多个实现已有强先例；“按目标而非代码检索技能”仍不够新。

<a id="sk07"></a>

### SK07. Memento-Skills

**书目与正文：** Huichi Zhou 等，*Memento-Skills: Let Agents Design Agents*，[arXiv v1 PDF](https://arxiv.org/pdf/2603.18743v1)。HTML 抽取缺少部分实验，本卡以 PDF 为准。

**方法与证据：** §2 冻结基础 LLM，失败后归因到技能并修订文件，也可新建或重组技能；但检索路由器使用对比学习，因此不能概括为“完全无需训练”。§3：GAIA 165 个分为 100 训练/65 测试；HLE 使用 788/342 子集。训练成功率不是测试成绩；GAIA 测试报告 66.0%，静态基线 52.3%。每题允许 3 次反思重试；作者还发现许多 GAIA 学得技能未在测试中被调用。

**边界：** 基础 LLM 不训练不代表整个学习系统零训练，也不代表技能一定迁移。报告的聚合比例不能自行换算为整数成功数。学习、重试、合成测试及路由器成本均需单列。

<a id="sk08"></a>

### SK08. Contract2Tool

**书目与正文：** Rahul Suresh Babu、Laxmipriya Ganesh Iyer，*Contract2Tool: Learning Preconditions and Effects for Reliable Tool-Augmented LLM Agents*，[arXiv v1](https://arxiv.org/html/2606.07904v1)。2026-06 预印本，不假定已同行评审。

**方法与证据：** §III–V 从元数据、文档或状态轨迹学习前置条件、效果、风险和成本，再用因果过滤选工具。实验固定状态词汇，含 100 个合成工具、102 个多步任务；另有 283 个黄金决策步。表 V 中全工具/学习契约成功率为 .775/.980，报告每任务平均 token 为 26,172/2,528。主要轨迹是受控模拟环境的成功路径；主聚合排除了调用兼容性很差的一个模型。

**边界：** 这不是开放词汇、真实 IFC 或全成本实证；文中也承认稀疏轨迹遗漏罕见效果的问题。它直接覆盖“学契约后选工具”。单加关系前后条件不能宣称创新；主动反例尚需与下面的经典行动模型学习区分。

<a id="sk09"></a>

### SK09. SLBench

**书目与正文：** Xuan Chen、Chengpeng Wang、Lu Yan、Xiangyu Zhang，*SLBench: Evaluating How LLM Agents Follow Logical Relations in Skills*，[arXiv v1](https://arxiv.org/html/2607.09016v1)。2026-07 预印本。

**方法与证据：** §3 分析前后条件、约束、回退、例外、覆盖等 8 类技能逻辑，构造仓库与产物检查任务。大规模构建语料不能混同评价分母：核心为人工审计的 86 例，39 控制/47 违规触发。表 2 同时有 unsafe 与 inconclusive。§4.3 的缓解结果是选出的 11 个此前违规案例降至 4 个；其守卫评价还把未违规的 inconclusive 合入 safe，不能直接解释为整体任务成功提升。

**边界：** 逻辑遵循和 IFC 空间关系并非同一种关系，但“技能有关系义务，调用前后检查”已有先例。附录约 1.017 亿 token 是整个构建/评价流水线的估计值，不是每项方法的精确线上成本。

## 3. 不可跳过的经典先例与近领域对照

<a id="sk10"></a>

### SK10. DreamCoder：程序库抽象不是新问题

Kevin Ellis 等，*DreamCoder: Growing generalizable, interpretable knowledge with wake-sleep Bayesian program learning*，[原始论文 PDF](https://arxiv.org/pdf/2006.08381)。F：读 wake/sleep、抽象学习与实验部分。它在搜索程序后学习可复用 DSL 抽象，考虑语义等价的程序重写，还训练识别网络引导搜索；不能把对照简化为字面片段去重。列表实验含 218 任务、半训练半测试，另覆盖多个领域；递归任务展示使用较大的时间与 CPU 预算。对我们的约束是：**“程序压缩促进组合泛化”已经是成熟研究问题**。冻结 LLM 的轻量实现可与其思想比较，但不能假装同样复现了完整 DreamCoder。

<a id="sk11"></a>

### SK11. 主动行动模型学习：区分前提的探测也不是新问题

Rushang Karia、Pulkit Verma、Alberto Speranzon、Siddharth Srivastava，*Epistemic Exploration for Generalizable Planning and Learning in Non-Stationary Settings*，ICAPS 2024，[出版商 PDF](https://ojs.aaai.org/index.php/ICAPS/article/download/31489/33649/35546)。F：§2–4、结论。方法考虑谓词作为前提/效果的正、负、缺省候选，构造区分候选行动模型的规划问题，执行探测后更新；环境变化时只重学有关部分。实验使用 4 个规划域、每任务 100,000 步和 10 个种子等条件。它学习的是行动模型，不是同时改写新宏程序。**主动探测本身已有先例，剩余问题必须落在“程序抽象与适用范围共同变化时如何决策”。**

另一条直接近邻是 CoLLAs 2023 的主动关系状态抽象学习，现已完成正文补核，见 [SK15](#sk15)。它使 S2 的新颖性边界进一步收窄。

<a id="sk12"></a>

### SK12. ToolMaker：自动获得新工具已有可运行系统

Georg Wölflein 等，*LLM Agents Making Agent Tools*，ACL 2025，[出版商全文](https://aclanthology.org/2025.acl-long.1266.pdf)。F：§3–5、表 2–3、局限。给定论文代码库与工具要求，先建立可重现环境，再实现和调试 Python 工具。TM-Bench 为 15 个工具任务、42 个测试调用、124 个单元测试；完整工具通过为 12/15，OpenHands 为 3/15。两者平均生成成本也不同：作者报告每工具 $0.94/$0.15、21.8/7.5 个动作。失败例揭示输入示例不覆盖特殊情况会限制泛化。因此“任务需要时自己造工具”不是新贡献，较高成功率也要与额外测试/搜索预算区分。

<a id="sk13"></a>

### SK13. CREATOR：抽象工具与具体求解分开已有

Cheng Qian 等，*CREATOR: Tool Creation for Disentangling Abstract and Concrete Reasoning of Large Language Models*，Findings of EMNLP 2023，[出版商全文](https://aclanthology.org/2023.findings-emnlp.462.pdf)。F：§3–4、表 2–4、附录 A。流程是创建通用函数、为实例决定调用、执行、根据错误修正。实验含 MATH、TabMWP 和 2K Creation Challenge；前两者只选数字答案，约覆盖原问题的 80%，不是完整测试集。基线包括带修正的程序求解以及不分离阶段的消融。若我们只把任务分成“先写小工具、再组合求解”，应先视为已知方案。

<a id="sk14"></a>

### SK14. AdaPlanner：子目标断言、继续执行和成功记忆已有

Haotian Sun 等，*AdaPlanner: Adaptive Planning from Feedback with Language Models*，NeurIPS 2023，[会议全文](https://papers.nips.cc/paper_files/paper/2023/file/b5c8c1c117618267944b2617add0a766-Paper-Conference.pdf)。F：§3、实验/附录 B、§6。Python 计划包含子目标断言，区分符合预期和偏离预期的反馈，必要时改计划并从中间恢复；成功计划作为后续示例。ALFWorld 134 环境；MiniWoB++ 53 类任务使用 38 个人工示例加 21 个发现示例，部分基线结果来自既有论文。作者承认复杂任务仍依赖专家示范。因此“有 Agent loop、子目标验证、失败恢复、经验库”都不宜作为新颖性主张。

<a id="sk15"></a>

### SK15. 主动关系状态抽象：效果分组与角色化算子已有

**书目与正文：** Amber Li、Tom Silver，*Embodied Active Learning of Relational State Abstractions for Bilevel Planning*，CoLLAs 2023，PMLR 232:358–375；[出版记录](https://proceedings.mlr.press/v232/li23a.html)、[会议全文](https://proceedings.mlr.press/v232/li23a/li23a.pdf)。**F**：§2–5、图 3、§7、附录 A.2–A.4；使用 18 页会议版。

**方法：** §3.2 按控制器及对象替换下等价的关系效果分组轨迹，用前态交集学前提，替换对象为变量角色，再学习连续参数采样器。§4 用神经网络集合的预测熵选择提问，并前瞻模拟到信息较大的状态；每轮重学谓词解释、算子和采样器。谓词名、对象类型和控制器事先给定。

**实验与代价：** 3 个模拟域、6 个基线；每域 50 示范、1,000 探索转换、50 留出任务、10 种子。Blocks 从 3–4 块迁移至 5–6 块。图 3 与 Ask All 成功表现接近但查询更少；随机查询只近似匹配数量。规划限 10 秒，主指标未合计全部模拟/训练成本；§7 报告每次运行通常 3–36 小时。已知模拟器、脚本专家标签和预设谓词限定结论。

**对候选的判断：** 效果分组、角色抽象、条件与参数学习均已有。尚未把自生成程序的代码修补、条件收窄和库拆分作为竞争方案选择；也未合成新的宏程序。因此 S1 仍须证明修订选择的增量；S2 若只给已有动作分组或重排，应降为基线。这个剩余空间判断是本项目的推论，不是论文替我们证明了新颖性。

### B12 回查. Cobbie：IFC 内的自动工具也未必更好

*BIM Information Extraction Through LLM-based Adaptive Exploration*，[arXiv v1](https://arxiv.org/html/2605.01698v1)；原卡见 [B12](ifc-evaluation.md#b12)。本轮复核 §3.3、实验设置、表 3 与局限。

它已包含自动工具提炼、错误工具分析、调试、复测与限量工具库。使用 513 个开发问题、514 个测试问题，涉及 21 项目/37 IFC，但按问题划分不等于未见建筑划分。GLM-4.7 无增强/自动工具为 56.0%/55.4%，较弱模型为 25.7%/23.8%；不能假定自动工具必然扩展能力。崩溃/超时被排除、单次运行，也限制全成本比较。这是 IFC 问答而非生成，但应纳入自动工具基线设计。

## 4. 候选 S1：用反例联合修订程序与适用范围

### 4.1 Motivation

一个成功过的“向墙加入窗”程序可能依赖隐含条件：输入是墙自身局部坐标、窗洞尚不存在、宿主和空间容器一致。另一栋建筑看起来相似，这些关系却可能不同。失败时，简单改代码可能破坏原来成功的场景；只写一句警告又可能放弃本来可解的场景。

问题不是有没有前置条件，而是：**一条失败证据究竟要求修实现、修适用范围，还是重新划分技能？** 成功轨迹本身通常无法区分这三种解释。

### 4.2 候选机制与新增行为

一个技能保存程序、参数对象的角色、适用条件、预期关系变化，以及在指定场景上观察到的不变关系。它们都是有适用域的经验描述，不能称为全局正确性证明。

面对失败，维护三类候选解释：

1. **实现缺陷：** 场景应在适用范围内，但程序遗漏坐标变换或绑定，应该修程序。
2. **范围过宽：** 程序原本只覆盖某一结构，应该修适用条件，随后交给其他已有技能处理。
3. **抽象不合适：** 一个名字混合了需要不同实现的关系模式，应该拆分技能，再调整检索与调用。

在开发场景的临时副本上构造这些解释会作出不同预测的探测例。探测必须保持初始模型有效，并尽量只改变宿主、对象别名、坐标关系或既有开洞等一个因素。执行结果用来选择或否定修订。结果仍不能确定时，保留“未知”，不能靠默认拒绝制造虚假的可靠性提升。

**先导版可执行决策规则：** 对每个候选修订，预测它在合法探测池上的“可调用/结果关系/破坏关系”；选择候选分歧最大且执行成本较低的探测。更新时共同比较开发任务覆盖、错误适用、原成功场景退化和库复杂度，不允许只凭最新失败被修好就接收。权重在开发集固定，测试集不参与选择。这个规则只是待检验的起点；若普通主动行动模型学习加自由代码修订就能达到同样效果，应承认组合机制没有额外贡献。

**研究假设 S1：** 与自由修改代码/注释、固定程序的行动模型学习和成功轨迹契约学习相比，联合选择“修程序/缩范围/拆技能”能够用相同探索成本减少负迁移，并提高未见关系场景的完整任务成功率。

这里可能新增的是**程序与适用范围共同变化时的修订准则和信息获取方式**。主动测试来自行动模型学习；代码修订接近 LearnAct；契约提取接近 Contract2Tool；拆实现接近 PolySkill。[SK15](#sk15) 也已联合更新谓词解释、行动算子与参数采样器，因此泛称“联合学习技能和条件”仍不够。要检验的是三个竞争修订之间的选择是否提供额外收益；仅把既有部件串成提示流程，仍有很高的增量不足风险。

### 4.3 与假设一一对应的实验 S1-E

| 要证明的行为 | 可执行对照 | 支持与否定信号 |
|---|---|---|
| 能区分程序错误与范围错误 | 同一失败前缀后，提供成对合法场景：一个应修程序，另一个需换实现；比较固定契约、代码单改与联合修订 | 既减少错误适用，又保留可解场景；若只增加拒绝，不支持 |
| 探测有信息价值 | 所有方法获得相同探测次数、候选数与模型预算；主动选择 vs 随机有效扰动 vs 通用 LLM 测试生成 | 等成本下更少探测达到相同未见成功率；若随机测试一样好，主动机制不成立 |
| 学到可迁移范围 | 在不同基础建筑、对象角色和关系配置测试，不沿用开发失败的近重复变体 | 未见关系族及边界例同时提升；只修好见过的例子不支持 |
| 联合修订有必要 | 相同探测器下比较代码单改、范围单改、允许拆分的联合版本 | 联合版本减少原成功任务变失败；若单改即可解释收益，联合方法不成立 |

**任务建议。** 先选原子 API 已支持的 3 个技能族，例如宿主开洞/填充、带局部坐标的重复构件、跨层容器绑定。这个列表是设计候选，尚未逐项核查当前 Generation 的原子操作覆盖；不能为制造难题同时给候选新增 API，而基线不给。每族至少包含正常例、表面相似的反例、参数边界例和另一基础场景。有关数据必须独立确认初始有效性。

**强基线。** 主表保留同模型 CodeAct 式直接编程；LearnAct 式代码/说明更新；SkillWeaver 式生成测试与调试；Contract2Tool 式文档+成功轨迹契约；固定程序的主动行动模型学习；完整 S1。无需先完整复现所有原作者系统，但每个适配版必须记录保留/改变之处。人工契约作为诊断上界，不冒充自动方法。

**预算与消融。** 各法获得相同原子操作、编译器、状态观察、初始库、开发案例、检索语料及检查器。把“主动/随机探测”与“单改/联合改”分开消融。每次失败调用、候选修订、探测、检查和保存库的成本全部计入。只有候选多拿探测预算的实验不能支持 S1。

**拆分。** 按基础建筑/模板来源划分，开发与测试隔离；另留出关系组合。只换 GUID、旋转同一模板或从同一 IFC 拆子文件不能当作独立建筑泛化。固定库的盲测与允许边测边学的连续任务流分开，后者必须给所有基线同样更新机会。

**指标。** 主指标为全部任务的几何、关系和用户要求联合成功；同时报告条件误接受率、误拒绝率、未知率、先成功后失败的负迁移率、条件/效果预测正确率，以及学习成本随后续 1/5/20/更多任务摊销的曲线。误接受率必须在真实不适用案例上定义；不能把通过测例说成普遍保证。

**停止或转向条件。** 成本匹配后收益消失；仅靠多拒绝提升安全率；只在手写谓词对应的已知边界上有效；或 LearnAct/固定契约更新已达到相同收益，则暂不主张这个方法创新。若技能拆分导致库爆炸，必须计入选择和维护成本。

### 4.4 投入与 Demo

**低投入先导版：** 冻结 LLM，先用小型有限关系词汇、现有原子操作、3 个技能族；LLM 提候选解释，确定性程序选择分歧最大的合法探测。先检查失败是否真的具有“修代码/修范围/拆技能”的歧义。这能验证机制是否值得投入，但手写全套适用规则不算自动学会。

**较强研究版：** 自动提出新关系谓词、学习角色绑定并联合做技能拆合。难度明显增加，需要防止候选模型空间不可控和错误观察传播；可以保持基础 LLM 冻结，不必先训练新模型。

**可演示结果：** 两个外观近似的场景原先共享错误技能；系统展示一个有区分力的探测，再解释为什么修实现或改用另一技能，最后展示在第三个未见场景的表现。演示应展示范围与未知状态，不宣称“一次修复后永久正确”。

## 5. 候选 S2：按可组合的关系效果学习技能抽象

### 5.1 Motivation

两段代码相似，未必可以安全地合为一个技能；两段代码不同，却可能完成相同的关系变化。例如“布置一排窗”不仅生成若干窗，还需各自属于正确的洞、宿主及楼层。把其代码压成函数能缩短提示，但未必让它能与另一层、共享墙或已有开洞的任务组合。

因此候选目标不是学习最短的程序库，而是学习**能在未见对象配置中正确绑定与组合的程序库**。这仍属于已有程序抽象和关系规划研究，需要用新行为来证明增量。

### 5.2 候选机制与新增行为

从合法的执行前后状态及程序中提取局部关系变化，把具体 GUID、绝对坐标替换为经过验证的角色和参数。抽象候选要同时说明：读了哪些角色、改变了哪些关系、产生哪些可供下一个技能使用的角色，以及在哪些上下文中未破坏已知关系。

程序相似度仅用来提出候选。是否合并技能，进一步依据**角色绑定后的效果是否在不同开发场景中一致，以及是否帮助留出的开发组合求解**。效果冲突则保留多种实现或拆分，不能为了压缩强行合并。组合时绑定输出和输入角色，并显式处理同一对象被两个技能共享、坐标层级和修改范围交叠。

**先导版可执行选择规则：** 给相同候选宏分别计算代码压缩得分，以及角色对齐后关系效果的一致率、开发组合成功率和副作用率；在相同库容量下各自选库，再交给完全相同的规划器盲测。候选生成也计成本，不能先用测试答案挑出正确宏。较强版本再把效果反例反馈到参数化与宏边界的修订中，而不只是给既有宏重新排序。

**研究假设 S2：** 在相同原子操作、库容量和总预算下，按关系效果与组合收益学习的抽象，比按程序压缩或文字目标形成的抽象，更能完成未见技能组合；优势不只来自代码变短。

可能新增的是**用组合表现来修订新宏程序本身的参数化与边界**，不是关系检查器、参数化函数或面向对象接口本身。[SK15](#sk15) 已覆盖对象替换下的效果分组和角色化算子；因此仅按关系效果聚类、提取前后条件或给既有宏重排，不能支撑 S2。新宏程序的抽象还须同时面对 DreamCoder/LILO 与 PolySkill 的先例，当前仍是高风险研究假设。

### 5.3 与假设一一对应的实验 S2-E

| 要证明的行为 | 可执行对照 | 支持与否定信号 |
|---|---|---|
| 抽象捕捉效果而非表面代码 | 加入“代码相似但关系效果不同”和“代码不同但效果相同”的成对程序 | 抽象决策与跨场景执行一致；若只有名称分类正确，不支持 |
| 能做未见组合 | 学库时只见单项技能和部分组合，测试留出组合拓扑，同时匹配对象数量与任务长度 | 留出组合完整成功提升；只是处理更多对象不支持组合泛化 |
| 角色绑定能迁移 | 更换合法对象身份、基础场景、局部坐标与共享对象结构 | 不依赖开发 GUID 或固定坐标；去角色绑定显著退化 |
| 收益超过压缩与多工具 | 同容量库、同模型、同检索器/规划器/检查器，比较 LILO 式抽象与多态目标抽象 | 同预算下新增可解任务；只有 token 减少而成功不升，只支持效率 |

**任务建议。** 开发见过宿主开洞、同层重复构件和局部空间绑定；测试组合为多层重复、两侧共享宿主或已有洞的插入。先保持原子几何和关系操作不变，避免把新几何类型的 API 支持混为学习能力。第二阶段才考察两种已有合法表示或作者工具链之间的迁移；不得一开始假设当前系统支持跨表示编译。

**强基线。** 完整程序检索但不抽象；LILO 思路的程序压缩+命名；PolySkill 思路的目标抽象+具体实现；SK15 思路的固定动作按效果/角色分组并学习前提；成功技能库检索；人工宏库诊断上界；完整 S2。程序压缩基线应允许适当的语义重写，不是只比较字符串。第一轮用同一规划器、同一契约检查和同一检索预算，隔离“库如何学”这一变化。SK15 适配基线只保留这里需要的结构学习机制；若额外训练神经谓词或采样器，必须另行标明并计费，不宣称是无需训练的等价复现。

**消融。** 去关系效果、去角色绑定、去共享对象分析、只按压缩得分选抽象、只按自然语言目标聚类，以及不做跨场景候选验证。库条目数量和文档 token 容量都要控制；宏的执行成本展开为原子操作，不能把十个动作包装后只算一步。

**拆分。** 使用基础建筑隔离和 leave-combination-out；同时报告参数外推、组合外推与表示迁移，不能合并成一个 OOD 数字。未见组合应具有与已见组合相近的对象数和所需操作数，减少“更长任务天然更难”的混淆。开发组合只能用于选择库，测试组合不可用于反复修库。

**指标。** 全任务联合成功、无效角色绑定率、跨技能副作用率、在给定预算内可完成的组合深度、库学习及调用总成本、库大小。报告每一项原子技能正确时组合仍失败的切片，直接测组合问题，避免结果主要受单项几何失败支配。

**停止或转向条件。** 只有代码长度变短；提升由人工定义的正确宏贡献；已见组合好而未见组合无收益；或者 PolySkill 式抽象已达到同样效果，则不支撑 S2 的新增机制。有限测试上的效果一致不是一般程序等价证明。

### 5.4 投入与 Demo

**低投入先导版：** 固定有限关系词汇，用现有 3–4 个宏候选和多场景执行记录，比较“按压缩选宏”和“按组合效果选宏”。这是对研究假设的诊断；如果候选全由人工写好，不可称完整自动技能发现。

**较强研究版：** 从多份程序自动归纳角色、效果和抽象，再做跨场景验证及拆合。实现与评估投入都高于 S1，尤其需要防止抽象提取器把评测规则答案编码进技能。可用冻结 LLM 提案与确定性验证，不必先做权重训练。

**可演示结果：** 展示学库时没有出现过的组合请求，解释各技能的角色如何衔接，并展示一个表面可组合却因共享对象而无效的候选为何被排除。价值在可迁移组合行为，而非工具数量动画。

## 6. 两个次级方向：适合作为实验轴，暂不独立宣称方法创新

| 方向 | 候选机制与 IFC 例子 | 一一对应的实验 | 主要风险与投入 |
|---|---|---|---|
| S3：Repair 经验迁移到 Generation | 将公开可用修复轨迹转为角色化关系变化与适用条件，供新建任务调用；如修正洞/宿主关系后，学会在新建时正确组合 | 未见建筑生成：原始修复轨迹 RAG、ExpeL 式文字经验、同成本生成成功轨迹技能、S1/S2 式抽象；固定全部尝试预算 | 跨工作流不是自动的方法创新。只有同一损坏模板复用不够；更适合作为 S1/S2 的迁移检验。低到中投入 |
| S4：只合成缺失的能力 | 从目标关系与已有技能效果的差额提出残余子任务，只合成可复用缺口；如已有宿主/填充技能，但缺少某种合法角色适配 | 对比整程序重写、检索后写程序、CREATOR/ToolMaker 式造工具、PolySkill 式实现适配；看新技能是否帮助多个未见任务并摊回获得成本 | “先复用再生成”和工具创造已有。差额是否真实取决于模型完备性，不能把 LLM 的自述当作最小性证明。中投入，高先例风险 |

S3 必须遵守输入隔离：修复时不可提供的 pristine、private Gold、损坏配方或私有身份映射，不得经“经验库”流入生成或修复 Agent。能用于学习的轨迹应事先明确来源和允许角色；目标测试建筑及其完整正确产物不进入库。缺失的用户意图不能从未获授权的评测答案补回。

S4 的“最小”在低投入版本只能限定为**给定技能/效果词汇下发现的一个小缺口**，不宣称全局最少操作、最小程序或真正能力边界。

## 7. 哪一个先做，以及什么结果才值得写论文

| 排序 | 方向 | 方法空间 | 近期可验证性 | 需要先回答的判断题 |
|---|---|---|---|---|
| 1 | S1 程序与适用范围联合修订 | 有空间但强先例多；关键是修订选择规则与样本效率 | 较高；可用有限关系词汇做小实验 | 真实失败中是否存在不能靠单纯修代码解决的范围歧义？ |
| 2 | S2 关系效果驱动的组合抽象 | 潜在上限更高，也更容易退化为已有抽象方法 | 中等；需可靠状态差分与组合数据 | 同样压缩度下，关系效果是否真的改变未见组合成功率？ |
| 3 | S3 Repair→Generation | 作为迁移证据有价值，独立方法新颖性较弱 | 较高，前提是轨迹来源/角色清楚 | 迁移的是关系知识，还是记住某种损坏或建筑模板？ |
| 4 | S4 缺口合成 | 已有工具创造和规划先例压力最大 | 中等 | 对比强复用+生成基线，是否还出现可重复的总成本优势？ |

建议先做机制诊断，再决定系统扩建。例如 S1 先冻结约 12 个开发场景、24–48 个组隔离测试场景，覆盖三个技能族；这些数量只是先导规划，不是足以支持统计结论的功效计算。若现有失败几乎全是单例代码缺陷而非范围歧义，应及早转向 S2 或其他方法问题。

正式实验预先确定主指标、组划分、预算和比较方向；用以建筑/任务族为单位的配对不确定性估计，保留全部失败。先导小样本只能决定是否值得继续。效果大小、后续任务数量与成本摊销都要足够实用，不能凭一例成功升级为系统能力。

**有希望的 Demo 叙述：** 一个可观察其学习过程的建模 Agent，从执行中发现技能的使用边界，并在新任务中正确复用或组合；用户可以查看请求、关系变化、失败原因和修订依据。这个叙述必须由上述对照支持。可演示系统的完整性与 AI 方法新颖性是两项不同判断，不能因为工程更完整就免除方法比较。

**当前可写的克制版本：** “我们研究冻结基础模型的建模 Agent 如何从执行经验中形成可迁移技能，重点考察程序抽象与适用范围的联合修订，以及关系效果对未见技能组合的帮助。”现在应使用“研究、提出候选、检验”，而不是“首次、保证、已经显著提升”。

本轮产出仅为文献与实验设计。没有修改 Generation/Repair 行为，没有新建数据集，没有模型训练或真实 LLM 调用。后续若进入行为修改或 Provider 实验，需要按现有 [Agent 能力评价协议](../../../validation/agent-capability-evaluation.md)完成相应阶段的测试与准入。
