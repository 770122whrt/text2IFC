# text2IFC：Self-Verification 重合核查与方法方向扩展

> **历史材料，2026-09-16已整合。** 当前方向与实验统一见[研究方案](../research-plan.md)，文献统一见[简版](../literature-review-short.md)和[完整版](../literature-review-full.md)。下文保留调查时的结论与编号，不再作为当前优先级。

日期：2026-09-15。当前讨论入口为 [简洁记录](https://github.com/770122whrt/text2IFC/blob/09e8e9311f0b8c3ffc022dc42a12a48165ed7aa1/docs/reports/generation-demo/research-shortlist.md)。本轮撤回“只在技能归因和空间澄清中选一条”的过早收敛；这两项保留为候选机制或演示设计。没有执行新实验，也没有选定或实现下列方法。

## 1. Motivation：现有系统能承载什么研究

Self-Verification 已经覆盖“把请求变成检查，再用反馈改 IFC”的核心流程。我们的确定性编译、ChangeSet、局部保全和证据记录提供了研究基础，但系统更加完整不能自动推出方法更加新颖。

更宽的切入点是：**把 text2IFC 作为一个能观察动作结果的空间环境，研究 Agent 怎样理解、规划并学习对这个环境的修改。** 同一个操作可能同时改变对象属性、宿主、洞口、楼层归属和世界坐标；多个操作可能相互影响，最终正确答案还可能不唯一。

这类问题也出现在数据库修改、机器人规划和复杂软件维护中，不能宣称 IFC 独有。IFC 的价值在于能把这些变化落到可检查的实际产物上。自然语言到空间仍是应用故事；AI 论文需要进一步回答某个具体的学习或决策问题。

对当前基础的判断：可以复用编译与重开检查、受支持的编辑、运行记录、部分恢复与渲染；尚不能把它们当成通用空间求解器、动作效果预测器或学习环境。部分现有检查从 Brief 派生，漏掉的用户要求可能同时漏出生成与评价。代码边界见后方证据与 [前轮代码核查](research-shortlist-evidence.md)。

## 2. Novelty：先展开，再筛选

以下 12 项是问题池，不是 12 项创新；只分三个模块。V、P、L 是本轮讨论编号，不替换原 N01–N08 历史记录。

| 模块 | 候选问题 | 本轮处理 |
|---|---|---|
| 验证与意图 | V1 检查能否区分有效与无效空间编辑；V2 原始要求到检查的遗漏定位；V3 多种合理解释与回答不确定性；V4 学习何时继续验证、重做或停止 | V1 展开；V2 是必要评价基础，已有直接方法；V3 保留旧澄清路线；V4 通用预算控制先例多，暂不主推 |
| 空间表示与规划 | P1 多步动作的关系/几何效果预测；P2 房间连接方式与连续尺寸联合求解；P3 坐标等价下的组合泛化；P4 生成可反复编辑的设计程序 | P1/P2 展开；P3 可做泛化约束与测试；P4 已有直接程序化场景/可编辑 CAD 工作，不能仅把 JSON 换成 DSL |
| 能力学习与扩展 | L1 按跨任务学习进展选课程；L2 从修复轨迹学习对未来生成有用的策略；L3 将知识转成可验证操作/约束；L4 从当前工具组合出新的建模能力 | L1 展开，L2 是迁移检验；L3 单纯工具化和知识编译已有先例；L4 仅自动建技能不新，需组合边界机制，成本较高 |

### P1：学习编辑效果，支持有保全要求的多步规划

**Motivation。** 改一个墙体尺寸，下一步开窗可能失败，远处的关系也可能受影响；只看当前错误报告，难以判断哪条修改路径更好。

**候选方法。** 从独立执行的状态—操作—结果学习对象/关系变化，并显式建模“不应改变的部分”和两步操作的相互影响。初期固定 LLM，训练小型效果模型或排序器，用预测筛选短序列；不确定的分支再实际执行，最终仍由真实编译检查接受。要研究的是这种效果分解能否跨建筑、对象身份和操作组合迁移。

**已知先例与可能空间。** 程序世界模型、动作模型学习和 repair 记忆都已有。只预测成功率或检索相似补丁不够；需要证明带关系/保全结构的状态转移表示，对未见组合和长序列有效。把预测称为“因果模型”还需要有效干预与识别条件，当前不作这个主张。

**Experiment P1。** 相同候选操作、训练轨迹和推理预算，比相似轨迹检索、标量成功预测、一般状态预测、候选效果分解；另比同预算纯真实执行搜索。留出建筑族、操作组合和更长序列，测最终完成率、副作用漏报、保全失败、预测校准和全部成本。若真实执行已足够便宜或分解不改善泛化，就不值得建立世界模型。不能从一步预测准确推出规划更强。

### P2：学习空间分解，联合处理连接关系与尺寸

**Motivation。** 例如“每个房间可达、走廊连续、房间面积达标”同时成立时，局部挪动一面墙可能无解；必须改房间连接方式或重新划分部分区域。

**候选方法。** 在受限平面布局子域中，LLM 提出关系/拓扑候选，确定性求解处理尺寸和已编码约束；沿生成来源，把几何冲突变量映射到造成冲突的连接、宿主或分解决策，再选择需要重开的边界、变量或拓扑分支。先研究固定关系集合下的冲突提升与分支选择，暂不声称自动发明任意建筑约束。学习策略还应比较简单来源规则，避免额外模型没有必要。

**已知先例与可能空间。** LLM+求解器、最小冲突核、程序搜索本身均已有。候选差异应落在跨几何与关系依赖的可迁移分解策略，并超过相同表示上的通用求解或搜索，而不是给自己的系统额外提供更强工具。

**Experiment P2。** 所有组使用同一约束表达和求解器，比直接数值生成、固定分包、通用搜索/冲突核修复、学习分解。按关系组合和空间规模留出，加入真实不可行请求；测满足全部要求的比例、错误拒绝/错误声称无解、求解分支与总成本。先用人工正确的约束隔离规划机制，再接自然语言，单列转译错误。只对求解器能证明的子域报告无解。

### V1：学习有区分力的空间检查

**Motivation。** 检查通过可能因为要求漏了，检查失败也可能是合法的另一种设计被误杀。Self-Verification 的案例和我们的 Brief 依赖都提示需要单独评价这个问题。

**候选方法。** 基于原始要求和有效编辑对，学习哪些干预应改变检查结论、哪些应保持结论，进而选择或修订检查。关注同图像不同关系、不同表示同空间效果等情况。需同时接受多种合法答案，不能将偏离单一参考 IFC 一律当错。

**Experiment V1。** 固定初始生成物，比静态 Gate、任务特定自验证、Spec-Harness 式随机有效变异、候选检查策略；测真实错误漏检、合法替代设计误拒与成本，再接闭环测最终成功。测试建筑与干预族独立留出，真值来自独立要求标注/规则。若只提高合成 mutation 分数，或者随机变异已同样好，按评价工具而非 AI 方法定位。先例压力很高。

### L1：用迁移收益选择训练课程

**Motivation。** 有生成和修复轨迹，不代表它们都会帮助未来任务；更难的修复样例也可能只让模型学会识别人工损坏模板。

**候选方法。** 在可执行场景中生成有保证可行的任务和局部破坏，按训练后对另一类开发任务的改善选择课程，同时约束旧能力退步。初期训练小策略或有限规模适配；若要提升 LLM 本身，则单列 LoRA/SFT/RL 版本、算力与数据成本。候选核心是跨任务学习价值估计，不是“自动造难题”或“把成功轨迹微调一遍”。

**Experiment L1。** 固定训练预算和底层操作，比随机任务、按失败率/难度取样、普通成功轨迹 SFT、迁移进展课程；测外来建筑上生成与编辑的共同提升、未见关系组合、旧任务退步。必须有“修复训练→无修复的首次生成”检验，排除仅靠更多重试取得成功。课程只能读取训练/开发反馈，最终测试集完全封存。若同量通用轨迹训练同样有效，就不主张新课程方法。

## 3. Evaluation、投入与原始文献证据

**当前建议：先比较 P1 与 P2 的先导信号，不再默认旧 A/B 优先。** 两者改变的是 Agent 对环境的预测或求解方式，更符合用户希望的能力层创新，但这不等于新颖性已经成立。V1 作为必须正面比较的自验证研究支线；L1 保留更长期的学习路线。不要四条同时实施。

初步工作量为一名熟悉仓库的研究开发者的累计人周，含小型诊断与基础数据整理，排除正式用户研究、投稿规模实验和算力等待；具体估计结合下方近邻与代码条件再确定。训练和模型选择成本必须计入，不以推理 token 节省掩盖前期投入。

| 方向 | 问题诊断 | 稳定方法与公平对照的累计工程估计 |
|---|---|---|
| P1 多步编辑效果 | 1–2 人周 | 8–14 人周；3–4 类受支持动作、有限长度计划，初期小模型 |
| P2 结构与几何联合搜索 | 1–2 人周 | 10–18 人周；正交布局、受限关系和一个求解器 |
| V1 检查区分能力 | 1–2 人周 | 5–8 人周；有效正负编辑对与独立要求标签 |
| L1 迁移课程 | 2–3 人周 | 8–12 人周；有限规模 SFT/LoRA，完整在线 RL 另估 |

下方独立报告中的 3–5/4–6 人周是更窄的判别/求解原型，不等于有全部强对照、跨任务迁移和稳定接入的完整方法。以本表作为当前综合估计。

共同对照保留两层：完整任务对照给通用 Coding Agent Python/IfcOpenShell 与正常调试能力；方法隔离对照固定基础模型、工具、编译器、公开信息和总预算。所有失败计入分母，按建筑/任务族隔离，允许多个合法结果；不使用同一份生成 Brief 作为唯一意图真值。真实 Provider 实验仍须遵循仓库现有准入协议，本轮未执行。

### 验证方向补查：先确认检查有没有漏，再讨论自验证

日期：2026-09-15。下列是指定版本正文核查，未复现作者结果。用户所指 Self-Verification 暂按已有矩阵 B03 的同名 Text-to-BIM 文章理解，尚未收到另一篇文章的定位信息。

#### 直接重合：Self-Verification

[A Self-Verification Framework Toward Reliable Text-to-BIM Generation](https://ec-3.org/wp-content/uploads/2026/08/EC32026_444.pdf)，Sesterhenn 等，EC³ 2026，2 页。重读全部正文与两幅图。Specifier 从请求产生 IDS 和非 IDS 要求，Modifier 创建/修改 IFC，Verifier 写并执行补充检查，结合 IfcTester 反馈继续修订；工具基于 MCP4IFC。非 IDS 明确涉及几何、拓扑、复杂关系，不能说它只查属性。

实验是 GPT-5.2 的一个两层住宅案例、五轮修订；房间计数、屋顶和材质改善，空间与楼层关联仍未解决。论文没有提供可支持总体优势的系统对照或消融；作者明确承认初始规格可能漏需求。**证据弱不代表方法不存在。**

[作者仓库](https://github.com/Tsesterh/Text2BIM-Self-Verification)另确认 spec.md、IDS、逐轮 IFC/报告与合并 patch plan 的实现组织，依赖 MCP4IFC；本轮只核 README，不宣称运行成功。

| 对比点 | 与 text2IFC 的关系 | 对 claim 的影响 |
|---|---|---|
| 请求→规格→模型→检查→修订 | 与 Brief、Expected Facts、Generator、Gate/Audit、ChangeSet 的总体逻辑重合 | 不能以闭环、角色拆分、自动反馈为独立方法创新 |
| 按任务产生检查 | 对方已有 IDS 与代码检查；我们部分事实从 Brief 派生 | 不能说任务特定验证是我们的首次贡献；双方都面临规格遗漏 |
| 执行边界 | 我们有确定性编译、受支持操作、局部保全等基础 | 可解释实现与保障范围，不能直接推出 AI 方法新颖性或质量更高 |
| Repair 的任务范围 | 对方案例是生成中的纠错；我们的已有 IFC 修改还涉及外来模型、目标定位与保留已有状态 | 是有价值的任务差异；若要成为方法，须证明一种机制跨生成和外来模型编辑迁移 |

#### 仍可研究，但不冒充已经新颖

**候选 V：学习区分“应该改变验证结论的编辑”与“不应该改变结论的编辑”。** 一个窗修改了 GUID 或整个模型合法换了坐标表示，要求的真假可能不变；窗移到别的宿主、空间误归楼层，真假可能改变，即使图像相似。对每条公开要求，从有效编辑对中学习检查选择/改写策略，兼顾漏检和误杀。重点是跨实体、关系与坐标层级的有效干预与迁移，不是给 mutation testing 改名。

**一一对应实验。** 固定生成器和初始产物，先比静态 Gate、Self-Verification 式任务检查、Spec-Harness 式随机有效变异、候选策略。测试集按建筑与编辑族同时留出；由独立规则/人工标注给出要求真假。测错误通过、正确结果误拒、真实错误定位、检查成本；再接闭环测最终任务成功。若只发现更多合成错误、对真实错误无增益，或随机有效变异同样好，则只作为评价工具贡献。

**难点与边界。** 需要有效正负干预对、替代合法设计和原始请求标签；开放场景不能把“与一个参考模型不同”当错误。运行期 checker 只能看公共请求与当前 IFC；隐藏 Gold、变异配方、被删身份仅供隔离训练构造/最终评价，不能进入被测 repair 输入。暂估诊断 1–2 人周、公平原型 5–8 人周；未计正式用户研究与论文规模实验。这个方向最贴合当前自验证缺口，但先例压力很高，不把它排成唯一主线。

这轮建议把问题扩大到两个层面：**模型怎样选择可行的空间构成，以及怎样预见多个编辑动作相互影响。** 它们比上下文筛选更接近 AI 推理问题，但“图＋求解器”“搜索＋修复”本身都已有方法。实验必须隔离真正增加的决策机制。

#### 1. 五个新增全文近邻

##### B-SP01 — SceneMotifCoder：少样本抽取可复用空间程序已经成立

**来源。** Hou In Ivan Tam 等，3DV 2025；[arXiv 2408.02211v2 正文](https://arxiv.org/html/2408.02211v2)，2025-06-03 camera-ready 修订。读 §3–5 与附录相关说明。

**方法。** 1–3 个实例先转成逐对象位置程序，再通过观察、改写和回放检查，抽成带数量、尺寸等参数的 meta-program。推理时选一个 motif 并补函数参数；检索网格后另做碰撞、接触、支撑优化。meta-program 验证包含复现实例数量和对象间相对方向，已超过简单存代码示例。

**实验。** 202 条测试描述、50 类物体；人工分别检查数量、布局、物理合理性，报告 0.93 / 0.90 / 0.76，三者不是联合成功率。用户偏好实验另抽 20 个提示、60 个比较问题、31 名参与者。Table 2 有直接 DSL、无观察、直接示例替代 meta-program 的消融。

**限制和对照意义。** 主要是简单 motif，依赖预先整理的物体库；与文本生成网格模型相比，任务表示和资产条件有差异。文中还展示多个 motif 填充场景，不能声称它完全没有组合。我们的接口合成或能力复用必须超越“抽程序、参数化、再组合”。

##### B-SP02 — PSDL：已有保持程序关系的无 LLM 参数搜索

**来源。** Maxim Gumin 等，*Procedural Scene Programs for Open-Universe Scene Generation: LLM-Free Error Correction via Program Search*，[arXiv 2510.16147v1](https://arxiv.org/html/2510.16147v1)，2025-10-17；arXiv 元数据注明将发表于 SIGGRAPH Asia 2025。本卡依据预印本正文 §3–7、Tables 2–6。

**方法。** 相对坐标、共享变量、循环构成 PSDL。搜索只改数值常量与四种朝向，目标包括越界/碰撞/支撑损失和相对初始布局的变化成本；共享参数同时带动多个对象。每个常量抽十个扰动，朝向枚举四个，迭代选择改善候选。运行异常仍重新请求 LLM，因此“无 LLM 修正”只指布局错误阶段。

**实验。** 自建 70 个提示，加 Holodeck 的 66 个提示；人工比较使用自建 70 个，10 名参与者分两组。Table 6 平均剩余错误：PSDL 1.1、逐对象局部搜索 0.8、梯度下降 0.5；PSDL 的人类代理偏好更高。PSDL 修正平均 9.3 秒，LLM 自修 106.7 秒。它没有在所有指标上占优。

**限制和对照意义。** 对象清单和大小由共同上游给定，方向限四个；搜索不改对象身份、关系结构或程序分支。相近代码与小几何变化只是语义保持的代理，论文明确未覆盖完整通行、视线等功能。它是“保持关系的局部搜索”的强基线，不能只用逐对象坐标优化作对照。

##### B-SP03 — CADIR：构造图、局部子结构与稳定实体绑定已有近邻

**来源。** Yu Liu 等，*CADIR: A Cross-Backend Editable Intermediate Representation for Agentic CAD Generation*，[arXiv 2608.00891v1](https://arxiv.org/html/2608.00891v1)，2026-08-01。读方法全部小节、Algorithm 1、Experiments / Tables 1–5。

**方法。** 115 个显式操作记录参数、依赖、约束、拓扑选择与产生的变化。实体选择使用来源范围、几何谓词、数量要求；跨后端用几何签名匹配并拒绝歧义，支持边分裂/合并。双塔对比训练对齐查询与构造图；子图取特征所需的上游依赖闭包，图检索模型只在整图上训练。

**实验。** 生成 200 模型，DeepCAD / Fusion 360 各 100；同 Agent、GPT-5.4 和文档条件比较表示。文本无检索 / 整图 / 整图加子图的 IoU 为 0.2702 / 0.2837 / 0.3064。检索另有 4K 训练、4K 测试；生成时案例库为独立 100 例。跨后端是独立 100 模型、30,466 构造节点、294 个编辑任务，不能混为同一分母。

**限制和对照意义。** 部分后端缺原生可编辑操作；跨后端几何不完全相同。生成成功率与独立用户要求满足不是同一件事，文中没有全流程成本匹配结果。构造图、可靠绑定、依赖子图复用均不能单独宣称新意；检索增益还包含新训练。

##### B-SP04 — TraceCAD：有条件、带负例的 repair 技能也不是空白

**来源。** Fengxiao Fan 等，*TraceCAD: Trace-Guided Repair for Agentic CAD Generation*，[arXiv 2608.03062v1](https://arxiv.org/html/2608.03062v1)，2026-08-04。读 PDF pp.2–7 的完整 Method、System、Experiments、Discussion，以及 Algorithm 1。

**方法。** 要求、执行步骤和失败证据持续绑定；疑似步骤加上游 1 跳作为编辑区，可扩到 2 跳，下游另行检查。每次最多 3 候选、2 个目标步骤。技能明确保存适用签名、原因、策略、补丁、验证证据和成功/失败复用统计；错误复用会降低排名。保全主要依赖视觉 shape-delta 反馈，不是几何等价证明。

**实验。** 200 模型消融，1K 模型对比；Agent 基线共用后端模型，消融共用重试预算。在 200 例上，去局部搜索的 Recovery Score 0.4865，完整冷启动 0.9167；这是按后续调用数加权的恢复分数，不是任务成功概率。冷启动评测允许先前测试任务形成技能供后续任务使用；warm-up 另用 1K 个互斥训练模型。前者属于有顺序的在线评测，不能写成冻结记忆的独立测试。

**限制和对照意义。** 功能步骤切分与视觉归因会错，冷启动结果受顺序/调度影响；成功导出与几何忠实分开。旧“条件化修复规则跨任务迁移”候选应降级。若继续做动作推理，应研究它未直接隔离验证的**多步效果交互与搜索顺序**，并直接复现同预算局部搜索作为基线。

##### B-SP05 — Graph-CAD：图分解、动作规划和能力边界课程都有直接先例

**来源。** Shengjie Gong 等，*Learning Hierarchical and Geometry-Aware Graph Representations for Text-to-CAD*，ICLR 2026。[正式 PDF](https://proceedings.iclr.cc/paper_files/paper/2026/file/90e06fe49254204248cb12562528b952-Paper-Conference.pdf)。读 §3–4、Tables 1–3、Appendix C.4、D 的相关实验。

**方法。** 三阶段是几何分解图→动作序列→bpy 代码。三个 Qwen3-8B 模块做 LoRA；SAPCL 生成易/中/难结构变体，在能力边界及稍难处补数据，再训练。也比较冻结通用模型的两示例三阶段推理，不能说全部改善只能靠训练。

**实验。** BlendGeo 约 12K 数据，90/10 训练/验证；CADBench 700 例。但 GCS 只基于其中 **280 例、约 500 条人工几何约束**，利用部件名称匹配和数值几何检查，并非全部 700 例的联合成功率。Table 3 有去图、去动作计划、直接生成；Figure 6 的课程对照匹配每轮数据量。训练每轮约 30 小时数据合成＋双 A800 上三天微调，共四轮。

**限制和对照意义。** GCS、图精度与 VLM 外观分数不同；复杂有机形状和精密装配仍失败，训练与评测部分共享 VLM 判别方式。不能把“分层图＋动作规划”或“按当前能力边界造题训练”重新命名为新方法。对冻结模型的研究，应与其三阶段提示版本比较。

#### 2. BS-H1：多步编辑效果与相互作用模型

**问题。** 一次编辑可改善目标 A，却使下一步的宿主、引用或几何条件失效。局部修复逐次成功，仍可能无法完成一串修改；也可能反复试验只是顺序不同、结果相同的操作。这个问题连接 generation 与 repair：从空模型到目标模型、从现有模型到新要求，都是带历史约束的状态转移。

**候选机制。** 不预测整份 IFC，而为受支持操作提炼显式前提、增加/删除的关系、受影响的几何范围，并在少量受控执行中探测操作对的效果。区分可交换操作、互相覆盖操作、需要合并执行的耦合操作；据此搜索短计划，并合并已确认效果等价的排列。第一次可以完全使用现有模型与符号记录，不训练神经网络。关系效果不能只看代码变量读写：共享宿主墙的两个开口在变量层面独立，几何范围却可能冲突。

**潜在增量在哪里。** WorldCoder 已有程序化转移模型，TraceCAD 已有有条件技能和局部搜索，传统规划已有前提/效果和部分序消减。可能的研究增量是**从执行中识别语义与几何之间的操作交互，并将可信交互用于计划压缩/重排**；不是“使用世界模型”。如果手工标注效果即可完成全部工作，方法贡献需要重新评估。

**具体任务。** 同一面墙先扩窗后增加门；先补宿主/开口关系再恢复 filling；多次修改下保持其他 openings 和楼层归属。原生删除、移动等能力若当前未支持，应在新研究动作层明确增加，不能假装已有。

| 固定实验臂 | 要隔离的作用 |
|---|---|
| 普通 ReAct coding agent；TraceCAD 式同预算 1–2 跳局部搜索 | 不是只胜过 one-shot 或无反馈基线 |
| 同一动作集的 beam search / MCTS，全量真实执行候选 | 预测效果是否值得，还是精确执行已足够便宜？ |
| WorldCoder 式单动作效果模型＋相同搜索器 | 新意是否来自动作交互，而非加一个预测器？ |
| 候选去交互项、去等价排列合并、全部候选；人工精确效果作诊断上界 | 哪一机制有必要？自动抽取能否接近人工上界？ |

**评测。** 冻结 2/4/6 步计划任务，按建筑家族与操作组合留出；报告最终全部要求成功、每步非目标关系保持、错误剪枝、执行/模型调用总成本、首次效果学习成本和后续累计成本。不能只统计被接受的计划。所有方法拥有同一检查器与动作权限。

**否定条件。** 同预算精确执行搜索同样好；交互模型漏掉共享几何效应；错误判为可交换而剪掉唯一有效计划；收益只来自人工效果标注。遇到这些情况就不主张方法新意。任何状态合并都必须保留用户要求、身份和既有几何差异，不能因为图片相似就合并。

**保守工作量。** 受支持的 3–4 类动作、短计划判别原型约 **3–5 人周**；可信效果抽取、组合留出评测与端到端接入约 **8–14 人周**。这是估计，不含重新训练大模型和无上限扩展动作库；多人的人周不等于同样长度的日历周。

#### 3. BS-H2：由几何冲突驱动空间拓扑与构造分解的联合搜索

**问题。** 有些失败不是坐标写错，而是房间连接、宿主选择或构造分解选错。固定关系图再怎么改数字也不可行；直接重写整份代码又浪费已正确部分。当前故事可以改为：**LLM 提供语义上合理的结构候选，几何证据决定哪些结构应该保留、替换或重新分解。**

**候选机制，不能省略的部分。**

1. 把用户已指定的关系冻结，把真正允许选择的宿主、连接、模块分解和共享边界列成离散决策；几何尺寸和位置是连续/整数变量。
2. 对一个结构候选求解几何。当得到可核查冲突时，将冲突变量沿生成来源映射到**造成冲突的结构决策**，形成带适用条件的禁用组合或局部重写请求。求解超时/数值失败只能记未知，不能冒充不可行证明。
3. 根据这些语义层冲突，重新选择宿主、连接或分解；保留与冲突无关的可行部分。共享参数的数值修正仍交给 PSDL 式搜索或求解器。这里真正可测的是“冲突怎样被提升到结构选择”，不是固定图上再接一个 solver。

**具体任务。** 给定外边界和房间需求，要求若干房间通过走廊相连；给定多层空间，楼梯与楼板开口必须形成可行连接；两个模块组合时决定共享墙还是各自封闭边界。先限制正交布局和已支持 IFC 类，避免一开始混进复杂自由曲面。

**最强反对意见。** 离散连续联合优化、CSP/SMT 禁用组合、冲突驱动回溯、任务与运动规划都是已有思想。AIDL 已会逐层开放自由度；Graph-CAD 已预测层次和动作；SceneMotifCoder 已抽取和组合程序。此候选最多是**利用自然语言生成来源，把底层几何反例用于上层语义重分解**的待证机制；缺乏直接对照时不能认定方法创新。

| 固定实验臂 | 目的 |
|---|---|
| 普通 coding agent；Graph-CAD 式两示例图→动作→代码 | 排除结构化提示本身造成的改善 |
| SceneMotifCoder 式模块程序＋LLM 拼装，使用相同组件和示例 | 排除程序复用本身造成的改善 |
| PSDL 式保持结构的参数局部搜索；AIDL 式逐层开放 | 检验任务是否真的需要改变拓扑，而非更多数值搜索 |
| **同一变量/约束的全局 CP-SAT/SMT/MILP 或合适几何求解器**，以及枚举结构＋数值求解 | 最重要的强基线：若标准求解器直接做得好，不能把领域封装当新 AI 方法 |
| 同样数量结构候选的 best-of-N/beam search；随机重分解；只有原始数值冲突；候选语义冲突提升 | 隔离候选的反馈与结构重写机制，匹配全部尝试成本 |

**评测。** 按三类任务分别报告：只需数值修正、必须换结构、需求本身不可行。每类按未见空间组合留出，严格计最终几何＋关系＋用户目标的联合成功，以及误报无解率、错误删要求率、无效结构重复次数、求解调用/时间和 LLM token。可行任务要有独立的可行证据；不可行任务只在受限形式系统中使用可核查证明，不从“所有 Agent 都失败”定义无解。

**可证伪结论。** 若收益来自增加候选数、标准全局求解已占优，或冲突提升无法优于原始反馈，应放弃当前机制声明。若只能在人工指定上层结构变量时有效，先写受限问题方法，不能声称从任意用户文本自动理解全部拓扑。

**保守工作量。** 小型正交场景、一个可行性求解器和两类结构重写原型约 **4–6 人周**；稳定的来源映射、跨实例冲突抽象、真正的组合泛化实验约 **10–18 人周**。它是更有思想空间、也更依赖新表示和求解层的方向。

本轮只做窄范围源码阅读，不根据文件存在宣称能力通过测试。

#### 5. 本轮取舍

- 优先做 **BS-H1 的短计划判别实验**：当前 repair 操作与执行证据更接近所需基础，但应停止把一般技能记忆当新颖性。
- **BS-H2 是更值得保留的神经符号方法方向**：关键实验必须包含标准全局求解、PSDL、AIDL，以及同预算结构采样。先证明存在“固定结构怎么调都不行，但受控结构重写能解决”的任务切片。
- 本轮不再把“自动学习可复用空间模块”单列第三点：SceneMotifCoder、CADIR、Graph-CAD 已有充分近邻。若后续研究接口自动合成，应作为 BS-H2 的结构重写机制，并与手工接口上界比较。
- 检索到 SceneCode / State-CAD 等额外线索，未在本轮展开到同等正文深度，不计入五篇全文卡，也不据此断言方法空白。



### 从可执行环境学习能力：Generation + Repair 的两条候选

2026-09-15。范围：动作效果学习、跨任务训练、自动课程。本轮核查 4 篇原始全文的方法和实验，以下均为待检验方向，没有新能力实验结果。没有调用 Provider，也没有修改产品或数据。起点为现有 `frontier-spatial.md` 的 WorldCoder、CAD 约束学习证据；不再把修复经验存成技能库作为主线。

**判断：可以提出更偏 AI 的问题，但“收集生成与修复轨迹一起训练”“让执行器自动出题”本身都已有充分先例。更值得研究的是：模型是否能学到可组合的操作效果，以及怎样的训练任务能让这种效果知识迁移到未见关系组合。二者目前都还不是已成立的 novelty。**

#### 1. 最强近邻及其限制

##### L1 — CWM: An Open-Weights LLM for Research on Code Generation with World Models

[原始全文，2510.02387v1，2025-09-30](https://arxiv.org/html/2510.02387v1)。本轮读 §2、§7.1–7.2、§8.3。

学习对象是代码执行后的状态和工具环境响应。32B 模型的中期训练含 120M 函数追踪、3M Agent 轨迹；后者保留成功和失败，并训练预测动作及环境响应。§7.1 的受控实验使用 8B、总计 7T token：加入执行追踪后 CruxEval-O 从 44.6 到 73.9，但 SWE-bench Verified 从 18.6% 到 18.4%；再加入 ForagerAgent 才到 22.1%。最终 32B 在全部 500 题上单次尝试平均 53.9%，65.8% 是 16 个候选及额外测试选择的结果。

**冲突与启发：**“学执行语义而非代码文本”已被明确提出。更会预测执行，不保证更会完成任务；必须证明所学关系效果实际改善规划或生成。论文未证明小规模 IFC 数据足以重现效果，其大规模训练不能当作本项目已有前提。

##### L2 — Absolute Zero: Reinforced Self-play Reasoning with Zero Data

[原始全文，2505.03335v1，2025-05-06](https://arxiv.org/html/2505.03335v1)。本轮读 §3–4、Appendix C、D.1–D.3。

同一模型同时出题和解题，Python 执行器构造并验证程序、输入、输出三类推理任务；出题奖励偏向部分可解的问题，用多任务 REINFORCE 更新权重。主实验是 Qwen 7B，另有 3B、14B、Llama 8B；评估 3 个代码、6 个数学基准，v1 主表未逐项列出题数，不能把 9 个基准当 9 道题。7B-Coder 综合均分提高 10.2 点。消融中不训练 proposer 只降 1.4 点。

**最相关负结果：**Appendix D.2 已尝试组合旧函数形成课程，未见显著收益，常退化为 `f(g(x)) = g(x)`；论文还提出用执行检查排除捷径。因此“组合课程 + 非退化检查”也不是可直接占据的空白。其零数据指无新增人工题库，仍依赖预训练模型和人工设计的任务/奖励。

##### L3 — SWE-smith: Scaling Data for Software Engineering Agents

[原始全文，2504.21798v1，2025-04-30](https://arxiv.org/html/2504.21798v1)。本轮读 §2–4、§6。

先建立可测试代码环境，再通过模型改写、AST 修改、组合错误、回退 PR 产生训练题；执行确认确实破坏既有测试。128 仓库约 50K 任务，从 20K 次专家尝试得到 5,016 条成功轨迹训练学生。32B 在 SWE-bench Verified 的 500 题上单次成功率 40.2%；另测 Lite 300 题。

**冲突与负证据：**自动破坏—修复、组合错误、执行筛选、成功轨迹训练都已做过。§4 固定每组 500 条训练轨迹，四档难度在 Verified 上为 12.4/10.8/13.6/12.2%，没有“更难即更有效”的趋势。将测试内容放入问题还改变了学生行为。迁移取决于数据分布和监督形式，不只取决于修复题难度。

##### L4 — Hybrid-Gym: Training Coding Agents to Generalize Across Tasks

[原始全文，2602.16819v1，2026-02-18](https://arxiv.org/html/2602.16819v1)；[作者代码及 ICML 2026 标注](https://github.com/Hybrid-Gym/Hybrid-Gym)。本轮读 §2–4、Appendix A.3。

通过函数定位、问题定位、依赖搜索、函数生成等辅助任务，训练与目标任务共用的探索、推理、文件修改能力。4,470 条轨迹、762 仓库；训练 7B/32B，在问题修复、测试生成、库生成上测迁移。32B 的 SWE-bench Verified 从 7.0% 到 32.4%，另两类分别提高 7.85/5.11 点。Table 5 有每种辅助任务 500 条、修复 491 条的对照；§4 部分机制消融仅在筛选的 Easy 50 上完成，不能当完整基准结论。本文未清楚列齐另两个主测试分母，此处不补猜。

**冲突与启发：**跨任务数据混合不是新意；输出接口、真实探索和轨迹结构本身会产生大影响。作者 7B 训练使用 8 张 A6000、32B 使用 2 张 H100，不能假设微调完全没有资源代价。对 text2IFC 必须控制输入表示和动作接口，否则所谓迁移可能只是学会格式。

#### 2. 候选 A：学习操作效果的组合，而不只判断最终对错

**问题。** 当前生成与修复都能获得“动作前状态—动作—动作后状态”。能否从中学习：动作直接改变哪些事实，以及多个动作合用时会额外影响哪些已满足的要求？例如共享类型的材料修改会影响多个构件，后续只修一个实例的类型关系，又会改变受影响范围。这个问题涉及关系传播与操作次序；仅预测 JSON 合法与否不足以回答。

**小机制。** 以构件角色和关系组成状态图，训练一个小模型分别预测新增事实、失效事实、应保持事实；为二步操作增加“组合后额外变化”的预测，而不是简单累加两个单步效果。用同一动作作用于不同背景场景的配对样本，惩罚把无关构件变化当作必要效果。推理时固定当前 LLM，效果模型用于比较短计划；最终仍通过真实执行检查。

可先仅覆盖 generation 和 source repair 都有明确操作语义的类型、材料、属性及相关关系。两套接口不应直接拼接原始 JSON；共同事实层及动作映射是新增组件。任何几何修改先限定于已支持的 generation 操作，不能把源 IFC 修复范围偷偷扩大。

**可能增量。** 不在“使用世界模型”，而在**可迁移的关系效果表示及其组合监督**。CWM 是强近邻；普通图动力学和组合世界模型也是待进一步核查的近邻，当前调研不足以证明原创。若最后只训练一个成功率分类器，应降为工程基线。

**对应实验。** 先冻结同一 LLM、候选动作、搜索宽度和总调用预算。训练场景与建筑家族隔离；训练单步/部分二步，测试未见的操作组合、不同次序和更长的 3–5 步计划。比较：①普通成功/失败 critic；②直接序列效果预测；③只累加单步效果；④所提组合模型；⑤同预算真实执行搜索。除联合任务成功率，报告遗漏副作用率、保持条件破坏率、逐步预测误差增长及全部尝试成本。另做生成训练→修复测试、修复训练→生成测试，确认是跨任务迁移。

**推翻条件。** 改善只发生在见过的组合、只能预测最终分数、或真实执行搜索更快且更准，都足以否定主要动机。IFC 编译器已是精确环境，不能仅为贴“世界模型”标签再学一遍便宜的确定性运算。

**投入。** 一周先做离线小样本诊断，确认是否存在长程副作用和昂贵检查；通过后约 4–7 人周做状态/动作记录、事实差分、小模型、组合划分与搜索对照。初步数据量级可规划为数千至数万条转移，具体需求由学习曲线决定；固定 LLM + 小图模型/编码器可先用单卡探索，不等于已有显卡满足要求。若改为生成器辅助损失微调，需另建训练路径与资源预算。

#### 3. 候选 B：按“对未见组合的学习进展”选择训练题

**问题。** 一个系统已经会单独创建、绑定和修改对象，却在它们组合时失败。继续增加随机样例或难题，是否真的有帮助？目标是让环境发现“哪类练习能让下一种组合能力进步”，而不是不断生成更大的模型。

**小机制。** 从合法训练模型及可执行解构造生成、补全、修复三类题；先通过执行确认目标可达且组成操作确实相互影响。维护训练内部的组合验证集，按短轮训练后各组合能力的实际进展分配下一批题，并将退步和轨迹采集成本计入选择。对已掌握操作引入新关系背景，主动区分“单操作不会”和“组合不会”。最终盲测建筑家族和组合均独立，不用测试集反馈调课程。

**可能增量与风险。** AZR 已覆盖可解性驱动出题及组合课程，SWE-smith 已覆盖合成复杂修复题，Hybrid-Gym 已覆盖辅助任务迁移。真正待验证的是：**识别组合失败后，选择能纠正该组合缺陷的训练任务，比难度、失败率或均匀任务混合更有效。** 课程选择器若只是标准 bandit，应如实写为实现；AI 方法新意仍取决于组合缺陷表征与训练效果预测是否独立成立。此方向风险高于 A。

**对应实验。** 相同初始开源模型、训练 token、优化步数和总数据生成预算，比较随机合成、SWE-smith 式错误组合、AZR 式部分可解难度选择、均匀多任务 SFT、仅按近期失败率选题及候选课程。固定测试生成/修复双任务，分开报告已见操作、未见组合和更长计划；画训练成本—联合成功曲线。去掉组合缺陷表征、去掉跨任务选择分别消融。若仅增加采样量可解释收益，或只在课程内验证集提高，就不支持能力扩展结论。

**投入与前提。** 冻结闭源 API 模型时只能评估题库与推理策略，不能宣称权重学习。真正的课程学习至少需要可训练的生成器或策略。先做单轮对照 SFT，约 6–10 人周；开放 7B 模型的 LoRA 是候选，不是保证够用的配置，长轨迹可能需要多卡。在线 RL 会再增加 rollout 服务、并发执行、奖励校准及持续重评成本，不宜直接作为 WWW Demo 的少量补强。

#### 4. 共同评估边界与建议

训练可以使用合法训练样本的解和执行结果生成监督，但私人测试 Gold、破坏配方及其派生事实不能进入 Agent 的实际输入。程序生成的要求与同一程序检查的结果不能独立证明自然语言理解正确；盲测还需从原始要求独立标注语义约束。保持几何、模式合法、关系正确、用户要求满足必须分别报告，再报告联合成功；全部失败和数据生成失败计入成本。

建议先做 A 的离线诊断，验证“单步懂、组合不懂”这一缺陷是否真实存在，以及精确搜索是否已经足够。若有稳定的组合缺陷和可学习结构，再做 B 来扩展能力。**二者不应为了凑三点创新同时上马；一条经强对照支持的方法，比三个通用模块更有论文价值。**
