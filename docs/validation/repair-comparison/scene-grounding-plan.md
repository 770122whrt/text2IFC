# Repair 场景定位修改计划

2026-10-07，用户已批准上一轮链路审查中的修改。范围是 B 的公共 IFC 场景定位；五道正式题只审题和离线检查，不参与调试或模型调用。

## 目标和实现边界

第一阶段同时接收原自然语言请求、公共损坏 IFC 的精简场景以及受支持操作目录。场景只来自当前 D：楼层与标高、世界坐标与单位、构件类别、宿主／洞口／填充关系以及参照构件。Name、GUID 可以作为系统内部引用，用户不需要提供。

新增只读、有限轮次的场景查询，按类别、楼层、宿主和空间范围补充构件；返回省略数量与完整性，不能把截断的邻窗列表当成完整排序。模型保留坐标、排序和参照关系，程序验证所引用身份确实在已提供场景中，并计算两点中点及墙局部偏移。

保留既有 RepairIntent、语义授权、Bound ChangeSet、确定性执行、回滚和产物评分。新场景响应使用独立版本的 Prompt／Schema；不改已注册版本。以明确的 scene 模式接入 API／实验 B，旧任务和旧运行继续按原合同读取，不能在待答任务中悄悄换方法。新增 B 开发尝试单独标注方法版本；旧失败不覆盖，也不合并成正式成绩。

## 判定标准

用户原请求无需补充直接 Name／GUID。窗题由公开现存窗确定排序与中点，程序算局部偏移；门题由世界坐标／标高确定现存空门洞，保留既有洞口并补门。参照外观的身份也必须来自公共 D，不能只恢复数量。

同尺寸多对象不能随意取首个。模型引用未提供的身份、需要的邻窗列表不完整、坐标依据未知或预算不足时不得发布。用户意图不唯一才提问；系统不能查询不是用户缺事实。

本轮验证属于功能回归与开发可运行性，不宣称系统级能力提升。不运行仓库 Full Preflight。用户已取消本轮重启安排。

## 已实现的链路

```text
公共 D → 原生索引＋精简场景
请求＋楼层/标高/坐标/关系 → 模型有限只读查询
已提供的目标、参照 Type、世界点或相邻序号
→ 身份核验＋程序推导墙局部位置
→ 原 RepairIntent 的路由/参数/语义检查
→ 必要人工澄清（同一任务恢复）或 Bound ChangeSet
→ 确定性应用＋回滚＋重新打开＋评估＋唯一产物发布
```

当前方法为 `text2ifc/ifc-scene-grounding/0.2`，对应新 Prompt/响应 Schema v0.2；v0.1 保留为开发合同历史。原 RepairIntent 0.10、TargetQuery 0.1 和既有操作参数没有改版本或放宽验证。场景最多 80 构件/页、8 轮，累计上下文有字节上限；耗尽明确终止，不能要求用户代查 Name/GUID 或提供墙局部偏移。

入口：`RepairAPI(..., scene_grounding=True)`；产品 CLI 的 `start --scene-grounding`；实验 CLI 的 `init --scene-grounding --arms B`。API 上下文、B 任务绑定和实验账本记录方法。恢复读取已存方法，禁止中途切换；旧运行默认沿用旧合同。

参照构件的 `type_id`/Type 摘要来自公共 D。其现有映射几何用于窗框、分格、玻璃和门扇复用，实例属性复用不冒充几何复用。离线完整链路发现旧安装逻辑以“窗相对洞口”的朝向投票；进口洞口的轴向可相对墙反转，从而翻转不对称的框和玻璃，边界框却仍正确。已保存红测产物，并改成相对宿主墙轴的方向，以同墙现存窗优先；同墙方向冲突明确拒绝。米/毫米、反向洞口、跨朝向及冲突族回归通过。
