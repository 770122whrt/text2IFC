# B Harness 当前链路与支持边界

更新：2026-10-12。B使用仓库自有`RepairAPI`，当前真实提交、评分与待评统一见[当前实验表](../../../dataset/processed/experiments/repair-comparison/current/README.md)。最新005已评通过，007保持失败；后十题提交不等于评分通过。此表包含已揭示案例的开发复测和版本差异，不能当作同版本、未见样本的四组能力提升证据。定位与反馈的最新开发试验从[实验入口](README.md)查看；旧表保留各次运行的原版本和结果。

## 公开场景到唯一发布

原始公开请求＋公共损坏IFC D → 本地索引和精简场景 → 模型有限只读查询 → 核验已公开的目标、参照和位置 → RepairIntent、确定性绑定与语义授权 → 模型ChangeSet → 从原D原子应用 → 重开、L0/L1/L2、原请求几何核验和保全 → 唯一正式发布。

当前场景方法与 Prompt 为`text2ifc/ifc-scene-grounding/0.7`，响应 Schema 沿用 v0.4，公开几何编译器为 v0.3；旧版文件、RepairIntent 0.10、TargetQuery 0.1及已注册操作合同不改写。API用`scene_grounding=True`，CLI用`--scene-grounding`；旧任务须使用原冻结运行包恢复，新代码拒绝静默迁移旧方法。查询默认40、最多80构件/页、最多8轮和384KiB上下文门限保持。程序可检查完整集合，只公开指定序号和覆盖证据；未知几何或真实歧义不按首项猜测。

本地程序读取完整公开D，模型接收概况和去重后的查询事实、共享类型及覆盖摘要；源G、损伤配方、删除身份和私有评分不进入模型或B挂载。summary查询不展开Body细节，必要时再按已返回身份查询geometry。减少传给模型的内容不等于不读取IFC；真实模型token节省比例尚未测量。

## 结构、属性与限制

当前结构支持水平直梁、竖直柱和矩形截面补建；不支持斜／曲／变截面、圆/I/H截面、移动既有梁柱或自动逐层拆柱。柱归属柱脚楼层，参数使用楼层局部坐标。007的跨层高度基准导致OPENING_OVERLAP拒绝并回滚，用户接受该失败，未发布错误位置的窗。

属性覆盖适用标准单值Pset，以及经过预览哈希确认的自定义单值实例属性，不改共享Type、不扩成任意字段或Quantity。精确指定的现存属性直接解析，模糊属性名称才进入RAG；RAG不替代既有实例的类型证据。对请求明确、目标集合及既有值类型可从公开输入核验的修改，实验宿主可按用户委托规则答复原确认接口；不把程序核验写成人工逐题审阅，缺项或歧义继续澄清。开关与记录方式见[批量脚本](README.md#批量脚本)。已有CPU属性镜像复用BGE/Qdrant与只读4.59GB模型缓存，独立任务缓存；构建已获准并完成，不增加新模型。真实Linux＋假Provider包含中文、持久澄清、共享属性、混合和回滚路径；属性状态卷导出／导入尚未单独原生核验。

有效单位从属性事实进入索引、确定性解析、公开确认预览和写回语义；不等于模型收到全部属性或单位图。几何定位使用的毫米坐标与既有属性单位分开，不能用坐标单位解释所有属性值。此次单位修复的离线公共API测试包含默认／显式单位、保全及拒绝边界；真实复测状态见[当前开发记录](../../../.tmp/repair-formal-1200-20261011/cycle/README.md)。

几何校准覆盖明确基点、尺寸和旋转的矩形梁柱，以及具有精确公开参照的门窗。门窗支持同向或相对180°平面旋转：窗复用参照完整几何及洞口相对变换，门可填充现存保留洞口，也可复制已核验参照门及其洞口安装到目标墙。其他旋转、非直立安装和缺失必要公开依据仍拒绝。参数由公开D重新核验，最终检查实际世界位置、朝向、尺寸和关系；普通自然语言继续走原定位路径，不代表任意表述均可解析。

梁新增受限的精确公开参照复制通路：只接受单 Body、单矩形截面拉伸体的水平直梁，同向复制；保留内部变换、偏移和实体样式，为新梁建立独立表示容器和 ObjectPlacement。程序按实际 Profile 轴向测量截面，最终核验 Body 图、网格和世界放置。缺失／重复参照、非矩形／多 Body、洞口扣除或结构分析关系、显式外观覆盖等未实现情形仍拒绝，不能用包围盒替代。普通梁柱的显式矩形参数重建保持原路径；此次公开实物及假模型 API 验证见[机制冻结收据](../../../.tmp/beam-copy-validation-20261011/scoped-freeze.json)，真实回测和完整批次冻结状态见上方开发记录。

011～020的唯一题意与接受状态见[正式题包](../../../dataset/processed/ifc-repair/repair-comparison/formal/README.md)：技术接受为`accepted_by_delegation`、`human_viewed=false`。015恢复源中真实梁Reference文字，016恢复真实柱FireRating文本，不能补造单位或源属性。014截面朝向、019柱平面位置、020窗洞底标高由事前私有答复卡提供，仅回答实际提问；不整卡预发，也不从私有G临时补答案。

## 最终检验回到 ChangeSet

B的入口是仓库自有`RepairAPI`与Repair Harness；本文回环不接入官方DSH。官方DeepSeek Harness的Python SDK与完整运行时属于D组，见[D配置](deepseek-harness-integration.md)。

用户确认本次修改指B的最终检验阶段。`RepairAPI`现在默认最多2次检验后修正，可显式设置0／1／2；实验新冻结配置登记`b_validation_corrections=2`，旧配置缺该字段时隔离B执行器仍使用0，旧任务不会因续接获得额外次数。

链路为：ChangeSet → 从原D应用 → 独立检验 → 失败诊断写入已有`VALIDATION_FEEDBACK`提示词变量 → 重新生成ChangeSet → 从原D重新应用并检验。初始候选加最多2个修正候选；原Provider与HTTP账本持续计量，格式重试也计入。每次ChangeSet、候选、报告和原样Provider记录独立保存，最终只发布一个终态。重复可执行ChangeSet会停止，单改draft ID不能绕过；中途崩溃保留证据并终止诊断，不自动重放收费调用。

反馈由生产检查ID、失败状态、对应操作及已绑定公开目标生成。位置可附当前授权的墙内偏移、窗台高度等；不转发评估自由文本、Gold期望值或私有身份。提示词内容采用“错误是什么、发生在哪个操作和目标、保持原公开绑定重新生成”的形式。第一版不自动给具体修复方案，减少建议本身引入错误的机会；注册提示词版本未改写。

只有应用与保全通过、L1／L2检查可测且反馈可用才回流。源变更、越权、保全失败、格式／重开安全门失败、检查无法测量等仍停止。这个回环保持RepairIntent、定位、授权尺寸和语义事实不变，因此无法修正错误Intent或确定性应用器缺陷；重复失败仍作为负面证据保留。当前真实实验表保持原运行版本，本轮没有重跑正式题或添加模型成绩。

代码：[API](../../../src/text2ifc_ifc_repair/api.py)、[Orchestrator](../../../src/text2ifc_ifc_repair/orchestrator.py)、[Provider阶段](../../../src/text2ifc_ifc_repair/provider_stage.py)。离线机制测试在[test_validation_correction_loop.py](../../../tests/ifc_repair/test_validation_correction_loop.py)，实验接线与旧配置边界在[test_b_validation_configuration.py](../../../tests/ifc_repair/repair_comparison/test_b_validation_configuration.py)。这些离线机制检查不是模型能力成绩。

## 定位反馈 v0.4

查询、参数构建与核验仍共用最多8轮。每轮反馈指出具体阶段、错误码和字段路径，并只附最近一次失败提案，避免模型从头猜。已有公开事实可以补查；确实缺少用户意图才澄清；明确不支持的几何和接口故障及时停止，不再一律记为定位耗尽。

简短诊断随现有状态账本、worker和`report.md`传递：记录轮次、阶段、错误码和查询数量，不增加逐调用导出日志。成功定位不等于修复成功，最终仍需通过产物校验与独立检查。旧运行没有保留的逐轮原因不反推补写。

## 定位 v0.3：实现与离线验证

最新随机抽样及只读检索核对见[当前 E 组结果](../../../.tmp/repair-e-random-20261010/results/README.md)。原失败保持原义。用户已批准并实现以下程序与新版本 Prompt 增量；构件向量检索仍为禁用扩展，属性 RAG 不等于空间定位。

本轮先冻结离线失败家族再实现：坐标原点／中心／包含点、旋转宿主局部位置、相对位移、空洞与关系、完整集合排序和同位歧义、部分几何未知、重复上下文、必要用户位置澄清与内部换算拒绝。根因假设分别是查询语法不能表达、全量页面重复输入、完整集合必须全量展示、位置澄清按字段类别误拒；针对性改变对应接口验证，不能从真实耗尽结果推断某一假设已经独立证实。共享公开 API 的假 Provider 成功、澄清恢复和失败无发布验证后再考虑真实模型准入。该节记录v0.3离线工作；后续v0.4反馈与参照几何扩展见上文，真实试验从实验入口查看。

现有定位阶段执行“描述解析 → 程序组合查询 → 候选事实核验”：

- 把请求中的构件类别、楼层、坐标、方位、参照和排序关系转成有来源的检索条件。明确基点与几何中心、世界与局部坐标，不另增一次必需的模型调用。
- 从公开 IFC 索引建立类别／楼层／宿主候选集合，再组合世界坐标、标签、相对位移／距离、宿主局部范围、空洞、真实填充／开洞／空间边界关系。`select`支持世界轴、宿主轴和显式点角色的最近邻排序。按相关空间和关系取邻域，不按STEP行切块。
- 模型接收去重候选、共享类型和查询覆盖摘要。完整集合的排序由程序完成并核验；只公开指定序号也能用于后续定位。影响所选序号的同位／同距按原有0.001mm严格阈值拒绝，无关远处的并列不阻断唯一目标。已验证查询范围会传给坐标绑定，不能由另一楼层的无关未知几何误阻断。
- 公共事实未读到时补查；真实缺少设计位置／尺寸或观察方向时澄清；内部坐标参考、已给世界坐标的换算、工具故障不能伪装为用户缺项。重复查询返回无新增证据反馈，仍计入原8轮上限。
