原因有三层：

1. T1只在确定性检查和修订证据内找完全相同的字典/数组，不处理请求、Brief、候选、metrics之间的重复。C还没进入ChangeSet修复，没有历史修订副本；B此前有收益的是修复后的Audit。
2. 在既定范围内，512字节与128字节阈值都找到0个重复对象。降至32字节找到20个小对象，但不能把其重复体积直接当收益，引用、表项及说明也占空间。
3. 当前没有可替换的大对象，实验格式增加931字节，所以177865变成178796；系统回退到177865。这是正确的无收益回退。

扩大到全部已发送字段做只读调查，可找到21个至少512字节的重复对象；最大为13017字节。重复对象可能嵌套，不能直接累加。该结果指出后续候选方向：跨字段无损引用、重复语义参数的共享表达、阶段依赖投影；尚未测量它们的净节省或真实质量影响。

因此，上轮“没有重复”的简略说法需要限定为“当前算法范围内没有可获益的重复大对象”，不能推广到完整pipeline。源码诊断入口：`scripts/agent/diagnose_audit_context.py`，重建消息与原request逐字比较。
