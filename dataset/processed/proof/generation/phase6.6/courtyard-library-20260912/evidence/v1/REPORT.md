## 当时提出的小步范围（已按下节实施）

1. **先收紧并校验语义角色。** 针对通用的Type定义/实例绑定、单材料/分层材料作用域、模板应作用于哪些对象，冻结正反/跨类别/冲突案例族。新增合同或Prompt版本；保留旧版本，不取消现有门禁。Type不能自指或串类别，材料不能停留在文字或错误作用域。
2. **只恢复获准的错误字段。** 在明确错误位置与权威映射后，用绑定原Brief的局部修改或受限迁移恢复；冻结几何、数量、位置、名称及已有合法语义。不能把本案例坐标、答案或独立评价器注入模型，也不能自动把不确定的材料意思改成猜测值。
3. **补通用屋盖开口投影。** 同时检查身份表、分包ownership和几何预期；用平移/不同尺寸的板与屋盖案例证明开口真实保留。不能仅靠手写编译探测宣称公共链路支持。
4. **随后恢复真实生成。** 继承本次71,204 token账本，剩余31个调用槽、1,928,796 token、3,422.875秒活动预算。原尝试不覆盖；该案例已是开发后重试，不是盲测。

这次没有测得token优化收益。短期不提高输出额度：49864尚未触顶，增加额度不能修复字段职责。后续若做压缩，优先考虑版本化的共享材料/模板定义加显式成员引用，由确定性投影展开；本次90条语义记录和重复构造说明提供了诊断线索。收益必须在同一固定请求和独立质量检查上测量，不能用字符减少直接冒充token收益，或通过删除要求省token。现有staged主要拆Generator，不能解决发生在它之前的Brief提取问题。

## 2026-09-12 局部修复结果

之前的相关修复：`2231c06b` 要求先有完整语义权威，防止提取遗漏变成“用户没有要求”并清空候选；`06abe9bd` 校验可执行的外观格式；`3abadabe` 在冻结前拒绝错误材料格式。这次旧门禁仍准确拦截了响应，没有证据说明上述保护退回了旧行为。

本次暴露的新边界是：Prompt 要求规范化，但自由结构的 known_facts 仍可容纳散落字段；旧恢复只允许改两个标准语义字段。光庭案例同时要求共享 Type、分层材料和屋盖洞口，使角色混用与不完整投影一起暴露。当前小步修复分为三个部分：

1. **在 Brief 2.4 冻结前验证角色。** 实例只能绑定兼容类别的 Type；拒绝 Type 自指、Type 绑定 Type、同一实例多个 Type，以及不唯一的语义定位。基础门窗模板只作用于对应实例；材料区分 Type 层定义、实例层用法和直接／继承作用域。同一目标同一作用域的材料或属性冲突须返回 Brief，不能静默选值。未用于全局语义定位的楼层局部几何名称仍保持原合同。
2. **有界恢复散落语义。** 仅可移除明确识别的实例／Type 记录上的语义叶子，并在标准数组中保留其含义；身份、类别、几何、数量、父对象和其他字段冻结。材料名、层序和层厚不能丢；误放在共享 Type 上的模板必须保留给每个已明确绑定的实例。几何改动、少修一成员、改材料或丢 Type 都阻断，不发布部分结果。恢复仍是最多一次 Provider 校正，沿用完整 Brief 输出及共享预算；不是新的压缩协议。
3. **屋盖洞口传递与实际验证。** 屋盖的单个／多个开口进入同一身份表、跨层分包和几何预期；检查精确宿主、开口关系、位置及高度。适用的 IfcSlab／IfcRoof 探针经编译、重开和网格化后，带洞实体体积为3.04立方米；错误宿主负例被拒绝。没有修改光庭输入或手写一份整栋候选替代真实生成。
